## 1. 产品概述

### 1.1 产品定位

AI漫剧工作台是一款面向个人与小型创作团队的**长篇 AI 漫剧创作工具**，在本机运行，把一个故事从"世界观与角色设定"一路推进到"可播放的漫剧视频"。

它与普通 AI 写作工具的区别在于：**剧情不是一句提示词生成的，而是被"推演"出来的**。系统维护一套可计算的故事状态——角色性格、好感轴、境界、已知信息集、伏笔台账、待办后果——让第 1 集埋下的因，在第 40 集结出果，而不是每集重新开始编。

### 1.2 目标用户

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 独立漫剧创作者 | 一人负责设定、剧本、出图、成片 | 用一套工具走完全流程，不用来回倒数据 |
| 小型创作工作室 | 2-5 人，分工商定 | 状态层共享，换人接着写不跑偏 |
| AI 内容进阶玩家 | 熟悉提示词与本地出图 | 可控、可改、可追溯，不接受黑盒生成 |

### 1.3 核心场景

**场景一：开新坑。** 用户新建项目，填题材与美术风格，写下故事框架与主角的主线任务，系统在世界观页引导填入境界体系与铁律，随后开始推演。

**场景二：长篇滚动推演。** 用户选择"快进一个月"，系统跑出这段时间的主干事件；用户挑一条粗事件"细化"，摊成若干细事件；反复推进直到时间轴够长。

**场景三：编一集。** 用户在时间轴上圈定一段事件，指定视角人物与目标时长，系统产出剧情骨架（冲突、场次落点、转折、落点），用户改到满意后成立一集。

**场景四：写正文与过审。** 系统按上下文切片生成剧本正文，责编逐项审查六类问题；有问题打回重写，通过后写入分集，同时回写事件、角色状态、伏笔台账。

**场景五：出片。** 用户为某一集生成分镜，绑定场景空镜与入镜人物、道具，逐镜出图、出视频、配音、音画对齐，最后合成整集视频。

### 1.4 术语表

| 术语 | 含义 |
|---|---|
| 项目 | 一部漫剧的全部数据容器，包含角色、场景、道具、事件、分集、伏笔等 |
| 事件流 | 推演引擎产出的结构化事实序列，记录"发生了什么"，不记录剧本全文 |
| 粗事件 / 细事件 | 粗推跑出的时间轴框架事件，与回头细化摊开的子事件 |
| 剧情编排 | 把一段事件圈成一集，产出剧情骨架（冲突、场次落点、转折、落点） |
| 剧本 | 一集的正文，按场次分段，含环境描写、人物动作、台词 |
| 视角人物 | 一集从谁的视角讲述；同一件事换视角就是另一场戏 |
| 已知信息集 | 某角色此刻知道哪些信息；角色不得说出他不知道的事 |
| 好感轴 | -100（死仇）到 +100（至亲）的单一数值轴，双向各记一条；正端为心、负端为火 |
| 伏笔台账 | 记录伏笔埋于何时、计划何时回收、当前是否已回收 |
| 待办后果 | 种下的因到期才结的果（寻仇、报恩、举报、偷袭、结盟、拦路），到期未触发则顺延不销账 |
| 编剧 / 责编 | 双 Agent：编剧负责写，责编负责独立审查，通过才入库 |
| 上下文切片 | 写某一集时喂给模型的内容，分常驻层、结构层、切片层、检索层四层且有字数预算 |
| 空镜 / 定妆照 / 样式图 | 场景的环境图、角色的主形象图、道具的形态图 |
| 音画对齐 | 配音时长与镜头时长的匹配处理，超出容差时给出建议 |

### 1.5 业务术语一致性约定

全文统一使用：**新增**（不写添加/创建）、**编辑**（不写修改/更新）、**删除**（不写移除/清除）、**启用/停用**（不写开启/关闭）。

## 2. 业务总流程

系统采用**三层创作模型**，上一层的事实是下一层的输入，不允许跳层直接生成：

```text
世界观 + 角色 + 主线任务
        │
        ▼
  ① 事件流（推演引擎）
     粗推：快进一段时间，跑出主干事件与角色状态快照
     细化：把一条粗事件摊成若干细事件
     后果：到期后果当场兑现或顺延
        │  产物：结构化事实（谁、在哪天、在哪、做了什么、带来什么）
        ▼
  ② 剧情编排（选视角、排节奏、出骨架）
     圈定一段事件 → 指定视角人物与目标时长 → 产出剧情骨架
        │  产物：分集（标题、冲突、场次落点、转折、落点、覆盖天数、素材缺口）
        ▼
  ③ 剧本（编剧写 → 责编审 → 通过才入库）
     上下文切片 → 编剧正文 → 责编六项审查 → 打回重写 / 通过入库
        │  入库动作：写入分集正文 + 回写事件 / 角色状态 / 伏笔台账
        ▼
  ④ 制作链路
     分镜 → 静帧 → 视频 → 配音 → 音画对齐 → 合成整集
```

**分层铁律**：剧本不得凭空出现事件流里没有的事实；编排不得跳过错过的天数；下游（分镜、道具、一致性）一律按集号与天数读状态，不读剧本全文。

### 3.4 权限与角色

本系统为**本机单人使用**，不做登录与角色权限划分。全部功能对使用者开放；涉及删除等不可逆操作，均以二次确认保护（确认文案见各模块"边界与异常"）。

多成员协作（工作室场景）依赖同一份项目数据文件，同一时刻仅允许一个工作台实例编辑同一项目，避免状态层被并发覆盖。

### 3.5.1 项目列表

**（一）功能需求概述**

项目是全部创作数据的容器。项目列表用于建立、打开与清理项目，让使用者在不同作品之间切换而不互相污染。

- 用户故事：作为独立创作者，我希望把每部漫剧的数据分开存放，以便同时开几个坑而不串数据。
- 验收标准：能新建项目并立即进入；能删除项目且关联的角色、场景、道具、事件、分集一并清理；项目列表展示状态与题材。

**（二）功能设计**

**列表功能**

| 列名 | 字段类型 | 说明 |
|---|---|---|
| 项目名称 | 文本 | - |
| 题材 | 文本 | 取自项目制作设置 |
| 状态 | 状态标签 | 草稿 / 进行中 / 已完成 |
| 简介 | 文本 | 无值显示"-" |
| 更新时间 | 日期时间 | 数据发生变化时刷新 |
| 操作 | 操作按钮 | 打开、删除 |

列表默认每页 10 条，支持切换每页数量。列表为空时显示：暂无项目数据。

**新增功能**

| 字段名称 | 类型 | 长度限制 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 项目名称 | 文本输入 | 1-50 字 | 是 | - | 项目内唯一 |
| 题材 | 文本输入 | 1-40 字 | 是 | - | 如"古风 · 奇幻" |
| 简介 | 多行文本 | 0-500 字 | 否 | - | 一句话故事 |
| 画幅 | 单选 | - | 否 | 未定义 | 取值见数据字典；分镜页首次选定时赋值 |
| 美术风格 | 单选 | - | 否 | 未定义 | 取值见数据字典；故事生成页选定时赋值 |

提交成功：项目已创建。提交失败：保留填写内容，显示具体错误原因。

**编辑功能**

点击"编辑"，自动填入当前项目数据，表单字段同新增。提交成功：项目已更新。

**业务规则**

- 项目名称在系统内全局唯一。新增/编辑时若重复，阻止提交，提示"项目名称已存在，请换一个"。
- 画幅与美术风格在新建时处于"未定义"，分别由分镜页与故事生成页首次选定时赋值；未定义时不影响推演与编排，仅在出图环节阻止生成并提示"请先选定画幅 / 美术风格"。
- 删除项目时，若该项目存在已定稿的分集，仍允许删除，但需二次确认，确认文案为："删除后该项目的角色、场景、道具、事件与分集将一并清除，且不可恢复。确认删除？"

**边界与异常**

- **空数据**：列表无数据时，显示"暂无项目数据"。
- **删除确认**：点击"删除"必须二次确认，取消则不执行。
- **打开失败**：项目数据文件损坏时，提示"项目数据读取失败，请检查文件"并留在列表页。

**（三）业务逻辑关联**

- 项目是全部模块的数据根；角色、场景、道具、事件、分集、伏笔、后果均归属于项目。
- 删除项目会级联清除其全部关联数据，不影响其他项目。

### 3.5.2 故事生成

**（一）功能需求概述**

故事生成是三层创作模型的第 ①、② 层：先用推演引擎把故事时间往前推，产出结构化事实（事件流），再把一段事件编排成一集。它解决的核心问题是"长篇从哪来"——不是一句提示词生成全文，而是让事件在可计算的状态上积累。

- 用户故事：作为长篇创作者，我希望先跑出一段时间里发生了什么，再挑一段编成一集，以便第 40 集还能接得住第 1 集埋的线。
- 验收标准：快进推演能产出带天数锚点的事件与角色状态快照；细化能把一条粗事件摊成细事件；确认落盘后事件进入事件流且故事时间游标前进；编排产出的分集带有覆盖天数、视角人物与素材缺口。

**（二）功能设计**

**故事框架功能**

| 字段名称 | 类型 | 长度限制 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 故事大纲 | 多行文本 | 0-5000 字 | 否 | - | 粗推的第一份输入，落盘保存 |
| 核心戏剧问题 | 文本输入 | 0-200 字 | 否 | - | 系列主线弧光字段；长篇项目使用 |
| 主角终极目标 | 文本输入 | 0-200 字 | 否 | - | 系列主线弧光字段 |
| 终极对手 | 文本输入 | 0-100 字 | 否 | - | 系列主线弧光字段 |
| 力量天花板 | 多条记录 | - | 否 | 空 | 按季登记解锁内容，防止后期力量通胀 |
| 结局方向 | 文本输入 | 0-200 字 | 否 | - | 系列主线弧光字段 |
| 主线任务 · 目标 | 文本输入 | 0-200 字 | 否 | - | 推演的发动机：主角要达成什么 |
| 主线任务 · 完成条件 | 文本输入 | 0-200 字 | 否 | - | 什么情况算办成 |
| 主线任务 · 当前阶段 | 文本输入 | 0-200 字 | 否 | - | 下一批事件从这里接着走 |
| 主线任务 · 阻力 | 文本输入 | 0-200 字 | 否 | - | 谁或什么在挡着 |

**快进推演功能**

使用者选择快进天数后执行推演。

| 字段名称 | 类型 | 说明 |
|---|---|---|
| 快进天数 | 数值 | 从当前故事时间起算 |
| 事件序号起点 | 数值 | 系统自动取事件流当前最大序号 |

推演产出的每条事件包含：序号、天数、时间锚点粒度、是否踩主线、驱动性格、发生概率、粗细、母事件、地点、参与角色、一句话事实、后续影响、新引入内容。

**业务规则（推演）**

- 事件数量由快进天数决定：快进一周约产出两个事件，快进一个月约产出十个事件。
- 时间锚点粒度跟着这段的长度走：跨年只写到"第几年"，一个月之内写到月，几天之内写到日。不得以粗粒度冒充细粒度。
- 事件抽取以性格标签为驱动：强度高者必触发（100%）、中者 60%、低者 30%；踩中主线任务（地点或事撞上主线）的事件概率上抬，并在事件流中标记"踩主线"，让拉力自己露出来。
- 事件模板带门槛：需要特定装备或境界的事件，角色不满足时不进入抽取范围。
- 跨故事年时好感轴向 0 趋近（宿敌类除外）：快进一年的人，关系网不得停在原处。
- 走到某一天时，先检查当天到期的待办后果；到期后果按"仇恨够不够、骰子掷不掷得中"两道闸判定，掷不中不是销账，按新日期继续排队并在台账写清本次未动手的原因。
- 推演阶段不产生集号：事件锚在天数上，集号是编排阶段的产物。

**边界与异常（推演）**

- **无视角人物**：项目内没有角色时阻止推演，提示"请先在人设管理中新增角色"。
- **无主线任务**：允许推演，但不做主线命中加成，并提示"未填写主线任务，事件将不会朝一个方向积累"。
- **快进天数过小**：快进天数不足一天时阻止执行，提示"快进天数至少为一天"。

**细化事件功能**

选中一条粗事件并指定子事件数量后执行细化。子事件均匀落在母事件到下一个锚点之间，母事件保留不动，作为时间轴锚点与"已细化"的凭据。

**业务规则（细化）**

- 细化的产物标记为细事件，并指向母事件。
- 未细化的粗事件不得直接用于编排：编排要求所选区间内的事件已细化到日。

**投放道具推演功能**

以某件道具为线索推演相关事件，用于把关键道具排进时间轴。

**业务规则（道具推演）**

- 只有持有该道具的角色才可能触发对应事件。
- 世界设定中登记为"特殊道具"的物品，按其登记的用途与触发条件参与推演。

**确认落盘功能**

推演结果需使用者确认后才写入事件流。

| 落盘内容 | 说明 |
|---|---|
| 事件 | 追加到事件流，序号全局递增 |
| 角色状态快照 | 每个参与角色落一条，锚在事件当天 |
| 新增伏笔 | 推演中新埋下的伏笔进入台账 |
| 待办后果 | 新种下的因、已兑现的果、顺延的账一并更新台账 |
| 关系变化 | 好感轴变化与跨年衰减一并写入 |
| 故事时间 | 游标推进到本批结束时间 |

**业务规则（落盘）**

- 未确认的推演结果不写入任何数据；可反复重跑，重跑结果覆盖未确认的批次。
- 落盘后不得回退故事时间游标；需要重来时，只能删除该批事件后重跑。

**因果链功能**

| 列名 | 字段类型 | 说明 |
|---|---|---|
| 后果种类 | 文本 | 寻仇 / 报恩 / 举报 / 偷袭 / 结盟 / 拦路 |
| 执行者 | 文本 | 谁来执行这个后果 |
| 对象 | 文本 | 寻仇对象 / 报恩对象 |
| 到期日 | 数值 | 第几天到期 |
| 状态 | 状态标签 | 待兑现 / 已兑现 / 已顺延 |
| 顺延次数 | 数值 | 到期却没动手的次数 |
| 挂起原因 | 文本 | 最近一次为什么没动手 |
| 来源事件 | 文本 | 哪个事件种下的因 |

**业务规则（因果链）**

- 后果到期时先校验触发条件：执行者的境界是否够、所在地点是否对、与目标的关系是否仍低于阈值（关系已修复则不来寻仇）。
- 条件不满足时按固定天数顺延，顺延次数累加，台账保留挂起原因，不得销账。
- 后果兑现后生成一条新事件，把执行者对目标的好感变化写回关系网，并记录兑现日与兑现事件。
- 执行者或对象已不在故事中（已退场）时，该后果作废，标注废弃原因。

**剧情编排功能**

使用者在时间轴上圈定一段事件，指定视角人物与目标时长，系统产出剧情骨架；确认后成立分集。

| 字段名称 | 类型 | 说明 |
|---|---|---|
| 集名 | 文本 | 由系统给出建议值，可改 |
| 目标时长 | 数值 | 单位分钟，决定场次数量 |
| 视角人物 | 单选 | 取值范围为项目内角色 |
| 冲突 | 多行文本 | 这一集两边各要什么 |
| 场次落点 | 多条记录 | 按时间排开的每场戏停在哪 |
| 情绪转折 | 多行文本 | 这一集人的心气怎么变 |
| 落点 | 多行文本 | 幕落时人与事变成什么样 |
| 一句话梗概 | 多行文本 | 进分集表用 |
| 覆盖天数 | 数值区间 | 由所选事件的天数范围自动得出 |
| 素材缺口 | 多条记录 | 编排倒逼出来的道具与临时角色 |

**业务规则（编排）**

- 场次数量由目标时长倒推（约每三分钟一场），与事件条数无关：事件多于场次则并进同一场，事件少于场次也只写这么多场。
- 同一段事件换一个视角人物就是另一场戏，允许为同一段事件编排多集（不同视角）。
- 分集记录来源事件，可追溯"这一集为什么存在"。
- 编排时若剧情需要但道具库与人设表中都没有的素材，登记为素材缺口，供后续补建。

**边界与异常（编排）**

- **未细化事件**：所选区间含未细化事件时阻止编排，提示"请先把这段事件细化到日"。
- **区间重叠**：所选天数区间与已有分集重叠时提示"该时间段已被第 N 集覆盖"，允许继续但标记重叠。
- **无视角人物**：未指定视角人物时，默认取主角视角并提示。

**（三）业务逻辑关联**

- 推演的输入依赖人设管理（角色性格、境界、装备）、世界观（境界体系、特殊道具）、道具（持有关系）与故事框架（大纲、主线任务）。
- 编排的产物是分集，为剧本编辑提供输入；分集覆盖的天数区间是下游按集读状态的桥梁。
- 编排倒逼出的素材缺口，需要在道具管理与人设管理中补建后才能真正出图。

**（四）用户操作流程图**

见《数据流.md》§2（推演引擎数据流）与 §3（三层转换）。

**（五）功能时序图**

见《数据流.md》§2、§3。

### 3.5.3 剧本编辑

**（一）功能需求概述**

剧本编辑是三层创作模型的第 ③ 层：把编排产出的骨架写成可拍的正文，并在入库前过一道审查。它解决的核心问题是"长篇不崩"——编剧只管写，责编独立挑错，通过之后才允许落库并回写状态。

- 用户故事：作为长篇创作者，我希望写完一集后系统能替我查出"这个人说了他不该知道的事"，以便第 50 集还不至于自相矛盾。
- 验收标准：能按上下文切片生成正文；能执行六项审查并给出分级问题清单；未通过的正文不得定稿入库；定稿后事件、角色状态、伏笔台账同步更新。

**（二）功能设计**

**选择分集功能**

按集次选择要编辑的分集，展示该集的集名、覆盖天数、视角人物、目标时长、状态（待写 / 草稿 / 已完成）与剧情骨架。

**上下文切片功能**

写某一集前，系统按四层组装本次要喂给大语言模型的内容，各层有字数预算，超出即截断（宁可少喂，不撑爆窗口）。

| 层级 | 名称 | 内容 | 字数预算 |
|---|---|---|---|
| 常驻层 | 系列核心与世界观铁律 | 系列主线弧光、世界观规则条目 | 500 |
| 结构层 | 本季与本集目标 | 主线任务当前阶段与完成条件、本集结构表 | 300 |
| 切片层 | 角色卡与伏笔 | 出场角色卡、角色即时状态、活跃伏笔 | 1500 |
| 检索层 | 历史事件与前情 | 与本集关键词相关的历史事件摘要、上一集结尾 | 800 |

展示本次切片的统计：纳入的规则条数、出场人数、伏笔条数、历史事件条数，以及实际字数与是否超出预算。超出预算时给出提示，不阻断生成。

**生成剧本正文功能**

| 字段名称 | 类型 | 说明 |
|---|---|---|
| 本集标题 | 文本 | 取自编排，可改 |
| 开场钩子 | 多行文本 | 本集开头要立住的东西 |
| 中段反转 | 多行文本 | 本集中段的翻面 |
| 结尾悬念 | 多行文本 | 留给下一集的问题 |
| 出场人物 | 文本 | 逗号分隔；未填时由系统按剧本与近期事件推定 |

**业务规则（生成）**

- 生成时须遵守四条硬约束：不得违反世界观铁律；角色不得说出他不知道的信息（以该角色已知信息集为准）；不得突破当前阶段的力量上限；本集到期的伏笔必须收，本集要埋的伏笔埋得自然。
- 输出格式按场次分段，每段含环境描写、人物动作、台词；结尾必须留悬念。
- 生成前若画幅或美术风格未选定，不阻断剧本生成（这两项只在出图环节使用）。

**审查功能**

生成完成后由责编独立执行六项审查，产出问题清单。

| 检查项 | 判定要点 | 阻塞级别 |
|---|---|---|
| 世界观一致性 | 正文涉及世界观铁律时提醒人工复核，不自动判违反 | 提示 |
| 人物一致性 | 未登记在角色表中的人开口说话；单人台词占比过高 | 阻塞 / 提示 |
| 信息集检查 | 角色说到了不在他已知信息集里的事实 | 阻塞 |
| 伏笔执行 | 本集到期的伏笔未收；本集计划新埋的伏笔未出现 | 阻塞 / 提示 |
| 节奏合规 | 开场未立住钩子；结尾没有悬念 | 提示 |
| 故事时间 | 正文未体现本集既定的故事时间 | 提示 |

**业务规则（审查）**

- 判定"通过"只看是否存在阻塞级问题；提示级问题允许带着走，但在清单中列出。
- 单人台词占比超过七成时给出提示，提示将部分台词分给在场其他人。
- 审查结论注明轮次：被打回重写后再次审查，轮次累加。
- 连续三轮仍未通过时，提示人工介入并给出全部阻塞问题，不再自动重写。

**打回重写功能**

未通过时按阻塞问题重写，重写后自动进入下一轮审查，轮次累加。使用者也可直接改写正文后再发起审查。

**边界与异常（审查）**

- **无正文**：正文为空时阻止审查与定稿，提示"请先生成或填写剧本正文"。
- **无角色表**：项目内没有角色时，人物一致性与信息集检查跳过，并提示"未维护角色表，人物相关检查已跳过"。
- **无伏笔台账**：伏笔台账为空时该项判定为通过，不产生问题。

**定稿入库功能**

审查通过后写入分集，并回写状态层。回写内容如下：

| 回写项 | 规则 |
|---|---|
| 分集正文 | 写入该集，状态置为已完成 |
| 事件 | 按场次切分提取结构化事实，一天一场，锚在该集覆盖天数区间内且不越过区间末日 |
| 角色状态 | 为出场角色落一条快照：已知信息集继承上一集并叠加本集新获得的内容；剧本提到的道具进入储物袋，不自动装到装备槽；境界、声望、宗门、阵营沿用上一集 |
| 伏笔台账 | 本集到期的伏笔若在正文中出现，标记为已回收并记录回收集次 |

**业务规则（定稿）**

- 只有审查通过的正文才允许定稿；未通过的正文不写入分集，也不回写状态。
- 重新生成本集时，按集号前缀清除上一版从剧本提取的事实，避免旧事实残留。
- 剧本是成品阶段的产物，从中提取的事件一律按最细粒度（日）记录，且天数落在该集区间内。

**伏笔台账功能**

| 字段名称 | 类型 | 长度限制 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 伏笔内容 | 多行文本 | 1-500 字 | 是 | - | - |
| 埋设集次 | 数值 | - | 否 | 0 | 编排后回填；推演阶段为 0 |
| 回收集次 | 数值 | - | 否 | 空 | 空表示跨季长线伏笔，暂不指定 |
| 埋设天 | 数值 | - | 否 | - | 推演阶段的真正锚点 |
| 计划回收天 | 数值 | - | 否 | - | - |
| 状态 | 单选 | - | 是 | 已埋待收 | 已埋待收 / 已回收 / 废弃 |
| 关联角色 | 单选 | - | 否 | 空 | 取值范围为项目内角色 |
| 备注 | 多行文本 | 0-500 字 | 否 | - | - |

**业务规则（伏笔）**

- 伏笔在两个锚点上各记一份：天（推演阶段的真正尺度）与集次（编排后回填）。
- 到期的伏笔在正文中命中关键词即判定已回收；未命中则记为阻塞问题。
- 废弃的伏笔保留在台账中，不计入活跃伏笔，也不再产生阻塞问题。

**边界与异常（伏笔）**

- **空数据**：台账无数据时，显示"暂无伏笔记录"。
- **删除保护**：已被某集回收的伏笔不允许删除，提示"该伏笔已被第 N 集回收，如需清理请改为废弃"。
- **回收集次早于埋设集次**：阻止提交，提示"回收集次不得早于埋设集次"。

**（三）业务逻辑关联**

- 剧本的输入来自剧情编排（分集与骨架）、人设管理（角色卡、已知信息集）、故事生成（事件流、伏笔台账）与世界观（铁律、境界体系）。
- 定稿后回写的事件、角色状态、伏笔，成为下一集生成与检索的依据。
- 分集正文是分镜生成的输入；正文改动后，分镜中源自剧本的台词需提示同步。

### 3.5.4 人设管理

**（一）功能需求概述**

人设管理维护角色的档案、形象资产、配音配置与关系网，是推演与剧本的共同底座：推演读性格与境界，剧本读角色卡与已知信息集，出图读形象变体与衣橱。

- 用户故事：作为创作者，我希望角色的形象、音色与性格只维护一次，以便写剧本、推演、出图读到的都是同一份人设。
- 验收标准：能维护角色档案与形象资产；能维护双向关系与好感值；能按集查看角色即时状态与已知信息集；角色年龄能随故事时间自动推算。

**（二）功能设计**

**角色档案功能**

| 字段名称 | 类型 | 长度限制 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 角色名 | 文本输入 | 1-30 字 | 是 | - | 项目内唯一 |
| 身份描述 | 文本输入 | 0-50 字 | 否 | - | 一句话身份 |
| 职能位 | 单选 | - | 是 | 配角 | 主角 / 男主 / 女主 / 配角 / 反派 / 线索人物 |
| 简介 | 多行文本 | 0-1000 字 | 否 | - | - |
| 标签 | 多条记录 | - | 否 | 空 | 自由标签 |
| 身份原型 | 多选 | - | 否 | 空 | 取自原型库与项目自定义原型 |
| 基准年龄 | 数值 | 0-999 | 是 | 0 | - |
| 年龄锚定年 | 数值 | - | 是 | 故事元年 | 基准年龄对应的故事年 |
| 自动推算年龄 | 开关 | - | 否 | 启用 | 启用后按故事年推算该集年龄 |
| 参考照片 | 文件 | - | 否 | 空 | 用于形象参考 |
| 是否视角人物 | 开关 | - | 否 | 停用 | 全项目至多一个主角视角 |
| 性格标签 | 多条记录 | - | 否 | 空 | 标签 + 强度（低 / 中 / 高） |
| 当前目标 | 文本输入 | 0-200 字 | 否 | - | 推演每跑一批会更新 |
| 长期驱动力 | 文本输入 | 0-200 字 | 否 | - | 基本不变 |

**业务规则（角色）**

- 角色名在同一项目内唯一。新增/编辑时若重复，阻止提交，提示"该角色名已存在"。
- 职能位决定叙事权重：主角为第一视角且镜头占比最高，线索人物仅在台词与闪回中出现。
- 年龄按"基准年龄 + 该集故事年 - 锚定年"推算；停用自动推算时以基准年龄为准。
- 性格标签强度直接决定该标签在推演中的触发概率：低 30%、中 60%、高 100%。
- 角色被分集引用（已入镜或已开口）时不允许删除，提示"该角色已在第 N 集出现，如需清理请先调整分集"。

**形象资产与配音配置功能**

| 字段名称 | 类型 | 说明 |
|---|---|---|
| 定妆照状态 | 状态标签 | 待生成 / 生成中 / 已完成 |
| 定妆照视图 | 多条记录 | 主形象锁定后的各视图 |
| 形象变体 | 多条记录 | 类型（年龄 / 状态 / 造型）+ 触发条件 + 提示词增量 |
| 衣橱 | 多条记录 | 部位、配色、材质、适用场景、是否默认套装 |
| 音色 | 单选 | 取自音色预设 |

| 参考音频 | 文件 | 用于声音克隆 |
| 全剧锁定音色 | 开关 | 启用后音色不因集数变化 |

**关系网功能**

| 字段名称 | 类型 | 说明 |
|---|---|---|
| 关系类型 | 单选 | 父子 / 母子 / 手足 / 师徒 / 同门 / 道侣 / 夫妻 / 朋友 / 主仆 / 仇人 / 宿敌 / 救命恩人 / 陌路 |
| 好感值 | 数值 | -100 ~ +100，双向各记一条 |
| 称呼 | 文本 | 发起方如何称呼对方 |
| 备注 | 多行文本 | - |

**业务规则（关系）**

- 好感轴是同一条数的正负两端：正端为心（友好），负端为火（敌意）。一个人不可能同时既爱又恨，亲密度提升即等同敌意下降。
- 好感值分档：负端按火计（1 火起有杀意），零为陌路，正端按心计；厌恶档（负值但未满 1 火）不会主动动手，最多言语冲突。
- 关系变化需记录来源事件与最近一次变化事件，可追溯到"为什么变成这样"。

**角色状态功能**

按集查看角色即时状态：所在地点、情绪、已知信息集、装备槽位、对他人的态度、当前境界、声望、所属势力、阵营。

**边界与异常（人设）**

- **空数据**：角色列表无数据时，显示"暂无角色数据"。
- **无形象资产**：定妆照未完成时，允许继续写剧本与推演，但出图环节阻止并提示"请先生成该角色的定妆照"。
- **关系自指**：不允许建立角色到自身的关系，提示"不能与自己建立关系"。

**（三）业务逻辑关联**

- 人设是推演的输入（性格、境界、装备）与剧本的输入（角色卡、已知信息集、称呼）。
- 定稿回写会更新角色状态快照；人设页的改动不影响已落盘的快照，只影响之后的生成。
- 形象变体与衣橱在分镜绑定入镜人物时被消费。

### 3.5.5 场景生成

**（一）功能需求概述**

场景生成维护场景档案与世界地图，为分镜提供可复用的空镜。场景不只是独立条目，而是世界里的一块地方：分区的气候、光线与势力会成为该区所有场景的默认约束。

- 用户故事：作为创作者，我希望同一地点在不同时间、天气下复用同一批空镜，以便几十集下来场景不会越画越野。
- 验收标准：能维护场景与世界分区；能把场景锚定到分区；能按角度与时间 / 天气变体生成空镜并指定基准图；能看出哪些分区还没有场景。

**（二）功能设计**

| 字段名称 | 类型 | 长度限制 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 场景名 | 文本输入 | 1-30 字 | 是 | - | 项目内唯一 |
| 时间 | 文本输入 | 0-20 字 | 否 | - | 如"清晨" |
| 氛围 | 文本输入 | 0-20 字 | 否 | - | - |
| 描述 | 多行文本 | 0-1000 字 | 否 | - | - |
| 氛围标签 | 多条记录 | - | 否 | 空 | - |
| 剧情阶段分组 | 文本输入 | 0-30 字 | 否 | - | 如"集市线" |
| 别名 | 多条记录 | - | 否 | 空 | 合并后按别名也能命中 |
| 所属分区 | 单选 | - | 否 | 空 | 取值范围为世界分区 |
| 首次出现集次 | 数值 | - | 否 | - | 由分镜引用与剧本解析自动刷新 |

**世界地图与世界分区**

| 字段名称 | 类型 | 说明 |
|---|---|---|
| 分区名 | 文本 | 项目内唯一 |
| 分区描述 | 多行文本 | - |
| 分区标签 | 多条记录 | 气候 / 势力 / 危险度 |
| 分区规则 | 多行文本 | 注入该区所有场景的默认约束 |
| 地图坐标 | 数值对 | 0-100 的相对坐标 |

**空镜图功能**

按角度与时间 / 天气变体生成空镜；同一分组内同时只有一张基准图生效。换基准图或重新生成后，图版本号递增。

**业务规则（场景）**

- 场景名在同一项目内唯一；别名可多个，用于剧本与分镜中同地异名的命中。
- 分区规则作为该区所有场景的默认约束注入出图；场景自身描述与分区规则冲突时，以场景描述为准并给出提示。
- 换基准图或重新生成后版本号递增；分镜记录了生成时所依据的图版本，据此判断静帧是否已被后续改图作废。
- 场景被分镜引用时不允许删除，提示"该场景已被分镜引用，如需清理请先解除引用"。

**边界与异常（场景）**

- **空数据**：场景列表无数据时，显示"暂无场景数据"。
- **未锚定分区**：允许存在未锚定分区的场景，在世界地图上归入"未分区"并提示补挂。
- **出图前置**：美术风格未选定时阻止生成空镜，提示"请先选定美术风格"。

**（三）业务逻辑关联**

- 场景在分镜绑定空镜时被消费，并回写首次出现集次。
- 世界分区的规则与世界观设定共同影响出图约束。
- 道具在"场景内"模式下出图时需要引用场景。

### 3.5.6 道具生成

**（一）功能需求概述**

道具管理维护道具档案及其形态状态。道具与场景最大的不同是会随剧情变化——会转手、会损坏，因此出图与分镜都要能指定"当时的形态"。

- 用户故事：作为创作者，我希望骨片在第 3 集完好、第 12 集出现裂纹这种事能被记住，以便出图不会画错。
- 验收标准：能维护道具及其形态状态；能为形态指定持有者与生效集范围；能按形态生成白底单体图与场景内图；能从剧本与分镜中自动提取道具。

**（二）功能设计**

| 字段名称 | 类型 | 长度限制 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 道具名 | 文本输入 | 1-30 字 | 是 | - | 项目内唯一 |
| 来源 | 文本 | - | 是 | 手动添加 | 自动提取 / 手动添加 |
| 类别 | 文本输入 | 0-20 字 | 否 | - | 随身 / 文书 / 器物 / 武器 … |
| 描述 | 多行文本 | 0-1000 字 | 否 | - | - |
| 正向提示词 | 多行文本 | 0-1000 字 | 否 | - | 材质、形制、质感 |
| 负向提示词 | 多行文本 | 0-1000 字 | 否 | - | - |
| 别名 | 多条记录 | - | 否 | 空 | 同物异名也能命中 |
| 首次出现集次 | 数值 | - | 否 | - | 由分镜引用自动刷新 |

**形态状态功能**

| 字段名称 | 类型 | 说明 |
|---|---|---|
| 形态名 | 文本 | 如"完好 / 裂纹 / 碎裂 / 认主发光" |
| 形态描述 | 多行文本 | - |
| 提示词增量 | 多行文本 | 出图时追加到道具正向提示词之后 |
| 持有者 | 单选 | 取值范围为项目内角色；空表示无主 |
| 生效集范围 | 数值区间 | 空表示不限 |

**样式图功能**

按形态生成两类样式图：白底单体图（用于做参考图）与场景内图（用于确认它在环境里的样子）。同一形态同时只有一张基准图生效。

**业务规则（道具）**

- 道具名在同一项目内唯一；别名可多个。
- 形态按剧情时间轴排列，转手与损坏都落在形态上；分镜未指定形态时，按镜头所在集自动推算当时的样子。
- 世界设定中登记为"特殊道具"的物品可触发特定事件，并参与推演。
- 道具被分镜引用时不允许删除，提示"该道具已被分镜引用，如需清理请先解除引用"。

**边界与异常（道具）**

- **空数据**：道具列表无数据时，显示"暂无道具数据"。
- **无持有者形态**：持有者为空的形态允许存在，表示失落或属于场景。
- **生效区间非法**：生效集起始大于结束时阻止提交，提示"生效集范围不合法"。

**（三）业务逻辑关联**

- 道具在分镜绑定道具时被消费，并回写首次出现集次。
- 剧本定稿回写时，剧本中提到的道具进入出场角色的储物袋，但不自动装到装备槽。
- 投放道具推演以道具为线索生成事件，需先有道具档案。

### 3.5.7 分镜生成

**（一）功能需求概述**

分镜把一集剧本拆成可拍的镜头序列，并把镜头与场景空镜、入镜人物、道具绑定起来。它是文本世界与图像世界的接缝。

- 用户故事：作为创作者，我希望分镜能自动带上剧本的台词与场景，以便我只改少数几镜就够用。
- 验收标准：能按剧本与目标时长拆分镜头；能为镜头绑定场景空镜、入镜人物与形象变体、道具及形态；能调整顺序、转场与时长；能锁定不希望被重新生成的镜头。

**（二）功能设计**

| 字段名称 | 类型 | 长度限制 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| 镜号 | 数值 | - | 是 | - | 集内顺序 |
| 画面描述 | 多行文本 | 0-500 字 | 是 | - | - |
| 景别 | 文本输入 | 0-20 字 | 否 | - | - |
| 运镜 | 文本输入 | 0-20 字 | 否 | - | - |
| 台词 / 旁白 | 多行文本 | 0-500 字 | 否 | - | - |
| 说话人 | 单选 | - | 否 | 空 | 取值范围为角色；旁白记为旁白 |
| 时长 | 数值 | 0.1-60 秒 | 是 | - | - |
| 入镜人物 | 多条记录 | - | 否 | 空 | 角色 + 形象变体 + 套装 |
| 绑定场景 | 单选 | - | 否 | 空 | 取值范围为场景 |
| 场景角度 | 单选 | - | 否 | 空 | 空表示用场景默认角度 |
| 时间 / 天气变体 | 单选 | - | 否 | 空 | 空表示用场景默认时间 |
| 出现道具 | 多条记录 | - | 否 | 空 | 道具 + 形态 |
| 转场方式 | 单选 | - | 否 | 硬切 | 硬切 / 淡入 / 淡出 / 淡入淡出 / 叠化 / 闪白 / 黑场 / 划变 |
| 转场时长 | 数值 | 0-5 秒 | 否 | 0 | 硬切为 0 |
| 锁定 | 开关 | - | 否 | 停用 | 启用后重新生成分镜时跳过该镜 |

**业务规则（分镜）**

- 镜头数量由本集目标时长与剧本场次决定，不按事件条数切分。
- 台词默认从剧本带出，并记录带出时的原文，用于判断是分镜侧改的还是剧本侧改的；人工改动内容字段后自动标记为已编辑。
- 已锁定的镜头在重新生成时保留不动。
- 镜头绑定场景时记录当时所用的空镜版本；后续换基准图或重新生成后，该镜静帧标记为已过时并提示重新出图。
- 未指定形态的道具，按镜头所在集自动推算当时的样子。
- 说话人为旁白时，该镜不参与配音。

**边界与异常（分镜）**

- **无剧本**：本集正文为空时阻止生成分镜，提示"请先完成本集剧本"。
- **无可用空镜**：绑定场景但该场景没有已完成空镜时，允许绑定但阻止出图，提示"该场景尚无空镜，请先生成"。
- **画幅未选定**：首次出图前未选定画幅时阻止出图，提示"请先选定画幅"。

**（三）业务逻辑关联**

- 分镜的输入是分集正文与目标时长；产出是图片 / 视频模块的出图任务。
- 分镜引用场景与道具会回写它们的首次出现集次。
- 剧本改动后，分镜中源自剧本的台词需提示同步。

见《数据流.md》§6。

### 3.5.8 图片 / 视频

**（一）功能需求概述**

图片 / 视频模块把镜头变成实际的画面与声音：生成静帧、由首尾帧生成视频片段、按角色音色生成配音，并处理音画对齐。

- 用户故事：作为创作者，我希望每个镜头一次出四张让我挑，以便不用反复重抽。
- 验收标准：能按镜头生成静帧候选并选定；能生成视频片段；能按音色生成配音；能在音画时长不一致时给出对齐处理或人工建议。

**（二）功能设计**

| 功能 | 说明 |
|---|---|
| 生成静帧 | 一次生成四张候选，选定后作为该镜画面；未出图时无候选 |
| 生成视频 | 以镜头的首帧与尾帧为依据生成视频片段，记录实际出片时长 |
| 生成配音 | 按镜头台词与角色音色生成配音，记录实际时长与所用语速倍率 |
| 音画对齐 | 在画面与配音时长不一致时处理对齐 |

**业务规则（媒体）**

- 配音时长按台词估算：每个字约 0.28 秒，每个标点约停顿 0.16 秒。
- 画面与配音时长差在 0.15 秒内视为已对齐，不做额外调整。
- 超出容差时按可用手段处理：无台词、刚好对齐、调语速、加长镜头、缩短镜头；语速可调范围为基准的 0.8 至 1.25 倍。
- 语速调不动时标记为待人工，并给出具体建议（如建议加长镜头多少秒）。
- 换基准图、重新生成静帧或改动画面内容后，已生成的视频标记为已过时并提示重新出片。

**边界与异常（媒体）**

- **前置资产缺失**：角色定妆照或道具样式图未完成时阻止出图，提示缺失的资产名称。
- **外部服务不可用**：本地绘图服务或大语言模型服务不可用时，提示"服务未就绪，请检查本地服务是否已启动"，并保留已生成的其它镜头。
- **无台词镜头**：无台词的镜头不参与配音与音画对齐。

**（三）业务逻辑关联**

- 输入来自分镜与角色配音配置、场景空镜、道具样式图。
- 产出是合成视频模块的输入。

### 3.5.9 合成视频

**（一）功能需求概述**

合成视频把一集的镜头视频与配音按序拼接，套用转场与画幅，产出可播放的整集视频并导出到项目目录。

- 用户故事：作为创作者，我希望一键把一集拼成片，以便直接看效果或发布。
- 验收标准：能按镜头顺序与转场合整集；能导出视频文件到项目目录；镜头资产缺失时给出明确提示而非静默跳过。

**（二）功能设计**

| 字段名称 | 类型 | 说明 |
|---|---|---|
| 目标集次 | 单选 | 取值范围为已完成的分集 |
| 画幅 | 文本 | 取自项目制作设置 |
| 合成范围 | 单选 | 整集 / 选定镜头 |

**业务规则（合成）**

- 按镜号顺序拼接，并在镜头之间套用该镜登记的转场方式与转场时长；第一镜无上一镜，记为开场。
- 以项目画幅为输出画幅；画幅未选定时阻止合成并提示"请先选定画幅"。
- 配音与画面按对齐结果合成；仍标记为待人工的镜头允许合成，但在结果中列出。

**边界与异常（合成）**

- **镜头未出片**：存在未生成视频的镜头时，提示具体镜号，允许跳过这些镜头后合成，并在结果中标注。
- **导出失败**：目标目录不可写时提示"导出失败，请检查项目目录权限"，保留已合成的中间结果。
- **音频缺失**：镜头无配音时按静音处理，不阻断合成。

**（三）业务逻辑关联**

- 输入是分镜与已生成的视频、配音；产出文件落在项目目录，供外部播放器与剪辑使用。

## 4. 非功能需求

### 4.1 性能

| 场景 | 指标 |
|---|---|
| 打开项目 | 100 集、500 条事件规模下，项目数据在 3 秒内加载完成 |
| 列表与切换 | 分集、角色、场景、道具列表切换在 1 秒内响应 |
| 快进推演 | 快进一个月（约 10 条事件）在 3 秒内给出结果 |
| 上下文切片组装 | 单集切片组装在 1 秒内完成，并给出字数与统计 |
| 审查 | 单集正文的六项审查在 1 秒内完成 |
| 出图与出片 | 由本地绘图服务决定，不以同步方式阻塞编辑；须展示进度并允许中途取消 |
| 合成 | 单集（约 30 镜）合成本地完成，须展示进度 |

长耗时操作一律异步执行并保留进度；期间界面保持可操作，不锁死。

### 4.2 数据与存储

- 每个项目的全部数据落在该项目的独立数据文件中，可整体拷贝、备份与迁移。
- 状态层（事件、角色状态、伏笔、后果、关系）以结构化方式落盘，不得以整包文本方式糊在一起，保证可按天数与集次检索。
- 编辑操作后自动保存；异常退出后重新打开，恢复到最近一次保存的状态。
- 删除操作以二次确认保护；定稿与落盘类操作不可撤销，须保留操作留痕（审查报告、推演批次）。

### 4.3 外部服务依赖

| 依赖 | 用途 | 不可用时的处理 |
|---|---|---|
| 本地绘图服务（ComfyUI） | 角色定妆照、形象变体、场景空镜、道具样式图、镜头静帧与视频 | 出图与出片功能阻断并提示"请先启动本地绘图服务"；其余创作功能不受影响 |
| 大语言模型服务（豆包 / DeepSeek 等） | 剧本正文生成、责编审查、剧情编排辅助 | 生成与审查功能阻断并提示服务未就绪；本地规则类校验仍可用；允许手工填写正文后走纯规则审查 |
| 视频合成（ffmpeg） | 整集视频合成与导出 | 合成功能阻断并提示；已生成的镜头资产保留 |
| 配音服务 | 角色配音与声音克隆 | 配音与音画对齐阻断并提示；无配音不影响画面合成 |

外部服务的地址与凭据由使用者在本机配置；系统负责检测可用性并在不可用时给出明确提示，不做静默失败。

**出图并发**：本地绘图服务单实例一次只排一个任务，默认并发为 1；使用者可在配置里调到 2，**不得超过 2**——超了本地绘图服务的显存与排队会互相踩。出图请求按顺序排队执行，允许中途取消单个任务。

### 4.4 隐私与安全

- 项目数据全部存放在本机项目目录，不上传。
- 调用大语言模型服务会把本次上下文切片发送到所选服务，需在首次调用时告知使用者，并在调用前展示本次将外发的内容范围。
- 声音克隆所需的参考音频仅在本机与所选配音服务之间使用，不随项目数据外发。

### 4.5 运行形态与兼容

- 本机运行，前端与后端为同一台机器上的两个本地服务，前端通过内部地址访问后端。
- 同一时刻仅允许一个工作台实例编辑同一项目，防止状态层被并发覆盖。
- 支持 Windows 桌面环境；首次使用需具备 Node 与 Python 运行环境。

### 4.6 可维护性与可观测性

- 推演、编排、审查、回写均以可重跑的纯逻辑实现：相同输入产生相同输出，便于回归与排查。
- 生成类操作保留本次输入快照（上下文切片、审查报告、推演批次），便于追溯"这一版是怎么来的"。
- 出图与出片失败时保留失败原因与外部服务返回信息，便于定位。

## 6. 验收标准

| # | 验收项 |
|---|---|
| 1 | 能新建项目，并在项目内完成一次完整链路：维护角色与世界观 → 快进推演 → 细化 → 确认落盘 → 编排成分集 → 生成并审查剧本 → 定稿入库 |
| 2 | 落盘后的事件带有天数锚点，且故事时间游标前进；重跑未确认的批次不产生脏数据 |
| 3 | 编排产出的分集带有覆盖天数区间、视角人物、目标时长与来源事件 |
| 4 | 审查能命中至少以下三类问题：未登记角色开口、角色说了不在已知信息集里的事实、到期伏笔未收 |
| 5 | 存在阻塞级问题时不允许定稿；定稿后事件、角色状态、伏笔台账同步更新 |
| 6 | 重新生成某一集后，上一版从该集剧本提取的事实被清除，不残留 |
| 7 | 分镜能绑定场景空镜、入镜人物与道具形态；换基准图后相关静帧标记为已过时 |
| 8 | 音画时长超出容差时能给出对齐处理或人工建议；无台词镜头不参与配音 |
| 9 | 外部服务不可用时，相关功能给出明确提示，且不影响其余功能与已生成资产 |
| 10 | 关闭后重新打开，项目数据恢复到最近一次保存的状态 |
