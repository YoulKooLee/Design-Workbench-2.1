# Phase 3 第一批 · 前端三页接后端

## 一、交付内容

| 页面 | 路径 | 接的后端 |
|---|---|---|
| 项目列表 | `/` | `GET/POST/DELETE /api/projects`、`POST /{id}/open` |
| 故事生成（推演面板） | `/projects/{id}/story` | `GET /characters`、`GET /events?confirmed=…`、`POST /simulate/fast-forward`、`POST /simulate/{batch}/confirm`、`DELETE /simulate/{batch}` |
| 人设管理 | `/projects/{id}/characters` | 角色 CRUD、`GET/POST/PATCH /character-states` |

推演面板的链路：选时间步（日 / 周 / 月 / 季 / 年）→ 快进推演 → 看临时态事件
（含性格演化、埋下的伏笔、兑现的后果）→ **确认这一批**（事件入流、故事时间推进）
或 **丢弃这一批**（连根收走）。也能对单条事件确认 / 打回。

## 二、关键决策与理由

**1. 搬「视觉与交互」，不搬「内存模型」。**
原型三页深度耦合内存里的 `Project` 大对象（一个类型几十个字段，含大量原型态
字段如定妆照 / 形象变体 / 配音）。整页照搬等于把 mock 一起搬过来。做法是：
原样复制 `theme.ts`（设计令牌）、`ui.tsx`（14 个无状态原子组件）、`styles.css`
（动画与滚动条）、`simulator/storyTime.ts`（故事时间算术，与后端同一把尺子），
页面则重写——结构、区块、交互照原型来，数据一律 fetch 后端。

**2. 项目打开状态放 zustand。**
`store/useProjectStore.ts` 存 `projectId / projectName / summary / storyTime`，
进项目调 `POST /{id}/open`，退出调 `POST /{id}/close`。直接按 URL 刷新也能用：
外壳发现 store 里没这个项目就先接上再渲染。

**3. 时间单位用中文，与后端同一套。**
`日 / 周 / 月 / 季 / 年`，后端 `days_of()` 也是这一套（`日1 周7 月30 季90 年360`），
前后端不换算、不猜。

**4. 为「角色状态」补了后端端点。**
豆包要人设页能编辑境界 / 声望 / 宗门 / 阵营，而此前 `character_states` 只能由
推演产出、没有读写口子。补了 `GET POST /character-states` 与 `PATCH /character-states/{id}`：
同一角色同一天重复提交视为改这一天的快照（不叠新的一条）；列表默认只返回已确认的
（`batch_id` 为空），临时态不被人设页读走。表结构没动，只加端点。

**5. 待确认批次的展示按 `batch_id` 分组。**
一次推演 = 一个 `batch_id`。页面把当前批次单独成卡（带确认 / 丢弃操作条），
其余未确认事件另列，避免上一轮没处理完的和这一批混在一起。
