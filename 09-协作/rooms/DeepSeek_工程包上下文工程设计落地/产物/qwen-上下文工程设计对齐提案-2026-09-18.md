## 四、qwen 补充的核心机制（v1 缺失，直接对应用户三痛点）

### 4.1 上下文装配公式（对 P3）

**这是本次对齐最重要的产出。** v1 有原则无公式，落地时智能体仍会自由发挥。

```
【常驻基线】每次会话都在，条目级摘要，禁止全文
  1. 需求清单        feature-list 条目（id + 一句话 + 优先级 + 状态）
  2. 数据模型        实体清单 + 关系（1:N / N:M）+ 关键字段，概念 ER

  4. 业务架构        核心业务流程 + 角色 + 领域边界
  5. 模块间数据流    接口契约表（源模块 → 目标模块 → 数据实体 → 方向）

【模块滑窗】进入某模块时装配，离开时卸载
  7. 当前模块设计方案   该模块 HLD 章节 + LLD

  10. 过程讨论记录 / 历史会话 / 被否决方案
  11. 其他模块的设计细节
  12. src/themes 全量（用户已确认「本就是按需安装，可以压缩」）、组件库全量
```

| 常驻基线 1-6 | ≈32 KB | ≈16K | 8% |

### 4.2 写入侧门禁（对 P1 —— v1 完全没覆盖）

v1 §二只管**读取侧**（什么常驻、什么按需），但 P1 的病根在**写入侧**：智能体把讨论写进 PRD。读取分层再细，也拦不住脏数据进基线。

**建议三条写入规则：**

1. **三态标注**：任何要写入基线的内容必须先归类
   - `[事实]` 客户原话 / 已签字需求 / 实测数据 → 可进基线
   - `[讨论]` 方案对比、试错过程、智能体推断 → **只能进过程层**（`project-memory.md` 讨论小节）
   - `[否决]` 被否掉的方案 + 否决理由 → **只能进过程层**，且必须写否决理由（防止后续会话重提）
2. **来源标注**：PRD/SRS 每条需求带来源（客户原话第 N 次沟通 / 设计讨论结论 / 智能体补全待确认）。`[智能体补全待确认]` 的内容**不得**作为 `SPEC_SOURCE` 真源。
3. **压缩时保留规则**：过程层可丢，基线层不可丢；`[否决]` 条目在压缩时**必须保留理由一行**（否则失忆后会重走弯路 —— 这正是 P2 的一个成因）。

### 4.3 模块完成快照（对 P2 —— v1 完全没覆盖，这是跨端失忆的解药）

用户痛点「web 端做完，到移动端失忆，要重新来」的根因：模块完成后的知识留在会话里，压缩即丢；且跨端需要的是**接口/数据契约**，不是实现细节。

**建议：每个模块验收通过后，产出一份 ≤300 字的快照，写入常驻基线第 6 项。**

```markdown
## 模块快照：<模块名>（端：web | mobile | both）
- 状态：已完成 / 进行中（完成度 %）
- 职责：一句话
- 对外接口：列出契约（输入实体 → 处理 → 输出实体），不写实现
- 依赖模块：上游 X（取什么数据）、下游 Y（给什么数据）
- 数据实体：本模块读写的实体名（与数据模型对齐）
- 关键决策：≤3 条，只写结论 + 一句理由
- 跨端差异：web 已实现的部分，mobile 需注意什么（组件/交互/字段差异）
- 未完成 TODO：≤3 条
```

**跨端失忆的具体解法：** 移动端启动「用户管理」模块时，装配公式取 = 常驻基线（含 web 端该模块快照）+ 移动端滑窗。**它读到的是 web 端的接口契约与跨端差异，不需要重读 web 端实现** → 不失忆，也不爆上下文。

**触发时机（关键设计，建议采纳）：** 快照的产出以 **v1 §四「数据流闭环验收」通过为前置门禁** —— 「A 的输出都能被某模块接住、无孤儿数据、无凭空数据」验收通过 → 才写快照 → 才允许压缩上下文 → 才进下个模块。

这样 v1 §四 从「一条质量判据」升级为「**压缩的闸门**」，用户说的「这个模块完成就压缩上下文」就有了可判定的「完成」定义。否则「完成」由智能体自报，等于没有门禁。

### 4.4 manifest 扩展（对 v1 §五 的补强）

v1 §五 的「组件↔文档章节↔模块」映射方向完全正确（我审查报告 §3.2 的溢出炸点正需要它）。建议**扩一个字段**支持跨端：

```json
{
  "component": "UserTable",
  "module": "user-management",
  "docRef": "SRS#3.2 / HLD#user-management",
  "platforms": ["web", "mobile"],
  "dataEntities": ["User", "UserRole"],
  "status": "web:done | mobile:todo"
}
```

`platforms` + `status` 让「web 做完、mobile 未做」在 manifest 里可见，滑窗装配时可据此只加载相关切片。

现有 `component-registry.json`(4.6KB)、`components.catalog.json`(58KB)、`layout.manifest.json`、`pages.catalog.json` 都在**组件库侧**，无此反向映射 → 新建不重复，但**必须声明与现有 4 个 json 的关系**（谁引用谁），否则又是双份真源。
