> 术语定稿（**与 AGENTS.md「PRD→SRS 转写门禁」一致**）

现有真源里 **SRS 一直是「需求规格说明书」（做什么）**，设计层是 HLD/LLD。逐条实测证据：

### 冲突 2：方案要「新增」的两个基线维度，现有 HLD 规范里已完整存在

方案 §一 把「**系统架构 + 数据模型**」列为新增基线维度，§六.1 要求「新增数据模型、系统架构作为基线维度（或并入 SRS 展开）」。

但 `.agents\knowledge\phase2-design\hld-spec.md` **已有完整章节**：

| 方案想新增 | hld-spec.md 现有章节 |
|---|---|
| 系统架构 | 「系统总体设计」（含**系统总体架构图**）+「应用架构」（分层设计 / 功能模块划分 / **模块依赖关系，避免循环依赖**）+「技术架构」+「部署架构」 |
| 数据模型 | 「数据架构」：核心业务实体清单、**实体关系（1:N / N:M）+ 概念 ER 图**、存储选型及划分依据 |
| （方案未提但已有） | 「接口架构」、「非功能性设计」（SRS 非功能需求 → 架构应对策略**逐条映射表**） |

而且 `hld-spec.md` 已有 **11 项质量清单**（系统边界、架构图+文字解读、模块清单每行标注对应 SRS 功能编号可追溯、无未说明的循环依赖、ER 图覆盖 SRS 数据需求、技术选型每项有理由、非功能需求逐条映射、无越界内容…）和**明确的 HLD/LLD 越界判据表**。

**后果**：若豆包「新增」这两个维度，会与 `hld-spec.md` 形成**双份真源** —— 正是 deepseek 自己在 P2 系列里反复要求消除的问题（P2-1 skills 三处重复、P2-2 hook 双配置、P2-3 两层 rules）。

**正确做法应是「引用」而非「新增」**：基线链写 `客户需求 → PRD → SRS(需求规格) → HLD(含系统架构+数据模型) → LLD`，然后指向已存在的 `hld-spec.md`。

### 冲突 3：「Mermaid vs 手绘 PNG」是个伪对立，现有链路已实现方案的理念

方案 §三 要求「一律用 **Mermaid 文本源码**存基线」「渲染交给工具（mermaid-cli / kroki）」「**不让 AI 手绘 PNG**」，价值定位是「**源码喂模型、渲染图对齐人**」。

这个**理念完全正确**，但现有链路**已经实现了**，只是源码格式不是 Mermaid：

- `.agents\skills\diagram-generator\`（1.0 MB）产出 **`.drawio` XML 源文件 + 渲染 PNG**，`examples\` 下 20 组 `.xml`+`.png` 成对存在（`architecture` / `bpmn-flow` / `cross-functional` / `er-diagram` / `flowchart` / `sequence` / `swimlane` / `system-arch` / `uml-class` / `uml-state` / `uml-usecase` / `mindmap` 等）
- `.drawio` XML **本身就是文本源码**：可版本、可 diff、可 grep —— 与方案对 Mermaid 的要求逐条对应
- `hld-spec.md:66,76` 已明确要求「配**系统总体架构图**（`diagram-generator`，architecture 类型）」「配**概念 ER 图**（`diagram-generator`，er 类型，概念级不含字段）」
- 另有 `.agents\skills\drawio-generator\`（1.0 MB）与 `.agents\skills\canvas-workspace\references\drawio\`（含 `spec.schema.json` + `cli.js`）

**所以方案说的「AI 手绘 PNG」在现有体系里并不存在** —— 现状是「AI 生成 .drawio XML → 工具渲染 PNG」。deepseek 可能误判了现状。

若强推 Mermaid：会与 `diagram-generator` / `drawio-generator` / `canvas-workspace` 三个技能（合计约 2 MB，含 40 组示例）形成**两套图源码格式并存**，而 `AGENTS.md:104` 的裁决表已经在处理这两个技能的边界纠纷了，再加 Mermaid 会让裁决更复杂。

实测现状基数（2,248 个 `.md`）：**仅 13 个含 mermaid 代码块，45 个含 PNG/JPG 引用** —— 说明 Mermaid 目前几乎没有使用基础，切换成本高于收益。

**建议**：保留 `diagram-generator` 的 `.drawio` XML 作为图源码真源（已满足「源码喂模型、渲染图对齐人」），只在方案里把「Mermaid」改为「文本源码（.drawio XML，或 Mermaid 视项目需要）」，**不要强制单一格式**。
