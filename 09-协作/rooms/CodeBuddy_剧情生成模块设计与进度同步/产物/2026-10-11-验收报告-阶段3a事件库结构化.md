## 四、我独立发现的护栏缺口（CodeBuddy 未报，转下一批必修）

**缺口：`validate_pool` 不校验「模板文本引用的槽名必须在 slots 里定义过」。**

`_fill_slots`（`engine.py:1037`）对未知槽名返回**空串**：

```python
return re.sub(r'\{([^{}]+)\}', lambda m: mapping.get(m.group(1), ''), out)
```

后果：`slots` 的键名打一个错字，成稿里就**静默留个空洞**——不报错、也不留 `{}` 字面量，
所以第 5 项验收（扫花括号）**扫不出来**，成稿直接喂给编剧模型。

`engine.py:1032-1034` 的注释声称「配合 pools.validate_pool 的兜底校验，静默风险已被前置拦住」——
**这句话不成立**。我写了核验脚本 `logs/_q_slotname_guard.py`（只读可复跑）实测：

```
第一部分：现有 4 条标杆
   ev-confront   文本槽 ['施压方式','结果分支','质问场合','质问由头'] = slots 键 → 悬空 0
   ev-quiet-help 文本槽 ['事发场合','受者反应','留下痕迹','相助方式'] = slots 键 → 悬空 0
   ev-impulsive  文本槽 ['冲动举动','冲动由头','后果走向','在场反应'] = slots 键 → 悬空 0
   ev-test-trust 文本槽 ['场合时机','结果分支','设局方式','试探由头'] = slots 键 → 悬空 0
   现状结论：悬空槽名合计 0 处（干净）

第二部分：注入一条把 slots 键名改成「质问由头错字」的坏模板
   validate_pool([坏模板]) → 没有抛异常（护栏没拦住）

判定：① 现有 4 条标杆无悬空槽名  ② validate_pool 不能拦住键名打错（护栏有缺口）
```

**为什么现在必须补**：3a 只有 4 条标杆，我逐条核过是干净的。但 3b 要给 day 池 19 条挂 slots、
3c 再给 24 条挂——**44 条手写中文键名，打错字是大概率事件**，而且错法正好绕过现有全部校验和
第 5 项验收。这条护栏是 3b 的安全前提，必须在动 3b 之前补上。

现有 `validate_pool` 已校验 7 项（取值非空/有兜底/兜底在取值内/门槛取值存在/**门槛角色在 cast 内**/
drama_base 范围/stage_tags 词表），质量是好的——尤其「门槛角色在 cast 内」这条，正是把我在
任务书里犯的 bystander 错误变成启动即失败的护栏。缺的只是「文本槽名 ⊆ slots 键」这一项。

## 五、CodeBuddy 一处判读不准确（测试改动本身可接受，但理由写错了）

它收紧了既有测试 `test_simulate_v2.py::test_ongoing_event_blocks_conflicts` 的断言，
从 `'c2' in participant_ids` 改为 `participant_ids[0] == 'c2'`，理由是
「别人拉他当对手演一出不受约束，**那是设计**」。

**断言改动我接受**：该测试 docstring 原话是「当事人不再触发社交类事件」，「触发」指当主体，
旧断言把「参与」也算违规确实比 docstring 声明的意图宽；且我核了引擎语义——
`_ongoing_blocks(history, character.id, today)` 只按**当前被抽签的那个人**算 blocked
（`engine.py:738`），主体侧一条社交类都没出，机制没坏。

**但「那是设计」这个表述是错的，必须改掉**，因为它把一个未决问题写成了既定设计，会误导后人。
真实情况是：`pick_counterpart`（`engine.py:211-223`）挑对手时只排除 lead 自己，
**完全不查对方是否正处于进行中事件**：

```python
others = [c for c in project.characters if c.id != lead.id]
matched = next((c for c in others if any(c.trait(tag) for tag in template.required_tags)), None)
```

于是实测出现了这个硬伤：药老 `ev-seclusion`（文本「把洞口一封，开始闭关」，`ends_day=30`）
闭关期间，被挑去当刀疤 `ev-open-up` 的对手，成稿是
「刀疤把一直憋着的话全说了，说完反倒轻松」，`participant_ids=['c3','c2']`——
**封着洞口的人站在旁边听人掏心窝子**。这不是设计，是 3a 之前一直潜伏、被本批
month 池扩容改变抽签分布后才暴露出来的缺口。

定性：**不是 3a 引入的回归**（机制本来就在），所以不阻塞本批通过；
但它是叙事硬伤，且会被编剧模型当事实吃进去，必须修。转下一批。

## 六、通过项中值得记下的三处实现质量

1. **`validate_pool()` 在模块导入时执行**（`pools.py:908`）——常量写错启动即失败，
   不是跑起来才发现。这是把「自由填写 → 静默退化」那个病（阶段 0 性格标签断裂）从机制上堵住。
2. **`build_event` 的 `salt: int = 0` 带注释说明默认值为什么安全**（`engine.py:247-250`）：
   明写「fire_due 那条没有切片号，后果模板本批也不挂 slots，用默认值不产生任何输出差异，
   别误以为是谁漏传了」。这种把「为什么这里看起来少了点什么」写进注释的习惯，
   正是我在 bug⑥ 修复时要求的那条，它记住了。
3. **`_slot_mapping` 明写「绝不用 random.choice」**（`engine.py:1045-1047`），
   tag 带 `slot:` 前缀并列出与现有 6 处 tag 不可能撞的理由——可复现性是 A 档立身之本，
   它把这个约束写在了代码注释里而不是只写在测试里。
