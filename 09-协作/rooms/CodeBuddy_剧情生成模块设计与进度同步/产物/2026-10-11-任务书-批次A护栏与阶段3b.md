## 二、批次 A：三项改动（小，先行）

### A-1 补槽名护栏（必修，3b 的安全前提）

**问题**：`_fill_slots`（`engine.py:1037`）对未知槽名返回空串：

```python
return re.sub(r'\{([^{}]+)\}', lambda m: mapping.get(m.group(1), ''), out)
```

`slots` 的键名打一个错字 → 成稿静默留空洞 → **不报错、不留 `{}` 字面量**，
所以 3a 验收第 5 项（扫花括号）扫不出来，成稿直接喂给编剧模型。

`engine.py:1032-1034` 的注释声称「配合 pools.validate_pool 的兜底校验，静默风险已被前置拦住」
——**这句话目前不成立**。我写了核验脚本实测（`logs/_q_slotname_guard.py`，只读可复跑）：

```
现有 4 条标杆：悬空槽名合计 0 处（干净）
注入一条把 slots 键名改成「质问由头错字」的坏模板：
   validate_pool([坏模板]) → 没有抛异常（护栏没拦住）
```

**要求**：在 `validate_pool` 里补一条校验——**模板文本引用的槽名必须是 `slots` 的键（或 `a`/`b`）**。
扫描范围与 `_q_slotname_guard.py` 一致：`title` / `description` / `location` /
`consequences` / `plants_foreshadowing`。

- 正则与引擎保持一致（`\{([^{}]+)\}`），别自己另写一套，两套正则会漂移。
- 白名单只有 `a`、`b`（引擎在替槽前先替人名）。
- 报错信息必须指明**哪个模板、哪个槽名**，例如
  `ev-xxx: 文本引用了未定义的槽「事发场合错字」——slots 里没有这个键，成稿会留空洞`。
- 顺手把 `engine.py:1032-1034` 那段注释改对：护栏补齐后这句才成立。

**为什么现在必须补**：3a 只有 4 条标杆、我逐条核过是干净的。3b 要给 day 池 15 条挂 slots、
3c 再给 24 条挂——**44 条手写中文键名，打错字是大概率事件**，而且错法正好绕过现有全部校验。

**验收**：跑 `logs/_q_slotname_guard.py`，第二部分必须从「没有抛异常」变成抛 `ValueError`。

### A-2 修 `pick_counterpart` 的互斥缺口（必修，叙事硬伤）

**问题**：`pick_counterpart`（`engine.py:211-223`）挑对手时只排除 lead 自己，
**完全不查对方是否正处于进行中事件**：

```python
others = [c for c in project.characters if c.id != lead.id]
matched = next((c for c in others if any(c.trait(tag) for tag in template.required_tags)), None)
```

实测后果（3a 验收 §五）：药老 `ev-seclusion`（「把洞口一封，开始闭关」，`ends_day=30`）闭关期间，
被挑去当刀疤 `ev-open-up` 的对手，成稿「刀疤把一直憋着的话全说了，说完反倒轻松」，
`participant_ids=['c3','c2']`——**封着洞口的人站在旁边听人掏心窝子**。

这会被编剧模型当事实吃进去，是叙事硬伤。**注意：这不是 3a 引入的回归**（机制本来就在），
是 month 池扩容改变抽签分布后才暴露的潜伏缺口。

**修法（按这个来，含一个必须保留的回退）**：

1. 判定口径：**候选 c 的进行中事件的 `blocks` ∩ 当前模板的 `required_tags` ≠ ∅ → 排除 c**。
   复用现有 `_ongoing_blocks(history, c.id, today)`，不要另写一套判定。
2. `pick_counterpart` 需要新增 `history` / `today` 参数才能查到进行中事件。
   **给默认值 `None`**，`None` 时跳过排除逻辑——与 3a 的 `salt: int = 0` 同一个做法，
   保证旧调用点不破、可复现性不受影响。主路径（`engine.py:999` 等）传真实值。
3. **全被排除时必须放宽回原候选集**，不能返回 `None`：

   ```python
   if not others:
       # 所有人都在互斥状态 → 放宽。宁可对手戏不完美，也不要事件凭空消失
       # （返回 None 会让 cast=['a','b'] 的模板降级成独角戏，等于变相删事件）
       others = [c for c in project.characters if c.id != lead.id]
   ```

   这条回退是本项的核心权衡，**不要省**。省了的话，一个角色长期闭关会让所有涉及他的事件消失。
4. 保持确定性：排除与放宽都按 `project.characters` 原顺序，**不引入新随机源**。

**验收**：写一条 INV——构造「c2 闭关到第 30 天」的快照，从第 5 天推 20 天，
断言 c2 不出现在任何「其进行中事件 blocks 与该模板 required_tags 相交」的事件的
`participant_ids` 里（主体位和对手位都不许）。**并加反向验证**：把排除逻辑去掉后该测试必须变红。

**关于第 2 项的阈值——有实测依据，不是拍的**（`logs/_q_3b_threshold.py`，只读可复跑，
口径与 `_diag22` 逐字一致）：

```
现状（3a 已交付态）：day 368 条 / 去重 174 种 / 重复率 52.7%
① 3b 待改造的 day 池 15 条 : 出现 159 次 / 当前只贡献去重 34 种
② 3a 已改造的 4 条标杆     : 出现 119 次 / 当前贡献去重 117 种   ← 117/119 = 98.3%
③ 其余池（month/year/epoch）: 出现  90 次
```

**②这行是阈值的依据**：3a 那 4 条改造后，119 次出现产出了 117 种不同文本（98.3%），
说明 slots 机制的组合空间是实的、几乎每次都能产出新文本。

按同一比例外推 3b：`159 × 98% ≈ 156 种` → day 去重 `174 − 34 + 156 ≈ 296 种`、重复率 ≈ 20%。
**我定的阈值 ≥250 种 / ≤32% 对应的是「只达到 70% 比例」的保守下限**，
留了 46 种余量，正常实现应该轻松过。

- 若实测**优于**阈值 → 直接过，报实际数字。
- 若实测**差于**阈值 → **先查是不是有槽没真生效**。最可能三种：
  ① 某条模板槽名打错、被 A-1 护栏拦下后你绕过去了；
  ② `slot_conditions` 把取值筛空、全走了兜底（兜底是固定值，等于没槽）；
  ③ 8 条无对手戏的模板只给了 1~2 个槽、没凑满 ≥3。
  **查完仍不达标再回来跟我商量阈值**，不要自行调参凑数、也不要自行加模板条数凑。

## 六、协作规矩（本轮新增两条，与既有的一并遵守）

   不要写「那是设计」。测试断言可以按当前实现收紧，但理由必须写准。
