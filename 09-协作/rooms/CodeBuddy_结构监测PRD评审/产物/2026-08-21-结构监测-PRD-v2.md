## 1. 接口字段总览

docx 推送的结构顶层 JSON，统一字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | string | 测点类型（对应 24 项监测项的英文 code），docx 给出标准值 |
| `period` | long | 数据周期（毫秒），推送到 平台的时间间隔 |
| `ts` | long | 采集时间（毫秒 Unix 时间戳） |
| `pointNo` | string | 测点编号，全局唯一 |
| `present` | double \| string | 本次变化量（依监测项见 §2） |
| `cumulative` | double \| string | 累计变化量（依监测项见 §2） |
| `ext` | string | 业务扩展字段（JSON 字符串），具体结构由业务平台自定 |

> **关于 ext**：v1 错误地把它描述为"专属字段"。`ext` 对所有 24 类都是同一类（业务扩展 JSON）。docx 在每节里还平铺了若干"专属字段"（直接挂在顶层，如 `temperature`, `liquid`, `distance`, `hz`, `val`, `stress`, `axial`, `shakeval`, `frequency`, `humidity`, `waterLevel`, `waterTemp`, `length`, `original` 等），这些**不是** ext 内的字段，而是一等顶层字段，类型多为 double。

### 1.1 present / cumulative 的两种形态

- **标量（double）**：直接是数值，与阈值比。
  - 适用项：3 应变-应力、4 水平位移、5 沉降、7 轴力、9 水位、10 混凝土支撑轴力、11 挠度、12 温湿度、13 拉线、14 磁致测缝、15 振动索力、16 八通道温度、17 六通道应变、18 静压水准、19 表贴弦式应变、20 弦式钢筋计、21 弦式土压力、22 弦式锚杆测力、23 光纤光栅-应变、24 光纤光栅测缝或者位移
- **矢量（string，逗号拼接多轴）**：必须先合成"向量模 M"再与阈值比。
  - 1 振动频率：`x, y, z`（M = √(x²+y²+z²)）
  - 2 倾斜：`X:°, Y:°`（二维向量模；docx 度量是角度差）
  - 6 深层水平位移：`x, y`（二维）
  - 8 测缝：docx 类型为 string，但实测业务多为标量值；按 docx 表述以"业务可合成"对待，前端展示按矢量渲染。

> 注：8 测缝的 docx 类型虽写 string，但语义上通常是单轴，故原型用"如 string 则合成向量模；如 double 则直接用"的兜底逻辑。研发期需向客户确认。

## 3. 告警机制（v2）

### 3.1 监测指标（M / 变化量）

- **双轴/三轴矢量**项：监测指标 → **向量模**（M = √(Σⁿ aᵢ²)）。
  - 显示名"向量模"；备注中可写"综合指标 M"。
  - 公式浮窗：ⓘ 点击展开，看到本监测项的合成公式（如二轴：M = √(x²+y²)；三轴：M = √(x²+y²+z²)）。
- **单轴标量**项：监测指标 → **变化量**（即原始 present/cumulative 本身）。注意：不是对 double 做"模"，而是直接用数值。

> 命名上"综合指标 M"是技术术语，给客户的应该是"向量模"或更直接"变化量"两个新名字。

**告警计算边界（v2.1 评审收敛）**：告警计算/阈值比对仅基于本监测项的监测指标——标量项直接用 `present`/`cumulative` 数值，矢量项合成向量模 M 后比对。顶层专属字段（`temperature`/`liquid`/`hz`/`distance`/`stress`/`axial` 等）仅用于**展示与校准**（温度补偿、液位换算、辅助距离等），**不直接参与阈值比对**；若个别监测项确需以其专属字段独立告警（如单独超温 / 低液位），必须在预警配置（§5.3）中**单独声明一条规则并配置独立阈值**，不得把专属字段隐式混入本项的主指标判档。

### 3.2 监测粒度

5 种粒度：

| 监测粒度 | 表名 | 数据来源 | 适用监测项 |
| --- | --- | --- | --- |
| 累计变化量 | cumulative | 累计变化量 字段直接做（不二次聚合） | 全部 24 项 |
| 每次变化量 | present | 本次变化量 字段直接做（单点原值，无聚合） | 全部 24 项 |
| 每时变化量 | hour | 每小时：当前小时第1笔累计变化量 − 上个小时第1笔累计变化量（秒级归一化） | 全部 24 项（振动高频场景不适用） |
| 每日变化量 | day | 每日：取每日各小时第 1 笔累计变化量，与昨日同时刻第 1 笔做差分（今日n时第1笔 − 昨日n时第1笔），每小时计算 1 次 | 全部 24 项 |
| 每月变化量 | month | 每月：取每天第 1 笔累计变化量，与 30 天前同日第 1 笔做差分（今日第1笔 − 前30天第1笔），每天计算 1 次 | 全部 24 项 |

> **振动高频场景说明（v2.1 评审收敛）**：监测项 1 振动频率等**高采样率项不适用「每时变化量」**——毫秒级高频数据下，相邻小时首笔 cumulative 的差分会随时间窗口对齐方式剧烈跳动，窗口代表值失去意义。处理口径：此类项在预警配置（§5.3 / §10.2.3）中「每时变化量」选项**禁用置灰**，用户从其余 4 种粒度中另选；演示默认回退「每次变化量（present 原值）」。趋势图「单次变化量 + 近24小时」场景对高频项同样不显示每时聚合曲线（显示为空并提示）；「每日 / 每月变化量」对高频项仍按 §3.2.1 正常计算（累计值在日级/月级窗口差分仍有意义）。

> 交互映射（趋势分析 / 历史数据弹窗趋势图）：「单次变化量」切换统计周期（近24小时/近30天/近12月）时，曲线即呈现为该周期对应的「每时/每日/每月变化量」，均基于 **cumulative 首笔差分** 计算；「累计变化量」则直接绘制 cumulative 原值（随周期只改 X 轴密度）。单次变化量(present) 在单点无聚合场景下即 present 原值。

> v1 粒度用了"前后两笔"这种容易歧义的写法。v2 统一为 5 种命名（last/每时/每日/每月/累计）。

#### 3.2.1 聚合算法（变化量计算口径）

「每时 / 每日 / 每月变化量」三者的计算口径如下（平台侧按监测粒度聚合，**取每时间窗口内第 1 笔累计变化量(cumulative) 作为该窗口代表值**后做差分；单次变化量(present) 在切换时间范围时即呈现为以下聚合值）：

- **每时变化量**：每过 1 小时，取「当前小时第 1 笔累计变化量 − 上个小时第 1 笔累计变化量」，再按两笔数据实际时间差做秒级归一化：
  ```
  每时变化量 = (当前小时第1笔累计变化量 − 上个小时第1笔累计变化量) × 3600 / 两笔数据时间差(秒)
  ```
  > 若两笔间隔恰好为 1 小时，则 `×3600/3600 = 1`，退化为简单的相邻小时首笔累计差分。

- **每日变化量**：每小时取「今日 n 时第 1 笔累计变化量 − 昨日 n 时第 1 笔累计变化量」（按同时刻小时窗口对齐，每小时计算 1 次，无秒级归一化）：
  ```
  每日变化量 = 今日n时第1笔累计变化量 − 昨日n时第1笔累计变化量
  ```

- **每月变化量**：每天取「今日第 1 笔累计变化量 − 前 30 天第 1 笔累计变化量」（滚动 30 天窗口，每天计算 1 次）：
  ```
  每月变化量 = 今日第1笔累计变化量 − 前30天第1笔累计变化量
  ```

> 说明：
> - 上述三式的"代表值"取 **累计变化量 `cumulative`**（标量 double 或矢量 string）；矢量类需先合成向量模 M = √(Σaᵢ²) 再参与差分。
> - "单次变化量"(`present`) 单点展示为原值；仅在配合统计周期（24h/30d/12m）做窗口聚合时，按上三式（基于 cumulative 首笔差分）呈现为每时/每日/每月变化量。
> - "累计变化量"（`cumulative`）为接口直接下发的累计值，不在上述三式内另行聚合；切换统计周期只改变展示密度（趋势图最多 100 点均匀采样，§3.3），数值取对应时刻原值。
> - 三式仅定义"变化量"口径；最终是否触发预警还需与三档阈值（§3.4）比对。

### 3.3 趋势图数据点约束（均匀采样）

- 趋势图 X 轴直接展示整段生命周期（开始 `triggeredAt` → 结束 `recoveredAt` 或当前）。
- 约束：**展示数据点最多只展示近 100 条**。实现方式：
  - 设真实生命周期内原始采样点数为 `RAW_COUNT`、展示上限 `MAX_POINTS = 100`。
  - 若 `RAW_COUNT ≤ 100`：全部展示，不做降采样。
  - 若 `RAW_COUNT > 100`：按 `stride = ceil(RAW_COUNT / MAX_POINTS)` 做**均匀采样**（每隔 stride 取 1 点），在保持时间跨度完整的前提下把点数压到 ≤ 100。
  - 即 `count = min(RAW_COUNT, ceil(RAW_COUNT / stride))`，X 轴时间按 `i × stride × rawStepMs` 推进。

### 3.4 三档阈值与触发类型（v2.1 明确 lt 反向排序）

- 触发类型：`gt`（大于）/ `lt`（小于），按监测项物理意义设定（示例：超温/超限告警用 gt，低温、低液位告警用 lt）。
- 三档阈值按**告警严重度**递增：黄（最轻）< 橙 < 红（最重）——这里的序指**等级**，不是数值大小。
  - **gt 触发**（数值越大越严重）：阈值数值应满足 黄档 < 橙档 < 红档（例：累计沉降 >10 / 20 / 30 mm 分别黄/橙/红）。判档：监测指标 ≥ 黄档即至少黄档，≥ 橙档即至少橙档，≥ 红档即红档，取**所越过的最高档**。
  - **lt 触发**（数值越小越严重）：阈值数值**反向**设置 黄档 > 橙档 > 红档（例：低温告警 <5℃ 黄、<3℃ 橙、<1℃ 红）。判档：监测指标 ≤ 红档即红档，≤ 橙档即至少橙档，≤ 黄档即至少黄档，同样取所越过的最高档。
  - 通用表述：监测指标（标量原值 / 矢量向量模 M）按上两式与三档阈值同向比较，命中即触发对应严重度档。
  - 说明：本文档其他章节（§6 判档函数、§6.6 结论文案、§10 配置说明）默认以 gt 实例书写（`≥`），lt 场景方向取反，判定语义与本条一致。

### 3.5 闭环节

- 告警生命周期：触发预警（triggered）→ 处理中（working）→ 已闭环/已忽略（closed/ignored）。再次告警 = 新的一笔。
- 历史数据展示：按"本笔预警"展示开始 → 结束（recoveredAt），期间段落为"告警"，其余为"正常"。

## 6. 智慧诊断（诊断看板）

诊断看板位于「智慧诊断」模块顶部，由两张卡片组成：**整体健康评分**（左，环形进度 + 等级徽章）与**风险概览**（右，饼图 + 统计方块）。两者均基于各监测项「当前最新值 vs 三档阈值」推导，与趋势预测（D1-D5）解耦，属于独立的实时聚合视图。

### 6.1 数据源与输入

- 输入：各监测项实时序列 `genHistory(item)` 的**最后一条（当前最新值）** `lastV`。
- 三档阈值：`item.thr = [黄档 T_y, 橙档 T_o, 红档 T_r]`（严重度升序，数值方向随 gt/lt 见 §3.4；矢量类取综合指标 M 判档）。
- 判档函数：gt 触发 `breach = thr.filter(t => lastV >= t).length`；**lt 触发 `breach = thr.filter(t => lastV <= t).length`**（此时三档数值反向，红档为最小数值）。越过几档（0=正常，1=黄，2=橙，3=红），口径同 §3.4。
- 演示态：数据由前端 30 点确定性序列生成；真实环境由接口返回「各档位测点计数」即可（无需逐点明细）。

### 6.2 健康评分算法（H1-H2）

| 步骤 | 公式 / 规则 | 说明 |
|---|---|---|
| H1 单测点评分 | `score_i = 100 − deduct_i`，`deduct_i ∈ {0, 40, 70, 100}` | 初始 100 分；超黄档扣 40、超橙档扣 70、超红档扣 100；下限为 0 |
| H1 扣分项映射 | `breach=0→0；1→40；2→70；3→100` | 取最高档位对应扣分，不叠加 |
| H2 整体评分 | `overall = round( Σ score_i / N )` | N = 监测项总数，取整 0-100 |

**等级划分（三档，用于徽章配色与文案）：**

| 等级 | 分数区间 | 主色 | 语义 |
|---|---|---|---|
| 健康 | `overall ≥ 90` | 绿 `#16a34a` | 全部测点远低于阈值，无需关注 |
| 良好 | `70 ≤ overall < 90` | 蓝 `#2b6cff` | 大部分正常，个别接近阈值，整体可控 |
| 风险 | `overall < 70` | 红 `#dc2626` | 多项已触发预警或逼近红档，需立即排查 |

### 6.3 风险概览（R1-R3）

职责：用「档位分布」概览风险，而非逐条列举测点（列举属于预警信息模块 §5）。

- **R1 统计口径**：按最高档位将全部测点分入 4 组——红 / 橙 / 黄 / 正常。各档计数 `countByLevel[lv]`，`正常 = N − (红+橙+黄)`。
- **R2 大规模兼容**：展示只依赖 4 个计数，与测点总数 N **无关**。无论 N=4 还是 N=1000，布局恒定为「饼图 + 一句话结论 + 4 个固定统计方块」，**禁止逐条列出测点名**（避免 O(N) 展开导致排版崩溃）。真实环境接口只需返回各档 count。
- **R3 饼图渲染约束**：
  - 四档位固定四色：红 `#dc2626` / 橙 `#ea580c` / 黄 `#f59e0b` / 正常 `#16a34a`。
  - `val=0` 的档位不绘制扇形（图例/方块仍展示），避免 0 角度奇异几何。
  - **单档占 100% 时 path 退化无法闭合**（起止点重合），必须改用 `<circle>` 元素渲染整圆，否则浏览器不绘制填充。
  - 扇形旁标注占比 %，hover 显示「档位：项数（占比%）」。

### 6.4 卡片视觉规范

- **健康评分卡**：SVG 环形进度条（灰底环 + 彩色进度弧，弧色随等级），圆心填大号分数 + 「/100」，右侧等级圆角徽章（彩色字 + 浅底 + 描边），副标题注明「基于 N 项监测项」+ 算法摘要。
- **风险概览卡**：左侧饼图（≤130px 固定尺寸），右侧结论句（如「共 N 项监测中，x 项红档、y 项橙档、z 项黄档，已超阈值合计 k 项」）+ 4 个等宽统计方块（档位名 / 项数 / 占比%）。
- 全正常态：饼图整圆绿色，结论句「当前无监测项超阈值，整体健康。」

### 6.5 趋势预测算法（D1-D5）

位于「智慧诊断 / 趋势预测」图表区，复用诊断看板同级的「测点 + 监测项 + 预测周期」筛选输入，对单监测项历史序列做**线性趋势外推 + 季节修正 + 95% 置信带**预测。

**输入**
- 历史实测序列 `series`：演示态由 `genHistory(item)` 生成 30 点确定性序列（基于 `base/slope/season/noise`，避免渲染跳动）；真实环境由接口返回历史序列。
- 预测周期 `period ∈ {day, week, month}`，对应预测步数 `steps`：**日 = 7、周 = 8、月 = 12**（即分别预测未来 7 天 / 8 周 / 12 个月）。

**算法口径（D1-D5）**

| 步骤 | 公式 / 规则 | 说明 |
|---|---|---|
| D1 趋势斜率 k | `k = Σ(tᵢ−t̄)(vᵢ−v̄) / Σ(tᵢ−t̄)²` | 对历史序列 (t,v) 最小二乘线性拟合；`tᵢ = i`（等距索引），`n≤1` 时 `k = 0` |
| D2 残差标准差 σ | `σ = sqrt( Σ(vᵢ − fittedᵢ)² / (n−2) )` | `fittedᵢ = v̄ + k·(tᵢ−t̄)`；`n>2` 才有效，否则兜底 `σ = |v_last − v̄| || 0.01` |
| D3 周期修正量 | `seasonMean[phase]`，`phase = i % seasonCycle` | 按相位聚合历史残差 `vᵢ − fittedᵢ` 取均值；`seasonCycle = day?7 : week?4 : 12` |
| D4 预测值 | `v_pred(s) = v_last + k·(s×30) + seasonMean[(histN−1+s) % seasonCycle]` | `v_last`=历史末值，`s = 1..steps`；线性趋势外推 + 季节性修正（`×30` 为采样单位示意时间推进） |
| D5 置信上下限 | `upper = v_pred + 1.96·σ`；`lower = v_pred − 1.96·σ` | `1.96` 为标准正态分布 95% 双侧临界值（z₀.₀₂₅ ≈ 1.96）→ 预测值约 95% 落于 `[lower, upper]` |

**图表展示规范**
- 历史实测（蓝实线）+ 预测趋势（橙虚线）+ 95% 置信区间（橙色半透明带，建议填充透明度 ≥ 0.22 以保证可辨识）+ 三档阈值线（黄 `#ca8a04` / 橙 `#ea580c` / 红 `#dc2626` 虚线，来自预警配置）。
- 当前/预测分界：竖向虚线 + "当前"时间标签；X 轴标注「实测起 / 当前 / 预测终」三个时间锚点，单位随监测项。

> 注：演示态数据由前端确定性公式生成；真实环境需接口返回历史序列与三档阈值，算法口径（最小二乘 + 季节修正 + 1.96σ 带）保持不变。矢量类以综合指标 M（同 §3 / §6.1）参与预测。

### 6.6 趋势解读结论

结论由「当前最新值是否超阈值」与「预测峰值是否破阈值」联合判定，**共 3 种**：

| 结论 | 触发条件 | 文案模板 |
|---|---|---|
| **【情况较差】** | 当前最新值 `latest ≥ 某档阈值`（已处黄/橙/红档） | `${name}当前已处【档位】档预警（实测 X ≥ 阈值 T）。未来 N{unit}趋势{trendWord}，预测峰值将升至 P${peakLevel?`（超${peakLevel}档）`:``}，较当前恶化约 +Y%。${confTxt}建议尽快处置，避免持续恶化。` |
| **【需要关注】** | 当前未超阈值，但预测峰值 `maxPred ≥ 某档阈值`（未来将破档） | `${name}当前实测 X 暂未触发预警，但未来趋势{trendWord}，预计第 K{unit}突破【档位】档（阈值 T），预测峰值 P。${confTxt}建议提前排查。` |
| **【情况良好】** | 当前未超阈值 **且** 预测期内无破档 | `${name}当前实测 X，未来 N{unit}趋势{trendWord}，预测峰值 P（最低 Q），均低于黄档阈值 T₀，预测期内无预警风险。${confTxt}` |

**组装规则**
- `trendWord`（走向词）：`k > 0.0001 → 上升`；`k < −0.0001 → 下降`；否则 `平稳`。
- `confTxt`（置信说明，三结论共用结尾）：`数据围绕趋势上下波动约 ±σ{unit}，预测值有 95% 把握落在 lower ~ upper{unit} 之间。`
- 恶化百分比 `Y = (maxPred − latest) / latest × 100`（末值 ≤ 0 时记 0）。
- 破档节点 `K` = 预测序列中首个 ≥ 阈值 的步序号（从 1 计）。
- 档位映射：`[黄, 橙, 红]` 依阈值越界档序取；`peakLevel` 为预测峰值所超最高档。
- 矢量类：判档与趋势解读均以综合指标 M 参与，不展示分量。

  - 🔺 每月变化量：记录每天第 1 笔数据，每月变化量 = 今日第1笔累计变化量 − 前30天第1笔累计变化量，每天计算 1 次每月变化量，判断 |每月变化量| 是否触发三档阈值

- **分页栏**：每页 10 条。

### 10.5 报表（report）

> 注：本文档此前无独立「报表」功能章节，以下设计说明为该模块 UI 真源，建议后续补 § 功能章节。

- **工具栏**：周期切换（月/季/年，支持历史月份/季度/年份下拉）+ 下载 PDF（`window.print()` + `@media print` 样式）。
