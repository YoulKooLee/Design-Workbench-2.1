# 任务房间（Rooms）使用说明 v0.3

> 任务房间是智能体**跨任务协作**的单元：一个任务一个房间，上下文按房间隔离（像 IM 群聊），多个智能体在房间内共同推进任务。
> v0.3 增强：**白板机制**（进房先读白板降上下文）、**Handoff 接力**（显式交接防踢皮球）、**intent 审计**（每条消息带意图，复盘有据）。

---

## 1. 房间是什么

```
rooms/
├── README.md
├── 豆包_智能体协作方式构建与案例查找/
│   ├── 00-任务说明.md        # 白板：任务说明/进展/结论/下一步/接棒人/状态（持续更新）
│   ├── messages.jsonl        # 房间对话消息流（每条带 from+intent+时间戳）
│   └── 产物/                 # 该任务产出（room put 放入）
├── 豆包_智能体协作方式构建与案例查找_2/
└── CodeBuddy_结构监测大屏设计/
```

- 一个任务一个房间，**只读写当前房间**，不把其他房间消息混入当前上下文（防串任务）。
- **命名规则**：`<发起者名>_<任务名>`（`room open` 自动生成，无需手写）。
  - 发起者名：用**显示名**（豆包/CodeBuddy/WorkBuddy/DeepSeek/千问），一眼溯源是谁发起的任务；
  - 任务名：简短（建议 ≤20 字）、可中文、去除路径非法字符 `\ / : * ? " < > |`，过长自动截断；
  - 例：豆包_智能体协作方式构建与案例查找、CodeBuddy_结构监测大屏设计。
- **其他智能体加入**：用**同一房间名**继续（`room read` 找到已有房间 → `room say` 加入），不另建新房间；
  同名任务由工具自动追加 `_2/_3` 消歧。
- 想找自己的房间：`room read`（列出你参与的所有房间）。

## 2. 白板（进房先读这个，别翻全部对话）

`00-任务说明.md` 是房间的**共享白板**——持续记录任务的核心状态，智能体进房 `room read` 只需读白板 + 消息流摘要，就能掌握任务全貌，**大幅降低上下文负担**。

| 白板段 | 内容 | 谁写 |
|---|---|---|
| 任务说明 | 任务目标 | 开房/创建者 |
| 进展 | 当前进展（追加式） | 各智能体 `room board --s 进展` |
| 结论 | 阶段性结论（追加式） | 各智能体 `room board --s 结论` |
| 下一步 | 待办/分工 | 各智能体 `room board --s 下一步` |
| 接棒人 | 当前该谁干（handoff 自动更新） | `room handoff` 自动写 |
| 状态 | active/review/done/blocked | `room status` 自动写 |

## 3. room 命令（智能体调用）

| 命令 | 作用 |
|---|---|
| `room open "任务名" --m 甲,乙` | 创建房间 + 登记参与者 |
| `room read` | 列出我参与的房间 |
| `room read T1-任务名` | 读某房间完整上下文（**白板 + 消息流**） |
| `room say T1-任务名 "内容" [--i 意图]` | 发言，intent 可选 ask/review/handoff/confirm/info（默认 info） |
| `room board T1-任务名 "内容" [--s 进展\|结论\|下一步\|说明]` | **记白板**（默认进展，追加式带身份+时间戳） |
| `room handoff T1-任务名 <接棒方> "内容"` | **显式交接**：把"接棒人"交给对方 + 留痕 + 自动检测踢皮球（往返≥2 次警告交用户仲裁） |
| `room put T1-任务名 <文件>` | 放产物到房间/产物/ |
| `room status T1-任务名 done` | 更新房间状态（active/review/done/blocked） |

> 工具：`messages/tools/room-cli.mjs`。身份用 `--who <你的ID>`（默认读环境变量 `AGENT_ID`）。

## 4. 协作流程（触发路由的第二步）

1. **触发**：对话中出现触发词（见 `docs/01-协作规范/trigger-routing.md`）→ 访问共享目录
2. **进房**：`room read` 找到对应房间；没有则 `room open` 创建
3. **看白板**：`room read <房间>` → 读白板（任务说明/进展/结论/下一步/接棒人）
4. **干活 + 记白板**：`room say`（发言）→ `room board`（更新进展/结论/下一步）→ `room put`（放产物）
5. **交接**：需要别人接力 → `room handoff <房间> <对方> "说明"`（接棒人自动更新，对方下次会话知道该它干）
6. **完成**：`room status <房间> done`，并在白板"结论"留总结

## 5. 约定

- **用户是最终仲裁者**：涉及批准/裁决，须用户留痕，禁止智能体代拍板。**同一任务 handoff 往返超 2 次强制交用户仲裁**（room 会自动警告）。
- **唤醒边界**：你在房间发言/交接后，对方智能体**不会自动被唤醒运行**——通知可自动（watcher），干活需用户轻唤对方一句。这是 LLM 会话制的客观限制。
- **审计**：每条消息带 intent（ask/review/handoff/confirm/info）+ 身份 + 时间戳，复盘能说清"谁在何时做了什么决定"。
- **产物归档**：跨任务沉淀的成果，另行复制到 `docs/02-项目档案/<项目>/`。
