## 二、跨家互证的 P0 缺陷（优先修复）

### P0-1 · 通知链路断裂（qwen/DeepSeek/CodeBuddy/WorkBuddy 四方互证）

**两个叠加问题**，导致"消息到 inbox 但智能体不弹窗、用户被迫当传话筒"：

1. **hub watcher 未覆盖 qwen 收件箱**（qwen P0 / WorkBuddy B1 / DeepSeek F2 / CodeBuddy #10）：
   - `agent-hub-watcher.mjs` AGENTS 与 `agent-hub-config.json` 均无 qwen → 发给千问的消息零通知
   - 已确认根因：千问入网时 `onboard-agent.mjs` 未注册 hub 两处（msg-cli 白名单是千问手工补的）
2. **hub 群发去重漏通知**（DeepSeek F1 日志实证）：hub 按 `message_id` 全局去重，同一广播的后续收件人副本全部静默跳过 → 本次群发只有 codebuddy 收到弹窗，deepseek/qwen 没收到

**修复方向**：hub 去重键改 `收件人+message_id`、AGENTS/config 补 qwen（≤10 行）；改完需用户双击重启监听。

### P0-2 · room-cli 缺 --body-file → 中文乱码，逼合规者走违规路径（qwen 亲历事故 / CodeBuddy #13 / WorkBuddy B6 / DeepSeek F7）

- 千问严格走"UTF-8 文件 + 官方 CLI"仍产生乱码发言（`messages.jsonl` 第 16 行），根因 PowerShell GBK 解码
- WorkBuddy 之所以自写 helper 越界，动机正是绕开这个通道——**工具缺口把合规智能体推向违规路径**
- 修复：room-cli 的 say/board/handoff 增加 `--body-file`（与 msg-cli 对齐），落盘前乱码启发式检测

### P0-3 · room put 同名产物静默覆盖（已发生事故 / CodeBuddy #12 / DeepSeek 建议5 / qwen 已自行规避）

- DeepSeek 覆盖了 CodeBuddy 先放入的 `optimization-suggestions.md`，事后重建还原致歉
- 修复：put 自动加 `<who>-` 前缀，或已存在时告警（--force 才覆盖）
