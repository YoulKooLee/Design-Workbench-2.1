# AI漫剧工作台 · 推演引擎详细设计：触发参数与调度

| 版本 | 日期 | 变更摘要 |
|---|---|---|
| V1.0 | 2026-10-17 | 首版：调度流程 + 事件数据模型 + 参数走向判定 + 连贯性校验器 |

> 本文档是「剧情生成模块」四阶段链路（框架→目标线→推演→剧本）中**阶段3 推演引擎**的详细设计，与《剧情生成器架构方案-目标驱动与框架约束-V1.0》衔接。设计原则遵循用户 2026-09-29 拍板基线：**推演=纯代码确定性，LLM 只做"一次性生成、入库冻结"的内容资产**。

---

## 一、架构定位（分层结论）

| 层 | 归属 | 职责 |
|---|---|---|
| 世界状态账本 | **纯代码权威（不可降级）** | 谁在哪儿、关系、境界装备、伏笔台账、身份暴露度——长篇一致性的锚 |
| 事件触发判定 | **纯代码** | 何时爆发、谁 vs 谁、什么类型（确定性、可复现、可断言） |
| 随机事件内容 | **纯代码** | 事件库模板 + slots 槽位组合（量大、套路化、低成本） |
| 必然事件内容 | **LLM 一次性生成→入库冻结** | 戏剧性关键节点（量少质高，百集 20~40 个）；推演运行时不调模型 |
| 世界事件 | **纯代码** | 周期/背景事件，上帝视角背景板 |
| 框架/目标线 | **LLM 生成→入库冻结** | 阶段1/2 产物，推演只读 |
| 剧本正文 | **LLM** | Writer 写 → Director 审 → 回写状态层 |
| 一致性校验 | **纯代码硬门禁** | 状态/时间线/伏笔回收核对；事件回填后状态清算 |

**降级边界**：降的是推演的"编剧身份"（事件内容来源），不降它的"记账身份"（世界事实来源）。

## 二、四阶段链路总览

```
阶段1 总体框架（LLM）→ 阶段2 故事线路拆分（LLM，多阵营目标线+倒排计划+时间切片）
  → 阶段3 推演（纯代码：世界/随机/必然事件，必然事件内容=LLM一次性生成）
  → 阶段4 写剧本（LLM：事件素材+边界装配上下文，Writer→Director→回写）
```

## 三、单时间步（切片）调度流程

每个时间切片按以下顺序调度，事件预算上限默认 6 条：

| STEP | 动作 | 归属 | 说明 |
|---|---|---|---|
| 0 | 世界事件结算 | 纯代码 | 周期/背景事件（战争、天灾、势力变动），上帝视角 |
| 1 | 必然事件检查 | 触发=代码 | 遍历 goal_conflicts：到窗口→到点必发或递增掷骰（首日30%、每天+10%、封顶90%、超窗强制）；**先占本片事件槽**；内容=LLM 一次性生成回填 |
| 2 | 主角保底 | 纯代码 | 本片主角无事件→强制从随机池抽 1 条（防"主角消失"） |
| 3 | 随机事件抽签 | 纯代码 | 填剩余槽：硬过滤→权重→归一化抽签→抢戏检查→连贯性校验（详见 §五/§七） |
| 4 | 结算与入账 | 纯代码 | outcomes 按参数选走向→后果串行结算→状态账本更新 |
| 5 | 填槽至预算上限 | 纯代码 | 进入下一时间步 |

## 四、事件数据模型

### 4.1 ER 关系

```
event_templates (1─N) event_outcomes
      │ 抽签+判定
      ▼
   events（事件实例）
      │ 效果结算
      ▼
character_state / relations / foreshadowings / pending_repercussions / world_states
```

### 4.2 event_templates（模板表，增量扩展）

```
基础：id / title / description / location
类别：event_type (random|world|system|inevitable) / themes[]
触发门槛：scale[] / stage_tags[] / cast[] / required_tags[] / min_realm /
         required_equipment[] / world_required[] / cooldown_days / blocks[]
权重：base / by_scale{} / trait_bonus / pillar_fit / goal_align / drama_base / urgency
行为：duration_days / life_line / slots{} / slot_fallback / slot_conditions[]
     / plants_foreshadowing / consequences[]
```

### 4.3 event_outcomes（新表：多走向参数化）

```sql
CREATE TABLE event_outcomes (
  id INTEGER PRIMARY KEY,
  template_id TEXT NOT NULL,
  order_no INTEGER NOT NULL,     -- 判定顺序，升序第一个命中即选
  cond_expr TEXT,                -- 条件DSL（NULL=无条件默认走向）
  result_text TEXT NOT NULL,     -- 该走向成稿（可含 {槽位}）
  prob REAL DEFAULT NULL,        -- 兜底权重（条件全不中时加权随机）
  effects TEXT NOT NULL,         -- JSON：status_delta/relation_delta/props/bag/伏笔/待办后果
  UNIQUE(template_id, order_no)
);
```

### 4.4 events（实例表，扩列）

新增：`event_type`、`outcome_selected`（走向ID）、`coherence_status`（pass/retry/suppressed）、`suppressed_reason`。

### 4.5 world_states（新表：世界状态断言）

```sql
CREATE TABLE world_states (
  id INTEGER PRIMARY KEY,
  project_id TEXT NOT NULL,
  stmt_type TEXT NOT NULL,      -- org|region|faction|person|artifact|realm_order
  target_id TEXT NOT NULL,      -- 实体名（青云宗/南疆/人族联盟…）
  attr TEXT DEFAULT 'status',   -- status|leader|size|relation_to
  value TEXT NOT NULL,          -- exists|destroyed|at_war|declining|active…
  updated_day INTEGER NOT NULL,
  UNIQUE(project_id, stmt_type, target_id, attr)
);
```

用途：`world_required` 门槛过滤（§五）+ 连贯性校验 D2（§七）的唯一数据源。

## 五、触发参数模型（每条模板三层参数）

```json
{
  "id": "ev-xxx",
  "type": "random | world | system | inevitable",
  "preconditions": {
    "themes": ["修仙"],
    "world_required": ["world.org.青云宗 == exists"],
    "stage_tags": ["中段"],
    "scale": ["day", "month"],
    "cast": ["a", "b"],
    "required_tags": ["冲动"],
    "min_realm": 3,
    "required_equipment": [],
    "cooldown_days": 3,
    "blocks": ["闭关", "逃亡"]
  },
  "weights": {
    "base": 1.0,
    "by_scale": {"day": 1.0, "month": 0.8, "year": 0.3, "epoch": 0.1},
    "trait_bonus": 0.5,
    "pillar_fit": 0.3,
    "goal_align": 0.4,
    "drama_base": 6.5,
    "urgency": 0.2
  },
  "behavior": {
    "duration_days": 5,
    "outcomes": [
      {"order_no": 1, "cond_expr": "a.realm >= 5 AND b.relation(a) < 20",
       "result_text": "{b}欲夺舍{a}，反被{a}以神识反噬，魂飞魄散。",
       "effects": {"status_delta": {"a.realm": 1}, "bag": ["夺舍残魂"]}},
      {"order_no": 2, "cond_expr": "a.trait in [冲动]",
       "result_text": "{a}怒而反击，两败俱伤。",
       "effects": {"status_delta": {"a.realm": -1, "a.health": -2}, "pending": "被宗门追查"}},
      {"order_no": 3, "cond_expr": null,
       "result_text": "{b}夺舍失败，遁走重伤。",
       "effects": {"pending": "夺舍之仇"}}
    ],
    "consequences": [], "plant_foreshadowing": ""
  }
}
```

### 参数设定规则（数值建议）

| 参数 | 设定原则 | 默认值建议 |
|---|---|---|
| base 权重 | 表达"这件事在世界里的常见度" | 日常 0.5~1.5 / 重要 2~4 / 必发类**不走随机池**（走必然通道） |
| 尺度权重 | 与 SCALE_DISTRIBUTION 联动，跨粒度降权 | day 池事件在 year 粒度 ×0.1（实测治理过 52.4%→9.8%） |
| 性格加成 | 命中一个 +0.5，**封顶 +2.0**（防单标签碾压） | +50%/标签，max 200% |
| 支柱/目标加成 | 加法、与主线取 max（现引擎已实现） | +0.3~0.4 |
| 冷却 | 同模板最小间隔，防刷屏 | day 3~10 天；month/year 按粒度换算 |
| 互斥 blocks | 进行中事件类型名，闭关中不社交 | 长持续事件（闭关/逃亡/养伤）必须挂 |
| 三源合并 | 系统默认 < 项目覆盖 < 事件级 | 项目可设"本世界修仙事件权重×2" |

**抽签用竞争式，不用独立掷骰**：候选集先过 preconditions 硬过滤，再按权重归一化抽一个。世界时间有限，事件互相竞争才有"世界感"。

## 六、参数走向判定（outcomes 判定机制）

### 6.1 条件 DSL（安全解析器，非 eval）

```text
语法：<路径> <运算符> <值>，AND/OR 组合（限3层）
路径：
  a.realm / a.trait / a.bag / a.equipment      # 主体（主角/触发者）
  b.realm / b.relation(a)                      # 对手侧
  world.<stmt_type>.<target_id>                # 世界状态断言
  count.<event_type>.<days>                    # 近N天同类事件计数
运算符：>= > == != < <=  in  has  not_has
```

### 6.2 判定流程（触发时一次性，确定性）

1. 按 `order_no` 升序遍历；第一个 `cond_expr` 命中 → 选中该走向，**终止**；
2. 全部不中 → 按 `prob` 加权随机选一个（走 `roll(seq,salt,'outcome:'+template_id+order)` 保持可复现）；无 prob 的默认走向（order_no 最大且 cond 为 NULL）兜底；
3. 选中后执行 `effects` 结算 → 落账本，`events.outcome_selected` 记录；
4. **条件判定是纯函数**，只有 prob 兜底消耗随机数——同输入必同走向，可测试可回放。

### 6.3 effects 结算器（纯代码）

| effects 类型 | 写入目标 |
|---|---|
| status_delta | character_state（境界/数值增减） |
| relation_delta | relations（谁对谁 ±N，四维可选） |
| props / bag | 装备栏 / 储物袋 |
| know_facts | 角色信息集（触发 knowsAbout 更新） |
| plant_foreshadowing | 伏笔台账（记 day + 回收条件） |
| pending | pending_repercussions（后续时间步触发因果链） |

## 七、连贯性校验器具体规则

位置：STEP 3e，抽中模板后、落库前。

### 7.1 五个校验维度

| 维度 | 检查内容 | 数据源 | fail 判定 |
|---|---|---|---|
| D1 进行中互斥 | 模板 blocks ∩ 该角色进行中事件 | snapshot.ongoing | 交集非空 |
| D2 世界门槛 | world_required 逐条与现状比对 | world_states | 任一不满足（宗门没了→大比 fail） |
| D3 关系一致 | 事件前提 vs 双方关系值 | relations | 模板声明 min_relation/max_relation 时越界 |
| D4 情绪连续 | 事件基调 vs 角色当前情绪 | character_state.emotional | 冲突对命中 |
| D5 时空可达 | 角色位置锁 vs 事件地点 | location / ongoing.duration | 闭关/囚禁/重伤期内跨地点 |

### 7.2 情绪冲突对白名单（D4）

```text
悲痛↔欢乐    狂怒↔温和    恐惧↔安心    绝望↔鼓舞    敌意↔亲近
```

情绪标签与事件基调标签分别从两个枚举池取；**不在白名单内的组合永不 fail**（避免过度拦截）；中性=永不冲突。

### 7.3 重抽逻辑

```
fail(任一维度) → 记录原因 → 重抽（上限3次）
  3次全 fail → 本片放弃该角色随机事件（不硬塞），记入统计
  频繁 fail 的模板 → 进"模板质量看板"（说明 preconditions 没写对，回修模板，不是放宽校验）
```

### 7.4 可观测性

每次 fail 写 `{template_id, dimension, reason}`；跑完一轮输出 fail 率报告——新事件池 fail 率基线建议 **≤10%**，超了先查模板门槛配错，不靠调校验放水。

## 八、随机 vs 必然冲突仲裁

| 冲突类型 | 仲裁规则 |
|---|---|
| 时间撞车 | 切片预算制：STEP1 必然事件先占槽，随机事件只填剩余槽；同片随机池降权 ×0.3 |
| 抢戏 | 本片有必然事件时，随机池只放 `drama_base < 必然事件` 或日常/背景类；渡劫、夺宝等大事件**让位到下一片** |
| 逻辑矛盾 | 硬门槛兜底：随机事件抽签前必须过 `world_required` + `blocks` |
| 状态矛盾 | 事件串行结算、后果累积入账；随机后果与必然后果冲突 → **随机后果 suppressed**（只留文本、不进状态账本） |

### 避免"突兀"的四个防线

1. **因果铺垫（硬门槛）**：随机事件声明前置条件（地点/资源/关系/世界状态），杜绝凭空刷屏。
2. **后果链（连续性）**：事件挂 `consequences`，下片产生连锁（杀人→通缉→逃亡），靠状态账本自然连贯。
3. **密度与粒度匹配**：尺度权重 + SCALE_DISTRIBUTION 联动，day 池只在日粒度活跃。
4. **连贯性校验器（兜底）**：§七 五维检查，冲突重抽 ≤3 次，仍不过则让位下片。

## 九、与现有代码的衔接

```
抽签选中模板（现有 pick_template_for）
  → coherence_check(t, snapshot)      # 新增：5维校验，fail 重抽
  → resolve_outcome(t, snapshot)      # 新增：DSL判走向 + effects结算
  → build_event + _fill_slots（现有，成稿）
  → 落库 events + 更新账本（现有 _write_staged 扩展）
```

- 现有 3a/3b 的 `slots/slot_conditions` 保留不动——outcomes 是它上层的新维度：slots 管"一句话里的词怎么填"，outcomes 管"整件事往哪个方向演"。
- 必然事件触发沿用目标线冲突四件套（conflicts_due 递增掷骰 + goals_ready + is_main 取代 main_quest）。

## 十、验收点（可断言）

| # | 验收项 | 断言方式 |
|---|---|---|
| 1 | 重跑同输入 → 事件流逐字节一致（含必然事件触发层） | diff 两次输出 |
| 2 | 必然事件 100% 在窗口内出现 | 测试断言 |
| 3 | 同片必然事件与随机大事件抢戏 0 次 | 测试断言 |
| 4 | 走向判定确定性：同 (seq,salt) 下无 prob 走向结果一致 | 复跑脚本 |
| 5 | 世界门槛生效：青云宗置 destroyed → 宗门大比 0 次被抽（正反两向） | 测试断言 |
| 6 | 连贯性：随机事件 fail 率 ≤10%（新池基线） | fail 率报告 |
| 7 | 后果链闭环：杀人→通缉→逃亡 | 因果链测试 |
| 8 | 状态账本对账无差：事件后果 Σ = 账本增量 | 对账脚本 |
| 9 | 现有 pytest（92）不回归 | 回归测试 |
| 10 | 全链路耗时/成本可接受 | 实测记录 |
