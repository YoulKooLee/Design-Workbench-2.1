# 工程包上下文工程设计 · 落地指令

> 提交：DeepSeek
> 接收/落地：豆包
> 目标：把产品设计工程包（02-模板/_project-template）的上下文管理升级为「基线(并列真相源) + 过程文档(条件加载) + 索引」，防项目设计对话上下文溢出。

## 一、基线层（并列真相源 · 版本化 · 源码可 diff）

术语定稿（与 AGENTS.md「PRD→SRS 转写门禁」一致）：
- 客户需求 = 原始输入
- **PRD = 需求文档**（产品要做什么，方向对齐）
- **SRS = 设计文档**（怎么实现，交付开发）
- **系统架构 + 数据模型 = 基线的设计展开维度**（与 PRD/SRS 并列）

基线链：客户需求 → PRD(需求) → 系统架构 + 数据模型 → SRS(设计文档交付开发)，五者并列真相源、共同版本化、头部登记版本+变更时间。

## 二、过程文档（条件触发加载，绝不常驻）

- **DECISIONS.md 决策记忆** → 命中"要改某逻辑/设计"时加载（查是否冲突，含决策+原因+影响范围+日期）
- **CHANGELOG.md 变更流水** → 排查问题/理解"最近改了啥"时加载（改了什么/改了哪些页面/是否改接口或数据结构）
- **TASKS.md 跨会话进度** → 新会话/接续任务时加载（已完成/进行中/待开发/阻塞，做到哪）

三者是"过程文档"非"基线"，必须条件触发、按需加载，不进常驻上下文。

## 三、图：源码 + 渲染（杜绝 AI 手绘 PNG）

- 系统架构图 / 业务流程图 / ER 数据模型图 一律用 **Mermaid 文本源码**存基线（可版本、可 diff、可 grep、可渲染）
- 渲染交给工具（mermaid-cli / kroki），渲染图给人看；**不让 AI 手绘 PNG**（排得惨不忍睹）
- 图的价值定位：**源码喂模型、渲染图对齐人**。源码是真相源，渲染图是对齐快照。

## 四、总-分视角（大项目拆模块）

- **总视角 = 系统总览**（Mermaid 架构图 + 模块清单 + 模块间数据流/接口矩阵）
- **细视角 = 每模块一份**（核心业务流程 Mermaid + 业务规则 + 数据模型 + 功能设计方案）
- **验收标准 = 数据流闭环**：每个模块输入/输出成矩阵，A 的输出都能被某模块接住、无孤儿数据、无凭空数据 → 拆分完整无遗漏
- 执行纪律：总览当导航、模块当工作区；做完一个模块回写总览进度标记，再切下一个

## 五、细节可定位（组件 ↔ 文档映射）

- 建 **组件 ↔ SRS 章节 映射 manifest**（组件ID → SRS章节 → 所属模块 → 设计说明文件路径）
- 改细节的精确展开：反查 manifest → 只加载"单模块 + 单组件说明"（不是整库重读）→ 判断人类提议是否合理 → 改 + 回写 SRS 章节 + 记 CHANGELOG

## 六、落地要求

1. 在 `02-模板/_project-template` 落地上述结构：
   - 新增数据模型、系统架构作为基线维度（或并入 SRS 展开）
   - 新增组件↔文档映射 manifest 骨架
   - 新增过程文档骨架（DECISIONS/CHANGELOG/TASKS，按需创建不预置空文件）
2. `AGENTS.md` 的「记忆分层与门禁」章节更新：
   - 基线术语纠正（PRD=需求文档，SRS=设计文档）
   - 图用 Mermaid 源码（不手绘 PNG）
   - 总-分视角 + 数据流闭环验收
   - 过程文档条件触发加载
3. 按模板复制同步到各项目。

## 验收标准
- 模板结构齐全 + AGENTS.md 记忆分层章节语义正确 + 过程文档条件加载规则落地 + 图用 Mermaid 源码（无手绘 PNG 依赖）。
