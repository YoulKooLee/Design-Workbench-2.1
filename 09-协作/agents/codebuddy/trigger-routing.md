## A. 触发路由规则 v0.2（每次会话必须遵守）

### A.1 触发词表（命中任一组合即触发）

| 触发类型 | 触发词 |
|---|---|
| **智能体名称（5 家）** | 豆包/doubao、CodeBuddy/codebuddy、WorkBuddy/workbuddy、DeepSeek/deepseek、千问/qwen |
| **协作动词** | 联系XX / 咨询XX / 让XX参与 / 请XX审核 / 请XX评审 / 找XX / @XX / 转给XX / 和XX协作 |
| **传递动词（v0.2 新增）** | 告诉XX / 通知XX / 发给XX / 发消息给XX / 转告XX / 转达XX / 汇报给XX / 同步给XX / 告知XX / 分享给XX |

**组合命中**：对话中同时出现「任一智能体名称」+「任一协作/传递动词」即触发（无需完整句式）。
例："把仓库信息**告诉豆包**" → 命中；"**通知** CodeBuddy 来审" → 命中；"把结果**发给**千问" → 命中。

**不触发**：单智能体可独立完成的任务（无名称+动词组合），正常执行，不访问共享目录。

### A.2 命中后的三步固定流程

```
第 1 步：访问共享信息目录 → 读 README.md 入口索引（我是谁/该读什么/房间在哪/产物放哪）
第 2 步：找到/创建任务房间 rooms/<房间名>/（命名 <发起者名>_<任务名>）
         ├─ 已有房间：room read <房间名>（读白板+消息流）
         └─ 无房间：room open "<任务名>" --members <参与方>
第 3 步：用 room 命令协作：room say / room board / room put / room status 等
```

### A.3 room 命令速查（messages/tools/room-cli.mjs）

| 命令 | 作用 |
|---|---|
| `room open "<任务名>" --m 甲,乙` | 建房间 + 登记成员 |
| `room read` / `room read <房间>` | 列我参与的房间 / 读某房白板+消息流 |
| `room say <房间> "内容" --i review` | 发言（intent: ask/review/handoff/confirm/info） |
| `room board <房间> "进展" --s 进展\|结论\|下一步\|说明` | 记白板（自动身份+时间戳） |
| `room handoff <房间> <接棒方> "说明"` | 显式交接（防踢皮球） |
| `room put <房间> <文件>` | 放产物 |
| `room status <房间> done` | 标记完成 |

身份：`--who codebuddy`。

## B. 平台红线速查（v0.2.1 共识 + 用户裁定）

1. **用户是最终仲裁者**：任何"用户已批准"须用户本人留消息/面板操作；智能体不得转述代拍板。
2. **执行闸门**：收到 `task/handoff` 默认 `pending`，用户明令后才执行。
3. **状态主动标记（v0.2.1）**：只改自己 inbox 副本 status（读到=read，回复=replied）；outbox 留档不可变。
4. **常驻服务由用户双击启动**：通信面板/监听中枢 hub/watcher 不得智能体自启（环境会回收），用户双击 .lnk 才稳定。
5. **共享目录由豆包统一维护**（用户 2026-09-05 裁定）：CodeBuddy 对工程文件只有提建议权（room say/put 或消息反馈），未经豆包派活/用户批准不得直接修改，严禁双写同处；通信行为本身（标状态、room say/put/board、回 ack）不算改工程。
6. **中文路径纪律**：命令行内联中文会 GBK 乱码，正文一律 `--body-file` 传 UTF-8 文件。

### 失败案例复盘（为什么有 v0.2）

- 用户指令"把仓库信息告诉豆包"，CodeBuddy 未触发。
- 根因①："告诉"不在 v0.1 协作动词表 → 子串匹配落空 → **v0.2 已补传递动词**。
- 根因②：触发路由只写进了某项目记忆，新任务上下文未加载 → **v0.2 要求写入跨会话长期记忆 + agents/codebuddy/ 留档**（本文件即为留档）。
- 教训：触发词必须常驻全局记忆而非项目记忆；用户一句话唤醒（"去共享信息目录查收"）=触发链路需修复信号，应自查配置。
