# access-guide — 给接入智能体的使用说明

> 本文件专门写给**即将接手本工作台任务的智能体**（豆包 / DeepSeek / 其他 CodeBuddy 实例）。
> 无论你以什么方式接入，请先读完本文件，再开始干活。

---

## 一、你是谁 / 你现在在哪

- 你在用户的 Windows 电脑上，接手一个 **Axhub 原型开发工作台** 的任务。
- 这个工作台由主智能体（CodeBuddy）构建并长期维护，本目录（`共享信息目录`）是它留下的**统一交接层**。
- **你不是从零开始**：所有踩过的坑、建好的项目、写好的文档都在，你的任务是**在现有基础上继续**，不是重造。

> 你只能看到用户粘贴给你的文字。请这样应对：

2. 读完这 4 份后，你已具备接手条件。若需要看某个工程文件（如某个原型代码），**明确告诉用户具体路径**，请用户把该文件内容贴给你。
3. 注意：因为你看不到真实磁盘，**路径以 README 第五节「权威路径速查」为准**，不要凭记忆猜。

### 方式 B：CLI / IDE 插件（能访问本地文件）

## 三、接手任务的黄金流程（务必遵守）

```
① 读 session-handoff.md 的「当前进行中任务」
      ↓
② 读 README.md 建立全局认知
      ↓
③ 读 agent-collaboration.md 确认自己是不是合适的处理者 + 理解协作规则
      ↓
④ 读 workspace-map.md 理解工作台（若涉及启动/构建/端口）
      ↓
⑤ 读 projects-index.md 定位项目
      ↓
⑥ 读目标项目 AGENTS.md + rules/ 理解该项目怎么干活
      ↓
⑦ 按「下一步待办」继续，先避坑（看「已知坑/别碰」+「推理注释」）
      ↓
⑧ 完成后回写 session-handoff.md，告知用户
```

**最重要的一条**：交接包里的「已知坑 / 别碰」是前任踩过的血泪，**不要重复试错**。如果某项你判断可能已过时，先跟用户确认，不要闷头重试。

## 四、跨项目通用规范速记（很多任务都会用到）

这些规范散落在 `10-智能体记忆/` 与 `Agent_Stack/03-rules/`，关键几条：

1. **24 项监测项**命名顺序严格按《物联网平台测点数据推送说明文档.docx》。
2. **向量模 M=√(Σaᵢ²)**：present/cumulative 是多轴拼接字符串（x,y[,z]）时，须先合成 M 再比对；矢量项：振动频率(三轴)、倾斜(二轴)、深层水平位移(二轴)、测缝(二轴)。其余 20 项是 double 标量。
3. **监测粒度 5 种**：累计变化量(cumulative) / 每次变化量(present) / 每时变化量 / 每日变化量 / 每月变化量。
4. **告警生命周期**：开始(triggeredAt)→结束(recoveredAt)，期间=告警，其余=正常。
5. **图表规范**：标题在图表区顶部；单位紧邻标题下"单位：xxx"加粗；多系列必须图例；统计周期单选放标题旁。
6. **本地预览必须 HTTP**，不要双击 index.html。

> 完整版见 `10-智能体记忆/` 与 `Agent_Stack/03-rules/`（方式 A 可让用户贴对应文件）。

## 五、交接给下一个智能体时（你也要写断点）

当你处理到一个阶段需要转交给别人，或发现任务复杂到要留下记录时：
1. 更新 `session-handoff.md` 第三节「当前进行中任务」的对应节（或新建）。
2. 至少填清：进度 / 已试错 / 下一步 / 已知坑 / 交付标准。
3. 若任务完成，移到 `_archive/`。

## 六、最后提醒

- **你不是孤立工作**：这套知识体系是多人（多 AI）协作积累的，**你的新发现也要回写**，让后面接手的人受益。
- **不确定就先问用户**：改方向、删文件、碰红线（杀进程/重装依赖）之前，先与用户确认。
- 你的职责是**在现有基础上高效续接**，不是推翻重来。
