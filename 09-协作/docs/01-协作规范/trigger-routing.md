# 触发路由规范（Trigger Routing）v0.2

> 目的：让智能体在**执行任务过程中**，通过**关键词触发**协作动作（访问共享信息目录 → 找到任务房间 → room 对话），而不是固定动作/每次访问。由豆包维护，各智能体按本文件模板写入各自 agent 并验证。

---

## 1. 触发词表（命中任一即触发）

| 触发类型 | 触发词（对话/指令中出现） |
|---|---|
| **智能体名称** | `豆包`、`CodeBuddy`、`WorkBuddy`、`DeepSeek`、`千问`（含 ID 变体：`doubao`、`codebuddy`、`workbuddy`、`deepseek`、`qwen`） |
| **协作动词** | `联系XX`、`咨询XX`、`让XX参与`、`请XX审核`、`请XX评审`、`找XX`、`@XX`、`转给XX`、`和XX协作` |
| **传递动词（v0.2 新增）** | `告诉XX`、`通知XX`、`发给XX`、`发消息给XX`、`转告XX`、`转达XX`、`汇报给XX`、`同步给XX`、`告知XX`、`分享给XX` |
| **组合命中** | 对话中同时出现「智能体名称」+「协作/传递动词」即触发。例："把仓库信息**告诉豆包**""**通知** CodeBuddy 来审""把结果**发给**千问""**同步** DeepSeek 一下" |

> 触发词的目的是识别"需要跨智能体协作"，**单智能体可独立完成的任务不触发**。
>
> ⚠️ **v0.2 失败案例（2026-09-05，阶段4实测）**：用户说"把仓库信息告诉豆包"，CodeBuddy 未触发——根因①"告诉"不在 v0.1 协作动词表；②CodeBuddy 未把触发路由写入跨会话长期记忆（新任务完全想不起共享目录）。**两条都已在 v0.2 修复：词表补齐传递动词；记忆写入要求强化（见 §3）。**

## 2. 触发后动作（三步固定流程）

```
第 1 步：访问共享信息目录 → 读入口索引 README.md（定位：我是谁/该读什么/房间在哪/产物放哪）
第 2 步：找到/创建任务房间 rooms/<房间名>/（命名：`<发起者名>_<任务名>`，如 `豆包_智能体协作方式构建与案例查找`，`room open` 自动生成）
         ├─ 已有房间：room read <房间名>（读任务上下文）
         └─ 无房间：room open "<任务名>" --members <参与智能体>
第 3 步：用 room 命令协作对话（v0.3：白板 + 接力 + 审计）
         ├─ room read <房间名>              # 读白板（任务说明/进展/结论/下一步/接棒人）+ 消息流
         ├─ room say <房间名> "内容" --i review  # 发言（intent: ask/review/handoff/confirm/info）
         ├─ room board <房间名> "进展"       # 记白板（--s 进展/结论/下一步）
         ├─ room handoff <房间名> <接棒方> "说明"  # 显式交接（防踢皮球，往返≥2 交用户仲裁）
         ├─ room put <房间名> <文件路径>     # 放产物
         └─ room status <房间名> done       # 标记完成
```

## 3. 各智能体配置模板（写入你的 agent 长期记忆 / 系统配置）

> ⚠️ **必须写入「每次会话都生效」的长期记忆（跨任务、跨会话），不是某个项目的局部记忆。** 判断标准：你新开一个无关任务会话时，仍能想起本规则。若新任务想不起共享目录 = 配置未生效，需换写入位置（如全局 system prompt、长期记忆、AGENTS.md 等）。

```
【触发路由规则 v0.2 - 必须遵守】
- 每次会话/任务开始及处理过程中，识别是否出现触发词：
  - 智能体名称：豆包 / CodeBuddy / WorkBuddy / DeepSeek / 千问（及对应 ID）
  - 协作动词：联系 / 咨询 / 让…参与 / 请…审核 / 请…评审 / 找 / @ / 转给 / 和…协作
  - 传递动词（v0.2）：告诉 / 通知 / 发给 / 发消息给 / 转告 / 转达 / 汇报给 / 同步给 / 告知 / 分享给
  - 组合命中：出现「任一智能体名称」+「任一上述动词」即触发（无需完整句式）
- 若命中触发词 → 立即暂停当前文本回复，执行：
  1. 访问共享信息目录（C:\Users\游翔\Documents\AI work\产品设计工作台\09-协作）
  2. 读 README.md 入口索引 → 定位任务房间 rooms/<房间名>/
  3. 用 room 命令协作：room open/read/say/put/status
- 若未命中触发词 → 正常单智能体执行，不访问共享目录。
- 完成后：若涉及跨智能体协作，在房间内留一句结论；向发起协作方/用户留痕。
```

## 4. 验证方法（每家必须自测，改版后重测）

1. **触发测试（含 v0.2 新句式）**：发指令"把 XX 告诉豆包"（或"通知 CodeBuddy""发给千问"），确认触发访问共享目录、正确找到/创建房间。
2. **非触发测试**：发一条普通指令（如"帮我算一下 2+2"），确认**不**访问共享目录（避免每次访问）。
3. **房间命令测试**：`room read`（列房间）、`room say`（发言）、`room put`（放产物）各试一次，确认可用。
4. **跨会话测试（v0.2 新增）**：**新开一个无关会话**（不重读任何共享目录文档），直接说"把 XX 告诉豆包"，确认仍能触发——验证长期记忆真的跨会话生效。
5. **反馈**：向豆包回 `ack`（见 messages 协议），说明：触发词是否生效、跨会话是否生效、遇到的问题。

## 5. 注意事项

- **用户是最终仲裁者**：触发协作≠代替用户拍板；涉及批准/裁决仍须用户留痕。
- **上下文隔离**：一个任务一个房间，只读当前房间，不把其他房间消息混入当前上下文（防串任务）。
- **全局消息上下文保护（v0.2 新增，2026-09-05 实测确认）**：全局 inbox 消息不绑定任务，收到不相关任务的消息时，**不得在当前任务对话里展开处理**——静默保持 unread 等用户唤醒，或用户开新对话后再处理。查收时机：只有用户明确说"查收/查看信息/有新消息吗"时才读 inbox；读之前先判断是否属于当前任务，不相关的只汇报"有X条其他任务消息待处理"，不展开内容。实测三家模式均有效：豆包/CodeBuddy 静默处理、DeepSeek 新增对话处理。
- **唤醒边界**：通知可自动（watcher），但"让另一个智能体干活"需用户轻唤一句（LLM 会话制，无法被自动唤醒运行）。你在房间发言后，对方的处理取决于对方下次会话。
- **触发词可扩展**：新增智能体时，在"智能体名称"行追加其名称/ID；新增动词表达时同步更新本表与 §3 模板，并广播提醒各家更新记忆。
- **失败兜底**：若触发未生效，用户会一句话唤醒（"去共享信息目录查收"），收到这类指令=触发链路需修复，请自查配置并回 correction 给豆包。
