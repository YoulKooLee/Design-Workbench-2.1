# 脚本编码规范（v1.0）

> 维护方：豆包（共享信息目录供应商）　|　适用范围：产品设计工作台全部脚本

## 规则（硬性）

**工作台内所有 `.cmd` / `.bat` / `.ps1` 脚本，一律保存为「UTF-8 带 BOM」。**

- 新增脚本时：写完后必须确认编码为 UTF-8 with BOM；不确定就用「编码体检」自动处理。
- 修改脚本时：保持 UTF-8 带 BOM，不要另存为 GBK/ANSI，不要去掉 BOM。
- 纯 ASCII 脚本（无中文）可以不带 BOM，但建议统一带。

## 为什么（背景事实）

1. 本机 Windows 代码页为 **65001（UTF-8）**：cmd.exe 按 UTF-8 解析 .cmd/.bat。若文件是 **GBK**，中文行会被乱码解析成 `'鎏崾静蛔瓒希?for' 不是内部或外部命令`，启动逻辑中途报错。
2. PowerShell 5.1 读取**无 BOM 的 UTF-8** 脚本时会按 ANSI(GBK) 解码，中文注释/字符串变乱码。
3. **UTF-8 带 BOM** 是唯一同时被 cmd.exe 与 PowerShell 5.1 正确识别的编码（GBK 在 65001 下乱；UTF-8 无 BOM 在 PS5.1 下乱）。

## 自动体检工具

- 入口：`09-协作\messages\tools\编码体检.cmd`（双击运行，显示报告）
- 脚本：`09-协作\messages\tools\编码体检.ps1`
  - 扫描工作台全部 .cmd/.bat/.ps1（排除 node_modules/.git/05-回收站/07-日志）
  - 已合规 → 跳过；合法 UTF-8 无 BOM → 自动补 BOM；GBK → 自动转 UTF-8 带 BOM
- 启动器（启动工作台.cmd）每次启动前会静默自愈一次，任何脚本编码错误都会被自动纠正，不再阻塞启动。

## 新增/修改脚本后的自检

1. 写完脚本 → 运行 `编码体检.cmd`，确认无 `[修复]` 条目（或修复结果正确）。
2. 提交到 git 前 `git diff` 检查，避免把脚本编码改坏。

## 历史教训（为什么会有这条规范）

- 2026-09-13 起多次出现：启动器/脚本在 65001 代码页下因 GBK 编码乱码报错（`'鎏崾静蛔瓒希?for'` 等）。
- 2026-09-17 已批量转码全部脚本为 UTF-8 带 BOM，并在启动器内置自愈。此后**任何智能体写的脚本都必须遵守本规范**，豆包在通信消息中已通知各智能体。
