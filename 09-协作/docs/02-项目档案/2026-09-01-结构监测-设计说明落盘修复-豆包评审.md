### 2) 落盘失败的根因（已定位，是 API 调用字段写错，不是逻辑断链）
- 落盘 API 真实存在：`vite-plugins/localEditingApi.ts` 注册 `/api/text-replace/replace`（同一预览服务 51720，同源，Origin 校验通过）。
- 契约（`handleTextReplace` / `normalizeResourcePath`）：
  - `body.path` 必须是**资源目录**、**无前导斜杠**、且以 `prototypes` 或 `themes` 开头，例如 `prototypes/dashboard`。它会 `resolve` 到 `src/prototypes/dashboard`，再递归扫描该目录下**所有** `.ts/.tsx` 源文件做替换。
  - `body.replacements` = `[{ searchText, replaceText }]`，`searchText` 需在目录内某文件里**精确匹配**（否则 409）。
  - 单条替换上限 `MAX_REPLACEMENT_CHARACTERS = 10_000` 字符。
- **我之前写错的地方**：`saveDesignNotesToSource` 传了 `path: '/src/prototypes/${current}/index.tsx'`（带前导斜杠、带 `/src/` 前缀、还是文件路径）→ `normalizeResourcePath` 直接抛 400「资源路径格式不正确」→ 我的代码判 `!data.ok` → 提示「落盘失败」。
- **修正方向**：`path` 改为 `prototypes/${current}`（目录、无前导斜杠）；`searchText` 用从 `?raw` 抓取的源码里精确抽出的 `return [ … ]` 块。这样 API 会在 `index.tsx` 里精确替换。
- 待豆包确认的风险点：
  - `?raw` 抓取是否返回**逐字节一致**的源码（决定 searchText 能否精确匹配）。
  - 目录递归替换：若 `searchText` 大块恰巧也出现在同目录别的文件，会误替（概率低，但需确认各模块目录只有 index.tsx 含该块）。
  - 某些模块块（如 dashboard 趋势分析长列表）是否超 10_000 字符上限 → 需分块或换策略。

### 3) 之前的设计说明“全没了”能否找回？—— 大概率能，且必须是“非破坏性恢复”
- 原实现把编辑只存浏览器 `localStorage`，key 为 `axhub-sm-notes-${current}-${moduleSig}`，值是**整个 ModuleDef[] 数组**（`moduleSig = modules.map(m=>m.id).join(',')`）。CodeBuddy 上一轮只是**删掉了读取这段代码**，并未 `removeItem`——数据物理上仍在用户浏览器 `localhost:51720` 的 localStorage 里。
- 我新代码改为「读源码 buildModules → 无 localStorage 读取」→ 显示退回最初生成的源码稿（与用户现象一致）。
- 已确认：`git diff` 显示各原型 `buildModules` 从未被写入过用户编辑（diagnosis 那次改动只是删了个 UI 下拉，与设计说明无关）。即**源码里确实没有过用户的编辑**，唯一副本在浏览器 localStorage。
- **恢复方案（非破坏性）**：组件挂载时扫描所有 `axhub-sm-notes-*` 键，把每项的 ModuleDef[] 回填进新的 `localOverride`（Map<id, ModuleDef>）。只读、不删，零风险。
- **前提**：用户没清过浏览器本地存储、没换浏览器。若已清/换，则只能从其它备份找回（当前未发现源码级备份）。
