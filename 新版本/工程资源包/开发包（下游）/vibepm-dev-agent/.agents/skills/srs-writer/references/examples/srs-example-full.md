## 二、项目概述

### 2.1 项目背景

示例科技销售团队目前用表格和即时通讯分散记录客户与跟进，存在以下问题：

1. **客户信息分散**：同一客户多人维护，名称不统一，联系人缺失，交接后无法追溯。
2. **商机阶段不透明**：进展停留在个人记录，管理者无法掌握漏斗分布与赢单障碍。
3. **跟进易中断**：承诺回访日期无提醒，超期无人催办。
4. **公海无规则**：无人跟进的客户无法被他人领取，或被重复占用。
5. **外勤难核验**：拜访是否到达客户现场缺少记录，无法与商机进展对应。

为提高线索转化与跟进及时率，建设客户关系管理模块，覆盖客户档案、线索、商机、跟进拜访与销售报表。

### 2.2 项目建设目标

1. **主数据统一**：客户、联系人一处维护，商机与拜访均引用已启用客户。
2. **商机可追踪**：商机按阶段流转，关键变更写入跟进记录并通知相关人员。
3. **跟进可催办**：到期未跟进的商机进入待办，超期可见。
4. **公海可流转**：符合规则的客户进入公海，销售人员可领取。
5. **过程可汇总**：按日、周、月查看新增商机、赢单金额、转化率与人员排名。

### 2.3 项目建设范围

**系统端：**

- PC 端管理后台
- 移动端（外勤拜访与待办处理）

**功能模块：**

- 客户管理：客户档案、联系人、公海领取与退回
- 线索管理：录入、分配、转化为商机
- 商机管理：阶段流转、赢单/输单
- 跟进拜访：跟进记录、外勤签到
- 销售报表
- 系统管理：用户管理、操作日志

**数据范围：** 本公司销售与市场人员名下的客户、线索、商机及跟进记录。

**不包含的功能：**

- 合同审批与电子签章
- 开票与回款核算
- 营销自动化群发
- 部门、角色、菜单的独立维护（复用现有办公平台的组织与权限）

### 3.5 功能详细设计

#### 3.5.1 客户管理

维护客户与联系人。线索转化、商机与拜访均以来源于本模块且状态为启用的客户作为可选范围。

##### 3.5.1.1 客户档案

**（一）功能需求概述**

客户档案用于维护成交与跟进对象的基本信息、级别与负责人，并支持将客户放入公海或从公海领取。

**（二）功能设计**

**查询/筛选功能**

支持以下条件筛选，条件之间为“与”关系，点击搜索按钮触发查询：

| 筛选字段 | 类型 | 说明 |
|---------|------|------|
| 客户名称 | 文本输入 | 支持模糊搜索 |
| 行业 | 单选 | 来源于系统预置行业，可空表示全部 |
| 客户级别 | 单选 | 枚举值：全部 / A / B / C |
| 负责人 | 单选 | 来源于用户管理中已启用且角色为销售的用户；可空 |
| 状态 | 单选 | 全部 / 启用 / 停用 / 公海 |

**列表功能**

| 列名 | 字段类型 | 说明 |
|-----|---------|------|
| 客户名称 | 文本 | - |
| 客户编号 | 文本 | 数据来源：新增时系统自动生成 |
| 行业 | 文本 | - |
| 客户级别 | 文本 | A / B / C |
| 负责人 | 文本 | 公海客户显示“公海” |
| 状态 | 文本 | 启用 / 停用 |
| 最近跟进时间 | 日期时间 | 数据来源：最近一条跟进或拜访的时间；无则显示“-” |
| 操作 | 操作按钮 | 编辑、启用/停用、放入公海、删除（无权限时隐藏） |

分页默认每页 10 条。列表为空时显示：暂无客户数据。

**新增功能**

点击“新增”，弹出编辑窗口。

| 字段名称 | 类型 | 长度限制 | 必填 | 默认值 | 说明 |
|---------|------|---------|------|-------|------|
| 客户名称 | 文本输入 | ≤100字 | 是 | - | 系统内唯一 |
| 行业 | 单选 | - | 是 | - | 预置行业列表 |
| 客户级别 | 单选 | - | 是 | B | A / B / C |
| 地址 | 文本输入 | ≤200字 | 否 | - | 外勤签到时用于核对到达位置 |
| 负责人 | 单选 | - | 是 | 当前用户 | 来源于已启用销售人员 |
| 备注 | 多行文本 | ≤500字 | 否 | - | - |
| 客户编号 | 只读 | - | - | 系统自动生成 | 不可手工修改 |

提交成功：新增客户成功。
提交失败：保留填写内容，显示具体错误原因。

**编辑功能**

点击“编辑”，自动填入当前记录（客户编号不可改）。负责人仅销售经理及以上可改。
提交成功：客户信息已更新。

**删除功能**

点击“删除”，弹出确认“确定删除客户【XXX】吗？删除后不可恢复”。
删除成功：客户已删除。
若存在关联商机或未完成拜访，阻止删除，提示“该客户存在关联商机或未完成拜访，无法删除”。

**启用/停用功能**

停用确认：“停用后不可再以该客户新建商机或拜访，确定停用吗？”。
停用成功：客户已停用。启用成功：客户已启用。

**放入公海 / 领取公海**

放入公海：负责人不为空时可用。确认文案：“放入公海后本人不再是负责人，其他销售可领取，确定放入吗？”。成功：客户已放入公海。
领取公海：仅状态为公海的客户。成功：领取成功，负责人为当前用户。
同一用户对同一客户 7 日内重复领取时阻止，提示“7 日内不可重复领取该客户”。

**导入 / 导出**

导入按模板上传。成功：提示“导入完成，成功 X 条，失败 Y 条”。模板不符：提示“文件格式不正确，请使用系统提供的模板”。
导出当前筛选结果。成功：提示“导出成功，文件已开始下载”。

**业务规则**

- 客户名称全局唯一。重复时阻止提交，提示“客户【XXX】已存在，请更换名称”。
- 停用后不允许新建商机或拜访；已有商机可继续推进至赢单或输单。
- 公海客户无负责人；领取后负责人为领取人，数据范围随 3.4 变化。

**边界与异常**

- **空数据**：列表无数据时显示“暂无客户数据”。
- **权限不足**：维护类按钮对无权限角色完全隐藏（非禁用）。
- **领取冲突**：两人同时领取时，后提交者提示“该客户已被他人领取”。

**（三）业务逻辑关联**

- 商机、跟进拜访的客户选择范围来源于本模块已启用且非停用的客户（含本人负责与按权限可见的公海）。
- 联系人必须挂在客户下。
- 最近跟进时间由跟进拜访模块回写。

##### 3.5.1.2 联系人

**（一）功能需求概述**

联系人用于维护客户下的对接人，商机与拜访需指定联系人时从本模块已启用数据中选择。

**（二）功能设计**

**查询/筛选功能**

| 筛选字段 | 类型 | 说明 |
|---------|------|------|
| 姓名 | 文本输入 | 支持模糊搜索 |
| 手机号 | 文本输入 | - |
| 所属客户 | 单选 | 来源于客户档案中当前用户可见且已启用的客户 |

**列表功能**

| 列名 | 字段类型 | 说明 |
|-----|---------|------|
| 姓名 | 文本 | - |
| 手机号 | 文本 | - |
| 职务 | 文本 | 无值显示“-” |
| 所属客户 | 文本 | 数据来源：关联客户名称 |
| 是否主联系人 | 文本 | 是 / 否 |
| 操作 | 操作按钮 | 编辑、删除 |

## 四、技术方案

### 4.1 技术架构

本模块建设于现有协同办公平台之上，复用其身份认证与组织数据。

**终端：**

- PC 端：办公平台 Web 中的 CRM 菜单
- 移动端：办公平台移动应用中的 CRM 功能

**外部能力：**

- 外勤签到在可获取定位时记录位置偏差；无法获取时改为手工签到

### 4.2 数据交互

- 管理端与移动端与服务端之间使用加密传输
- 业务提醒以站内通知为主，必要时辅以短信

### 4.3 外部系统集成

| 集成系统 | 方式 | 说明 |
|---------|------|------|
| 协同办公平台 | 用户与组织同步 | 内部用户账号来源于办公平台 |
| 定位能力 | 签到时可选 | 无定位时不影响跟进与商机流转 |

### 4.4 安全方案

- 使用办公平台统一认证
- 传输加密；手机号等敏感字段存储加密
- 功能权限按角色控制到操作级；数据权限按本人 / 本部门 / 全部隔离

## 五、非功能需求

### 5.1 性能需求

- 页面操作响应：95% 请求不超过 3 秒
- 同时在线：不少于 300 人

### 5.2 安全需求

- 身份认证见 4.4
- 传输使用 HTTPS
- 操作日志保留见 6.2

### 5.3 可用性需求

- 系统可用性不低于 99.5%
- 移动端在网络恢复后同步未完成提交

### 5.4 兼容性需求

- PC 端：Chrome、Edge、Firefox 近两个大版本
- 移动端：当前办公应用所支持的操作系统版本
