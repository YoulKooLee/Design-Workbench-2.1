# 模块依赖关系描述规范

> 供 req-analyzer agent 使用。分析功能模块时，必须识别并输出模块间的依赖关系。

---

## 依赖关系的三种类型

### 类型一：数据来源依赖

本模块的某个字段，数据来源于另一个模块。

**识别方式：** 表单中有"选择"类字段（下拉、层级选择、多选），其选项来自其他模块的数据。

**输出格式：**
```
[本模块].[字段名] 来源于 [依赖模块]
  - 依赖条件：[依赖模块]中[状态/条件]的数据
  - 影响：[依赖模块]无数据时，本模块该字段无可选项
```

**示例：**
```
商机.客户 来源于 客户档案
  - 依赖条件：客户档案中已启用的客户
  - 影响：无可用客户时，新增商机时客户字段无可选项

商机.联系人 来源于 联系人管理
  - 依赖条件：该客户下已维护的联系人
  - 影响：该客户无联系人时，联系人字段无可选项
```

---

### 类型二：状态联动影响

本模块的数据状态变更，影响其他模块的行为。

**识别方式：** 业务规则中有"停用后不可选"、"删除后影响"、"状态变更后"等描述。

**输出格式：**
```
[本模块].[状态变更] → 影响 [目标模块].[具体行为]
  - 触发条件：[状态从X变为Y]
  - 影响范围：[目标模块中哪些操作受影响]
  - 影响方式：[不可选/隐藏/自动更新等]
```

**示例：**
```
客户档案.状态=停用 → 影响 商机.客户选择
  - 触发条件：客户状态变更为"停用"
  - 影响范围：新增商机、新增拜访时的客户选择
  - 影响方式：该客户不可选

用户.状态=停用 → 影响 客户档案.负责人字段
  - 触发条件：用户被停用
  - 影响范围：新增/编辑客户时的负责人选择
  - 影响方式：停用用户不出现在选项中
```

---

### 类型三：关联保护约束

本模块的数据被其他模块引用时，不能直接删除。

**识别方式：** 业务规则中有"删除前检查"、"有关联时阻止"、"先解除绑定"等描述。

**输出格式：**
```
[本模块] 被 [引用模块] 引用
  - 引用关系：[引用模块]的[字段名]引用了[本模块]的数据
  - 保护规则：[本模块]有被引用数据时，阻止删除
  - 提示文案：[原文]
```

**示例：**
```
客户档案 被 商机 引用
  - 引用关系：商机.客户 引用了 客户档案 的数据
  - 保护规则：该客户下有商机时，阻止删除客户
  - 提示文案：该客户存在关联商机或未完成拜访，无法删除

联系人 被 商机 引用
  - 引用关系：商机.联系人 引用了 联系人 的数据
  - 保护规则：联系人被未结束商机引用时，阻止删除
  - 提示文案：该联系人已被商机引用，无法删除
```

---

## req-analyzer 输出格式

分析完一个功能模块后，在摘要末尾附上依赖关系：

```
## 模块依赖关系

### 数据来源依赖
- [字段名] ← [依赖模块]（[依赖条件]）
- [字段名] ← [依赖模块]（[依赖条件]）

### 状态联动影响
- [本模块状态变更] → [目标模块受影响行为]

### 关联保护约束
- 本模块被 [引用模块] 引用，有引用时阻止删除
- 本模块引用了 [被引用模块]，需先确认被引用模块有数据
```

## 初始化顺序推断

根据依赖关系，推断功能模块的初始化顺序（哪些模块需要先配置）：

```
基础数据层（无依赖）：
  用户管理、行业预置

业务数据层（依赖基础数据）：
  客户档案（依赖：用户/负责人）
  联系人（依赖：客户档案）

业务流程层（依赖业务数据）：
  线索管理（依赖：用户）
  商机管理（依赖：客户档案、联系人、线索）
  跟进拜访（依赖：客户档案、商机）
  销售报表（依赖：商机、用户）
```
