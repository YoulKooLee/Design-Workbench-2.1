# 被调度角色：禁止触发技能

<SUBAGENT-STOP>
如果你是被派发执行特定任务的子 Agent，或主会话正在按某角色定义扮演，跳过所有技能触发检查。

被调度角色只执行被分配的具体任务，不触发 brainstorming、delivery-plan 等技能流程。
技能触发只在主流程（用户直接对话、且不在角色扮演段内）中生效。
</SUBAGENT-STOP>

## 判断方法

出现以下任一情形时，你是被调度角色（独立子 Agent 或主会话扮演）：

- prompt 以「【强制前置步骤】」开头
- prompt 含 `【角色】`
- 当前步骤标明「主会话正在扮演 `{role}`」
- 含明确的任务指令（如「审查以下代码」「实现以下功能」）且要求只做本职

主会话在**角色扮演段结束、回到技能主流程后**，技能触发恢复生效。禁止把整段用户对话都当成扮演段。

## 被调度角色可以做的

- Read `.agents/knowledge/` 下对应规范文件获取规范
- 执行被分配的具体任务
- 报告四状态之一（DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED）

## 被调度角色不能做的

- 触发技能（brainstorming、delivery-plan、feature-dev 等）
- 自行决定下一步行动
- 再调度其他角色
- 修改不在任务范围内的文件
