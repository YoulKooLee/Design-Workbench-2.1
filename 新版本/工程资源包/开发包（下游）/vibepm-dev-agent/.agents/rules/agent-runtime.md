# 运行时能力与降级

> 冻结口径：运行时能力 ⊥ 交付模式；审查降档 ≠ 运行时降级；无独立子 Agent 时主会话扮演同一角色、同一审查范围；Hook 为可选增强，不得写成「无 Hook 则工作流不可用」；编排用语为「角色调度」，「子 Agent」仅指独立上下文派发。

本文件管 **怎么跑**。何时必须跑哪个角色见 `agent-orchestration.md`；审查是否执行、审多深见 `AGENTS.md`「交付模式」与当前 `DELIVERY_MODE`。调度话术见 `role-dispatch.md`。

## 术语

| 用语 | 含义 |
| --- | --- |
| **角色调度** | 按技能步骤执行某个角色定义（派发或扮演） |
| **角色定义** | `.agents/agents/{role}.md` |
| **独立子 Agent** | 运行时能力：在独立上下文中执行角色，只回收结果 |
| **主会话扮演** | 运行时降级：当前会话按同一角色定义逐步执行 |
| **审查降档** | `DELIVERY_MODE` 为快速时收窄审查范围或跳过某审查角色 |
| **运行时降级** | 环境无独立派发 / 无 Hook 时只换执行方式，不改审查档位 |

## 两轴正交

| 轴 | 管什么 | 谁决定 |
| --- | --- | --- |
| **交付模式** | 审查深度、确认轮次、能否跳过/收窄 reviewer | 用户声明 + 分技能默认 + 自动升严格 |
| **ADE 运行时** | 能否独立派发、有无 Hook 硬拦 | 当前 IDE / ADE 能力 |

## 合成规则

1. 先读 `DELIVERY_MODE`，决定本步要不要跑 reviewer、跑多深（审查降档）。
2. 再看运行时：能独立派发则派发；不能则主会话扮演**同一角色、同一审查范围**（运行时降级只换「怎么跑」，不擅自加严或放宽）。
3. 禁止因「环境无独立子 Agent / 无 Hook」而额外跳过交付模式要求执行的审查；也禁止在「快速」模式下以「通用化要求审查不可跳过」为由强行全量审查。
4. 角色执行 prompt 首行继续传入 `交付模式：{DELIVERY_MODE}`。若 `DELIVERY_MODE` 规定本步跳过该审查角色，则整步跳过，不扮演、不派发。

无独立派发时，原计划并行的多个角色改为**组内串行扮演**，仍不得缩小审查范围。

## 运行时降级表

下表只描述运行时降级；表中「审查」均须再叠加当前 `DELIVERY_MODE`。

| 能力 | 增强环境（有 Hook / 可独立派发） | 运行时降级（仅 L0+L1） |
| --- | --- | --- |
| 子角色（req-writer、code-reviewer 等） | 独立上下文派发 | 主会话按角色定义扮演；**是否执行、审多深仍看 `DELIVERY_MODE`** |
| 只读子 Agent | 只读派发 + 主会话落盘 | 文本角色可只读派发；需 Bash/写文件则改扮演，不跳过角色 |
| GateGuard（先读后改） | 工具调用前注入/拦截 | 改文件前必须先读；写进铁律与技能步骤 |
| config-protection | 工具调用前拒绝 | 禁止改 eslint/tsconfig 等，违反须自行纠正 |
| review-reminder / tracker | 工具调用后注入与记状态 | 技能步骤显式完成「已审查」（仅当交付模式要求审查时） |
| stop-quality-gate | 结束前拦截并要求续写 | 宣称完成前执行 verification；自检 console.log；若本模式要求 reviewer 则确认已跑 |

无 Hook 时上表「软约束」的可执行条文见 `.agents/rules/soft-gates.md`。本文件仍只描述怎么跑。

## 产品承诺

- **通用核（L0+L1）**：`AGENTS.md` + skills / agents / knowledge / rules。保证流程可执行、角色不跳步。
- **增强包（L2+L3）**：`hooks/` 与厂商接线。保证可拦截、可自动续写、可追踪审查状态。未接入时按上表软约束执行。
- 禁止对外宣称「所有 IDE 硬门禁等价」。Hook 未接入 ≠ 工作流不可用。Cline / Roo / Copilot 的路径映射与只读限制见 `.agents/rules/ade-compat.md`。
