# 角色调度 · 独立派发前置注入（兼容入口）

完整调度模板见 `.agents/rules/role-dispatch.md`；运行时降级见 `.agents/rules/agent-runtime.md`。

## 规则

当以独立上下文派发角色时，必须在角色执行 prompt 开头注入以下强制指令。主会话扮演时由扮演者自行 Read 规范，不必注入本段，但仍须遵守角色定义与四状态。

```
【强制前置步骤】在开始工作前，你必须先 Read `.agents/knowledge/conventions/coding.md` 获取编码规范。
这是强制要求，不可跳过，不存在任何例外。未完成此调用前禁止执行任何后续操作。
你是被派发的子 Agent，不是主会话，只执行分配的任务，不触发任何技能流程。
```

## 适用范围

所有独立上下文派发的角色执行，包括但不限于：
- code-reviewer
- planner
- 任何临时通用角色（无预置定义时，仍须在 prompt 中给出角色职责与四状态；禁止写死厂商工具类型名）

## Prompt 结构要求

好的角色执行 prompt 必须包含：
1. 强制前置步骤（上方模板；仅独立派发时注入）
2. 明确的任务范围（具体文件、具体问题）
3. 所需上下文（不要让被调度角色自己去找）
4. 期望的输出格式（四状态报告）
5. 约束条件（不能修改哪些文件）

## 原因

- 独立派发不继承主会话的 `AGENTS.md` 上下文，必须在 prompt 中显式传递知识库调用要求
- 被调度角色不应触发技能流程（由 `subagent-stop.md` 规则保障）
- 被调度角色不应再调度其他角色（防止递归失控）
- 主会话扮演时共享上下文，但仍须先 Read 角色定义，且不得串戏、不得触发技能、不得再调度其他角色
