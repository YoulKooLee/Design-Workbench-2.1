# 崂山国家实验室数字孪生大屏 · 原型复盘与工作守则

> **复盘时间**：2026-11-05
> **项目周期**：2026-09-21 ～ 2026-11-05
> **技术栈**：React 18 + Vite 5 + TypeScript + Three.js + AntV G2Plot，3840×1080 大屏
> **复盘依据**：本项目会话轨迹 1,172 条（用户 136 轮 / 助手 536 条 / 工具结果 500 条）+ 工程代码 + PRD/SRS/HLD/LLD 四份文档
> **说明**：`01-项目` 工作副本未纳入 Git，无法做提交级回溯；涉及"谁改的"的判断，均以页面现状和文件时间为准，不做无证据归因。

## 摘要（先看这 5 条）

1. **最大的成本不是"做不出来"，而是"改完没验证就报完成"**——定位打点连续 4 轮失败、视距修复回弹、弹窗内容"依然未调整"，都是同一类问题。
2. **局部需求最容易伤到全局**——一次主题漂移让用户连续 4 轮要求回退，且因为工程无 Git，事后无法定位来源。
3. **大屏布局必须先把尺寸算清楚再写代码**——用户 136 轮指令里，"高度"出现 15 次、"宽度"11 次、"调整"36 次，园区总览布局至少返工 8 轮。
4. **数据口径和文档章节必须打开原文再写**——把能耗默认成接口、把 §3.10.2 写成 §4.8.2，都是"凭印象"的代价。
5. **单文件超过 600 行就要拆**——`chartBlock.tsx` 已到 1,684 行 / 36 个图表分支，`Campus3D.tsx` 1,642 行，后续每加一个图都在给下一次事故埋雷。

## 三、踩过的坑（按严重程度）

### 🔴 P0 — 直接导致返工或功能丢失

#### 坑 1：主题漂移，连续 4 轮返工

**现象**（用户原话）：

1. `我没让你改深色主题适配，改回去`
2. `怎么大屏变暗色调了，谁在捣乱，你帮我改回去`
3. `园区总览-园区简介没改，还是暗色；以及中间三维还是黑色`
4. `好多了，但还是有点深色，之前建筑是白色`

**现场**：轨迹中没有定位到一次明确的"改主题"调用；`project-memory.md` 已记录 2026-10-19 客户端更新会覆盖工程文件。结合工程无 Git、无法 diff，判断为外部变更或大范围样式改动叠加所致。

**根因**：

- 改动没有隔离，局部需求动了全局样式/主题。
- 没有"改前基线截图"，异常出现后只能靠回忆。
- 发现变暗后第一反应是继续改色，而不是先定位当前生效的样式来源。

**代价**：4 轮返工 + 1 次运行时错误。

**守则**：全局色板、主题、字体、背景属于"受保护区域"；变更必须单独授权、单独提交、改前存档截图、改后逐页比对。来源不明时先查 `.axhub/make/backups` 和最近修改文件，不要重写主题。

---

#### 坑 2：没按用户入口复现，却宣布"修复完成"

**现象**：

- `点击定位没有打点效果`
- 助手回复"修复完成"，并解释了 `group` 未定义的根因。
- 用户复测：`没有看到光柱，点击定位直接弹窗告警详情了`
- 助手回复"两个问题都修了"，说明只改了详情弹窗按钮。
- 用户：`还是没有，你测试下。`
- 最终：`还是不行，你先把定位触发弹窗效果删掉吧，红光高亮效果不做了`

**根因**：只验证了自己改的那条代码路径，漏了列表卡片上同名"定位"按钮（不同的 handler）；没有按用户的真实点击顺序复现。

**代价**：4 轮 + 功能被砍。

**守则**：修复类改动必须"按用户入口点一遍"；同一功能有几个入口，先列入口清单，逐个验证并留下截图/控制台证据。没有证据不得说"已修复"。

---

#### 坑 3：重写共享组件，把既有功能改丢

**现象**：

- `监控告警弹窗，视频回放功能被你删了`
- 告警排行榜先按需求新增，随后又因空间不足被要求删除。

**根因**：用整块替换代替定点修改；重写前没有列该弹窗的"字段/按钮/交互"清单。

**守则**：重写弹窗、列表、图表等共享组件前，先列功能清单（字段、按钮、空态、回放、定位等），改后逐项打勾；**不删任何用户没要求删的东西**。

---

#### 坑 4：数据来源与文档引用凭印象

**现象 A**：数据策划表把"查询历史告警数据"标成 `§4.8.2`，用户核对后指出应为 `3.10.2`。
**现象 B**：能耗默认按接口取数设计，用户纠正：`用电 / 用水 / 用热数据走人工填报，每月填写一次，填写每栋楼每月用电 / 用水 / 用热数据`。

**根因**：

- 把"接口文档里有这个能力"当成"业务实际这么走"。
- 章节号没有打开原文检索，靠记忆填写。

**守则**：每个指标必须写清四要素——**谁产生、多久一次、存在哪、哪份文档哪一节**；引用前在原文搜关键词定位章节，不凭印象写编号。接口"能取"不等于业务"在用"。

## 六、大屏原型专项经验（可直接复用）

### 6.1 布局与尺寸

```text
3840 × 1080
┌──────────────────────────────────────────────────────────────┐
│ 标题栏 64                                                     │
├──────────────┬──────────────────────────────┬────────────────┤
│ 左列          │ 三维 2260×980                │ 右列            │
│ x50 y80      │ x790 y80                     │ x3070 y80      │
│ 720×980      │                              │ 720×980        │
└──────────────┴──────────────────────────────┴────────────────┘
```

- 高度档位：**315 / 480 / 645 / 980**；半宽 **350**；整宽 **720**。
- 并排用 `pairRow`，子项 `flex:1`（各 350）；整行用 720。
- 每列 flex 合计必须等于 980；不齐时显式留白，不靠"大概"。
- 图表容器必须有确定高度，否则图例会溢出到相邻卡片（曾出现"能耗统计背后有数字"，实为设备设施图例溢出）。

### 6.2 图表选型

- 占比 ≤5 类用饼图/环形；趋势用折线；类别比较用柱状/条形。
- 双系列趋势用 `dualLine` / `dual`；多系列柱状用 `column`；堆叠横向用 `bar`。
- 饼图统一：环形约 180×180 + 图例约 180 + 间距 50；允许业务例外，但要在文档记录。
- 不用 AntV line 的 `path-in` 入场动画（会触发 `getTotalLength` 报错），改 `fade-in`。

### 6.3 列表与轮播

- 上下滚动，**不用滚动条**。
- 可见条数固定；`currentIndex >= maxIndex` 时回 0，保证末条能回到首条。
- 告警卡片高度约 100，三行布局；列表数据量按"最新 100 条"设计。

### 6.4 弹窗

- 同一告警在地图、列表、顶栏三个入口，**字段与顺序必须一致**：告警类型 / 等级 / 设备 / 位置 / 时间 / 内容 / 处理状态。
- 关闭按钮白色、位置固定；地图定位按钮与关闭按钮不互换。
- 重写弹窗前先列"字段 + 按钮 + 联动"清单，防止视频回放这类功能被无声删除。

### 6.5 三维点位

- 5 类图标：建筑、监控摄像头、门禁、停车场道闸、鹰眼。
- 2 态配色：正常绿、告警红；不再出现青/蓝/紫等第三、第四种状态色。
- 拖拽保存：localStorage 覆盖 → 导出 JSON → 写回默认坐标 → 跨页同步。
- 建筑标签与图标绑定，拖动时一起移动。

### 6.6 数据口径

- **能耗**：后勤物业按月人工填报，维度为楼栋 × 月份 × 电/水/热；不走 API-5。
- **告警**：智能感知平台 §3.10.2 历史告警；事件 §3.10.1；不要把两者混用。
- **安全态势**：只放安防类（周界、入侵、异常通行）；消防告警归消防运行页。
- **能源弹窗**：显示上月用电/用水 + 近 6 月迷你趋势，离线设备也能显示人工填报值。
