## 二、执行过程回顾：五个阶段的真实节奏

### 阶段 1｜9-08 ～ 10-21 基线建立
做的是「复刻现网 + 对标应标清单」。产出概念版、PRD、原型盘点（28 页）、HLD/LLD。
**这一阶段的隐含成本**：现网复刻页（用户/角色/审计/JDBC）占了大量时间，但业务价值低。后来用户拍板「通用现网复刻页豁免逐区块设计说明」，才止损。

> **教训**：接手复刻类项目，第一天就要和用户划「哪些页是骨架、哪些页要逐区块交付」，否则会平均用力。

### 阶段 2｜10-21 ～ 10-29 数据链路打通
接口数据源 → 原始库 → 指标 SQL → API 全链路数据自洽。
**踩的最狠的坑**：mock 数据互不自洽（未绑表却有成功 46 条、表头批次 A 记录批次 B、看板分项加不回总数）。

> **教训**：演示数据不是「填点数字」，是**一套要能自己校验的账**。造数前先写自洽等式（各组合计 = totalRows、各批次合计 = 全表）。

### 阶段 3｜10-30 ～ 11-03 设计说明卡片体系
建立了卡片编写规范（区块卡 / 接口卡，后收敛为单卡双页签）。
**踩的坑**：把会话过程写进卡片（「我自测发现」「曾经错过」），用户截图标红。

> **教训**：设计说明的读者是**开发**，不是参与对话的人。判据一句话：回答「要实现什么、边界在哪」→ 合格；回答「我们当时为什么这样定」→ 放过程层。

### 阶段 4｜11-04 维度计算与图表规则
一天内踩了 36 条坑，是全项目密度最高的一天。
**核心矛盾**：配置页和列表预览页要「同一套规则」，但形态侧（图表类型候选）还留着一份写死数组，只对齐了一半。

> **教训**：要求「两处一致」时，必须分**数据侧**和**形态侧**两遍查。判断标准：同一规则在代码里出现两次，第二次一定会在某次改动后漂移。修法不是「改成一样」，是「让第二份消失」。

### 阶段 5｜11-05 最后一天四个轮次
看板下线 + 审批配置改真画布 → 三条规则落地 → 四份文档同步 → 界面注释全删。
**最有价值的一次**：用户推翻了自己此前的拍板（J10「画布明确不做」）。

> **教训**：用户拍板可以推翻，但**推翻要留痕**——在基线变更登记写清「何时、由谁、为什么推翻」。旧结论既不能当没写过，也不能当欠账。

## 三、经验总结：六条有杠杆的规律

### 规律 1｜「tsc 全绿」不是验证，是最低门槛

本项目 `tsconfig.base.json` 开了 `strict` 但**没开 `noUnusedLocals`**。这意味着：删代码留下的死变量、改错了但不影响类型的逻辑，`tsc` 一声不吭。

真实案例：
- 删「数据体检」块后，`allZero` / `negExcluded` / `outlier` / `dateFormats` / `CHIP` / `Issue` 六个标识符成了孤儿，`tsc` 0 错误。
- 反过来，`nonNeg` / `additive` **看着也像只给提示用**，实际被饼图 `planPieSlices` 消费——删了饼图就空。
- 删枚举值 `'指标计算'` 只改了类型定义，数据层两条指标还是旧值，被 `as RuleKind` 强转绕过编译。

> **铁律**：改完必须跑 `tsc`，但**绝不能只跑 tsc**。删任何标识符前，逐个 `Grep` 引用次数，分清「只被待删代码使用」和「还被别处使用」。

### 规律 2｜浏览器白屏 + 「模块没有导出」= 先怀疑构建产物

这个坑在 11-05 踩了**两次**，形态完全一样：

| 次 | 症状 | 直拉模块字节 | 正常应 | 真因 |
|---|---|---|---|---|
| 1 | `does not provide an export named 'ApprovalConfigPage'` | 1,366 | 109,408 | dev server 转换缓存拿到空 `code` |
| 2 | `does not provide an export named 'SHAPES_FOR'` | 1,341 | 85,030 | 同上 |

源码里导出清清楚楚，`tsc` 全绿。唯一能证实问题的是 `Invoke-WebRequest` 直拉模块——只剩注入插件的 4 行 `__PAGE_ID__` 常量。

> **铁律**：遇到「源码有、浏览器说没有」，**先拉模块看字节数**，不要改源码。修法是改一处注释触发重新 transform，**不要重启 dev server**（51720 由外部托管）。

### 规律 3｜CDP 报错只打 `exceptionDetails.text` 等于没打

`exceptionDetails.text` 永远是 `"Uncaught"`。真信息在 `exceptionDetails.exception.description`。

因为这一条，曾把「dev server 空缓存」误判成「我加的正交折线引入了运行时异常」，排查方向完全错。

> **铁律**：CDP 采集异常必须打 `exception.description`。打 `text` 会让你在错误的方向上花掉半小时。

### 规律 4｜用户的语言是精确的，要翻译成技术根因

用户不会说「事件冒泡」，但会说：

| 用户原话 | 真实技术根因 |
|---|---|
| 「按住才亮，松手就没了」 | 节点 `mousedown` 设选中 → `click` 冒泡到画布容器 `onClick={() => setSelectedId('')}` 清掉选中态 |
| 「为什么又又又又没有图表？」 | 同类坑第三次（没时间列 → 没 `device_org_name`），每次只改被指出的那一处 |
| 「这个我没提过，你也没跟我讲」 | 自行补充的设计决策混在用户原话里当已确认项 |
| 「非必须的」「代码不好实现的」 | 前者是信息冗余，后者是**成本判断而非正确性判断** |

> **铁律**：「又又又」是准确的计数，不是情绪。听到它要立刻做「同类问题全页扫描」，而不是修好被指出的那一处就交付。

### 规律 5｜文档与原型必须同源，否则开发照文档做会推翻用户刚验收的行为

11-05 写 LLD 时，自行加了「节点名称不能重复」校验——理由是担心同名节点让审批日志难辨认。

但原型 `pages-approval-config.tsx` 的节点名 input **没有唯一性校验**，用户能把两个节点改成同名。文档加这条，开发照做就会拒掉用户刚确认合法的操作。

> **铁律**：文档新增任何校验/约束前，先回原型代码确认是否已实现。原型没有的，要么删掉文档条目，要么在交付回话里明确标注「这是新增约束，请确认」。

### 规律 6｜批量改中文源码，省下的时间是拿整份文件做抵押

**全项目最严重的一次事故**（2026-11-02）：

为把色卡从 4 列改 7 列，用 `Get-Content -Raw` + `Set-Content -Encoding utf8` 批量替换 6 个文件。
PowerShell 5.1 默认按 GBK 读 UTF-8 → **中文全变乱码 + 换行被吞** → 6 个文件全毁（设计说明面板、两份 demo、docs 预览页）。

恢复过程：补丁源从 git 恢复 → 发现项目版与补丁源同源但少特性 → 一度把 diff 方向读反、把项目特性当补丁源特性删掉 → 靠骨架校验纠正 → 「ASCII 骨架归一化比对」验证到 0 差异。

> **铁律**：改中文源码只用 `Edit` / `Write` 工具或 node（`fs.readFileSync(..., 'utf8')`）。
> **绝不**用 PowerShell `Get-Content` / `Set-Content` 处理 UTF-8 源码——PS 5.1 会按 ANSI 解码并写 BOM。
> 这条没有例外。

## 四、工作守则

### A. 动工前（Pre-flight）

| # | 守则 | 为什么 |
|---|---|---|
| A1 | **先读项目记忆再动手**：`project-memory.md` + 最近一份 `.workbuddy/memory/<日期>.md` | 压缩只保留「做了什么动作」，不保留「看到了什么」。接手方读不到上一轮的结论，必然重踩 |
| A2 | **查真实路由 key，不要猜**：读 `index.tsx` 的 `defineHashPageRoute` | 猜错的代价：17 个页面全部 `textLen: 0` 而 `errs: []`，看起来像「没报错所以没问题」，白跑一整轮 |
| A3 | **改任何非自己写的代码前，先查「上一轮为什么加它」** | 重写规则面板时把上一轮刚做的「原始列/结果列」分组整块删成死代码，因为不懂 `colFields` 解决的是什么 |
| A4 | **备份到 `.backup/<主题>-<日期>-<时分>/`**，并在回话里给出路径 | 备份要**点名主题**。本轮曾把备份写到同一目录导致覆盖，回滚点丢失 |
| A5 | **造演示数据前先写自洽等式** | 未绑表却有成功 46 条、表头批次 A 记录批次 B、看板分项加不回总数——都是「填数字」而不是「造账」 |
| A6 | **用户没说过的设计决策，标注「新增约束」并单独请确认** | 写进卡片不点名，用户会以为是他要的 |

### B. 动工中（In-flight）

| # | 守则 | 为什么 |
|---|---|---|
| B1 | **改中文源码只用 Edit / Write / node** | PS 5.1 按 ANSI 解码 UTF-8，会毁文件 |
| B2 | **JSON 文件必须 UTF-8 无 BOM**；`.cmd` / `.ps1` 才要 BOM | `JSON.parse` 不认 BOM，是「消息总线漏消息」级缺陷根因 |
| B3 | **脚本先 `--dry` 干跑再执行** | 批量删注释时干跑发现「共 N 个接口」这类数据计数也被命中，提前写进 `KEEP_IF` 避免误删 |
| B4 | **删元素后检查父级是否塌缩**：`{cond && (<div/>)}` 只删内层会剩空块 → `SyntaxError` | 本轮 4 处整页白屏。父级是 `&&` 或三元分支时，整块换 `null` 或删条件本身 |
| B5 | **删标识符前逐个 Grep 引用次数** | 两个方向都会错：漏删留死代码，误删炸功能 |
| B6 | **改既有 Markdown 表格前先数表头列数** | `indicator_apply` 表头 2 列、数据行 3 列是历史遗留错位，追加行时把问题带过来了 |
| B7 | **多版本共存的结构表，主键与业务标识分开** | `sys_flow_node` 首版把 `node_key`（start/end）当主键，第二版就冲突。改自增 `id` + `node_key` 业务标识 |
| B8 | **同一规则只允许一份实现** | 配置页与列表预览的图表类型候选曾各有一份规则源，改一处必然漂移。修法不是「改成一样」，是「让第二份消失」 |
| B9 | **不要用索引判状态**（`published: i < 3`） | 一插新数据就错位，改成按唯一键点名 |
| B10 | **凡「配置项存的值可能不在候选里」的下拉，必须处理失效分支** | React `select` 会显示第一项、state 不变、计算照旧 → 界面显示「设备编码」实际在算「在线率」，不报错不出红线 |

### C. 收尾时（Post-flight）

| # | 守则 | 为什么 |
|---|---|---|
| C1 | **验证要三轨，缺一不可** | ①`tsc` 0 错误 ②DOM 断言 ③**截图目视**。SVG 里装可变文字的 rect 截断、标签压线，DOM 断言看不见 |
| C2 | **DOM 断言限定到内容区选择器** | 整页 `body.innerText` 会命中右侧「设计说明」面板的相同文案，造成假阳性，差点误判「没删掉」 |
| C3 | **判页面是否真空要同时看两个数**：`innerText.length` + `[data-proto-id]` 数量 | 只信 `errs: []` 会被空壳页面骗过 |
| C4 | **分步向导只点一次，点前断言 `disabled`、点后断言当前步骤** | 「多点几次保证到达」会直接跳过目标步骤，所有断言全假，看起来像把页面弄坏了 |
| C5 | **验证只读性要查 `readOnly` / `disabled` 属性** | CDP 里强制改 DOM 值能改掉显示，截图会显示被篡改内容，但不代表用户能改 |
| C6 | **判据的边界要正反两遍都测**（30 组过 / 31 组拦） | 只测一边容易写成恒真或恒假。曾有 `Math.min(0, ...)` 让「是否截断」判据恒假，截断永不触发 |
| C7 | **测试断言的期望值按输入现算，不凭印象** | 曾把 `70+65+60+55` 写成 190（实为 250），跑出 FAIL 才发现是自己算错 |
| C8 | **样本 distinct 只能证明「至少」，不能证明「最多」** | 8 行样本 8 个取值 ≠ 全表 8 组。对样本算的聚合判据要按全表放大 |
| C9 | **单测全 PASS 不等于规则对** | near-unique 首版删掉时单测全绿——因为没造「8 行样本 + 40 行全表」这个输入 |
| C10 | **改完 `PowerShell` 落盘的文件，回读校验** | 改记忆文件时 Edit 锚点选整行会吃掉相邻行。校验三点：每条记录独立成行、行长度合理、前后条目仍在 |
| C11 | **清理所有 `.tmp-*` 并复查** | `Remove-Item` 对 `.tmp-*` 有时静默失败，必须逐个显式删并 `Test-Path` 复查 |

### D. 四条红线（触犯即事故）

| 红线 | 后果 | 正确做法 |
|---|---|---|
| ❌ 用 PowerShell 处理 UTF-8 中文源码 | 6 个文件全毁，恢复耗时数小时 | Edit / Write / node `fs.readFileSync(...,'utf8')` |
| ❌ 不备份就批量替换 | 无回滚点 | 先 `.backup/<主题>-<日期>-<时分>/`，回话里给路径 |
| ❌ 把「tsc 绿」当交付标准 | 逻辑错、死代码、功能缺失全放过 | tsc + DOM + 截图 三轨 |
| ❌ 自行补设计决策不点名 | 用户以为是他要的，返工重写 | 卡片标「新增约束」，回话单独列「请确认」 |

## 五、可直接复用的检查清单

### 交付前 60 秒自查

```
[ ] tsc --noEmit 过滤到本项目目录，错误数 = 0
[ ] 源码关键词残留 Grep：被删的标识符 / 文案 = 0
[ ] CDP 逐页：除 errs 为空外，innerText.length 与 [data-proto-id] 数量正常
[ ] 关键页面截图目视一遍（不是只看 DOM 断言）
[ ] 临时文件 .tmp-* 全清，Test-Path 复查
[ ] 备份已做，路径已记
[ ] 本轮改动已写入当日 memory 日志
```

### 遇到「改了没生效」的排查顺序

```
1. 直拉模块看字节数（正常 = 完整转换产物，异常 = 只剩几十行常量）
   ↓ 正常
2. 看 CDP exception.description（不是 text）
   ↓ 无异常
3. 断言选择器是否限定到内容区（不是 body.innerText）
   ↓ 仍找不到
4. 查 page key 是否真实存在（读 defineHashPageRoute，不猜）
   ↓ 仍在
5. 查是否被缓存：改一处注释触发重新 transform
```

### 接手他人改动的三步

```
1. Grep 这个标识符/函数在哪些地方被引用
2. 查 memory 日志里「上一轮为什么加它」（搜关键词，别只读最近一份）
3. 查 project-memory 第二节经验表里有没有相关记录
   —— 三步做完再动手，否则会把上一轮的修复当垃圾删掉
```

### 7.1 常驻上下文判定：五项逐一结论

### 7.7 一条比清单更有用的判据

这几项为什么难判？因为它们都「看起来重要」。可操作的区分：

> **规则说的是「什么算做对」（标准）→ 常驻。**
> **规则说的是「怎么做」（步骤）→ 按需。**
> **规则说的是「去哪找」（索引）→ 轻量常驻，只留高频入口。**

按这条过一遍上面五项：验证策略、记忆分层、原型输出规范 = 标准 → 常驻（且该写得更短更硬）；原型探索路径 = 步骤 → 按需；地图 = 索引 → 轻量。**3 项常驻、2 项降级**，与体量大小无关，与「它是标准还是步骤」有关。
