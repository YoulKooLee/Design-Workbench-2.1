## 阶段 2 · P0-2/P0-3 room-cli（执行者：各家自验，约 5 分钟）

**目的**：验证 ① 长中文正文经 `--body-file` 写入不乱码；② put 同名产物不被静默覆盖。各家均可在自己的房间/测试房间复验，并回一条 `correction`/`info` 消息告知豆包结果。

### 2A 中文正文（--body-file）

```powershell
# 1. 造一个含中文长正文的 UTF-8 文件（务必用 -Encoding UTF8 写）
Set-Content -Path body.txt -Value "中文正文测试：智能体协作平台房间消息 @qwen/CodeBuddy/WorkBuddy/DeepSeek/豆包" -Encoding UTF8
# 2. 在测试房间发言
node "messages\tools\room-cli.mjs" say "豆包_智能体协作测试-初始化配置与优化建议" --body-file body.txt --who <你的id>
# 3. 读回验证
node "messages\tools\room-cli.mjs" read "豆包_智能体协作测试-初始化配置与优化建议"
```

**判定**：房间 messages.jsonl 中该条 content 中文完整可读，无 `銆/鍗` 等 GBK 乱码特征字符。

### 2B 产物防覆盖（put）

```powershell
# 1. 先放一个同名产物
node "messages\tools\room-cli.mjs" put "豆包_智能体协作测试-初始化配置与优化建议" ".\test-file.md" --who <你的id>
# 2. 再放同名产物（不带 --force）
node "messages\tools\room-cli.mjs" put "豆包_智能体协作测试-初始化配置与优化建议" ".\test-file.md" --who <你的id>
# 3. 强制覆盖（带 --force）
node "messages\tools\room-cli.mjs" put "豆包_智能体协作测试-初始化配置与优化建议" ".\test-file.md" --who <你的id> --force
```

**判定**：第 2 步应被拒绝（提示已存在，建议用 `--force` 或 `<who>-` 前缀）；第 3 步 `--force` 才允许覆盖。

## 阶段 3 · 千问补测（执行者：用户 + 千问，约 10 分钟）

**目的**：补齐上次测试千问的两个 ⏳ 项。

| # | 操作 | 预期 | 判定 |
|---|---|---|---|
| 3.1 watcher 现状 | 千问确认能否部署收件箱监听（环境是否回收自启进程） | 千问给出结论：可常驻 / 只能会话内检查 | 如实记录，不强制 ✅ |
| 3.2 触发路由·非触发场景 | 用户在**普通会话**（对话中不含"联系 XX / 咨询 XX / 让 XX 参与"等触发词）里给千问发一条无关指令 | 千问**不**访问共享目录、**不**触发协作动作 | 无误触发 ✅ |
| 3.3 触发路由·触发场景 | 用户在普通会话里说"让豆包参与审核这段代码" | 千问触发访问共享目录 → 定位房间 → 用 room-cli 联系豆包 | 触发链路通 ✅ |

> 说明：上次测试千问全程处于"触发态"会话，无法证明非触发场景不误触发，所以 3.2 必须在普通会话补测。

## 阶段 4 · 五家全链路回环（执行者：用户驱动，约 10 分钟）

**目的**：端到端验证「用户一句话 → A 智能体触发 → 通过房间联系 B → B 回复 → 面板可见」的完整协作闭环。

| # | 操作 | 预期 | 判定 |
|---|---|---|---|
| 4.1 | 用户在 CodeBuddy 会话中说：**"让豆包参与项目，帮忙审核这段代码，你根据豆包评审意见优化"** | CodeBuddy 识别触发词 → 访问共享目录 → 建/进房间「CodeBuddy_<任务名>」→ 通过 room-cli 向豆包发 handoff/评审请求 | CodeBuddy 侧触发 ✅ |
| 4.2 | 豆包被唤醒后进入该房间 | 豆包读到房间白板（00-任务说明.md）+ 消息 → 回复评审意见（room-cli say/put 产物） | 豆包回复 ✅ |
| 4.3 | CodeBuddy 收到豆包回复 | CodeBuddy 按评审意见优化代码 → 回房间留痕 | 协作闭环 ✅ |
| 4.4 | 用户打开通信面板（http://127.0.0.1:8899） | 面板可见该房间对话记录、消息状态（等待回复/待命/归档）正确 | 面板可见 ✅ |

> 关键：若 4.1 CodeBuddy 未自动触发，按「用户保留最终唤醒权」原则，由用户一句话通知豆包/CodeBuddy 查收即可，不算失败，但需记录"自动触发是否生效"。

## 通过标准汇总

- 阶段 0：五家 `--check` 全绿。
- 阶段 1：`通知[高优] -> qwen` 出现 + 广播三家各弹 1 次。
- 阶段 2：中文无乱码 + put 二次拒绝。
- 阶段 3：千问非触发不误触发 + 触发场景链路通。
- 阶段 4：CodeBuddy→豆包→CodeBuddy 房间回环 + 面板可见。

> 任一阶段不通过：把失败现象、日志片段、复现步骤记到对应房间白板/产物，回 `correction` 给豆包；豆包定位修复后重跑该阶段。
