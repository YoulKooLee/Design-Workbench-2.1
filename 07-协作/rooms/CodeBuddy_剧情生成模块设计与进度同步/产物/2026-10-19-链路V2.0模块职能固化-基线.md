## 一、五段链路与 9 个模块的对应关系

```
① 总体框架 ──→ M1 框架实例生成器
② 故事线路 ──→ M2 故事线路生成器
③ 剧情结构 ──→ M3 章纲装配与校验器
④ 写正文   ──→ M4 套路库抽卡服务 + M5 正文生成器
⑤ 校验回写 ──→ M6 director 两层校验器 + M7 状态台账回写器
横切全部   ──→ M8 上下文装配器 + M9 人审工作台
```

## 二、模块职能矩阵（固化）

### M1 框架实例生成器

| 项 | 内容 |
|---|---|
| 职能 | 把「可插拔框架模板」（七支柱/三幕式/英雄之旅…）按本书题材生成**专属实例**（如支柱2=「井中浮尸，验尸翻案」） |
| 输入 | 用户 idea（一句话+题材+基调）；框架模板库（可选模板） |
| 输出 | `story_pillars` 记录（每支柱：本书实例文本 + 天数配额） |
| 实现形态 | **LLM 起草 + 人审拍板**（M9）；模板库为代码常量 |
| 现状 | 表已建（`StoryPillar`）、内置种子已灌入、已驱动推演（`pillar_fit`+`PILLAR_PULL=0.35`）；**缺 LLM 生成路径与多框架可插拔** |
| 验收口径 | 同 idea 可生成 ≥1 套实例；框架文件冻结后成为 M6 判「偏离框架」的**唯一基准**（director 不自创标准） |
| 缺口 | 框架模板库只有七支柱一种；LLM 生成化未做 |

### M2 故事线路生成器

| 项 | 内容 |
|---|---|
| 职能 | 拆多阵营目标线 + 时间切片 + 主角倒排计划；为主要人物生成**支线**（用 45 原型库的 `relations.pair` 推荐关联角色、`personality.fear` 定考验抓手、配角用 `friction_points` 转 beats） |
| 输入 | 冻结的框架实例；45 原型库（`backend/app/data/archetypes_45.json`）；角色卡 |
| 输出 | `goal_lines` / `goal_stages` / `goal_conflicts` 记录；每角色的支线目标与考验点 |
| 实现形态 | **LLM 起草 + 人审拍板**；原型库为只读检索源 |
| 现状 | 三表已建（阶段2a 验收通过）、19 端点+6 模板+12 词词表可用、前端两步向导在；**引擎零消费（悬空）→ 正由 4a 解决**；45 原型库已入库但**无 service/API** |
| 验收口径 | 冲突窗口 `window_open_day` 可被引擎读出并产出「必然冲突日历」；原型引用**必须用 code 精确匹配**（16 组正反面同神话原型，禁用简称做键） |
| 缺口 | archetype_service 与 API 未做；LLM 拆分初稿未做 |

### M3 章纲装配与校验器

| 项 | 内容 |
|---|---|
| 职能 | 双向：**(a) 事前**引擎产出「约束包」给 writer；**(b) 事后**校验 writer 起草的 beats（时间线/信息集/伏笔额度/因果） |
| 输入 | (a) 状态账本现值 + 必然冲突日历 + 信息集；(b) writer 起草的 beats |
| 输出 | (a) 约束包（JSON）；(b) 校验报告（过/不过+意见） |
| 实现形态 | **纯代码**（引擎侧）+ LLM 起草（writer 侧） |
| 现状 | `EpisodeBeat` 表已存在但**只有 `seq`+`content` 两个字段**（纯文本，无视角/套路引用/走向参数/伏笔关联）；`Episode` 有 `confirmed`+`batch_id`（人审机制已在）、`plot_conflict/turn/ending`（V1.x 三件套，来自事件流）；**约束包格式未定义、章纲校验器不存在**（模拟中由千问手写伪 JSON） |
| 验收口径 | 约束包字段固定可解析；校验器对模拟中那 4 类问题（时间线穿帮/信息集越界/伏笔超额/凭空因果）各有一条真断言测试 |
| 缺口 | **闭环模拟缺口 3**：约束包 Schema + 章纲校验器全缺；`EpisodeBeat` 需扩字段 |

### M4 套路库与抽卡服务

| 项 | 内容 |
|---|---|
| 职能 | 存套路模板（从其他作品提炼、换人即用）；按需检索→抽卡→冷却→台账 |
| 输入 | writer 检索请求 `{题材, 阶段, 角色关系, beat类型}` |
| 输出 | K 个候选套路（默认 K=3），每个含：触发条件/参与者槽/**多走向(参数化)**/随身NPC |
| 实现形态 | **纯代码服务**（检索+加权抽卡+冷却记账）；套路内容由提取管线产出 |
| 现状 | `EventTemplate` 48 条已全结构化（3c 收官：slots/slot_fallback/slot_conditions/drama_base/goal_alignment），护栏齐（槽名/cast一致性/槽取值禁人名位）；**但全是修仙向、无题材闸门、无多走向分支、无随身NPC、无抽卡台账** |
| 验收口径 | 三道闸门（题材/阶段/关系）真实过滤——模拟中「滴血认亲」被阶段闸门滤、「赏花宴下毒」被关系闸门滤，须有对应测试；**走向参数必须绑定状态账本字段**，writer 只能在账本允许值域内选（缺口 2） |
| 缺口 | **闭环模拟缺口 1/2/4**：库空（换题材即空转）、走向参数无账本绑定、抽卡冷却粒度未定 |

### M5 正文生成器

| 项 | 内容 |
|---|---|
| 职能 | 按**人物视角**写正文（不是上帝视角倒设定）；素材=章纲 beats + 抽卡套路 + 账本切片 |
| 输入 | 冻结章纲（含人审批注）；M4 抽卡结果；M8 装配的上下文 |
| 输出 | `Episode.script`；`script_source` 标明来源（rule/model） |
| 实现形态 | **LLM**（writer 角色） |
| 现状 | `script_runner.py` 在跑、`script_source` 字段已支持 rule/fallback/model 三态；**上下文装配是临时的、无 Me2AI/AI2AI 体系** |
| 验收口径 | 正文视角=章纲指定视角角色；套路只给结构、文字全重写（不得复制套路原文表达，版权红线）；同章纲多次生成不得逐字节相同（LLM 天然特性，**不再要求逐字节一致**） |
| 缺口 | 上下文装配器（M8）未建；视角约束未硬校验 |

### M6 director 两层校验器

| 项 | 内容 |
|---|---|
| 职能 | 抓基线+抓逻辑+内容审核；**代码层**（人名/时间线/伏笔到期/信息集越界，便宜必过）+ **LLM 层**（偏离框架/动机合理/AI腔/节奏） |
| 输入 | 成稿正文；冻结框架文件；状态账本；章纲 |
| 输出 | `ReviewReport`（passed/round/source）+ `ReviewIssue`（level/type/message/suggestion） |
| 实现形态 | **代码 + LLM 双层**；只读不改正文 |
| 现状 | `ReviewReport.source` 已支持 `'rule'` / `'{provider}-assist'` 两态——**正是两层校验的落地位置**；`ReviewIssue.level` 决定阻塞与否（对应红线3：代码层不过=硬失败）、`type` 对应 SRS 六项检查；`GenerationRun` 可留痕 |
| 验收口径 | 代码层不过=硬失败（不许进回写）；LLM 层不过=带意见打回，最多 N 轮超限报人裁决；两层都过才回写状态 |
| 缺口 | 代码层规则库未成体系（散在测试里）；LLM 层的「偏离框架」判定未接 M1 冻结文件 |

### M7 状态台账与回写器

| 项 | 内容 |
|---|---|
| 职能 | 维护世界状态真相（关系值/暴露度/位置/blocks/进行中事件/伏笔台账/后果链）；校验通过后回写 |
| 输入 | director 通过的成稿；本章发生的事实 |
| 输出 | 更新后的账本 → 成为**下一集 M3 约束包的输入**（链路自续） |
| 实现形态 | **纯代码**（引擎） |
| 现状 | `Relation`/`CharacterState`/`Foreshadowing`/`PendingRepercussion`/`EventConsequence` 表齐；4a 正在扩 `foreshadowings`（kind/creditor/expected_payoff_day）+ 冲突引擎化；**ada600 实测伏笔 39 条全 planted、0 回收**（伏笔只埋不收铁证） |
| 验收口径 | 回写幂等（同章重复回写不产生双份）；伏笔到期必被催办（INV-26）；账本是 writer 不可推翻的真相（红线1） |
| 缺口 | 回写触发点未接 director 通过事件；伏笔催办待 4a 交付 |

### M8 上下文装配器（横切）

| 项 | 内容 |
|---|---|
| 职能 | 按需检索注入，不整份塞；分 **Me2AI**（用户写、AI 必守的"法律"：agent.md/世界观/角色卡/主线/文风宪法）与 **AI2AI**（AI 自写自更新的"台账"：章节状态/时间线/伏笔/角色线） |
| 输入 | 当前任务类型（写框架/写章纲/写正文/审核）+ 项目文件 |
| 输出 | 装配好的 prompt 上下文包 |
| 实现形态 | **代码管线**（skill 形态，用户已定：不照搬文章那 12 个 Agent skill） |
| 现状 | **完全未建**——用户 10-15 点名承认的缺口；资料已收集（`docs/03-上下文工程与创作资料/`，含小菇三篇 SOP + Me2AI/AI2AI 二分法） |
| 验收口径 | 物理文件夹按性质分区（对标产品设计工作台）；写第 N 章时 AI 读文件而非凭记忆；注入量可控（不整份塞） |
| 缺口 | 目录结构未建、装配逻辑未写、规则库未成体系 |

### M9 人审工作台（横切）

| 项 | 内容 |
|---|---|
| 职能 | 三处拍板点：①框架 ②故事线路 ③章纲；用户的审美决策必须能**穿透到下游** |
| 输入 | writer 各阶段产物 |
| 输出 | 冻结版（成为下游基准）+ 批注 |
| 实现形态 | **前端 + 代码**；已有 `confirmed`/`batch_id` 机制 |
| 现状 | `Episode.confirmed`+`batch_id` 支持草案→确认；目标线两步向导前端在；**框架/章纲的人审界面与批注穿透未做** |
| 验收口径 | 人审批注能改变下游走向且被系统承接（模拟已证：改结局→框架冻结；批注"第三处证据留下集"→走向参数=证据充分度2），须有测试固化 |
| 缺口 | 批注的结构化落库与穿透机制未做 |

## 三、四方职责红线（固化，不得逾越）

| 角色 | 干什么 | 绝不干什么 |
|---|---|---|
| **用户（人）** | 灵感、创意、关键决策、审美判断；①②③三处拍板 | 不写执行细节 |
| **writer（LLM）** | M1 框架实例、M2 目标线拆分、M3 章纲起草、M5 正文；结构推演=**宏观搭骨架链** | **不碰世界状态"真相"**——关系值/暴露度/伏笔台账以 M7 账本为准 |
| **引擎（纯代码）** | M3 约束与校验、M4 抽卡、M7 台账；管冲突窗口/冷却/解锁/对账 | **不生成剧情文本**（4a 的 `build_clash_event` 产物降级为样本） |
| **director（=reviewer）** | M6 两层校验、抓基线、抓逻辑、内容审核；只读不改正文 | 不做创作决策（判定标准来自 M1 冻结框架，不自创） |

**红线1**：剧情走向硬骨架（谁跟谁必然冲突、何时爆发、世界状态数值）只能来自 引擎+用户拍板的框架/目标线，writer 不得推翻。
**红线2**：writer 自由度在"怎么讲"（视角/节拍/台词/场景切分/套路选用），不在"发生了什么"（账本数值、必然事件）。
**红线3**：director 代码层不过=硬失败，LLM 层不过=带意见打回；两层都过才回写状态。

## 四、与 V1.1 架构方案的冲突清单（以本文为准）

| V1.1 章节 | V1.1 口径 | V2.0 口径 |
|---|---|---|
| §2 七层架构 L4 | 「事件流=目标驱动推演」，事件流是剧情骨架 | 事件流降级为**约束日历+素材索引**；剧情骨架=章纲（M3） |
| §5.1 事件库 | 「从事件成品到事件生成器」，事件库是推演**唯一内容源** | 降级为 M4 **套路库抽卡**（writer 按需检索）；slots/标注/护栏转型为检索元数据+抽卡排序依据 |
| §5.3 扩库方式 | 代码组合出文本变体（3c 做的 914 短语零共用） | 文本由 writer 用 LLM 重写；**3c 的代码级文本变体优化价值缩水**（沉没成本，已认） |
| §6.1 推演引擎 | 引擎在主循环里抽模板产事件 | 引擎=M3 事前约束源 + 事后校验器 + M7 台账维护者 |
| §7 L5/L6 | SceneSpec 实例化 + writer/reviewer | 保留；reviewer 正名为 **director**，两层校验（代码+LLM） |
| SRS §2.1（漫剧工作台 V1.0） | 「事件库是推演的唯一内容来源」 | **须改版**（待剧情生成部分定稿后一起改） |

**仍然有效、不改的**：§3 框架层（含双时间轴边界）、§4 目标线三表与谓词化、§6.2 概率公式（门控+加法）、§6.3 性格标签打通、确定性 `roll(seq,salt,key)`、INV 体系（27 条，继续扩）。

## 五、闭环模拟验证结论（固化依据）

《凤仪宫变》端到端手动模拟（2026-10-17）判定：**五段链路每段输出恰好是下一段输入，四方职责无一处打架**。

- 三道闸门真实过滤：「滴血认亲」被阶段闸门滤、「赏花宴下毒」被关系闸门滤，只剩「验尸立威」命中
- 人审两次介入均改变下游且被承接：改结局→框架冻结；批注"第三处证据留下集"→走向参数=证据充分度2
- 状态回写自续：第1集回写的状态成为第2集约束包输入

暴露 4 个缺口（已分配到 M3/M4，见各模块「缺口」行）：

1. 套路库只有 48 条修仙向，换题材即空转 → M4 + 提取管线
2. 走向参数由 writer 自选会破坏因果 → M4 绑状态账本字段
3. 约束包格式未定义、章纲校验器不存在 → M3
4. 抽卡冷却记账粒度未定 → M4 台账
