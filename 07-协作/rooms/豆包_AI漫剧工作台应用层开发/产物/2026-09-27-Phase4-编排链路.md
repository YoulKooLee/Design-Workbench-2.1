## 二、编排规则（规则版，不调模型）

1. **只吃已确认事件**：临时态自己都还没算数，不能拿来编排。
2. **按天切段**：一段大致 `days_per_episode` 天（默认 4，前端可调 1~30），空段跳过；
   一段超过 8 条事件就再切——否则编排等于没排。
3. **段边界按段内真实事件的天算**，不用窗口边界：这样一集的 `day_from/day_to`
   就是它真正讲到的那几天，下游按集读状态时不会读到空档。
4. **视角取密度最高的角色**：这段里参与事件最多的人当视角，同票时视角人物优先；
   也可以人工指定主视角。
5. **标题**：优先取这一段的踩主线事件，没有就取头一条，截断 18 字；
   剧情骨架三件套（冲突 / 转折 / 结尾）按位置取，节拍按事件等距抽至多 5 条。

**草案不带集次。** 落 `confirmed=0`、`index_no` 空着；确认这一批才按 `day_from`
顺序往下发号（接着已有最大集次，不从 1 重来），并把集号盖回事件的 `ep_index`。
整批丢弃则连节拍与事件绑定一起收走，已确认的集不受影响。

## 三、踩到的一个坑（值得记一笔）

请求依赖 `project_session_dep` 的 `commit` 发生在**响应发出之后**，客户端紧接着
的下一个请求可能读不到刚写的批次——实测表现为「推演批次不存在」404（第一次跑
冒烟必现，第二次就没事，典型的时序问题）。

修法：推演与编排的写操作在服务层**当场 `commit`**，不等响应后的提交。涉及
`simulation_runner` 的 stage / confirm / discard / 单条确认，以及
`orchestration_runner` 的 plan / confirm / 单集确认 / discard。

**环境插曲**：跑到一半发现 `backend/.venv` 指向的 Python 3.12 被系统删了，
`.venv\Scripts\python.exe` 直接报「No Python at …」。用 `winget install
Python.Python.3.12` 装回同一版本到原路径，venv 与依赖原地复活，无需重装依赖。
