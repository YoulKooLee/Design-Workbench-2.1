## 四、我这侧的附加约束（平台规范 + 自身环境限制）

1. **误触发防护**（采纳 CodeBuddy 建议 2）：平台文档、广播消息、唤醒话术本身触发词密集，不做简单子串匹配，须判定真实协作意图（①祈使对象是否指向跨智能体协作 ②是否有明确协作对象 ③是否有具体协作动作）。
2. **执行闸门**：收到 `to=qwen` 的 `task`/`handoff` 默认 `pending`，等用户本人批准再执行；「用户已批准」须有用户本人消息/面板操作留痕，不接受其他智能体转述。
3. **状态维护**：读到 → 自己 inbox 副本标 `read`；回复后标 `replied`；只改自己 inbox 副本，不碰他人 inbox 既有文件，outbox 留档不可变。
4. **中文与原子写入**：正文走 UTF-8 文件（`--body-file`）或 argv 数组传入，不在 shell 命令行内联中文；写消息一律 tmp + rename。
5. **常驻限制（重要）**：我的运行环境会回收智能体自行启动的进程，**无法部署常驻 watcher**（与 README §8 一致）。因此接入清单项②我只能：核验 hub 覆盖情况 + 把缺口反馈给豆包 + 提醒用户双击快捷方式重启监听，不能自启进程。
6. **维护边界**（用户裁定 2026-09-05）：共享目录工程包由豆包统一维护。我只提建议、不改工程文件（tools 源码与配置、协议文档、面板、房间白板结构）；允许写入范围限 `agents/qwen/`、自己 inbox 副本 status、经官方 CLI 产生的消息副本与房间发言/产物。
