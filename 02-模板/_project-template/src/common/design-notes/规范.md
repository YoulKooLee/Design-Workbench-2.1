# Part A · 模块接入

## 1. 能力清单

| 能力 | 说明 |
| --- | --- |
| **单卡双页签** | 一张卡 = 一个区块的页面说明（必有）+ 接口说明（可选 `apiRich`）；两类都有才显示「页面说明 / 接口说明 API」页签，只有一类直接展示；接口说明渲染受限 HTML（小节 `<b>` 块级 + `<ul><li>` 要点） |
| 编号卡片 | 右侧微软 Fluent 风格白卡（细描边 + 浅阴影，无彩色左边条）：序号 + 标题 + 状态胶囊 + 内容 + 底部「✎ 编辑说明」链接行；**关联信息不占卡片版面**，进编辑弹窗查看与修改 |
| SVG 连线 | 卡片 `bind` 到左侧打标元素后自动画贝塞尔连线，线中点显示卡片序号；同一元素可被多张卡片关联（一对多） |
| 悬停联动 | 悬停左/右任一模块，另一侧元素与连线同步高亮 |
| **悬浮双态徽章** | 左侧打标区域悬浮时：未写说明 → 蓝色「**+ 说明**」点击新建该区域卡片；已写说明 → 绿色「**✓ 已说明**」点击滚动并高亮对应卡片 |
| **富文本编辑（单框）** | 正文与要点合并为一个 `contentEditable` 编辑框；工具栏一排 6 个控件：加粗 / 斜体 / 下划线 ｜ 字体颜色（Word 风格 A+色条，点开为固定 7 色色卡：正文黑 / 警示红 / 提醒橙 / 通过绿 / 主题蓝 / 强调紫 / 次要灰，点色块即应用并收起，Esc 或点外部关闭）｜ 项目符号 ｜ 清除格式 |
| **状态标记** | 5 态：设计中 / 已评审 / 待开发 / 开发中 / 已完成；编辑弹窗点选（再点一次取消），卡片与面板头部按状态汇总 |
| **空卡片占位** | 内容全空的卡片显示「＋ 待补充说明 — 点击编辑」，允许先占位、后续由人在弹窗或对话里补写 |
| **收起 / 展开** | 面板可收成 54px 竖向标签（显示卡片数），状态存 `localStorage`，切页保持；收起时连线与徽章自动停用 |
| 新增 / 编辑 / 删除 | 弹窗编辑标题、状态、关联区域、内容；右侧「+ 添加模块」或左侧徽章新建；**删除入口在弹窗左下「删除这张卡片」，弹窗内二次确认**（Esc/点遮罩=取消，确认后才执行） |
| 动态 DOM 自适应 | 面板对左侧容器挂 `MutationObserver`（childList + subtree），弹窗 / 页签 / 步骤条打开后新出现的打标元素自动补连线、补进下拉 |
| 数据落盘（可注入） | 编辑结果通过 `onSave` 写回真源；无适配器时降级为 localStorage 本地草稿 |
| 草稿兜底与容错 | 落盘前先写 localStorage；失败保留草稿并提示「⚠ 落盘失败」，数据不丢 |
| 重置 | 放弃未落盘修改，回退到真源版本 |

## 2. 数据契约

### 2.1 卡片 `ModuleDef`

```ts
export type NoteStatus = 'designing' | 'reviewed' | 'todo' | 'developing' | 'done';

type ModuleDef = {
  id: string;            // 稳定唯一 id；新增卡片形如 custom-<timestamp>
  title: string;         // 卡片标题
  status?: NoteStatus;   // 状态标记；不填 = 未标记（面板不渲染胶囊）
  text?: string;         // 纯文本正文（支持换行）。与 rich 互斥
  list?: string[];       // 要点列表。与 rich 互斥
  rich?: string;         // 富文本正文（受限 HTML）；存在时卡片只渲染它，忽略 text/list
  apiRich?: string;      // 接口说明（受限 HTML 小节）；为空 = 本区块无对接，卡片不出「接口说明」页签
  bind?: string;         // 关联的左侧元素 id（对应 data-proto-id）；为空则视为「未关联」
};
```

**`rich` / `text` + `list` 的格式分流（重要）**

保存时按内容自动分流，保证旧数据回写源码零无意义 diff：

| 编辑内容 | 保存形态 |
| --- | --- |
| 只有纯文本与项目符号（`div` / `br` / `ul` / `li`） | `text` + `list` |
| 含任何格式标签（`b` `strong` `i` `em` `u` `s` `font` `span` `ol` `h1-6` 或 `style=`） | 整体存 `rich`，同时清空 `text` / `list` |

老卡片（只有 `text` / `list`）打开编辑器时自动转为「正文 + 项目符号」视图，未加格式直接保存仍还原为 `text` + `list`。

**`apiRich` 接口说明排版（重要）**

- 受限 HTML 紧凑排版：小节标题 `<b>…</b>` 独占一行（块级），参数 / 字段用 `<ul><li>` 一条一行；**不堆空行、不逐行源码缩进**；
- 顺序固定：基本信息 → 请求 → 请求参数 → 响应字段 → 错误码 → 数据绑定与落库 → 时效与安全 → 报文样例；
- 无接口对接的区块 `apiRich` 留空（不要写「无」占位句），卡片按「只有页面说明」直显；
- 写作要点（页面说明 8 项 + 接口说明 8 项）见 Part C §3 / §4。

### 2.2 宿主侧约定

- **左侧主内容区**内，任意可独立说明的区域打 `data-proto-id="<模块id>"`，并**必填** `data-proto-label="<中文可读名>"`（悬浮徽章与关联下拉都显示它；不写则退化取标题/首段文字，容易读不准）。
- 面板与左侧内容需处于**同一水平可视范围**：连线基于 `getBoundingClientRect` + `position:fixed` 全屏 SVG。
- 窄屏（≤900px）连线自动隐藏。
- **弹窗 / 页签里的区域要打在弹窗内容根元素上**，不要打在 Modal 外壳上——外壳常驻会连到遮罩，内容区才随视图开关。

### 2.3 源码真源约定（落盘到 Axhub 原型源码时）

- 每个原型页面 `src/prototypes/<pageKey>/index.tsx` 内含 `function buildModules(sub)`，返回 `ModuleDef[]`。
- 每个页面 id 一个独立分支：`if (sub === '<pageKey>') { return [ ... ]; }`；下钻页是**独立页面 id**，自然另起一页说明。
- 复合条件分支也支持：`if (sub === 'a' || sub === 'b') { ... }`（适配器按 `sub === '<pageSub>'` 前缀宽松匹配）。

```
    设计说明模块-接入手册.html
```

### 3.2 最简用法（本地草稿模式，不落盘）

```tsx
import { useRef } from 'react';
import { DesignNotesPanel, NOTES_PANEL_WIDTH, type ModuleDef } from './common/DesignNotesPanel';

const leftRef = useRef<HTMLDivElement>(null);
const modules: ModuleDef[] = [
  { id: 'kpi', title: '核心指标', status: 'designing', text: '展示当日关键指标。', list: ['对接 /metrics', '待补单位字段'] },
  { id: 'chart', title: '趋势图', bind: 'trend-chart' },
];

<div style={{ display: 'flex' }}>
  <main ref={leftRef} style={{ flex: 1, minWidth: 0 }}>
    <section data-proto-id="trend-chart" data-proto-label="趋势图">…</section>
  </main>
  <DesignNotesPanel modules={modules} pageKey="dashboard" leftContentRef={leftRef} />
</div>;
```

面板展开态宽 `NOTES_PANEL_WIDTH`（360px），收起态 54px。它用 `position: sticky` 挂在三栏 flex 右侧，**不需要**给主内容预留 padding-right。

### 3.3 落盘用法（注入 onSave 适配器）

```tsx
import { createAxhubDesignNotesAdapter } from './common/axhubSaveAdapter';

const onSave = createAxhubDesignNotesAdapter(); // 默认对接 Axhub 预览服务
// 或自建：const onSave = async (next, meta) => { await myApi.save(meta.pageKey, meta.pageSub, next); };

<DesignNotesPanel
  modules={modules}
  pageKey="indicator"
  pageSub="list"
  leftContentRef={leftRef}
  onSave={onSave}
/>;
```

### 3.4 子页切换 / 可选属性

```tsx
<DesignNotesPanel
  modules={modules}
  pageKey="dashboard"
  pageSub={activeSub}
  leftContentRef={leftRef}
  onSave={onSave}
  contentKey={activeSub}          // 子页或左侧 DOM 重渲染时变化，触发连线与可绑定清单重扫
  title="设计说明"                 // 可选，默认「设计说明」
  hint="自定义顶部提示语"           // 可选，不传则不显示提示行
/>;
```

> 有 `MutationObserver` 兜底后，弹窗 / 页签 / 异步数据引起的 DOM 变化会自动重扫；`contentKey` 主要用于「整块子页切换」这类大范围重渲染。

## 4. Axhub 落盘参考实现

`axhubSaveAdapter.ts` 提供 `createAxhubDesignNotesAdapter()`，依赖 Axhub 预览服务两个接口：

1. **读取源码**：`GET /prototypes/<pageKey>/index.tsx?raw`
2. **文本替换**：`POST /api/text-replace/replace`
   - Body：`{ path: "prototypes/<pageKey>", replacements: [{ searchText, replaceText }] }`
   - 成功返回 `{ success: true }`

内部流程与关键处理：

| 步骤 | 处理要点 |
| --- | --- |
| 取源码 | `?raw` 有两种包裹（JSON 字符串 / 反引号模板），统一剥壳后**按 JS 转义规则单遍还原**（`\r\n` / `\\` / `` \` `` / `\${` / `\uXXXX`） |
| 定位块 | 先定位 `function buildModules` 函数体范围，再按 `sub === '<pageSub>'` 宽松找 `return [`，避免误命中文件其它 `return [` |
| 子页校验 | 传了 `pageSub` 但源码里没有该分支 → **直接报错**，绝不回退到「最后一个 return 块」（否则会把说明写进别的页面） |
| 串页防护 | 带子页时把 `if (sub === ...)` 到块末尾整段作为 `searchText`，避免空数组块 `return [\n\n  ]` 在多页同时命中 |
| 序列化 | 字段顺序固定 `id / title / status / bind / text / rich / apiRich / list`；缩进沿用原 `return [` 行前导空白，减少无意义 diff |
| 回写 | `POST /api/text-replace/replace`，失败抛错 → 面板保留草稿并提示 |

> 其他项目若没有该预览服务，只需实现 `(next, meta) => Promise<void>`：把 `next` 写进自家真源（DB / 文件 / CMS）即可，组件本身零后端依赖。

- [ ] 拷贝 `DesignNotesPanel.tsx` + `designNotesTypes.ts`（最小可运行集，仅依赖 react）。
- [ ] 左侧内容区为可说明区域打 `data-proto-id` + `data-proto-label`（按 Part B §2.2 必标清单）。

- [ ] 子页 / 下钻页：每页在 `buildModules(sub)` 有独立分支，切页传 `contentKey`。

## 6. 已知约束 / 踩坑

- **页签显隐是硬规则**（判定表见 Part C §1.2）：AI 写卡时不要为空区块写「无」占位句——空 `apiRich` 本身就是「无对接」的表达。
- **`?raw` 反转义必须单遍整体还原**：旧实现只把反斜杠减半，换行仍是字面 `\r\n`，`searchText` 与磁盘永不相等 → 落盘 409。这类缺陷只在「源码含 CRLF」的项目暴露，容易被漏测。
- **子页缺失要报错不要兜底**：回退到末尾 return 块会静默写进别的页面，比报错危险。
- **连线基于视口坐标**：`position:fixed` SVG + `getBoundingClientRect`，页面缩放 / 布局异常会漂移；已监听 scroll / resize 与左侧 DOM 变化重绘，窄屏隐藏。
- **`bind` 允许一对多**：同一 `data-proto-id` 可被多张卡片关联（默认卡 + 补充卡），下拉**不过滤**已绑定项，只标「已被第 N 条使用」；编辑时不做静默清空。
- **打标元素必须真实渲染**：条件渲染（弹窗 / 页签 / 步骤）里的区域未打开时扫不到——面板会把「打开过一次」的区域按页记入 localStorage，之后在下拉「本页识别过」组里随时可选（选中后打开对应视图自动连线）；下拉支持搜索，识别不到时可用「＋ 手动填写区域 ID」直接填 `data-proto-id`。关联状态提示是引导，不是故障。
- **删除必须二次确认**：落盘模式下删除会直接改真源。删除入口在编辑弹窗左下「删除这张卡片」，弹窗内二次确认（Esc=取消 / 确认后才执行），取消可回到继续编辑。
- **落盘成功后保留乐观视图**：真源（静态 `buildModules` 等）热更新追平草稿后才收敛回真源视图；若落盘成功立即回退，刚删掉的卡片会「消失又回来」。
- **草稿 key 含内容签名**：`dn-notes-<pageKey>-<pageSub>-<ids>-<内容哈希>`，真源改版后旧草稿自动失效，避免旧文案覆盖新说明。
- **乐观更新 + 草稿兜底**：落盘成功才清本地草稿并回退真源视图；失败保留草稿并提示，不丢数据。
- **z-index**：连线 SVG `9999`（置顶），悬浮徽章 `10000`，编辑弹窗 `1000`；宿主有更高浮层需自行协调。
- **富文本净化**：落盘前去除 `script/style/iframe/object/embed/link/meta` 与 `on*`、`javascript:` 属性，只保留排版能力；卡片用 `dangerouslySetInnerHTML` 渲染，勿绕过 `sanitizeRichHtml`。
- **类名前缀 `dn-`**：与宿主业务类名不冲突；左侧高亮用全局 `[data-proto-id].active-highlight`，不依赖宿主容器类名。
- **卡片容器不要加 `overflow: hidden`**：会裁掉卡片内行内「更多」下拉；需要圆角裁切时只作用于背景层。

# Part B · AI 生成页面：三步法与打标

## 0. AI 生成页面的固定三步（必须按顺序执行）

AI 画原型时，设计说明不是「画完页面再补」，而是**与页面生成同步**的三步：

| 步骤 | 做什么 | 依据 | 产出 |
|---|---|---|---|
| **第 1 步 · 打标** | 生成页面 JSX 时，给每个可独立说明的区块加 `data-proto-id` + `data-proto-label`（弹窗/页签区块打在弹窗内容根元素上） | 本规范 §2 命名规则与必标清单 | 页面源码里所有区块带标 |
| **第 2 步 · 关联卡片** | 在 `index.tsx` 的 `buildModules(sub)` 里为本页建卡片，每张卡 `bind` 指向一个区块 id；来不及写说明的先建**空卡片占位** | 本规范 §3 卡片规范 | 每个打标区块至少一张卡片 |
| **第 3 步 · 写说明** | 按 Part C 为每张卡片编写说明：**页面说明**（用途意图 / 字段口径 / 交互 / 校验 / 状态迁移 / 数据来源 / 边界 / 本期不做 8 项）+ 可选**接口说明**（`apiRich`，紧凑 HTML）；**不是照抄界面文字**；写不完的留空卡，同对话后续补；**内容来源红线与 humanizer-zh 去 AI 味要求见 Part C §8.1** | 设计文档 + 区块源码实现 | 卡片有内容，或明确留待补 |

**给 AI 的提示词模板**（生成新页面时直接附带）：

```
生成 <页面名> 页面，并同步按《规范.md》Part B 三步执行：
1. 按 §2 给页面各区块打 data-proto-id / data-proto-label（前缀用 <页面前缀>-）；
2. 在 buildModules 增加本页分支，为每个打标区块建设计说明卡片（bind 指向区块 id）；
3. 按 <设计文档名/路径> 与《规范.md》Part C 写说明（页面说明 8 项 + 可选接口说明；内容出自 PRD/SRS，红线见 Part C §8.1），写不完的先放空卡片。
完成后按 §5 清单自查并在回复里给出自查结果。
```

**使用者怎么用面板**（给人看的一分钟说明）：

- 鼠标悬浮左侧已打标区域：未写说明显示蓝色「**+ 说明**」点击建卡，已写显示绿色「**✓ 已说明**」点击跳到卡片。
- 卡片上只有「序号 + 标题 + 状态标记 + 说明内容 + ✎ 编辑」；**关联了哪个页面模块、删除操作都在「✎ 编辑」弹窗里**（连线本身就是关联的表达，卡片上不再重复展示）。
- 删除卡片：进「✎ 编辑」弹窗 → 点左下「删除这张卡片」→ 弹窗内二次确认（取消可回到继续编辑，确认后才真删；落盘模式会直接改源码）。
- 卡片可以放空（「＋ 待补充说明」占位），之后点卡片补写，或直接在对话里让 AI 按区域补上。

## 1. 机制总览

原型右侧的「设计说明」面板（DesignNotesPanel）按以下机制工作，规范的所有条款都围绕它：

1. **打标即可识别**：源码里给区块加 `data-proto-id`，面板自动扫到并出现在「关联」下拉里；没打标的区域无法关联。
2. **悬浮即交互**：鼠标悬浮任何已打标区域——未写说明的显示蓝色「**+ 说明**」按钮，点击直接新建该区域的卡片；已写说明的显示绿色「**✓ 已说明**」，点击跳到对应卡片。
3. **卡片可放空**：新增卡片允许内容为空，显示「＋ 待补充说明」占位；后续可在对话里让 AI 按区域补写。
4. **按页独立**：每个页面（含下钻页）在 `buildModules(sub)` 里有独立分支，说明面板随页面切换、下钻页另起一页说明。

## 2. 打标规范（生成页面时同步执行）

### 2.1 命名规则

```
data-proto-id="<页面前缀>-<区块名>"
data-proto-label="<中文可读名>"
```

- `页面前缀`：与页面 id 一致的短前缀，如 `ind-`（指标）、`tlb-`（原始库）、`dsi-`（接口）、`cfg-`（指标配置）。
- 整页标注用 `page-<页面id>`（如 `page-indicator-list`），用于页面级说明卡。
- id 全局唯一、只增不改：改名会导致旧卡片变成「未关联到页面元素」。
- `data-proto-label` 必填，悬浮按钮与关联下拉都显示它。

### 2.2 必标区块清单（列表页模板）

**先判别，再对照清单**：一个区块要不要打标，满足下面任一条即为**必标**——

1. **有自己的数据**：展示一批数据（列表 / 树 / 统计值 / 详情字段）或有数据写入（表单 / 导入）；
2. **有自己的交互**：可点击、可切换、可配置，且行为需要一句话以上才能讲清；
3. **有独立的状态或校验**：启停、发布、显隐联动、必填校验、二次确认等。

反之，**纯装饰与纯排版容器不打标**：分隔线、留白、仅做样式包装的 div、纯静态图标。粒度拿捏：一个区块 = 能独立讲清楚的一组功能，**宁大勿小**——同一操作行里紧密协作的按钮打一个标（如 `ind-list-actions`），不逐按钮拆；但操作行与数据列表职责不同，分两个标。

**纯二次确认弹窗不单独打标**：只有一句确认语 + 确定 / 取消的「提示」弹窗（如「确定删除 XX 吗」），语义写进触发它的那张行操作卡片，不单开卡片，避免十几张“确认框”卡片淹没真正要读的内容。例外是**带后果说明的确认**（如改绑前逐条列出失效影响）——它有独立规则，要打标。

通过判别后，生成一个**列表页**时，以下区块全部打标（以指标列表页 `pages-indicator.tsx` 为基准样例）：

| # | 区块 | 标签示例 | 位置 |
|---|------|---------|------|
| 1 | 左侧目录/分类树 | `ind-list-tree` | 页面左栏根元素 |
| 2 | 筛选条件区 | `ind-list-filter` | FilterBar |
| 3 | 操作按钮区（新增 / 行操作等，批量类按钮以现行页面为准） | `ind-list-actions` | op-bar |
| 4 | 数据列表 | `ind-list-table` | table-wrap |
| 5 | 分页栏 | `ind-list-pager` | Pagination |
| 6 | 新增弹窗·表单 | `ind-add-form` | Modal 内表单根元素 |
| 7 | 修改弹窗·表单 | `ind-edit-form` | Modal 内表单根元素 |
| 8 | 详情弹窗·各页签区块 | `ind-detail-form` / `ind-detail-io` 等 | 每个页签一块 |

配置/下钻页按步骤打标（每步一块，如 `cfg-rules` / `cfg-rule` / `cfg-fields` / `cfg-params`）。

### 2.3 弹窗与页签的打标位置

- 弹窗内容打在 **Modal 内部的表单/区块根元素**上，不打在 Modal 组件本身。弹窗表单多、内容长时，把 `FormGroup` 们包一层 `<div data-proto-id data-proto-label>` 即可，不必逐个字段打标。
- **新增 / 修改共用同一份表单时用同一个 id**（如 `tlb-form`），只在标题与初值上有差别；仅当两者可配字段不同（如改 API 时不能换关联指标）才各给一个 id。
- 页签 / 步骤条里的区块各打各的；面板会在对应视图打开时自动识别连线。区块未打开时连线暂时隐藏（关联状态在卡片的「✎ 编辑」弹窗里有提示），说明内容不受影响。
- **弹窗区域怎么关联**：弹窗内容只在打开时才渲染进 DOM——先打开一次对应弹窗，面板即把该区域按页记入本地（localStorage）；之后在「关联页面模块」下拉的「本页识别过 · 需打开对应弹窗 / 页签才画出连线」组里随时可选，选中后打开对应视图自动连线。「当前视图可见」组则是此刻已渲染、选中即连线。下拉支持按名称 / ID 搜索；仍识别不到时用「＋ 手动填写区域 ID」直接填 `data-proto-id`。

## 3. 卡片规范（buildModules）

### 3.1 按页独立，下钻页另起一页

- 每个页面在 `index.tsx` 的 `buildModules(sub)` 里一个独立 `if (sub === '<页面id>')` 分支；**下钻页（如指标配置）是独立页面 id，自然另起一页说明**，不与来源页混排。
- 保持 `if (sub === '<key>') { return [ ... ]; }` 字面结构——落盘适配器按此整块替换写回。

### 3.2 卡片条目写法

```tsx
// 已写内容的卡片：页面说明 text+list（纯文本/要点）或 rich（富文本 HTML）二选一；
// 有数据读写的区块再加 apiRich（接口说明，紧凑受限 HTML）——两类都有时卡片出「页面说明 / 接口说明 API」双页签
{ id: 'ind-03', title: '指标列表与发布', bind: 'ind-list-table', text: '……', list: ['…', '…'] },
{ id: 'ind-15', title: '图表预览弹窗', bind: 'ind-chart', text: '……', list: ['…'], apiRich: '<div><b>请求</b>…</div>' },
// 空卡片（占位待补）：内容留空即可，面板显示「＋ 待补充说明」
{ id: 'ind-14', title: '新增指标弹窗', bind: 'ind-add-form', text: '', list: [] },
```

- `id`：卡片编号（与区块前缀一致，序号递增），落盘后作为真源主键。
- `title`：默认取区块的 `data-proto-label` 中文名。
- `bind`：指向区块 `data-proto-id`；一个区块可被多张卡关联（连线一对多）。
- 状态标记 `status`（designing/reviewed/todo/developing/done）可选，编辑弹窗里点选。

### 3.3 覆盖要求

**每个打标区块至少有一张卡片**（哪怕放空）。判断方法：页面所有 `data-proto-id` 都应出现在 `buildModules` 某条 `bind` 里，或由用户明确决定某区块不需要说明。

## 4. 后补流程（对话里让 AI 补写）

空卡片放出去之后，同一对话里用户说「把 XX 卡片补上说明」时，AI 按以下流程补写：

1. **定位**：按 `bind` 的 `data-proto-id` 找到源码位置——卡片在 `index.tsx` `buildModules(sub)` 分支里，区块在对应页面文件里。
2. **读实现**：AI 先读该区块的页面源码（交互、字段、校验、联动），再写说明；说明写「设计意图 + 关键规则」，不照抄界面文字。
3. **回写**：把 `text: ''` 换成正文，`list: []` 换成要点；需要格式时用 `rich`（受限 HTML，div/b/font/ul/li）；区块有数据读写时按 Part C §4 补 `apiRich`（紧凑受限 HTML：请求 / 参数 / 响应 / 错误码 / 绑定落库 / 样例）。
4. **格式分流铁律**：页面说明——纯文本+要点 → `text`+`list`，含加粗/颜色等格式 → `rich`，此时不再写 text/list；接口说明一律进 `apiRich`，与页面说明字段互不挤占。
5. **验证**：改完刷新页面，卡片内容与连线正常；说明口径与该页面其它卡片一致（术语、批次号、规则引用等）。

用户在面板里手动编辑并「保存到真源」时，整块替换 `buildModules` 分支——两种补写方式并存兼容，以最近一次写入为准。

# Part C · 卡片编写（一张卡写什么）

## 1. 卡片形态总则

### 1.1 一张卡对应页面上一个打标区块

设计说明卡片**以页面区块（`data-proto-id`）为唯一单位**，不再拆成"区块卡 + 独立接口卡"两套：

- 一张卡片 = 页面上一个可见区块（表单段、按钮组、表格、弹窗、统计卡等）；
- 卡片内部有两个说明区：
  - **页面说明**（主体，必有）：讲页面结构、字段口径、交互、校验、状态、边界；
  - **接口说明**（可选）：本区块涉及的数据读写时，讲请求响应、绑定表、批次规则、错误码、报文样例；
- 同一区块的页面信息与接口契约在同一张卡上对照阅读，开发不需要在两组卡片之间来回拼。

### 1.2 页签显隐规则（与演示原型一致）

| 页面说明 | 接口说明 | 卡片表现 |
|---|---|---|
| 有内容 | 有内容 | 显示「页面说明 / 接口说明 API」页签，默认落在页面说明，可切换 |
| 有内容 | 为空 | **不显示页签**，直接展示页面说明 |
| 为空 | 有内容 | **不显示页签**，直接展示接口说明 |
| 都为空 | 都为空 | 显示「＋ 待补充说明 — 点击编辑」占位条，点进去补写 |

要点：页签只是"两类内容都存在时的切换壳"；只有一类内容时直接展示，不给开发增加一次点击。

### 1.3 为什么不再做"一个接口一张卡"

- 纯前端信息（按钮联动、弹窗校验、空态、开关、筛选行为）若没有独立接口承载，就会无处安放；
- 一个管理页通常对应一套 CRUD（列表 / 保存 / 删除 / 启停），逐接口建卡会碎片化，页面结构反而看不清；
- 接口说明跟随区块卡落位后，接口与它服务的页面字段、按钮、校验就近对照，联调效率更高。

## 3. 页面说明编写要点（必填 8 项）

### 3.1 八项要点

| # | 要点 | 写什么 | 落到 |
|---|---|---|---|
| 1 | **用途意图** | 一句话说清这个区块解决什么业务问题（不是念标题） | `text` |
| 2 | **字段与列口径** | 字段 / 列名、含义、单位与格式、来源、空值显示规则、枚举值含义 | `list` |
| 3 | **操作与交互** | 按钮与行操作清单、点击去向、弹窗 / 抽屉动作、批量操作、开关 / 发布行为 | `list` |
| 4 | **校验规则** | 必填、格式、长度、范围、唯一性、前后端共同校验点、拦截时的大白话提示 | `list` |
| 5 | **状态与可见性（状态迁移）** | 每个状态变化（状态 A → 状态 B）必须写清三点：①**触发条件**——什么操作、什么数据条件下发生；②**触发角色**——谁触发（管理员 / 普通用户 / 系统定时任务 / 外部平台推送等）；③**影响结果**——数据、界面、后续流程各发生什么变化（如按钮置灰、记录归档、停止调度、进入下一步审批）。同时注明各状态下元素可见 / 可点 / 置灰 / 禁用条件 | `list` |
| 6 | **数据来源与提交（业务指向先行）** | 先从业务侧写清"读哪个功能模块 / 哪个页面的数据，写回到哪个模块或哪类业务数据（如设备实时表、告警表、用户台账、配置项）"；原型阶段接口尚未规划时**不要求写 URL、请求方法和报文**，只描述业务流向；待接口确定后，再在本卡「接口说明」补充技术契约 | `text` 或 `list` |
| 7 | **边界与异常** | 空态展示、分页条数、删除保护与二次确认、重复提交防护、无权限 / 无数据兜底、刷新即重置等运行期行为 | `list` |
| 8 | **业务口径与不做边界** | 计算 / 统计口径、术语定义；本期**明确不做**什么及原因，防止过度设计 | `list` |

#### 3.1.1 状态迁移写法（第 5 项展开）

不要只写"状态：草稿 → 已发布"这种箭头结论，每个迁移单独成行，按"条件 / 角色 / 结果"三段写：

```
【状态迁移：待开发 → 开发中】
① 触发条件：开发人员在任务列表点「开始开发」，且卡片评审状态为「已评审」；
② 触发角色：开发人员（本人）；
③ 影响结果：卡片标记为开发中、在统计区计入开发中数量，未完成前不可标「已完成」。
【状态迁移：开发中 → 已完成】
① 触发条件：前后端联调通过并自测无阻断错误；
② 触发角色：开发人员发起、测试 / 产品确认；
③ 影响结果：卡片转为已完成、对应区块纳入验收清单，后续改动需重新进入开发中。
```

#### 3.1.2 数据来源写法（第 6 项展开）

原型阶段先写业务流向，不预设接口：

- ✅ "**读**：原始库管理 · 设备台账列表（设备编号、名称、在线状态）；**写**：专题配置保存后，数据进入原始库表 `t_raw_device_realtime`，供看板在线率统计使用。"
- ❌ "调用 GET /api/device/list，返回 code=0……"（接口未定前不写报文；技术细节留待「接口说明」。）

### 3.2 写法模板


## 4. 接口说明编写要点（可选；有数据读写才填）

### 4.1 八项要点

| # | 要点 | 写什么 |
|---|---|---|
| 1 | **基本信息** | 接口名称、类型（出站服务 / 入站拉取 / 入站推送 / 资源 CRUD / 统计查询 / 登录会话）、触发页面与区块、用途一句话 |
| 2 | **请求定义** | 方法、路径、鉴权方式与凭证来源、必要请求头、分页参数约定 |
| 3 | **请求参数** | 参数名、类型、必填、含义、取值范围 / 枚举、默认值、示例 |
| 4 | **响应定义** | 成功结构（字段 / 类型 / 含义 / 示例）、分页结构、列表字段与列表节点路径（JSON Path） |
| 5 | **错误码** | HTTP 状态 + 业务 code、含义、触发条件、前端处理建议（提示 / 置灰 / 重试） |
| 6 | **数据绑定与落库** | 目标原始库表 / 指标编码；批次号规则（PL 拉取 / PS 推送 / MA 手工批量，手工录入无批次号）；去重键；存储方式（增量更新 / 全量更新 / 临时存储：先清表再存最新一批，用于查询类且更新情况不明的数据） |
| 7 | **时效与可靠性** | 调用时机、取数周期 / 触发方、超时与重试、幂等规则、单次条数上限、失败处理口径 |
| 8 | **安全与样例** | 凭证处理规则（不回显 / 脱敏 / 签名参与方式）、白名单、推送应答约定；请求 / 响应报文样例（示例值、脱敏） |

### 4.2 紧凑排版规则（AI 生成必须遵守）

1. `apiRich` 使用受限 HTML：段落 `<div>`、小节标题 `<b>…</b>`、要点 `<ul><li>`；不堆空行、不逐行源码缩进、不写大段空白。
2. 顺序固定：基本信息 → 请求 → 请求参数 → 响应字段 → 错误码 → 数据绑定与落库 → 时效与安全 → 报文样例。
3. 小节标题独占一行（`<b>` 块级）；参数 / 字段用无序列表逐条列出，一条一行。
4. 表格化信息（参数表、错误码表）在卡片宽度内用列表展开，不依赖外部表格组件。
5. 无接口对接的区块 `apiRich` 留空，不要写"无"占位句；卡片按 §1.2 直接展示页面说明。

### 4.3 写法模板

```tsx
{
  id: 'tcf-03',
```

### 4.4 本系统五类接口的落位方式

| 接口类型 | 在区块卡上的接口说明怎么写 |

| 入站拉取（平台拉取） | 绑定到"接口对接配置 / 数据维护"区块卡；写厂商地址、鉴权、六个取值参数、字段映射（JSON Path → 表列，数组拆多行）、PL 批次、三种存储方式 |
| 入站推送（订阅推送） | 绑定到"主动上报配置"区块卡；写接收地址 / 订阅 ID、信封结构与二次解析节点、UUID 去重、固定应答、PS 批次、重推约定 |
| 管理页 CRUD（用户 / 角色 / 数据源等） | 合并为该管理页区块卡的一条"接口清单"小节：GET 列表 / POST 保存 / DELETE 删除 / PATCH 启停，不逐按钮拆说明 |
| 统计查询（看板 / 监控） | 绑定统计视图区块卡；写统计口径、时间范围参数、返回结构、空数据补 0 规则；演示 mock 注明"演示样例数据，正式版由接口返回" |
| 登录 / 会话 | 一张页面级区块说明集中写登录、锁定、超时、验证码规则 |

## 5. 页面级总览说明

每个页面可在首区块（如页头 `tcf-header`）的页面说明里补一段总览，替代旧版独立"页面卡"：

1. 页面职责（一句话）与面向角色；
2. 进入入口（菜单 / 行操作 / 跳转来源）；
3. 前置条件（先配好哪些基础数据，如先建接口台账再绑表）；
4. 相邻页面关系（可跳到哪些页、哪些页跳回本页）；
5. 本页卡片编号清单，便于开发按图索骥。

## 6. 编辑弹窗与排版规范（交互实现口径）

### 6.1 弹窗结构

- 固定高度弹窗（演示原型 `height: min(720px, 88vh)`），标题栏 / 主体滚动区 / 底部操作栏三段式；
- 主体上方常驻：模块标题、状态标记、关联页面模块（连线目标）；
- 下方说明区用**弹窗内小节页签**切换「页面说明 / 接口说明 API」，与卡片页签交互一致。

### 6.2 两个文本域要求

1. **高度一致且固定**：页面说明、接口说明两个编辑框等高（演示原型 280px），不随内容伸缩；
2. **超出内容滚动**：内容超过文本域高度时由文本域自身纵向滚动条承载，不撑高弹窗；
3. **引导句进占位提示**：写作要点说明（如"写清请求方式 / 路径 / 鉴权、参数与响应字段、绑定表与批次规则、错误码、报文样例；本区块不涉及接口对接时留空"）放在文本域 `data-placeholder`：为空时灰色显示，输入文字后自动隐藏；弹窗 label 只保留短标题「页面说明」「接口说明」；
4. 工具栏分工：页面说明用完整工具栏（加粗 / 斜体 / 下划线 / 颜色 / 列表 / 清除格式）；接口说明用精简工具栏（加粗 / 列表 / 清除格式）。

### 6.3 遮罩与连线

- 编辑弹窗遮罩为轻量半透明、`pointer-events: none`，不拦截下层界面的悬停与点击；连线层始终绘制在最上层；弹窗开关时触发连线重绘，避免弹窗打开后连线"断开 / 消失"的观感。
- 删除确认层叠在弹窗之上，独占 Esc / Enter，不与弹窗事件串扰。

### 6.4 状态字典（沿用组件五态）

| status | 显示 | 含义 |
|---|---|---|
| `designing` | 设计中 | 说明初稿撰写中 |
| `reviewed` | 已评审 | 要点已评审确认 |
| `todo` | 待开发 | 可进入开发排队 |
| `developing` | 开发中 | 开发正在对照实现 |
| `done` | 已完成 | 前后端联调完成 |

未完成的卡片不得标 `done`；状态在弹窗状态选择器中点选切换，再点一次可取消。

### 6.5 保存规则

- 保存时页面说明拆为 `text`（主叙述）+ `list`（要点列表）；接口说明原样存入 `apiRich`；
- 两说明区都为空 → 卡片显示占位条；任一为空 → 卡片按 §1.2 不显示页签；
- 原型演示为运行期 / 本地落盘模拟，正式版由保存接口承接，不把模拟存储当真实后端。

## 7. 与设计文档的分工（不重复抄写）

| 载体 | 讲什么 | 不讲什么 |
|---|---|---|
| 卡片·页面说明 | 页面结构、字段口径、交互、校验、状态、边界、本期不做项 | 不写总体架构、不抄需求条目原文 |
| 卡片·接口说明 | 本区块接口的请求响应、绑定表、批次、错误码、样例 | 不讲页面布局、不做技术选型论证 |
| PRD / SRS | 业务需求条目、功能清单、验收条件、用户故事 | 不细化到字段级报文 |
| HLD | 总体架构、模块划分、数据流主干、安全总体策略 | 不逐接口列字段 |
| LLD | 表结构、SQL / 算法、内部模块接口设计 | 不重复页面交互描述 |

原则：**口径唯一、就近对照**——同一规则在最合适的一处写全，其余处引用名称 / 编号。

## 8. 写作风格与禁忌

1. 卡片给开发看，允许写技术细节（字段名、类型、JSON Path、错误码、表名、批次规则）；面向用户的页面可见层用大白话，技术细节只进卡片；
2. 字段名、表名、指标编码、术语必须与源码、表档案、接口台账完全一致，不自创别名；
3. 不照抄界面按钮文字；不粘贴整段实现代码（代码在源码里，卡片写规则与约定）；
4. 凭证只写处理规则（如"Secret 参与签名、保存后不回显"），不写真值；样例报文用虚构示例值并标注"示例"；
5. "本期不做"显式写出并配一句原因或去向（如：不做定时调度、图表配置不落库、不做文件导出）；
6. 状态、枚举、错误码、批次规则在同一页面各卡之间保持一致，冲突先改卡再写码；
7. 空卡片只允许作为"待补充说明"占位，交付开发前不允许留空；接口说明允许空（无对接区块），按 §1.2 表现。

### 8.1 内容来源红线（AI 编写必守，违反即返工）

设计说明的读者是**对照页面做开发的工程师**，每一条都必须能追溯到该页 PRD / SRS 或其蒸馏产物（`spec.md`、表档案、接口台账、功能清单）的具体条目。以下两类内容**禁止写进卡片**：

1. **会话过程与上下文残留**——本次对话怎么商量的、用户中途改过什么需求、AI 自己补充而未经基线确认的设计。后者要先回写基线文档并经用户确认，才能进设计说明。
2. **经验教训与踩坑叙事**——"曾经抓错表""以前刷新会丢状态，所以……""我们吸取教训不要……"这类开发过程信息。它们属于 `project-memory.md` 过程层（记忆分层规则），不是开发要看的页面规格。

判断标准：把这条内容给一个**没参与过原型对话的开发者**看——若它在回答"这个区块要实现什么、边界在哪、数据从哪来到哪去"，合格；若它在回答"我们当时为什么这样定 / 曾经错过什么"，移到基线或过程层，删出卡片。

**去 AI 味**：成稿后加载 `humanizer-zh` 技能润色措辞，**只调表达、不动内容**——遵守其编辑约束：不新增原文没有的事实/数字/因果，不把"可能"写成"确定"，不因"去痕迹"删掉边界条件、限定词与【本期不做】声明。去味发生在红线之后：先保证每条出自 PRD/SRS，再让文字自然。

## 10. 与 v1.0 双轨版的差异（迁移说明）

| 维度 | v1.0 双轨制（已废止） | v2.0 单卡双页签（现行） |
|---|---|---|
| 卡片单位 | 区块卡 + 独立接口卡两类，分两组展示 | 一个区块一张卡，接口内容并入同卡接口说明 |
