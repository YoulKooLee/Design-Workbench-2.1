## 这份文件是什么
> 本项目专属记忆。**优先级最高**：与工作台通用规则（`06-智能体记忆/rules/`）冲突时，以本文件为准。
> 本文件只放**摘要 + 路径**，不放正文；基线正文永远在三件套（`docs/01-需求与规划/*SRS*.md`、`docs/02-架构与设计/*概要设计*.md` / `*详细设计*.md`）。
> **正文外迁（2026-11-07）**：变更流水正文 → `docs/03-基线变更史.md`；踩坑经验正文 → `docs/04-项目经验库.md`（按模块分组＋状态列）；模块完成快照满 3 份后整体迁 → `docs/05-测试与验收/`。本文件常驻体积目标 ≤8K 字符。
> `project-memory.md`是项目记忆，用于保存上下文窗口外重要事宜，包括不限于项目当前进度、关键决策、协作分工（如 owner_agent 归属）、遗留事项，跨会话延续上下文，避免智能体 "失忆"。
> **读到本行 → 顺手确认一次 `AGENTS.md` 是否还在上下文里**；不在就重读一次；
> **每个模块闭环后立即写快照**——压缩只保留「做了什么动作」，**不保留「看到了什么」**

## 四、模块快照（跨端不失忆的解药；完成归档 → `docs/05-测试与验收/`）

> 模板与字段定义见 `.agents/rules/compaction-recovery.md`「模块完成快照」，每模块 ≤300 字，只写摘要与路径。
> **时机（2026-10-30 定调）**：不等 hook、不等验收——检测到压缩就**立即补**当前模块快照；模块闭环通过时也立即写，不攒到会话末尾。
> 「怎么知道压缩过了」：① 想不起上一轮读过什么文件；② 早前细节只剩「做了什么」没有「看到了什么」；③ 文件内容与记忆不符。任一出现即当作已压缩。
> 没验完也照写，状态写「进行中（完成度 x%）」+ 下一步。

```markdown
## 模块快照：<模块名>（端：web | mobile | both）
- 状态：已完成 / 进行中（完成度 %）
- 职责：一句话
- 对外接口：契约（输入实体 → 处理 → 输出实体），不写实现
- 依赖模块：上游 X（取什么数据）、下游 Y（给什么数据）
- 数据实体：本模块读写的实体名（与数据模型对齐）
- 数据流：闭合 / 待补（缺什么）      ← 待补的模块不得进下一个模块
- 关键决策：≤3 条，只写结论 + 一句理由
- 跨端差异：web 已实现的部分，mobile 需注意什么（组件/交互/字段差异）
- 未完成 TODO：≤3 条
```

> 主规格 `src/prototypes/<slug>/.spec/spec.md` 是本模块方案依据，**不是** PRD / SRS；快照只引路径，不复述正文。
