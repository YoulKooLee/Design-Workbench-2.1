# 上下文装配协议

> 位置：`.agents/rules/context-assembly.md` ｜ 读取层：按需 Read
> 来源：自 `AGENTS.md` v09（2026-09-19）该章节原文外移。**2026-10-30 已改写**：预算表按实测更正（第 0 项 35 KB→9 KB）、「超限必须阻断」改为记账制（与 `_project-development` 同口径），故不再是「原文」。

> 上一节「上下文预算」管**什么不能读**；本节管**每次会话该装什么**。两者互补：先按本节装配，再按上节禁读清单自查（`context-budget.cjs` 命中时会给一句提醒，但**不阻断**）。

### 装配公式（三层）

**【常驻基线】每次会话都在，条目级摘要，禁止全文灌入**

0. **本文件 `AGENTS.md`**（模板级固定开销，所有项目相同；自身只讲执行，解释见 rationale）
1. **需求清单**：feature-list 条目（id + 一句话 + 优先级 + 状态）
2. **数据模型**：实体清单 + 关系（1:N / N:M）+ 关键字段（概念 ER，引用 `.agents/knowledge/phase2-design/hld-spec.md` 数据架构章节）
3. **总体架构**：分层 + 模块清单 + 模块依赖（每模块标注端：web / mobile / both）
4. **业务架构**：核心业务流程 + 角色 + 领域边界
5. **模块间数据流**：接口契约表（源模块 → 目标模块 → 数据实体 → 方向）
6. **已完成模块快照**：模板见 `.agents/rules/compaction-recovery.md`「模块完成快照」，每条 ≤ 300 字

> 第 0 项 = 模板级固定开销，第 1-6 项 = 项目级可变开销，分开设限（第 0 项超 → 瘦身本文件；1-6 超 → 压缩条目粒度）；**不得删第 0 项**。

**【模块滑窗】进入某模块时装配，离开时卸载**

7. **当前模块设计方案**：该模块 HLD 章节 + LLD
8. **该模块组件清单**：由 `.agents/component-manifest.json`（若工程内有） 反查（只取单模块 + 单组件说明，不整库重读）
9. **上下游契约切片**：只取与本模块相关的接口行，不取整表

**【阶段滑窗】第二维：按工作流阶段换切片（需求→设计→开发→测试验收，对应 phase1-4）**

10. **阶段知识**：只读当前阶段 `.agents/knowledge/phaseN-*/` 中本任务所需 1-2 个文件，离开即卸载
11. **阶段接力件 = 基线三件套相应章节**：上一阶段交付物即下一阶段输入契约；跨阶段只靠三件套接力，不重读上一阶段过程讨论（路径见「基线记忆维护」）

单次装配 = 基线（0-6）+ 阶段滑窗（10-11）+ 模块滑窗（7-9）≤ 120 KB；阶段内多模块并行时阶段滑窗只装配一次

**【按需检索】永不常驻**

12. 过程讨论 / 历史会话 / 被否决方案（过程层，见「写入侧三态门禁」）
13. 其他模块 / 其他阶段的设计细节（靠三件套与快照接力）
14. `src/themes/` 全量、组件库全量、`vendor/`（禁整目录 Read，见预算铁律）

### 预算与硬红线

|层|内容|体量上限|token（估，1 token≈2 中文字符）|占 200K 窗口|
|-|-|-|-|-|
|**模板级固定开销**|第 0 项 AGENTS.md|≤ 9 KB（实测 8.6 KB / 4,929 字符；自身声明上限 **≤8,000 字符**，以字符数为准）|≈ 4.5K|2.3%|
|**项目级常驻基线**|第 1-6 项|≤ 40 KB|≈ 20K|10%|
|**模块滑窗**|第 7-9 项|≤ 20 KB|≈ 10K|5%|
|**阶段滑窗**|第 10-11 项|≤ 15 KB|≈ 8K|4%|
|**合计**|常驻 + 双滑窗|≤ 84 KB|**≈ 42.5K**|**≈ 21%**|
|留给生成与对话|||≈ 157K|79%|

> ⚠️ 本表原写「第 0 项 ≤35 KB」，那是**外移前** `AGENTS.md` 含全部章节时的旧值；外移后实测 8.6 KB。2026-10-30 更正——单一真源是 `AGENTS.md` 自身声明的 **≤8,000 字符**，本表只是换算，冲突时以字符数为准。

**红线断言与超限动作：**

|断言|阈值|超限动作|
|-|-|-|
|`AGENTS.md` 体量|≤ 8,000 字符|瘦身本文件 / 外移解释至 rationale|
|项目级常驻基线（1-6 项）|≤ 40 KB|压缩条目粒度（摘要化、去冗余字段）|
|单次装配（基线 + 阶段滑窗 + 模块滑窗）|≤ 120 KB|记账一行后继续，并在当轮**主动卸载**非必要滑窗|

> ⚠️ **「阻断」改为「记账 + 主动卸载」（2026-10-30 定调，与 `_project-development` 同口径）**
>
> 本文件原写「超限**必须阻断**并强制压缩，不允许『继续但注意』」——该表述已撤销，理由有三：
> 1. **无机制可阻断**：`context-budget.cjs` 只返回 `additionalContext` 提醒，不含 deny / exit(2) 出口；宿主不加载 `.agents/hooks/` 时更是不执行。没有任何东西能真的拦住一次读取，「必须阻断」是空文（同类虚假断言已在 `context-budget.md` 与 `AGENTS-rationale.md` 一并更正）。
> 2. **与实测结论相反**：2026-09-22 MarkDesk 实测单阶段实读 302.8 KB、单次装配 172 KB，超 120 KB 红线 43%，归因是门禁要求全章扫描（三件套须整读才能判定合规）——属**必要开销**而非浪费。若按「必须阻断」执行，正常工作流会在第一步就卡死。
> 3. **本文件冻结在旧结论**：文首声明「自 `AGENTS.md` v09（2026-09-19）原文外移，正文未改写」，即定稿于 09-22 实测**之前**，未吸收校准结果。
>
> 现行口径：超限 → 在 `project-memory.md`「运行态留痕」记一行（本次 XX KB + 原因）→ 继续，但当轮主动卸载非必要滑窗。**真正必须阻断的只有第 14 项**（组件库 / `src/themes/` / `vendor/` 整目录递归读），因为那是纯浪费、无任何必要开销可辩护。
>
> 依据与历史事故见 `.agents/rules/AGENTS-rationale.md` §一、§二。

### 组件与生成器边界（引用核对结论，防止双套误读）

* **组件真源**：原型层 React 组件以 `src/component-templates/`（六个分类：业务组件 / 反馈 / 基础 / 布局 / 数据展示 / 表单，各有 `index.html` + `index.tsx`）为准；`03-组件库` 是母版 / catalog（JSON + 提示词），运行时按白名单拷贝、**禁止整目录 Read**。
* **生成器裁决**：`page-generator`（→ `admin/` Vue 开发层，输入须 SRS）与 `vibepm-web/app-generator`（→ 原型层）按「交付层」二选一，不得同时加载两套；选错即浪费整个滑窗预算。
* **跨端装配**：模块有 web/mobile 双端时，切端只装配「该端滑窗 + 对端已完成模块快照」，不重读对端实现（见快照模板「跨端差异」字段）。
