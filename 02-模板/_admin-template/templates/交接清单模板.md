# 研发基线交接清单（模板）

> 用途：原型阶段（`_project-template` 产出）→ 研发阶段（本包）的**接单门禁**。
> 使用方式：新项目接入时，复制本文件到 `{WORKSPACE_PATH}/docs/交接清单.md`，逐项填写；**七项缺一不接单**（见 §八 门禁）。
> 落位说明：研发基线是**项目级数据**，不常驻模板包。本文件只是空白模板。

## 二、七项必备交付物（门禁项）

### 2.1 SRS 定稿 ✅/❌

- 路径：`docs/01-需求与规划/*SRS*.md`

  - [ ] **3.3 页面功能清单**
  - [ ] **3.5 功能详细设计**
  - [ ] **6.1 数据字典**（如有枚举）
- 版本号与定稿状态：{填写}
- 若 SRS 缺失或不达标 → **先跑 `srs-writer` 补齐，不得开工**

### 2.2 功能清单 ✅/❌

- 路径：`docs/01-需求与规划/*功能清单*.md`（或 SRS 3.3 章节）
- 逐条可追溯到 SRS 编号：{是/否}
- 条目数：{填写}

### 2.3 HLD（含功能架构、数据模型、数据流）✅/❌

> 实测约定：**数据模型与数据流不是独立文档，是 HLD 的章节**。

- 路径：`docs/02-架构与设计/*概要设计*.md`
- [ ] 二、应用架构（分层设计、功能模块划分、模块依赖关系）→ **功能架构**
- [ ] 三、数据架构（核心业务实体、实体关系 ER、存储选型）→ **数据模型**

- 若 HLD 缺失 → 跑 `hld-design`；若仅缺第八章 → 单独补数据流闭环

### 2.4 LLD（逐模块实现设计）✅/❌

## 三、文档落位规范（技能扫描路径已写死，必须遵守）

| 文档 | 必须落位 | 消费方 |
|---|---|---|
| SRS | `docs/01-需求与规划/*SRS*.md` | `feature-dev`、`srs-writer`、`delivery-plan` |
| 功能清单 | `docs/01-需求与规划/*功能清单*.md` | `delivery-plan` |
| HLD | `docs/02-架构与设计/*概要设计*.md` | `hld-design`、`page-spec-loader` |
| LLD | `docs/02-架构与设计/*详细设计*.md` | `lld-design`、`feature-dev` |
| 交付计划 | `docs/delivery-plan.md` | `delivery-plan`、批量 `feature-dev` |
| 项目实现规范 | `{PROJECT_PATH}/README-DEV.md` | `page-spec-loader`（**最高优先级**） |
| 本交接清单 | `docs/交接清单.md` | 接单门禁 |

> ⚠️ 路径不合规 = 技能扫不到 = 等于没写。历史项目实测：`指标管理平台`、`结构监测` 把 PRD 直接堆在 `docs/` 根、无 `01-需求与规划/` 子目录，导致技能无法按约定加载。

## 五、验收双门禁（每个页面）

| 门禁 | 对照物 | 检查内容 | 责任角色 |
|---|---|---|---|
| 还原度 | 原型截图 / 预览 | 布局层级、控件类型、状态种类（空/加载/错误/正常）、交互反馈 | `page-reviewer` |
| 需求覆盖 | SRS 条目 | 逐条打勾，**特别检查原型未实现但 SRS 有规定的项**（权限、校验、异常流、边界） | `code-reviewer` |

权限项额外检查：SRS 有权限/角色要求时，页面必须挂 `v-auth` / `v-roles`（原型上看不出来）。

## 八、门禁规则

**七项（§2.1–§2.7）任一为 ❌ 或缺失 → 不接单。**

处置：
1. 明确告知缺哪一项、缺什么内容；
2. 指向补齐路径（`srs-writer` / `hld-design` / `lld-design` / 补截图 / 补否决记录）；
3. 不得以"先开工后补文档"方式绕过——这正是原型阶段失忆与开发期返工的根源；
4. 若用户明确要求跳过某项，须在 §四 待办表登记「已豁免项 + 豁免理由 + 补做期限」。
