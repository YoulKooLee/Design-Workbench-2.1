# 门禁和通行管理设计方案（Access Control / 通行管理）

> 整理日期：2026-09-11
> 用途：软件产品模块设计知识库。覆盖门禁和通行管理的业务需求全景、各场景解决方案、通用设计方案（最优解）与设计说明。
> 一句话本质：门禁和通行管理解决 **"谁、用什么凭证、在什么时间、通过哪个门/通道/闸口、是否放行、如何留痕"**——本质是一套面向实体空间的"认证 + 授权 + 执行 + 记录"系统。

---

## 一、模块概述：通行管理管什么

门禁和通行管理（Access Control System）管理人员/车辆在物理空间中的进出，核心决策链：

```
身份凭证（卡/人脸/二维码/车牌/NFC/密码）
   → 认证（你是谁）→ 鉴权（有无此门/此通道/此时段的权限）
   → 执行（开门/抬杆/亮灯/放行 or 拒绝）→ 记录（通行日志/抓拍/留痕）
```

系统分层（硬件 + 平台）：

| 层 | 组成 | 职责 |
| --- | --- | --- |
| 感知层 | 读卡器、人脸识别终端、车牌识别摄像头、指纹仪、门磁、按钮 | 采集凭证与门状态 |
| 控制层 | 门禁控制器（单门/双门/四门）、梯控控制器、道闸控制器 | 本地权限判定、驱动电锁/道闸/电梯，离线自治 |
| 平台层 | 门禁管理平台（本地/云/SaaS） | 人员/凭证/权限管理、规则配置、通行记录、告警、联动 |
| 应用层 | 管理端、移动端（小程序/App）、访客机、API 开放平台 | 业务操作与对外集成 |

## 二、业务需求全景（场景清单）

### 场景 1：人员通行（员工/常驻人员）
- 多凭证认证：刷卡（IC/ID/CPU 卡）、人脸、二维码、指纹、NFC 手机、蓝牙、密码，及组合认证（刷卡+人脸双重核验）；
- 分级权限：不同角色（员工/管理者/运维）绑不同凭证与门点、时段、次数约束；
- 多门点/多区域：按楼栋、楼层、机房、库房等精细管控；
- 通行模式：单向/双向、进出区分、闸机/门锁/旋转门/摆闸；
- 特殊开门：首卡开门、多重卡开门（逻辑开门：多人同时刷卡才开）、超级卡/超级密码、中心远程开门、按钮开门。

### 场景 2：访客管理
- 预约：员工邀约（员工填访客信息）或访客自主预约（扫码填信息、身份证/事由/时段/区域）；
- 审批：被访人一键同意/驳回；
- 授权：审批通过自动下发临时凭证——临时二维码（动态、限时、限次）、临时人脸权限、临时密码、临时卡；
- 通行：访客到访刷脸/扫码通行，轨迹记录；
- 销权：离场权限自动回收（预约结束时间+30 分钟自动失效）、手动标记离场即时回收、超次/超时自动失效；
- 管控：仅能去授权区域，越权区域门禁上锁并告警；联动监控录像归档至访客档案。

### 场景 3：车辆通行
- 车牌识别：固定车（月卡）绑定车牌，识别即抬杆；临时车按规则放行/收费；
- 预约放行：货车预约月台时段，按预约放行车道与道闸；
- 人车分流：人行通道（人脸/刷卡）+ 车行通道（车牌/道闸）分离，潮汐车道（早高峰只进不出）；
- 车牌防伪与异常车牌处理；
- 车-人-梯联动：车辆入场识别 → 关联车主身份 → 电梯按权限点亮楼层（"车到杆起、人到梯开"）。

### 场景 4：梯控联动
- 呼梯授权：人脸/刷卡/二维码识别后仅可呼梯；
- 楼层权限：按人员权限分配可达楼层（仅至首层/按楼层组）；
- 联动：闸机识别事件下发梯控、电梯预下行等候、保留物理按键紧急旁路；
- 访客梯控：预约通过后电梯权限自动下发，离开自动失效。

### 场景 5：安全与反潜回
- 反潜回（Anti-passback）：刷卡记录一进一出严格对应，未按规定路线进出则下一通道无效，防止权限回传他人；
- 防尾随：通道内人形检测+轨迹跟踪，监测人员数量与行为；关门才能开下一门（双门互锁）；
- 胁迫报警：胁迫卡/胁迫密码触发，表面正常开门、暗地报警联动视频；
- 非法闯入报警（强行开门）、门未关/开门超时报警、黑名单报警、非法卡超次刷卡报警；
- 消防联动：消防信号到达自动打开所有门（逃生），断电保护（断电开锁/断电闭锁按场景配置）；
- 紧急开门：紧急按钮/远程一键开门。

### 场景 6：离线与高可用
- 断网本地权限：控制器离线存储白名单/黑名单，本地判定放行；
- 离线记录补传：恢复联网自动补传通行记录；
- 边缘识别：人脸特征在端侧本地提取比对，毫秒级响应，断网可通行；
- 故障冗余：双 RS485 环路设计、断点检测、防拆/防剪报警。

### 场景 7：多园区 / 多租户 / 分级管理
- 多级权限：超级管理员/园区管理员/部门操作员分级管理；
- 多园区、多建筑统一平台，一卡通/一脸通跨园区；
- SaaS 多租户：物业/园区各自管理自己的门禁数据（与"权限模块"的多租户设计联动）。

### 场景 8：数据与联动（进阶）
- 通行记录：实时查询、报表导出、人员分类统计、抓拍对比存档；
- 联动：视频联动抓拍（开门瞬间抓拍）、短信/微信/语音告警通知、考勤联动（通行即考勤）、对讲联动、照明/空调联动；
- 开放平台：RESTful API/SDK 对外集成（物业 ERP、停车系统、HR 系统）。

## 三、各场景的解决方案

### 3.1 人员通行：认证方式对比与选型

| 方式 | 识别模式 | 优点 | 缺点/注意 | 适用 |
| --- | --- | --- | --- | --- |
| IC/ID 卡 | 卡号匹配 | 成本低、稳定、快 | 可复制、易忘带 | 员工、会员 |
| CPU 卡 | 加密认证 | 防复制 | 成本较高 | 高安全门点 |
| 人脸识别 | 1:N 底库比对 | 无感通行、防代刷 | 需活体检测、光照/角度要求 | 楼宇、园区、学校 |
| 二维码 | 动态令牌 | 下发快、限时限次 | 依赖手机与网络 | 访客、临时 |
| 指纹 | 1:1/1:N | 唯一性强 | 环境要求高 | 机房、库房 |
| NFC 手机/蓝牙 | 近场 | 随身 | 需手机 | 员工 |
| 密码/动态密码 | 键盘 | 简单 | 安全性低 | 应急、门点 |

**认证组合**：刷卡+人脸双重核验（先核对卡信息，再做 1:1 人脸比对）、多因子认证用于高安全门点。

**人脸识别通行流程（1:N）**：
```
人员靠近 → 人脸检测（多脸/干扰过滤）→ 关键点定位 → 特征提取 → 1:N 底库比对
   → 命中后联动权限系统判断"该人有无此区域权限"
   → 有权限：开门指令/闸机开；无权限：提示"权限不足"并记录
```
**活体检测（防伪，必须）**：双因子活体（眨眼+点头动态行为、皮肤纹理分析、双目红外 RGB+IR），防照片/视频/3D 面具攻击。

### 3.2 访客管理：全流程闭环
```
邀约/自主预约 → 审批（被访人同意/驳回）→ 授权（临时凭证自动下发）
   → 到访（刷脸/扫码/人证核验）→ 通行轨迹记录 → 离场（权限自动/手动回收）
```
- 凭证安全：动态二维码（限时 1~24h、限定次数、防截图转发）、临时人脸权限（下发至门禁终端）、临时密码（长效/临时/脱机）；
- 越权防护：仅授权区域可通行，越权门禁上锁 + 安保终端告警；
- 记录归档：通行时间+点位形成轨迹；访客时段监控录像一键链至访客档案；
- 联动：会议场景结束 30 分钟后权限自动失效、设备联动恢复。

### 3.3 车辆通行
- 固定车：车牌绑定权限，识别即抬杆，显示屏/语音播报车牌；
- 临时车：入场抬杆，出场按停车时长收费（收费规则可设置）；
- 预约车：货车/访客车预约时段+车道，到场自动核验放行；
- 异常处理：车牌防伪、异常车牌告警、无牌车人工核验；
- 人车梯联动：车牌→车主身份→楼层权限（见场景 4）。

### 3.4 安全与反潜回实现要点
- 反潜回：控制器维护"在场状态"，进出记录严格一一对应；脱机防潜回与联网防潜回双支持；
- 防尾随：深度学习人形检测+轨迹跟踪，闸机通道内实时监测人数与行为；双门互锁（一门未关另一门不可开）；
- 胁迫：胁迫卡/胁迫密码触发正常开门 + 静默报警联动视频；
- 消防联动：消防信号 → 继电器动作打开所有门/启动警笛 + 软件记录；可配置常开/常闭；断电保护按场景配置（如监狱断电闭锁、商场断电开锁）。

### 3.5 离线与高可用
- 权限下发：批量下传 + 增量下传，控制器本地存储（如 2 万条权限）；
- 白名单/黑名单本地生效；脱机密码、临时密码本地可用；
- 记录补传：联网后自动补传离线期间的通行/告警记录；
- 边缘识别：端侧完成特征提取比对（毫秒级），网络中断不影响通行。

### 3.6 平台能力
- 组织/人员/凭证/门点管理，权限分组与下发；
- 通行记录检索与报表（分类查询、导出）；
- 告警中心（非法闯入、胁迫、门未关、防拆、黑名单、超时）+ 多通道通知；
- 开放 API/SDK：预约免登记、访客预约记录、修改/取消预约、通行事件订阅等。

## 四、通用设计方案（最优解）

### 4.1 总体架构（端-边-云）

```
应用层：管理端（Web）/ 移动端（小程序、App）/ 访客机 / 第三方系统（API）
   │
平台层：门禁管理平台（云/SaaS 或本地）
   │  人员·凭证·权限管理 | 通行规则 | 记录与报表 | 告警联动 | 开放API
   │  策略下发（批量/增量） | 事件汇聚 | 离线补传
   │
控制层：门禁控制器 / 梯控控制器 / 道闸控制器（本地判定、离线自治）
   │  本地协议：韦根 Wiegand / RS485 / 开关量
   │
感知层：读卡器 / 人脸终端 / 车牌识别 / 指纹仪 / 门磁 / 按钮 / 道闸 / 电锁
```

- **纵向端-边-云协同**：终端 4G/WiFi 连云端同步策略与上报数据；本地协议联动梯控、道闸；边缘本地完成识别与判定，断网可通行，恢复后补传；
- **横向 API 开放**：云端提供 RESTful API 与多语言 SDK，供物业 ERP、停车、HR 等系统集成。

### 4.2 通行权限模型（核心）

```
人员（Person）── 凭证（Credential：卡/人脸/车牌/二维码…）
   └── 权限组/角色 ── 门点/区域（Door/Area）── 时段（Time Window）── 次数（Count）
        └── 有效起止日期 ── 状态（正常/挂失/过期/黑名单）
```
- **授权维度**：谁 × 什么凭证 × 哪个门/区域 × 什么时段 × 几次 × 何时生效；
- **动态授权**：会员期/月卡/季卡同步权限，过期自动收回；访客临时权限到期/超次自动失效；
- **分级管理**：多级操作员权限（超管/园区/部门）；
- **黑白名单**：黑名单本地生效，非法卡/超次刷卡触发告警。

### 4.3 通行决策流程
```
凭证采集（刷卡/人脸/车牌…）
  → 认证：凭证是否有效（挂失？过期？黑名单？）＋ 生物特征比对（若需）
  → 鉴权：查（人员, 门点, 时段, 次数）规则
  → 决策：放行（开门/抬杆/呼梯）或拒绝（提示原因）
  → 记录：通行记录 + 抓拍 + 状态更新（在场状态、剩余次数）
  → 联动：视频抓拍、考勤、通知、梯控等
```

### 4.4 数据模型（核心表结构）

```
organization（组织/园区）─ department（部门）
person（人员）── person_credential（人员凭证）
  ├── access_group（权限组）── access_rule（通行规则：门点+时段+次数+有效期）
  ├── visitor（访客预约）── visitor_credential（临时凭证）
  └── vehicle（车辆/车牌绑定）
door（门点/通道）── controller（控制器）── area（区域）
access_record（通行记录）│ alarm_record（告警记录）│ device_status（设备状态）
```

| 表 | 关键字段 | 设计要点 |
| --- | --- | --- |
| `person` | name, org_id, dept_id, status | 人员主数据 |
| `person_credential` | person_id, type（卡/人脸/车牌/二维码）, value, status（正常/挂失/过期/黑名单） | 一人多凭证 |
| `access_rule` | person_id / group_id, door_id/area_id, time_window, max_count, valid_from/to | 授权矩阵核心 |
| `door` / `area` | controller_id, name, type（单双向/互锁）, 联动配置 | 门点与区域 |
| `visitor` | 预约人/被访人, 时段, 区域范围, 状态（待审/通过/在场/离场）, 审批记录 | 访客全流程 |
| `access_record` | person/visitor, door, time, result（放行/拒绝+原因）, 抓拍 URL, direction | 通行审计 |
| `alarm_record` | type（非法闯入/胁迫/门未关/防拆/黑名单/消防）, time, door, 处理状态 | 告警闭环 |

### 4.5 离线与可靠性设计
1. 控制器本地权限库（白名单/黑名单/临时密码），断网自治；
2. 记录本地缓存，联网增量补传；
3. 批量+增量下发策略，支持大容量权限（万级）；
4. 双 RS485 环路冗余、防拆防剪、断电策略按场景（开锁/闭锁）配置。

### 4.6 访客与车辆联动落地
- 访客：预约 → 审批 → 凭证下发（人脸下发至终端/动态二维码/临时密码）→ 限区域通行 + 轨迹 → 自动销权；
- 车辆：车牌绑定（固定车）/ 预约（访客车、货车）→ 识别抬杆 → 人车梯联动（车牌→身份→楼层）；
- 联动：越权告警、监控归档、会议联动（结束自动回收权限）、考勤联动。

## 五、设计说明

### 5.1 核心设计原则
| 原则 | 说明 |
| --- | --- |
| **安全与便捷平衡** | 低安全区（大门）无感通行；高安全区（机房/金库）多因子+反潜回 |
| **本地自治优先** | 控制层离线可用，平台故障不影响通行与安全 |
| **权限最小化** | 默认拒绝，仅授"门点×时段×次数"所需最小权限，临时权限自动失效 |
| **全量留痕可审计** | 通行记录、抓拍、告警、审批全程留痕，可追溯 |
| **端-边-云分层** | 边缘快判定、云端做管理，避免单点依赖网络 |
| **开放集成** | API/SDK 打通考勤、停车、ERP、HR，避免数据孤岛 |

### 5.2 常见设计坑与规避
| 坑 | 后果 | 规避 |
| --- | --- | --- |
| 只做前端认证、后端无权限校验 | 凭证被复制/冒用 | 平台统一权限判定 + 黑白名单 + 状态实时同步 |
| 离线期间权限无法生效 | 断网即瘫痪 | 控制器本地权限库 + 增量下发 |
| 尾随/借卡无人管 | 安防形同虚设 | 反潜回 + 防尾随 + 双门互锁 |
| 人脸识别无活体检测 | 照片/视频即可开门 | 双因子活体检测 + 双目红外 |
| 临时权限不回收 | 访客长期滞留/冒用 | 到期/超次自动失效 + 手动离场回收 |
| 消防联动缺失 | 火灾无法逃生 | 消防信号强制全开 + 断电策略 + 联动测试 |
| 通行记录不同步 | 审计无据 | 离线缓存 + 联网补传 + 记录与抓拍归档 |
| 胁迫报警被察觉 | 人身安全风险 | 胁迫卡/密码表面正常、静默报警 |

### 5.3 演进路线
```
阶段1 单点门禁：刷卡/密码，控制器本地管理
   ↓ 联网集中管理
阶段2 一卡通/平台化：集中授权、通行记录、告警、多门点统一管理
   ↓ 多凭证多场景
阶段3 一脸通/多模态：人脸+NFC+二维码+车牌，访客全流程、梯控/停车联动
   ↓ 云化与生态
阶段4 云平台 + SaaS 多租户：端-边-云架构、开放 API、AI 识别（防尾随/行为分析）
```

### 5.4 业界参考实现
- **海康威视 / 大华**：门禁控制器 + 综合管理平台（一脸通、反潜回、联动）；
- **HID / 泰科 C·CURE / LenelS2**：企业级门禁平台（区域反潜回、多级权限、审计）；
- **AWS/华为云/阿里云 IoT**：设备影子、规则引擎支撑门禁设备云化；
- **中优云联 / 魔点 / 钉钉门禁**：云门禁 + 小程序访客 + 人车梯联动；
- **Prometheus Alertmanager 思路**：告警分组/抑制可借鉴到门禁告警收敛。
