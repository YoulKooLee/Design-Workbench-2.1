# 工单管理设计方案（服务/运维闭环）

> 整理日期：2026-10-13
> 用途：软件产品模块设计知识库。覆盖工单管理模块的业务场景全景、各场景解决方案、通用设计方案（最优解）与设计说明。
> 一句话本质：把"问题→处理→解决→评价"固化成可跟踪、有时效、有责任链的工单流转闭环——回答"工单怎么来（报修/巡检/告警自动生成）、怎么分（派单/抢单/转派）、怎么催（SLA 计时/升级）、怎么结（验收/评价/归档）"四个问题。IoT 场景下与设备管理、触发器（告警）、运维管理强联动。

---

## 一、模块概述：工单引擎四段闭环

```
创建（来源：手动报修/扫码/巡检异常/设备告警自动生成）
   ↓
路由分配（规则引擎自动派单 / 工单池抢单 / 人工派单 / 转派退回）
   ↓
执行与时效（状态流转 + SLA 双计时器：首响 SLA、解决 SLA）
   ↓
验收归档（待验收 → 验收通过关闭 / 不通过退回；满意度评价 → 报表/知识库）
```

| 核心概念 | 说明 |
| --- | --- |
| 工单类型 | 维修工单（CM 纠正性）/ 保养工单（PM 预防性）/ 巡检工单（合规检查） |
| 工单状态机 | 待派单→待接单→处理中→待验收→已完成→已取消（含拒绝/退回/转派/挂起分支） |
| 派单规则 | 技能匹配 + 负载均衡 + 轮询；抢单池兜底；超时未接自动回收 |
| SLA 时效 | 首响时限 + 解决时限双计时；多级预警：80% 提醒 → 超时升级主管 → 超时升级总监 |
| 验收闭环 | 验收通过关闭 / 不通过退回；满意度评分；故障原因分类沉淀知识库 |

## 二、业务场景全景

### 场景 1：设备报修（纠正性维护 CM）
- 扫码报修、手动报修、APP 报修、客服代报；
- 设备故障 → 维修工单：报修时间/报修人/设备信息/故障现象/是否停机。

### 场景 2：巡检工单（合规/状态检查）
- 周期性巡检计划自动生成巡检任务并派发；
- 巡检发现隐患 → 一键生成整改工单（巡检-上报-派单-整改-复检闭环）。

### 场景 3：保养/预防性维护工单（PM）
- 按时间周期或累计使用量触发保养计划；
- 保养到期自动生成保养工单，防止漏保。

### 场景 4：告警自动生成工单（IoT 联动）
- 设备遥测超阈值（触发器/规则引擎）→ 自动建单；
- 工单携带故障代码、实时数据快照、知识库推荐故障原因。

### 场景 5：工单分配（派单/抢单/转派）
- 自动派单（按业务类型分流、按技能匹配、按负载均衡）；
- 工单池抢单（谁有空谁抢）+ 超时未接自动回收；
- 转派/退回，责任链完整记录每一手处理人。

### 场景 6：SLA 时效管控
- 首响时限（多久有人接单/响应）、解决时限（多久处理完）；
- 多级预警与自动升级：剩余 30% 时限推送 → 超时 10 分钟通知主管 → 超时 1 小时升级总监。

### 场景 7：验收与评价闭环
- 完工提交维修报告 → 待验收 → 报修人确认；
- 验收通过关闭 / 不通过退回继续处理；满意度评分作为服务量化依据。

### 场景 8：工单看板与统计分析
- 按状态/类型/处理人/超时多维看板；
- 工作量统计、超时分析、重复故障分析 → 流程优化与人员绩效。

## 三、各场景的解决方案

### 3.1 工单分类（三级可配置）
```
一级业务域：售前咨询 / 售后处理 / 外部投诉 / 设备报修 / 运维巡检 / 保养
二级类型：设备报修-维修 / 设备报修-换件 / 巡检-隐患整改 …
三级子类：按产品或问题细化
原则：分类绑定模板与派单规则——选"设备报修"模板即自动绑定维修组
```

### 3.2 工单状态机（六态 + 异常分支）
```
待派单 → 待接单 → 处理中 → 待验收 → 已完成
                ↑        │
                └──退回─┘（验收不通过）
异常分支：拒绝（→待派单重新分配）· 转派（记录责任链）· 挂起（SLA 暂停计时，等备件/客户反馈）· 取消
每个状态变更强制填写处理进展（可审计）
```

### 3.3 派单规则引擎（四类派单）
| 规则 | 说明 | 兜底 |
| --- | --- | --- |
| 按业务类型分流 | 设备故障→维修组、投诉→客服主管、退款→财务 | — |
| 技能匹配 | 工单分类 ↔ 处理人技能标签过滤 | 无匹配→人工 |
| 负载均衡 | 合格处理人中选未处理工单最少者 | 同负载→轮询 |
| 抢单池 | 低优先级/归属难定的单进池，谁有空谁抢 | 超时未接自动回收；连续拒接 N 次降权 |

### 3.4 SLA 计时与升级（双计时器 + 多级预警）
```
SLA 配置维度：按客户层级（Free/Pro/Enterprise）× 优先级（P0/P1/P2）
双计时器：首响 SLA（接单）+ 解决 SLA（处理完/有进展更新）
挂起（pending）暂停计时，恢复后继续
升级链路：
  剩余 30% 时限 → 处理人 APP 推送
  超时 10 分钟  → 部门主管短信通知
  超时 1 小时   → 服务总监 + 客户道歉模板
  自动标记重复超时的工单类型 → 供流程优化分析
```

### 3.5 告警自动建单（IoT 联动）
```
设备遥测超阈值 → 触发器（规则引擎）→ 自动创建维修工单
工单内容：设备信息 + 故障代码 + 实时数据快照 + 知识库推荐原因（如振动超标→轴承磨损/转子不平衡）
自动通知：设备负责人/维修组；现场大屏/公共账号推送异常
```

### 3.6 验收与评价
```
维修完成 → 工程师提交维修报告（处理措施/更换部件/修复时间/故障原因分类/是否重复故障/改善建议）
   → 工单状态"待验收"
验收通过 → 关闭工单 + 满意度评分
验收不通过 → 退回，维修人员继续处理（可转专项分析）
```

### 3.7 工单字段最小集（IoT 设备维修单）
```
报修时间 · 报修人 · 设备信息 · 故障现象 · 是否停机 · 维修接单人 · 到场时间
处理措施 · 更换部件 · 修复时间 · 验收人 · 故障原因分类 · 是否重复故障 · 后续改善建议
每张工单自带时间线和现场照片（时间水印），事后查责复盘有依据
```

## 四、通用设计方案（最优解）

### 4.1 工单引擎架构
```
接入层：报修表单（扫码/APP/客服）· 巡检计划 · 设备告警（触发器）· 邮件/工单导入
   ↓
工单核心服务：
  工单服务（创建/状态机迁移/事件流）
  路由分配服务（规则引擎：分流/技能/负载/抢单池）
  SLA 服务（双计时器/多级预警/自动升级）
  通知服务（APP/短信/企微钉钉）
   │
数据层：工单主表 + 流转记录（全事件留痕）+ SLA 配置 + 派单规则 + 附件
   ↓
应用层：工单看板 · 工作量统计 · 超时分析 · 知识库沉淀 · 满意度
```

### 4.2 核心表结构
```sql
work_order（工单主表）：
  id, order_no（业务单号）, category_path（三级分类路径）,
  title, source（MANUAL/SCAN/INSPECT/ALARM/SCHEDULE）,
  priority（P0/P1/P2）, status（六态 + 异常态）,
  device_id（IoT 关联设备）, fault_code, snapshot（实时数据快照 JSON）,
  reporter, assignee, group_id, current_handler,
  first_response_at, resolve_at, close_at,
  satisfaction, create_time

work_order_flow（流转记录，全事件留痕）：
  id, order_id, from_status, to_status,
  action（ACCEPT/REJECT/TRANSFER/PAUSE/RESUME/CLOSE…）,
  operator, comment（处理进展，强制填写）, create_time

sla_config（SLA 配置）：
  id, category_path, priority, customer_tier,
  first_response_timeout, resolve_timeout,
  warn_ratio（如 0.8）, escalate_level1, escalate_level2

dispatch_rule（派单规则）：
  id, name, category_path, strategy（TYPE/SKILL/LOAD/POOL）,
  target_group, enabled, priority

work_order_attachment（附件/照片）：
  id, order_id, file_url, type（PHOTO/REPORT/VIDEO）, watermark_time
```

### 4.3 关键设计点
- **状态机事件化**：每次迁移落 flow 记录 + 触发通知/规则，全流程可审计；
- **规则引擎驱动派单**：派单规则可配置而非硬编码，分类绑定模板自动分流；
- **SLA 独立计时**：双计时器 + 挂起暂停 + 多级升级，防工单卡死；
- **告警自动建单**：与触发器联动，工单带故障上下文（代码/快照/推荐原因）；
- **验收强制闭环**：不验收不关闭，满意度量化服务质量；
- **责任链完整**：转派/退回记录每一手处理人；
- **防挑单**：抢单池只对简单单开放 + 连续拒接降权。

## 五、设计说明

### 5.1 核心设计原则
| 原则 | 说明 |
| --- | --- |
| 一单一号 | 工单号全局唯一，全流程可追踪可溯源 |
| 状态机闭环 | 六态 + 异常分支，每次变更留痕 |
| 规则可配置 | 分类/派单/SLA 均可配置，不写死业务 |
| SLA 前置 | 时效风险前置化、管控刚性化 |
| 自动化为先 | 告警自动建单、到期自动生成、超时自动升级 |
| 验收必闭环 | 验收 + 满意度，服务质量可量化 |
| 数据沉淀 | 故障原因/重复故障 → 知识库与流程优化 |

### 5.2 常见设计坑与规避
| 坑 | 后果 | 规避 |
| --- | --- | --- |
| 状态机缺异常分支 | 拒单/转派/挂起无处安放，流程卡死 | 设计拒绝/退回/转派/挂起 |
| 派单硬编码 | 换人/改组要改代码 | 规则引擎可配置 |
| 无 SLA 计时 | 工单滞留无人跟进 | 双计时器 + 多级升级 |
| 挂起不停表 | 等备件期算超时误报 | pending 暂停计时 |
| 无验收环节 | 修没修好无确认 | 验收通过才关闭 |
| 不记录责任链 | 转派后追责无据 | flow 表全事件留痕 |
| 抢单池无约束 | 挑肥拣瘦、简单单没人做 | 仅开放简单单 + 拒接降权 |
| 告警建单无上下文 | 维修人员到场不知情况 | 带故障代码+数据快照+推荐原因 |
| 无满意度评价 | 服务质量无法量化 | 验收时评分 |
| 无重复故障分析 | 同一故障反复修 | 标记重复故障 + 专项分析 |

### 5.3 演进路线
```
阶段1 报修登记：表单 + 状态记录（Excel/简表）
   ↓
阶段2 流程化：状态机 + 派单 + 时间线 + 附件
   ↓
阶段3 时效化：SLA 双计时 + 多级升级 + 看板报表
   ↓
阶段4 智能化：告警自动建单 + 知识库推荐原因 + 预测性维护（与设备/触发器/运维联动）
```

### 5.4 业界参考实现
- **Zendesk / 客服工单体系**：四级优先级、四态流转、SLA 按层级×优先级配置；
- **黑湖小工单**：设备在线报修流程拆解、验收与满意度；
- **简道云**：维修工单最少字段清单、"待受理→处理中→待验收→已完成→转专项分析"；
- **达实智能（智慧园区）**：扫码报修、巡维保任务、人工/自动派单智能切换；
- **易点易动**：监控数据自动触发维修/保养/巡检工单、抢单 + 无人抢超时通知；
- **EMCP 物联网云平台**：设备台账、报修、工单管理、巡检计划、角色权限；
- **纷享销客 CRM**：7 标准状态节点 + 客户确认 + 满意度闭环。
