# 设备管理设计方案（物联网 IoT 平台）

> 整理日期：2026-10-10
> 用途：软件产品模块设计知识库。覆盖物联网平台设备管理模块的业务场景全景、各场景解决方案、通用设计方案（最优解）与设计说明。
> 一句话本质：给每台设备"上户口、建模、管生命周期、下发控制、持续运维"——回答"设备怎么进来（注册认证）、云端怎么描述它（物模型/设备影子）、怎么管它（分组/生命周期/OTA）、怎么用数据（采集/命令）"四个问题。与触发器（规则引擎）、运维管理、智控场景、工单管理联动形成 IoT 平台核心闭环。

---

## 一、模块概述：设备层 → 接入层 → 平台层

```
设备端（传感器/网关/终端，MQTT/CoAP/HTTP/私有协议）
   │ 接入层（协议适配 + 身份验证：一机一密/一型一密/证书）
   ▼
平台层（设备管理的"管控大脑"）：
  产品管理（物模型：属性/服务/事件）
  设备管理（注册/激活/在线状态/生命周期/分组/标签/拓扑）
  设备影子（desired/reported 双向状态同步）
  命令下发（远程控制/配置/OTA）
  数据采集（遥测上报/离线缓存补传）
   │
   ▼
行业应用（智慧园区/工业/水务…）：运维管理 · 智控场景 · 工单管理 · 报表告警
```

| 核心概念 | 说明 |
| --- | --- |
| 设备注册 | 给设备分配身份（DeviceID/密钥/证书），云端认识它 |
| 物模型 | 属性（Property）/服务（Service）/事件（Event）三要素，统一描述设备能力 |
| 设备影子 | JSON 文档存"期望状态 desired + 上报状态 reported"，离线可同步、命令可缓存 |
| 生命周期 | 注册 → 激活 → 在线/离线 → 退役/删除，全流程可追踪 |

## 二、业务场景全景

### 场景 1：设备接入与注册（上户口）
- 单台录入、批量注册、免注册极简接入；
- 解决"云端怎么知道这台机器是你生产的、不是伪造的"。

### 场景 2：设备建模（物模型）
- 同类设备（水表/门禁/温湿度计）批量纳管；
- 统一属性、服务、事件，让分析、规则引擎、报表对不同设备类型一致工作。

### 场景 3：设备在线状态与离线管理
- 心跳/断线检测、离线提醒；
- **离线期间**：状态同步靠设备影子，数据靠本地缓存补传。

### 场景 4：远程控制与配置下发
- 远程开闸/关阀/重启/校准/参数设置；
- 离线命令缓存、重试、超时、重复过滤（防重复充值/重复执行）。

### 场景 5：设备分组、标签与拓扑
- 按区域/类型/项目分组，批量升级/配置/操作；
- 标签灵活打标；网关-子设备父子拓扑管理。

### 场景 6：OTA 固件升级
- 远程推送固件，分阶段灰度（先 1% 试运行再放量）；
- A/B 双分区、校验、失败回滚。

### 场景 7：设备运维与健康监测
- 电池电量/信号强度/设备健康监控、预测性维护；
- 设备故障 → 触发告警 → 生成工单（联动运维管理/工单管理）。

### 场景 8：设备退役与安全处置
- 设备报废/更换：解绑账号、吊销凭证、擦除数据、关闭资产记录；
- 防止"无人监管的遗留设备"成为安全漏洞。

### 场景 9：数据采集与补传
- 周期遥测上报（用量/状态/信号）；
- 断网期间数据环形缓存，恢复后按时间顺序批量补传。

## 三、各场景的解决方案

### 3.1 设备注册与认证（三种"上户口"方式）
| 方案 | 适用 | 说明 |
| --- | --- | --- |
| **一机一密** | 安全要求高 | 每台设备独立 DeviceSecret，平台签发；密钥泄漏只影响单台 |
| **一型一密** | 批量大规模 | 同型号共用密钥，设备用产品密钥+设备标识动态获取凭证；省成本、需防密钥扩散 |
| **证书认证（PKI）** | 强安全/工业 | 每设备签发 X.509 证书，根证书链校验；支持吊销、短生命周期凭证轮换 |
| **免注册接入（注册组）** | 量产极简 | 证书策略+注册组，设备首次上线自动注册，免人工录入 |

### 3.2 物模型（统一建模三要素）
```
属性 Property：设备状态/测量值（温度、电量、开关）——可读可设，支持上报
服务 Service：可调用的设备能力（开闸、重启、校准）——带入参/出参
事件 Event：设备主动上报的告警/异常（超限、故障、离线）——带事件类型
```
- 同类设备共用同一"产品"物模型，平台只需为产品定义一次；
- 物模型是规则引擎、报表、智控场景的统一数据口径。

### 3.3 设备影子（离线/异步的关键）
```
每个设备有且只有一个影子（JSON）：
  reported 区：设备最近一次上报的状态（云端权威缓存）
  desired  区：应用期望下发的配置（命令先写这，设备上线后拉取执行）
同步方式：
  设备在线：应用改 desired → 影子 → 实时推送给设备
  设备离线：应用改 desired → 影子缓存 → 设备上线后拉取对齐（reconcile）
好处：应用不阻塞等待设备、拿到"最后已知状态"、支持断网重连状态对齐
```

### 3.4 生命周期管理（全流程状态机）
```
已注册（未激活）→ 激活（首次上线）→ 在线 ⇄ 离线 → 已停用 → 已注销/已删除
退役处置：解绑账号 · 吊销/轮换凭证 · 擦除本地数据 · 关闭资产记录（防遗留设备漏洞）
```

### 3.5 命令下发（远程控制）
```
应用 → 平台：下发命令（含 requestId 唯一标识）
平台 → 设备：设备在线实时下发；离线则入命令队列/写影子 desired
超时重试：按次数+间隔重试；失败回执给应用
防重复：通过序列号/requestId 过滤网络重发的指令（如防重复充值）
```

### 3.6 分组/标签/拓扑
```
群组：一系列设备的集合（按区域/类型/项目），用于批量升级/配置/操作
标签：灵活 key-value 打标，跨维度检索
拓扑：网关（父）— 子设备（子）关系，管理网关下挂设备
```

### 3.7 OTA 固件升级（安全灰度）
```
1. 固件上传对象存储（签名校验）
2. 按目标推送：按设备类型 / 固件版本 / 设备组圈定范围
3. 灰度：先 1% 设备（canary）→ 监控错误率 → 逐步放量
4. A/B 双分区：新固件写备用分区，失败自动回滚旧分区
5. 设备回报状态：下载成功/校验通过/安装完成/失败原因
```

### 3.8 数据采集与离线补传
```
在线：按物模型周期上报遥测 → 平台异步入流（Kafka）→ 冷热分离存储
离线：断网数据写 MCU Flash 环形缓存 → 恢复后按 original timestamp 批量补传
       → 补传完成清缓存（避免乱序/重复）
```

## 四、通用设计方案（最优解）

### 4.1 总体架构（百万级扩展）
```
设备端 SDK（MQTT 长连接 + TLS + 心跳 + 离线缓存）
   │
接入层（无状态可水平扩展）：
  协议网关（MQTT/CoAP/HTTP/私有协议适配）
  设备认证（一机一密/一型一密/证书校验）
   │
平台核心服务：
  产品服务（物模型/产品定义）
  设备注册服务（单台/批量/免注册）
  设备影子服务（desired/reported + 命令队列）
  命令下发服务（路由到在线设备/离线入队/重试超时）
  在线状态服务（心跳/断线检测）
  设备分组/标签/拓扑服务
  OTA 服务（固件管理/灰度/回滚）
   │
数据链路：
  遥测上报 → Kafka → 实时计算/规则引擎（触发器）/ 冷热存储（TSDB/OSS）
   │
安全：密钥加密存储 · 证书吊销 · 设备隔离 · 凭证轮换
```

### 4.2 核心表结构
```sql
iot_product（产品/物模型）：
  id, product_key（全局唯一）, product_name,
  model_json（属性/服务/事件三要素定义 JSON）,
  auth_type（DEVICE_SECRET/SECRET_GROUP/CERT）,
  protocol（MQTT/COAP/HTTP）, net_type（WIFI/4G/NB-IOT/以太网）,
  status, create_time

iot_device（设备）：
  id, product_id, device_name, device_key,
  device_secret（加密存储）, cert_id（证书认证时）,
  status（REGISTERED/ACTIVE/OFFLINE/ONLINE/DISABLED/RETIRED）,
  last_online_time, last_offline_time, firmware_version,
  group_id, tags（JSON）, parent_device_id（拓扑）,
  create_time, retire_time

iot_device_shadow（设备影子）：
  id, device_id（唯一）,
  reported（JSON：设备上报状态）,
  desired（JSON：应用期望配置）,
  version（乐观锁，防并发覆盖）, update_time

iot_command（命令下发）：
  id, device_id, request_id（唯一防重）, command（服务名+参数）,
  status（PENDING/SENT/SUCCESS/FAILED/TIMEOUT）,
  retry_count, timeout, create_time

iot_ota（固件升级）：
  id, device_id, firmware_id, target_version,
  status（DOWNLINKED/INSTALLING/SUCCESS/FAILED/ROLLED_BACK）,
  error_code, update_time
```

### 4.3 关键设计点
- **身份先于设备**：设计硬件前先定 provisioning→decommissioning 全生命周期流程；
- **影子是离线基础**：命令先写 desired，设备上线对齐，避免同步调用阻塞；
- **认证分级**：消费类用一机一密，工业/强安全用证书 + 短生命周期凭证轮换；
- **遥测异步化**：上报走消息队列异步消费，不阻塞设备链路；
- **热冷分离**：热数据（近期遥测）TSDB/内存，冷数据（历史）OSS/数仓；
- **OTA 必须可回滚**：A/B 分区 + 灰度 + 失败自动回滚，防大批设备变砖；
- **退役必须安全**：吊销凭证、擦数据、关资产记录；
- **租户隔离**：tenant-aware 授权，跨租户不可见。

## 五、设计说明

### 5.1 核心设计原则
| 原则 | 说明 |
| --- | --- |
| 一设备一身份 | DeviceID 全局唯一，密钥/证书标识可信 |
| 物模型统一口径 | 属性/服务/事件三要素，规则引擎/报表/智控共用 |
| 影子优先 | 离线可同步、命令可缓存、状态可读 |
| 遥测异步 | 上报入队异步消费，不阻塞链路 |
| 安全分级 | 一机一密/证书按场景选，凭证可轮换可吊销 |
| OTA 可回滚 | 灰度 + A/B 分区 + 失败回滚 |
| 生命周期闭环 | 注册→激活→在线/离线→退役，全流程留痕 |
| 离线不丢数据 | 本地缓存 + 时间戳补传 |

### 5.2 常见设计坑与规避
| 坑 | 后果 | 规避 |
| --- | --- | --- |
| 密钥明文存储 | 泄露即设备被仿冒 | 加密存储 + 仅创建时展示 + 轮换 |
| 同步调用设备 | 设备离线/慢 → 应用阻塞超时 | 设备影子 + 命令队列异步 |
| 命令无唯一标识 | 网络重发重复执行（重复充值） | requestId/序列号去重 |
| 物模型不统一 | 每类设备一套字段，规则/报表没法做 | 属性/服务/事件三要素统一建模 |
| 离线数据丢失 | 断网期间数据缺口 | 本地环形缓存 + 补传 |
| OTA 全量推送 | 固件有问题大批设备变砖 | 灰度 + A/B 分区 + 回滚 |
| 设备退役不处置 | 遗留设备成安全漏洞/被攻击 | 吊销凭证/擦数据/关记录 |
| 在线状态靠查询 | 设备多时状态延迟/不准 | 心跳 + 断线检测主动维护 |
| 遥测同步入库 | 高并发上报打爆 DB | Kafka 异步 + 热冷分离 |
| 无租户隔离 | 跨租户互操作数据泄露 | tenant_id 贯穿 + 授权校验 |

### 5.3 演进路线
```
阶段1 单产品接入：手动注册 + MQTT 接入 + 物模型属性上报
   ↓
阶段2 平台化：批量注册/分组标签/设备影子/在线状态/命令下发
   ↓
阶段3 规模化：一型一密/证书认证 + OTA 灰度回滚 + 遥测异步冷热分离 + 拓扑
   ↓
阶段4 智能化：预测性维护 + 数字孪生 + 与运维/工单/智控场景联动闭环
```

### 5.4 业界参考实现
- **阿里云物联网平台**：产品/设备/物模型/设备影子/Topic 体系；
- **华为云 IoTDA**：设备影子 desired/reported、群组标签、注册组免注册接入；
- **Azure IoT Hub**：设备孪生、设备管理概览（监视/配置/更新）、Device Update（A/B/灰度）；
- **OneNET（中国移动）**：资源模型、设备创建鉴权（IMEI/IMSI）；
- **通用 IoT 平台分层**：设备层→接入层→平台层，协议适配 + 身份验证 + 生命周期管理。
