怎么用：AI 生成页面的固定三步 必读

AI 画原型时，设计说明不是画完页面再补，而是与页面生成同步、顺序固定的三步：

步骤做什么产出
① 先打标 生成页面 JSX 时，给每个可独立说明的区块加 data-proto-id + data-proto-label；弹窗 / 页签里的区块打在弹窗内容根元素上 页面源码所有区块带标
② 再关联卡片 在真源（如 buildModules）里为本页建设计说明卡片，每张卡 bind 指向一个区块 id；来不及写说明的先建空卡片占位 每个打标区块至少一张卡片
③ 按设计文档写说明 根据 PRD / 标书 / 需求纪要编写说明：写「设计意图 + 关键规则 + 数据口径」，不是照抄界面文字；写不完的留空卡，同对话后续让 AI 补 卡片有内容，或明确留待补

命名规则、必标区块清单、提示词模板与自查清单见 规范.md Part B；卡片写法与内容来源红线见 Part C（v3.0 起三份合一，规范.md 为唯一真源）。

人怎么用面板：悬浮左侧已打标区域 → 未写显示蓝「+ 说明」建卡、已写显示绿「✓ 已说明」跳卡；卡片上只有「标题 + 状态 + 内容 + ✎ 编辑」，关联了哪个页面模块、删除操作都在「✎ 编辑」弹窗里；删除点弹窗左下「删除这张卡片」，弹窗内二次确认后才执行。

这是什么

为原型页面提供右侧设计说明面板：单卡双页签 + SVG 连线 + 悬停高亮 + 富文本编辑 + 状态标记 + 收起展开 + 新增/编辑/删除 + 数据落盘（可注入）。

本打包件已与具体项目解耦，三层内容：DesignNotesPanel.tsx（组件本体）、designNotesTypes.ts（数据契约）、axhubSaveAdapter.ts（落盘参考实现）。

一句话：左侧画原型、右侧挂「这是什么 / 为什么这么设计」的卡片；卡片用 SVG 线连到左侧对应区块，鼠标悬浮左侧任何打过标的区域就能就地新建或跳转说明。

能力清单

能力说明
编号卡片 改白底卡片只承载「看说明」：序号 + 标题 + 状态胶囊 + 内容 + 编辑/删除按钮；关联信息不占卡片版面，进「✎ 编辑」弹窗查看与修改
删除二次确认 新删除入口在编辑弹窗左下「删除这张卡片」，弹窗内先弹确认层（Esc=取消），确认后才真删——落盘模式删除会直接改源码
关联三态提示 新编辑弹窗里显示当前关联状态：绿色已关联 / 琥珀「区域在弹窗、页签中未渲染」/ 灰未关联
SVG 连线bind 到左侧打标元素后自动画贝塞尔连线，线中点显示卡片序号；同一元素可被多张卡片关联

状态标记 新设计中 / 已评审 / 待开发 / 开发中 / 已完成；弹窗点选（再点取消），面板头部按状态汇总
空卡片占位 新内容为空显示「＋ 待补充说明 — 点击编辑」，支持先占位、后补写（人或 AI）
收起 / 展开 新收成 54px 竖向标签（含卡片数），状态存 localStorage 跨页保持；收起时连线与徽章停用
动态 DOM 自适应 新MutationObserver 监听左侧容器：弹窗 / 页签 / 步骤条打开后新出现的打标元素自动补连线、补进下拉
数据落盘（可注入）编辑结果通过 onSave 写回真源；无适配器时降级为 localStorage
草稿兜底落盘前先写 localStorage；失败保留草稿并提示「⚠ 落盘失败」
重置放弃未落盘修改，回退到真源版本

数据契约

1. 卡片 ModuleDef

type NoteStatus = 'designing' | 'reviewed' | 'todo' | 'developing' | 'done';

type ModuleDef = {
  id: string;            // 稳定唯一 id；新增卡片形如 custom-<timestamp>
  title: string;         // 卡片标题
  status?: NoteStatus;   // 状态标记；不填 = 未标记
  text?: string;         // 纯文本正文（支持换行）。与 rich 互斥
  list?: string[];       // 要点列表。与 rich 互斥
  rich?: string;         // 富文本正文（受限 HTML）；存在时忽略 text/list
  bind?: string;         // 关联左侧元素 id（对应 data-proto-id）；为空 = 未关联
};
格式分流（保存时自动判断）：只有纯文本 + 项目符号 → 存 text + list；含任何格式标签（b i u font span ol style= 等）→ 整体存 rich。这样老卡片不改格式重新保存时，源码零无意义 diff。

2. 页面侧约定（宿主需满足）

  • 左侧主内容区内，可独立说明的区域打 data-proto-id="<模块id>"
  • 必填 data-proto-label="可读名"：悬浮徽章与关联下拉都读它；不写则退化取标题 / 首段文字，容易读不准
  • 弹窗 / 页签里的区域打在内容根元素上，不要打在 Modal 外壳上
  • 面板与左侧内容需处于同一水平可视范围（连线基于 getBoundingClientRect）
  • 窄屏（≤900px）连线自动隐藏

3. 源码真源约定（Axhub 项目）

  • 每个原型页面 src/prototypes/<pageKey>/index.tsx 内含 function buildModules(sub)，返回 ModuleDef[]
  • 每页一个独立分支 if (sub === '<pageKey>') { return [ ... ]; }；下钻页是独立页面 id，自然另起一页说明
  • 落盘适配器按 sub === '<pageSub>' 前缀宽松匹配，兼容 || 复合条件分支

快速接入

最简用法（本地草稿模式，不落盘）

import { useRef } from 'react';
import { DesignNotesPanel, NOTES_PANEL_WIDTH, type ModuleDef } from './common/DesignNotesPanel';

const leftRef = useRef<HTMLDivElement>(null);
const modules: ModuleDef[] = [
  { id: 'kpi', title: '核心指标', status: 'designing',
    text: '展示当日关键指标。', list: ['对接 /metrics', '待补单位字段'] },
  { id: 'chart', title: '趋势图', bind: 'trend-chart' },
];

return (
  <div style={{ display: 'flex' }}>
    <main ref={leftRef} style={{ flex: 1, minWidth: 0 }}>
      <section data-proto-id="trend-chart" data-proto-label="趋势图">…趋势图…</section>
    </main>
    <DesignNotesPanel modules={modules} pageKey="dashboard" leftContentRef={leftRef} />
  </div>
);
面板展开态宽 NOTES_PANEL_WIDTH（360px），收起态 54px；用 position: sticky 挂在三栏 flex 右侧，不需要再给主内容预留 padding-right。

落盘用法（注入 onSave 适配器）

import { createAxhubDesignNotesAdapter } from './common/axhubSaveAdapter';

const onSave = createAxhubDesignNotesAdapter(); // 默认对接 Axhub 预览服务
// 或自建：const onSave = async (next, meta) => {
//   await myApi.save(meta.pageKey, meta.pageSub, next);
// };

<DesignNotesPanel
  modules={modules}
  pageKey="indicator"
  pageSub="list"
  leftContentRef={leftRef}
  onSave={onSave}
/>

子页切换 / 可选属性

<DesignNotesPanel
  modules={modules}
  pageKey="dashboard"
  pageSub={activeSub}
  leftContentRef={leftRef}
  onSave={onSave}
  contentKey={activeSub}   // 子页或左侧 DOM 大范围重渲染时变化，触发重扫
  title="设计说明"          // 可选，默认「设计说明」
  hint="自定义顶部提示语"    // 可选，不传则不显示提示行
/>

有 MutationObserver 兜底后，弹窗 / 页签 / 异步数据引起的 DOM 变化会自动重扫；contentKey 主要用于整块子页切换。

Axhub 落盘原理

axhubSaveAdapter.ts 依赖 Axhub 预览服务两个接口：

接口方法作用
/prototypes/<pageKey>/index.tsx?raw GET 读取源码文本；两种包裹（JSON 字符串 / 反引号模板）统一剥壳后按 JS 转义规则单遍还原
/api/text-replace/replace POST Body：{ path, replacements: [{ searchText, replaceText }] }，成功返回 { success: true }

内部关键处理

步骤处理要点
取源码剥壳后单遍还原 \r\n / \\ / 反引号 / \${ / \uXXXX，不能分段多次 replace
定位块先圈定 function buildModules 函数体，再按 sub === '<pageSub>' 找 return [，避免误命中文件其它 return
子页校验传了 pageSub 但源码无该分支 → 直接报错，不回退到末尾 return 块（否则会写进别的页面）
串页防护带子页时用「条件语句起点 → 块末尾」整段作 searchText，避免空数组块在多页同时命中
序列化字段顺序 id / title / status / bind / text / rich / list；缩进沿用原 return [ 行的前导空白
其他项目接入：若没有 Axhub 预览服务，只需实现 (next, meta) => Promise<void>，把 next 写进自家真源（DB / 文件 / CMS）即可。组件本身零后端依赖。

适配到新项目的清单

  • 拷贝 DesignNotesPanel.tsx + designNotesTypes.ts（最小可运行集）
  • 按《规范.md》Part B 给区块打 data-proto-id + data-proto-label
  • 三栏 flex 布局里把面板挂右侧，传 leftContentRef、pageKey
  • 需要落盘：拷贝 axhubSaveAdapter.ts 并对接自家接口，或自己实现 onSave
  • 纯预览 / 暂存：不传 onSave，自动进入 localStorage 本地草稿模式
  • 子页 / 下钻页：每页在 buildModules(sub) 有独立分支，切页传 contentKey
  • 自检：悬浮任一打标区域能出「+ 说明 / ✓ 已说明」；弹窗打开后其卡片的连线自动出现；未打开时该卡片「✎ 编辑」弹窗里的关联状态为琥珀色提示；删除卡片走编辑弹窗左下角并二次确认

已知约束 / 踩坑

  • ?raw 反转义必须单遍整体还原：只把反斜杠减半会让换行仍是字面 \r\n，searchText 与磁盘永不相等 → 落盘 409。只在源码含 CRLF 的项目暴露，容易漏测
  • 子页缺失要报错不要兜底：回退到末尾 return 块会静默写进别的页面，比报错危险
  • 连线基于视口坐标（position:fixed SVG + getBoundingClientRect）：页面缩放 / 布局异常会漂移；已监听 scroll / resize / DOM 变化重绘，窄屏隐藏
  • bind 允许一对多：同一 data-proto-id 可被多张卡片关联，下拉不过滤已绑定项，只标「已被第 N 条使用」，编辑时不静默清空
  • 打标元素必须真实渲染：条件渲染（弹窗 / 页签 / 步骤）里的区域未打开时扫不到，该卡片「✎ 编辑」弹窗里的关联状态显示琥珀色提示——是提示，不是故障；打开对应视图后自动连线
  • 删除必须二次确认：删除入口在编辑弹窗左下「删除这张卡片」，确认弹层后才执行删除回调；落盘模式下删除直接改真源，不能裸删
  • 落盘成功后保留乐观视图：等真源热更新追平草稿再收敛回真源视图；若立即回退静态真源，刚删掉的卡片会「消失又回来」
  • 草稿 key 含内容签名：dn-notes-<pageKey>-<pageSub>-<ids>-<内容哈希>，真源改版后旧草稿自动失效，避免旧文案覆盖新说明
  • 乐观更新 + 草稿兜底：落盘成功才清本地草稿；失败保留草稿并提示
  • 富文本净化：落盘前剔除 script/style/iframe/object/embed/link/meta 与 on*、javascript:，只留排版能力；卡片用 dangerouslySetInnerHTML 渲染，勿绕过 sanitizeRichHtml
  • z-index 层级：连线 SVG 9999、悬浮徽章 10000、编辑弹窗 1000；宿主有更高浮层需自行协调
  • 类名前缀 dn-；左侧高亮用全局 [data-proto-id].active-highlight，不依赖宿主容器类名
