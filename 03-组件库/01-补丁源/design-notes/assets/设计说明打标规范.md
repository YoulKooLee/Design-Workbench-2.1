# 原型设计说明打标规范

> 版本 v1.4 · 2026-11-01 · 来源：指标管理平台 `docs/2026-10-30-原型设计说明打标规范.md`
> 适用范围：全部原型页面（含后续新增页面）。示例中的 `ind-` / `cfg-` 等前缀取自指标管理平台，其他项目换成自家页面前缀即可。
> 目的：生成原型页面时**同步**完成设计说明的打标与卡片占位，让「页面区块 ↔ 设计说明卡片」全覆盖、可悬浮、可后补。
> v1.4（2026-11-01）：§2.2 增加打标判别标准（先判别再枚举）；§3.2 / §4 补 `apiRich` 写法对齐编写规范 v2.0。v1.3（2026-11-01）：第 3 步「写说明」对接《设计说明卡片编写规范-单卡双页签.md》——单卡双页签（页面说明 + 可选接口说明 apiRich）。v1.2：删除入口收进编辑弹窗（弹窗左下「删除这张卡片」+ 弹窗内二次确认），卡片上不再放删除按钮；v1.1 新增「AI 生成页面固定三步」（打标 → 关联卡片 → 按设计文档写说明）、卡片改版——关联信息只在编辑弹窗展示。

## 0. AI 生成页面的固定三步（必须按顺序执行）

AI 画原型时，设计说明不是「画完页面再补」，而是**与页面生成同步**的三步：

| 步骤 | 做什么 | 依据 | 产出 |
|---|---|---|---|
| **第 1 步 · 打标** | 生成页面 JSX 时，给每个可独立说明的区块加 `data-proto-id` + `data-proto-label`（弹窗/页签区块打在弹窗内容根元素上） | 本规范 §2 命名规则与必标清单 | 页面源码里所有区块带标 |
| **第 2 步 · 关联卡片** | 在 `index.tsx` 的 `buildModules(sub)` 里为本页建卡片，每张卡 `bind` 指向一个区块 id；来不及写说明的先建**空卡片占位** | 本规范 §3 卡片规范 | 每个打标区块至少一张卡片 |
| **第 3 步 · 写说明** | 按《设计说明卡片编写规范-单卡双页签.md》为每张卡片编写说明：**页面说明**（用途意图 / 字段口径 / 交互 / 校验 / 状态迁移 / 数据来源 / 边界 / 本期不做 8 项）+ 可选**接口说明**（`apiRich`，紧凑 HTML）；**不是照抄界面文字**；写不完的留空卡，同对话后续补 | 设计文档 + 区块源码实现 | 卡片有内容，或明确留待补 |

**给 AI 的提示词模板**（生成新页面时直接附带）：

```
生成 <页面名> 页面，并同步按《原型设计说明打标规范》执行三步：
1. 按 §2 给页面各区块打 data-proto-id / data-proto-label（前缀用 <页面前缀>-）；
2. 在 buildModules 增加本页分支，为每个打标区块建设计说明卡片（bind 指向区块 id）；
3. 按 <设计文档名/路径> 与《设计说明卡片编写规范-单卡双页签.md》为每张卡片写说明（页面说明 8 项 + 可选接口说明），写不完的先放空卡片。
完成后按 §5 清单自查并在回复里给出自查结果。
```

**使用者怎么用面板**（给人看的一分钟说明）：

- 鼠标悬浮左侧已打标区域：未写说明显示蓝色「**+ 说明**」点击建卡，已写显示绿色「**✓ 已说明**」点击跳到卡片。
- 卡片上只有「序号 + 标题 + 状态标记 + 说明内容 + ✎ 编辑」；**关联了哪个页面模块、删除操作都在「✎ 编辑」弹窗里**（连线本身就是关联的表达，卡片上不再重复展示）。
- 删除卡片：进「✎ 编辑」弹窗 → 点左下「删除这张卡片」→ 弹窗内二次确认（取消可回到继续编辑，确认后才真删；落盘模式会直接改源码）。
- 卡片可以放空（「＋ 待补充说明」占位），之后点卡片补写，或直接在对话里让 AI 按区域补上。

## 1. 机制总览

原型右侧的「设计说明」面板（DesignNotesPanel）按以下机制工作，规范的所有条款都围绕它：

1. **打标即可识别**：源码里给区块加 `data-proto-id`，面板自动扫到并出现在「关联」下拉里；没打标的区域无法关联。
2. **悬浮即交互**：鼠标悬浮任何已打标区域——未写说明的显示蓝色「**+ 说明**」按钮，点击直接新建该区域的卡片；已写说明的显示绿色「**✓ 已说明**」，点击跳到对应卡片。
3. **卡片可放空**：新增卡片允许内容为空，显示「＋ 待补充说明」占位；后续可在对话里让 AI 按区域补写。
4. **按页独立**：每个页面（含下钻页）在 `buildModules(sub)` 里有独立分支，说明面板随页面切换、下钻页另起一页说明。

## 2. 打标规范（生成页面时同步执行）

### 2.1 命名规则

```
data-proto-id="<页面前缀>-<区块名>"
data-proto-label="<中文可读名>"
```

- `页面前缀`：与页面 id 一致的短前缀，如 `ind-`（指标）、`tlb-`（原始库）、`dsi-`（接口）、`cfg-`（指标配置）。
- 整页标注用 `page-<页面id>`（如 `page-indicator-list`），用于页面级说明卡。
- id 全局唯一、只增不改：改名会导致旧卡片变成「未关联到页面元素」。
- `data-proto-label` 必填，悬浮按钮与关联下拉都显示它。

### 2.2 必标区块清单（列表页模板）

**先判别，再对照清单**：一个区块要不要打标，满足下面任一条即为**必标**——

1. **有自己的数据**：展示一批数据（列表 / 树 / 统计值 / 详情字段）或有数据写入（表单 / 导入）；
2. **有自己的交互**：可点击、可切换、可配置，且行为需要一句话以上才能讲清；
3. **有独立的状态或校验**：启停、发布、显隐联动、必填校验、二次确认等。

反之，**纯装饰与纯排版容器不打标**：分隔线、留白、仅做样式包装的 div、纯静态图标。粒度拿捏：一个区块 = 能独立讲清楚的一组功能，**宁大勿小**——同一操作行里紧密协作的按钮打一个标（如 `ind-list-actions`），不逐按钮拆；但操作行与数据列表职责不同，分两个标。

通过判别后，生成一个**列表页**时，以下区块全部打标（以指标列表页 `pages-indicator.tsx` 为基准样例）：

| # | 区块 | 标签示例 | 位置 |
|---|------|---------|------|
| 1 | 左侧目录/分类树 | `ind-list-tree` | 页面左栏根元素 |
| 2 | 筛选条件区 | `ind-list-filter` | FilterBar |
| 3 | 操作按钮区（新增 / 行操作等，批量类按钮以现行页面为准） | `ind-list-actions` | op-bar |
| 4 | 数据列表 | `ind-list-table` | table-wrap |
| 5 | 分页栏 | `ind-list-pager` | Pagination |
| 6 | 新增弹窗·表单 | `ind-add-form` | Modal 内表单根元素 |
| 7 | 修改弹窗·表单 | `ind-edit-form` | Modal 内表单根元素 |
| 8 | 详情弹窗·各页签区块 | `ind-detail-form` / `ind-detail-io` 等 | 每个页签一块 |

配置/下钻页按步骤打标（每步一块，如 `cfg-rules` / `cfg-rule` / `cfg-fields` / `cfg-params`）。

### 2.3 弹窗与页签的打标位置

- 弹窗内容打在 **Modal 内部的表单/区块根元素**上，不打在 Modal 组件本身。
- 页签 / 步骤条里的区块各打各的；面板会在对应视图打开时自动识别连线。区块未打开时连线暂时隐藏（关联状态在卡片的「✎ 编辑」弹窗里有琥珀色提示），说明内容不受影响。

## 3. 卡片规范（buildModules）

### 3.1 按页独立，下钻页另起一页

- 每个页面在 `index.tsx` 的 `buildModules(sub)` 里一个独立 `if (sub === '<页面id>')` 分支；**下钻页（如指标配置）是独立页面 id，自然另起一页说明**，不与来源页混排。
- 保持 `if (sub === '<key>') { return [ ... ]; }` 字面结构——落盘适配器按此整块替换写回。

### 3.2 卡片条目写法

```tsx
// 已写内容的卡片：页面说明 text+list（纯文本/要点）或 rich（富文本 HTML）二选一；
// 有数据读写的区块再加 apiRich（接口说明，紧凑受限 HTML）——两类都有时卡片出「页面说明 / 接口说明 API」双页签
{ id: 'ind-03', title: '指标列表与发布', bind: 'ind-list-table', text: '……', list: ['…', '…'] },
{ id: 'ind-15', title: '图表预览弹窗', bind: 'ind-chart', text: '……', list: ['…'], apiRich: '<div><b>请求</b>…</div>' },
// 空卡片（占位待补）：内容留空即可，面板显示「＋ 待补充说明」
{ id: 'ind-14', title: '新增指标弹窗', bind: 'ind-add-form', text: '', list: [] },
```

- `id`：卡片编号（与区块前缀一致，序号递增），落盘后作为真源主键。
- `title`：默认取区块的 `data-proto-label` 中文名。
- `bind`：指向区块 `data-proto-id`；一个区块可被多张卡关联（连线一对多）。
- 状态标记 `status`（designing/reviewed/todo/developing/done）可选，编辑弹窗里点选。

### 3.3 覆盖要求

**每个打标区块至少有一张卡片**（哪怕放空）。判断方法：页面所有 `data-proto-id` 都应出现在 `buildModules` 某条 `bind` 里，或由用户明确决定某区块不需要说明。

## 4. 后补流程（对话里让 AI 补写）

空卡片放出去之后，同一对话里用户说「把 XX 卡片补上说明」时，AI 按以下流程补写：

1. **定位**：按 `bind` 的 `data-proto-id` 找到源码位置——卡片在 `index.tsx` `buildModules(sub)` 分支里，区块在对应页面文件里。
2. **读实现**：AI 先读该区块的页面源码（交互、字段、校验、联动），再写说明；说明写「设计意图 + 关键规则」，不照抄界面文字。
3. **回写**：把 `text: ''` 换成正文，`list: []` 换成要点；需要格式时用 `rich`（受限 HTML，div/b/font/ul/li）；区块有数据读写时按《编写规范 §4》补 `apiRich`（紧凑受限 HTML：请求 / 参数 / 响应 / 错误码 / 绑定落库 / 样例）。
4. **格式分流铁律**：页面说明——纯文本+要点 → `text`+`list`，含加粗/颜色等格式 → `rich`，此时不再写 text/list；接口说明一律进 `apiRich`，与页面说明字段互不挤占。
5. **验证**：改完刷新页面，卡片内容与连线正常；说明口径与该页面其它卡片一致（术语、批次号、规则引用等）。

用户在面板里手动编辑并「保存到真源」时，整块替换 `buildModules` 分支——两种补写方式并存兼容，以最近一次写入为准。

## 5. 落地检查清单（生成新页面后自查）

- [ ] 页面所有主要区块已打 `data-proto-id` + `data-proto-label`（先过 2.2 判别标准，再对照清单查漏）
- [ ] `buildModules` 有本页独立分支，每个打标区块至少一张卡片（可为空卡片）
- [ ] 浏览器悬浮任一打标区域：出现「+ 说明」或「✓ 已说明」
- [ ] 弹窗/页签区块打开对应视图后能连线；未打开时该卡片的「✎ 编辑」弹窗里关联状态为琥珀色「不在此视图已渲染的区域里」
- [ ] 卡片删除入口在编辑弹窗左下角，弹窗内二次确认：取消不删除（弹窗留在原地），确认后卡片消失
- [ ] 下钻页说明在独立页（切到下钻页后卡片列表随之切换）
