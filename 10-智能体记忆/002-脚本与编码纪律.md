# 002-脚本与编码纪律

> 类目：PowerShell / Node / .cmd / 中文路径 / 架构。Windows 环境下最容易反复踩的坑。

## 1. PowerShell 5.1 启动 Node 子进程的坑（2026-08-12）✅

- **现象**：`Start-Process -ArgumentList` 数组会**按空格拆分参数**，即使每个元素用双引号包起来。当 NodePath=`C:\Program Files\nodejs\node.exe` 或脚本路径含 `Documents\AI work` 等空格时，出现：(a) `Cannot find module 'C:\Users\游翔\Documents\AI'` 截断错误；(b) `文件名、目录名或卷标语法不正确`。
- **正确做法**：用 .NET `System.Diagnostics.Process` 直接调 CreateProcess（`[System.Diagnostics.Process]::Start($psi)`），能正确处理含空格路径。
- **8.3 短路径**（`for %A in ("path") do @echo %~sA`）可辅助但不是必须。
- **PS 5.1 语法**：不能在赋值表达式里直接用 if 子表达式 `$x = (if (...) {...})`，会报错。必须先 `if (...) { $a=... } else { $a=... }; $x = $a`。

## 2. Windows 中文环境操作纪律（2026-08-14）✅

- **不要在命令行内联中文路径**（PowerShell 传输会 GBK/UTF-8 混乱，路径变 01-椤圭洰 乱码）。要操作中文路径文件：用 write_to_file 写 UTF-8 编码的 .mjs/.js 脚本，脚本内部用字面量中文路径，再用 node 执行。
- **.cmd/.bat 必须 GBK/ANSI 编码**保存，不能用 UTF-8，否则中文乱码、goto 标签定位失败报"找不到批处理标签"。改 .cmd 用 node + PowerShell `[System.Text.Encoding]::GetEncoding('GBK')` 写。
- **CodeBuddy IDE 注入环境变量** `NODE_OPTIONS=--require=...node-language-shim.cjs` 和 `CODEBUDDY_SAFE_DELETE_ENABLED=1`，会劫持子进程 fs 删除操作触发 SAFE_DELETE_BULK_CONFIRM_REQUIRED；spawn 子进程（启动 Make/Vite）时需**剔除这些环境变量**。
- **打开浏览器**用 `rundll32.exe url.dll,FileProtocolHandler <url>`，不要用 explorer.exe（explorer 会把 URL 当文件夹打开）。
- **fs 删除文件常被 CodeBuddy shim 拦截**，删除失败不代表文件不存在（可用 [System.IO.Directory]::Delete 绕过）。

## 3. Windows 批处理 .cmd 防闪退铁律（2026-08-12）✅

- **现象**：停止工作台.cmd 曾因"平铺式 + chcp 936 + if not errorlevel 1 (...) else (...)"复杂嵌套闪退，报乱码命令错误。
- **根因**：该结构 + GBK 中文在 cmd 解析时字节错位，把正常词拆成乱码命令。
- **正确方向**：**子函数结构** `call :killport 7788 "..."` / `call :killvite`：
  - 取 PID：`for /f "tokens=5" %%a in ('netstat -ano ^| findstr ":%PORT% " ^| findstr "LISTEN"')`（`:PORT` 后必须有空格）；
  - `if defined PID` 判断，`taskkill /PID !PID! /T /F`，第二次 netstat 复查 STILL 变量报告成功/失败；
  - killvite 用 `tokens=2,5` + `findstr /r ":517[0-9][0-9] "`。
- **不要用 chcp 936**；不要用 if not errorlevel 1 嵌套。
- **测试方法**：node spawn('cmd.exe',['/c',脚本]) 真实运行抓 EXIT code 和 stdout，EXIT=0 且无乱码=通过。

## 4. server.mjs logBase 计算坑：不要过滤非 ASCII（2026-08-12）✅

- **现象**：`safeName(relative).replace(/[\\/]/g,'_').replace(/[^a-zA-Z0-9\-_]/g,'_')` 把中文当非法字符全替换，导致"学校卫生/健康档案/演示项目"三个项目映射到**同一个** log 文件 `launch-01-______.log`，读取的 openUrl 全部错乱，浏览器全打开同一个项目。
- **正确做法**：保留中文，只把 `/` 和 `\` 替换成 `-`：`safeName(relative).replace(/[\\/]+/g,'-')`。
- **教训**：Windows 路径计算不要用 `[^a-zA-Z0-9]` 类"非 ASCII 字符过滤"，中文目录名是合法且重要的区分标识。

## 5. Make 联动路径匹配：必须统一正斜杠（2026-08-12）✅

- **现象**：syncMakeActiveProject 里 `path.join(AXHUB_ROOT, rel)` 返回**反斜杠**路径，与 Make 返回的**正斜杠** root 比较永远不匹配，Make active 切不过去。
- **修复**：`const norm = s => String(s).replace(/\\/g,'/').toLowerCase().replace(/\/+$/,'')`，两边都 norm 后再比。
