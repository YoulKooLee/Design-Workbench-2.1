## 三、踩坑（4 条，已回流房间请 qwen 裁定是否并入工作台经验条目）

1. **`ELECTRON_RUN_AS_NODE=1` 陷阱** —— Electron 系宿主 shell（WorkBuddy / VS Code）会注入该变量，使 `electron.exe` **退化成纯 Node**，`require('electron')` 拿不到 `app`（返回空对象）。修：spawn 时 `delete env.ELECTRON_RUN_AS_NODE`（同清 `ELECTRON_NO_ATTACH_CONSOLE`）。**凡在 Electron 宿主内拉起 Electron 应用都会踩。**
2. **`npm install --prefix <子目录>` 不改依赖解析 cwd** —— 只改安装目录、不改依赖解析基准：npm 按「当前目录所属工程」解析依赖树，于是把**工程根包写进子工程 dependencies**（`"@axhub/make-client": "file:.."`）并把工程根整棵依赖装进子目录，进而打包报 `Failed to locate module "b4a" ... tar-stream`。修：**以子目录为 cwd 安装**。
3. **Electron postinstall 静默失败** —— `npm install` 退出码 0 但 `node_modules/electron/dist` 不存在。修：手动 `node node_modules/electron/install.js`，带 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` + `npm_config_arch=arm64`。
4. **无焦点窗口 `Page.captureScreenshot` 超时** —— Electron 窗口无焦点/被遮挡时**合成器不产帧**（与代码无关）。修：多策略兜底 `direct → repaint（`Emulation.setDeviceMetricsOverride` 强制重绘后截，用完 clear）→ fromSurface:false`。

**另：ESM/CJS 互操作** —— `electron` 是 CJS 包，ESM 下 `import { BrowserWindow } from 'electron'` 直接报 `does not provide an export named`，改默认导入解构仍失败 → 主进程/preload **整体改 CJS**（`.cjs` + `require`），工具脚本保持 ESM。

## 四、环境实录（本机硬约束）

- 真机 **ARM64**（Qualcomm ARMv8），但 x64 node 在 **Prism** 下运行、`process.arch` 报 x64 → 装 Electron **必须显式 `npm_config_arch=arm64`**，否则拿到 x64 二进制。已验 `electron.exe` PE machine = **`0xaa64`**（ARM64 原生）。
- **Bash 工具链损坏**：`dirname` / `cd` / `head` 不可用（宿主 shim 报 `command not found`），需 `export PATH="/usr/bin:/bin:/c/Windows/System32:/c/Windows"` 兜底；且 **Git Bash 会把 `/c/...` POSIX 路径改写成 `c:\c\...`** → 调 node 脚本须用 `MSYS_NO_PATHCONV=1` + Windows 风格路径（`C:/...`）。PowerShell 工具 stdout 不回传（exit 0 但无输出）。
