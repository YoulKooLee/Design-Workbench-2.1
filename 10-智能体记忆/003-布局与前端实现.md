# 003-布局与前端实现

> 类目：Tailwind 4 / PrototypeLayout / 大屏布局。前端原型最常踩的样式坑。

## 1. Tailwind 4 默认不生成 .contents utility（2026-08-13）✅ 【scope: universal】

> 所有用 Tailwind 4 的项目都可能中招。对应规则 R-LAYOUT-01。

- **场景**：Tab 子组件用 `<div className="contents">` 试图让子元素提升到外层 grid，但 Vite 转译后 className 存在而 **CSS 没生成**，`display: contents` 不生效，grid 三栏塌陷成单列堆叠。
- **修复**：必须用 inline style `<div style={{ display: 'contents' }}>` 强制指定，绕过 Tailwind class。
- **教训**：Tailwind 4 不会自动生成所有 utility，只有显式 import 的 class 才出现在生成的 CSS 里。对 `display: contents` 这种不常用但关键的属性，优先用 inline style 兜底。

## 2. PrototypeLayout fullWidth 模式布局铁律（2026-08-13）✅ 【scope: universal】

> 框架行为，所有 fullWidth 项目通用。对应规则 R-LAYOUT-02。**16:9 仅为示例比例，具体以项目 `project-memory.md` 规定为准**（R-LAYOUT-04）。

- **现象**：该模式下 `.plx-shell{display:block}`，`.plx-left{padding:24px; max-height:100vh; overflow-y:auto}`——**父容器没有显式 height**，子元素不能用 h-screen/calc(100vh-X) 计算高度。
- **正确做法**：自建比例容器，用 viewport 单位保持比例且不受父容器高度限制（示例 16:9）：
  ```css
  width: min(100%, calc((100vh - 80px) * 16 / 9));
  height: min(calc(100vh - 80px), calc(100vw * 9 / 16));
  ```

## 3. 学校卫生大屏 2026-08-13 布局重构（2026-08-13）✅ 【scope: project】

> **仅学校卫生大屏项目的场景记录，2026-08-18 起不再作为通用规范**。其可复用教训已提炼到 R-LAYOUT-01~03（universal）；本项目 16:9 等具体要求只对该项目有效，**不套用到其他项目**（R-LAYOUT-04）。若该项目已结项，本段经验按结项流程归档。

- **连续 4 次运行时错误**（每次一个）：symptomType() 缺右括号；React is not defined；useMemo is not defined；typeColor 定义在 useEffect 内层、图例 JSX 在顶层访问不到 → 提升为模块级 TYPE_COLOR 常量。
- **布局"乱"的根因**：PrototypeLayout fullWidth 模式下 `.plx-full{display:block}` 不提供高度约束；大屏组件用 h-screen/calc(100vh-64px)/h-full 等依赖父容器高度的样式全部失效 → grid 三栏塌陷成单列，地图 h-full=0 不可见。
- **修复方案**：
  - 外层容器从 h-screen 改为 **aspect-video (16:9) + 内部绝对定位**；
  - main 用 `grid-template-columns: 260px 1fr 260px` 三栏；
  - 三个 Tab 组件内部从 grid 嵌套改为 `display:contents`，让子元素提升到外层 grid；
  - 去掉所有 calc(100vh-64px) 高度约束。
- **技术约束**：ECharts CDN 动态加载；pnpm workspace 项目只能用 npm+CDN；中文路径需 UTF-8 脚本绕过；PrototypeLayout fullWidth 是 block 不是 grid。
- **教训**：在 fullWidth 模式下不能假设父容器有高度；必须自建比例容器(aspect-ratio) + 确保所有子元素有 min-h-0 + flex-1 链路完整。
