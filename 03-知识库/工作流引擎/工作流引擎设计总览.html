工作流引擎设计总览

流程定义 → 流程实例 → 任务流转 → 网关路由（BPMN 2.0，结构示意，业界通用实践）
① 四大核心概念
流程定义
BPMN 2.0 静态模板（XML/JSON），描述节点、流转线、条件、参与者
→
流程实例
定义的运行时对象，存储状态、变量、执行上下文
→
任务
用户任务（人工审批）｜服务任务（自动接口/脚本）｜抄送｜定时
→
网关
排他（单选）｜并行（多支并行）｜包容（可多可少）
② 审批方式（四人模式）
依次审批
只放出当前处理人，前一人通过后下一人 pending
或签
一人通过节点通过，其余待办 skipped 作废（单任务多候选）
会签
全部通过才过，任一驳回整体驳回（多实例）
比例会签
同意比例达阈值（人数/权重/部门）即通过，剩余待办跳过
③ 任务操作全集与驳回

运行时操作

  • 同意 / 拒绝 / 加签（前加后加）/ 减签 / 转办 / 委派（含归还）/ 改派 / 撤回 / 抄送 / 催办
  • 全程留痕审计

驳回策略

  • 驳回发起人（从头来）/ 驳回上一节点 / 驳回指定节点（退回修改节点）
  • 撤回：仅"下一节点未处理前"可撤回

超时与兜底

  • 超时升级上级 / 自动通过 / 转抄送（边界事件）
  • 审批人为空自动转交上级，流程永不卡死
④ 中国式审批语义（比 BPMN 标准更细）

会签计票

  • 会签人：启动时固定 vs 到达时实时按组织计算
  • 同部门去重 / 岗位空缺降级 / 弃权计票
  • 通过比例按人数/权重/部门/层级

运行中变更

  • 加签后分母与完成条件是否重算（节点级配置）
  • 达到条件后未办任务：取消/转抄送/保留记录

条件分支

  • 排他网关 + 条件顺序流 + 默认路径兜底
  • 条件按优先级依次匹配，命中即停；复杂条件可接规则引擎
设计铁律：流程与业务解耦（可视化建模）· BPMN 2.0 标准 · 运行时表小且快（实例结束即删）· 历史全量留痕 · 流程永不卡死 · 操作全审计 引擎选型：Flowable（Java OA/中国式审批底座）· Camunda 8（云原生）· Activiti（历史存量） 协同：权限（办理人/候选组）· 通知中心（待办/催办/升级）· 数据字典（表单枚举）· 规则引擎（条件）
