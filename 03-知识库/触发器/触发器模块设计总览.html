触发器模块设计总览

告警 / 远程控制 / 自动化 共用规则引擎底座（结构示意，业界通用实践）
① 触发器设计：ECA 模型（与魔兽争霸3 触发器同构：事件→条件→动作）
E事件 Trigger（启动 · OR）
  • 数据/遥测上报
  • 业务事件 / 生命周期（上线/下线）
  • 定时（cron）
  • API / 外部事件 / AI 结果
触发策略：pulse 电平 / reverse 边沿
→
C条件 Condition（判断 · AND）
  • 阈值 / 范围 / 状态判断
  • 时间窗口 / 延时 / 防抖（持续 N 秒）
  • 滞回双阈值（80 触发 / 75 恢复）
  • 表达式脚本 / 跨对象组合
→
A动作 Action（执行）
  • 指令下发（同步/缓存/影子）
  • 创建/清除告警 + 通知
  • 数据转发 / 写库
  • 外部 API / 子规则 / 脚本
治理：去重窗口 · 防抖 · 滞回 · 共因收敛
② 任务编排：规则链（节点 + 关系的有向图 DAG）
Filter 过滤→ Enrichment 丰富→ Transformation 转换→ Action 动作→ External 外部
串行并行（一进多出）条件分支（True/False） 循环/批处理子规则链复用延时/定时失败重试/死信
执行引擎：Actor 模型 · 消息不可变 · 处理完成才 ACK · 集群分区

告警治理（三道闸门）

  • 重复轰炸 → 去重合并（窗口内合并+计数）
  • 边界抖动 → 滞回双阈值 + 防抖
  • 共因群发 → 共因收敛 + 分级抑制
  • 辅助：分组通知 · 静默 · 时间屏蔽 · 升级

远程控制（三种下发模式）

  • 同步 RPC：命令状态机 + 超时重试
  • 异步缓存：离线排队串行补发 + 有效期
  • 影子模式：desired / reported / delta 收敛
  • 幂等：request_id 全局唯一

设计铁律

  • 规则与业务解耦：新增规则不改代码
  • 可靠不丢事件：队列 + 处理完成才 ACK
  • 触发质量优先：宁可少触发、不误触发
  • 可视化：触发器三栏表单 + 规则链画布
  • 可观测可审计：触发轨迹 · 执行链路
  • 云边协同：关键规则下推边缘
