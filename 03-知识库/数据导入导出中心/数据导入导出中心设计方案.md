# 数据导入导出中心设计方案（Excel / CSV / 异步任务）

> 整理日期：2026-09-29
> 用途：软件产品模块设计知识库。覆盖数据导入导出的业务场景全景、各场景解决方案、通用设计方案（最优解）与设计说明。
> 一句话本质：把"**批量数据进出**"从业务列表页抽成平台通用能力——导出用**流式写入 + 异步任务 + OSS 文件**解决 OOM 和 HTTP 超时；导入用**模板 + 逐行校验 + 错误回显 + 分批落库**解决"一行错整批废"；与权限、文件管理、任务调度、审计联动形成闭环。

---

## 一、模块概述：通用导入导出中心

```
导出链路：列表页"导出"按钮
   → 小数据（<5万行）：同步流式写 response 直接下载
   → 大数据：写任务表（taskId）→ 发 MQ → 消费者分页游标取数 + 流式写 Excel
       → 上传 OSS → 更新任务状态 → 前端轮询进度/通知完成 → 预签名 URL 下载
导入链路：模板下载 → 用户填数据 → 上传文件
   → 阶段1 预检：SAX 逐行解析 + 格式/业务校验，不入库，返回校验报告
   → 阶段2 执行：用户确认 → 分批事务落库 → 成功 N 条 / 失败 M 条 + 错误清单下载
```

| 核心痛点 | 后果 | 解法 |
| --- | --- | --- |
| 大数据量导出 OOM | XSSF DOM 全量驻内存，并发即宕 | SXSSF/EasyExcel 流式滑动窗口 + 分页取数 |
| 导出 HTTP 超时 | 浏览器等几分钟断开 | 异步任务 + 轮询进度 + OSS 文件下载 |
| 深分页慢 | LIMIT 100000, 5000 越翻越慢 | 游标分页（where id > last_id） |
| 导入一行错整批废 | 用户重传整个文件 | 逐行校验 + 错误清单 + 幂等重导 |
| 越权导出 | 用户导出他人/全租户数据 | 走当前用户数据权限 + 导出审计 |

## 二、业务场景全景

### 场景 1：列表页同步导出（小数据）
- 用户在订单/用户/日志列表点"导出"，筛选条件直接导出；
- 行数少（几千~几万），同步写 HTTP response，浏览器直接下载。

### 场景 2：大数据量异步导出（数十万~百万行）
- 运营/财务月度全量对账、全量用户导出；
- 同步会超时/OOM，必须异步：提交任务 → 轮询进度 → 完成后下载文件。

### 场景 3：模板下载
- 导入前先下标准模板（含表头、示例行、下拉字典、必填标注）；
- 禁止用户自造列，避免列错位。

### 场景 4：批量导入（基础数据初始化）
- 用户批量录入、商品/会员/组织批量导入、历史数据迁移；
- 典型 5 万~10 万行。

### 场景 5：错误数据回显与修正
- 导入不是非黑即白：100 条成功 85 条失败 15 条；
- 返回错误清单（行号、字段、原因），用户修正后重传失败部分。

### 场景 6：多 Sheet / 复杂表头
- 报表类导出：一级表头合并、多级表头、固定列/列宽样式。

### 场景 7：敏感数据导出审计
- 客户手机号、身份证、薪资等敏感数据导出；
- 必须留痕（谁、什么时候、导了多少、筛选条件），必要时脱敏。

## 三、各场景的解决方案

### 3.1 导出方案：按数据量分层
| 量级 | 方案 |
| --- | --- |
| < 1~2 万行 | 同步 EasyExcel 直接写 HttpServletResponse |
| 2 万~5 万行 | 同步 + 游标分页 + 流式写，仍可接受 |
| > 5 万行 / 耗时 > 10s | **异步任务**：建任务 → MQ 消费 → OSS 文件 → 轮询下载 |
| 多文件/大结果 | 打成 zip 包，单 Sheet 上限 100 万行（xlsx 物理上限） |

### 3.2 导出内存 OOM 根治：流式 + 分页取数
```
错误（XSSF DOM）：一次性把所有数据查到 List<ExcelRow>，再整个丢进 Workbook → 百万行直接 OOM。
正确（SXSSF / EasyExcel）：
  1. 游标分页查 DB：每页 5000 条（where id > last_id ORDER BY id LIMIT 5000）
  2. 每批数据直接 write 到 Excel 流
  3. 滑动窗口：内存只保留最近 N 行（如 100 行），老行刷到磁盘临时文件
  4. 写完一批释放引用，让 GC 回收
  → 内存常驻对象从 O(N) 降到 O(window)，百万行内存 < 50MB
```

### 3.3 深分页问题：游标分页替代 OFFSET
```
翻页越翻越慢：SELECT * FROM order WHERE status=1 ORDER BY id LIMIT 100000, 5000
  → MySQL 要扫描丢弃前 10 万行，越深越慢。
游标分页（推荐）：
  第1页：SELECT * FROM order WHERE status=1 ORDER BY id LIMIT 5000
  第2页：SELECT * FROM order WHERE status=1 AND id > {last_id} ORDER BY id LIMIT 5000
  → 每次走主键索引，恒定快；且天然规避翻页期间新数据插入导致重复/漏数。
```

### 3.4 导入三阶段：预检 → 执行 → 回执
```
阶段1 预检（不入库）：
  上传文件 → SAX 逐行解析（EasyExcel，内存不爆）
  → 逐行校验：
     格式层：必填、长度、正则（手机/邮箱/日期）、数字范围、字典值匹配
     业务层：唯一性（用户名/编码不重复）、存在性（部门/上级ID存在）、关联关系合法
  → 输出校验报告：总行数、通过数、错误数、错误清单（行号+字段+原因）

阶段2 执行（用户确认后）：
  只处理通过的行；分批事务（每 1000~2000 行一个事务）
  → 部分成功部分失败不整批回滚
  → 失败行落错误表，支持按业务唯一键幂等重导

阶段3 回执：
  生成结果文件：成功 N 条、失败 M 条、失败明细
  → 用户下载错误清单 → 修正 → 只重传失败部分
```

### 3.5 异步导出中心通用化
```
业务侧只需提供两个东西：
  ① 分页查询接口（接收筛选条件 + 游标 + pageSize）
  ② 表头字段映射（字段名、列名、字典翻译规则）

导出中心平台侧：
  接请求 → 建任务表（taskId / 用户 / 业务类型 / 查询条件 / 状态 / 进度 / 文件URL）
  → 发 MQ
  → 消费者按业务类型路由到对应 Service
  → 游标分页拉数 + EasyExcel 流式写
  → 上传 OSS（预签名）
  → 更新任务状态为"完成"，写文件URL
  → 通知中心推消息 / 前端轮询进度条
```

### 3.6 权限与审计
- 导出 SQL 自动拼当前用户的数据权限条件（与权限模块数据权限联动），**不能导出越权数据**；
- 敏感字段（手机号/身份证/薪资）按角色脱敏（导出前配置脱敏规则）；
- 导出操作写审计日志：谁、什么时间、哪个业务、筛选条件、导出行数、文件留存路径。

### 3.7 文件留存与清理
- 导出文件存 OSS，设生命周期（如 7~30 天自动删除）；
- 与任务调度中心联动：定时清理过期导出文件、失败任务。

## 四、通用设计方案（最优解）

### 4.1 总体架构
```
导入导出中心（平台通用能力，业务零代码接入）：
  任务服务：任务表 CRUD、进度上报、超时管理
  执行引擎：分页拉数（游标）→ 流式写 Excel/CSV → 上传 OSS
  导入引擎：SAX 解析 → 逐行校验 → 分批事务落库 → 错误清单
  模板服务：模板下载、表头字段映射元数据
   │
存储：OSS（导出文件/导入文件/错误清单）
   │
集成：
  权限模块（数据权限拼接 + 脱敏）
  任务调度中心（定时清理、超时任务重投）
  文件管理（预签名 URL、temp 生命周期）
  消息通知中心（导出完成通知）
  审计日志（敏感导出留痕）
```

### 4.2 核心表结构
```sql
io_task（导入导出任务）：
  id, task_id（唯一）, biz_type（订单导出/用户导入...）,
  operator_id, tenant_id,
  action（IMPORT/EXPORT),
  query_condition（JSON：筛选条件）,
  header_mapping（JSON：字段↔列名）,
  status（PENDING/RUNNING/SUCCESS/FAILED/EXPIRED）,
  progress（0~100）, total_rows, success_rows, fail_rows,
  file_url（OSS 预签名）, error_file_url（错误清单）,
  fail_reason, create_time, finish_time, expire_time

io_task_error（导入错误明细）：
  id, task_id, row_no, field, error_reason, raw_row（该行原始数据）
```

### 4.3 关键设计点
- **游标分页而非 OFFSET**：主键/唯一键作游标，恒定快、防重复；
- **流式写而非整表加载**：SXSSF 滑动窗口 / EasyExcel 逐行，内存 O(window)；
- **大导出必异步**：HTTP 不等待，轮询/通知；
- **导入必预检**：先校验不入库，用户确认再执行；
- **错误必给清单**：行号 + 字段 + 原因 + 原始行，可下载修正；
- **分批事务**：千行级一事务，部分成功不整批回滚；
- **幂等键**：按业务唯一键去重，重导不重复入库；
- **导出必限行数**：单任务上限（如 50 万行），防恶意拖库；
- **敏感必脱敏 + 审计**。

## 五、设计说明

### 5.1 核心设计原则
| 原则 | 说明 |
| --- | --- |
| 业务零代码接入 | 业务只给分页接口 + 表头映射，平台统一处理异步/流式/OSS |
| 内存恒定小 | 流式 + 分页取数，不把全量数据驻内存 |
| 不阻塞 HTTP | 大导出走异步，前端轮询 |
| 导入错误前置 | 预检不入库，错误不进库 |
| 部分成功可接受 | 分批事务 + 错误清单，不整批回滚 |
| 数据权限贯穿 | 导出 SQL 自动拼数据权限，敏感脱敏 |
| 全链路留痕 | 导入导出操作进审计 |
| 文件过期自动清理 | OSS 生命周期 + 调度中心清理 |

### 5.2 常见设计坑与规避
| 坑 | 后果 | 规避 |
| --- | --- | --- |
| 用 XSSF DOM 写大 Excel | OOM 宕机 | SXSSF/EasyExcel 流式 |
| 大导出同步写 response | HTTP 超时断开 | 异步任务 + OSS 文件 |
| LIMIT OFFSET 深分页 | 越翻越慢 | 游标分页（id > last_id） |
| 导入一行错整批回滚 | 用户重传整文件 | 逐行校验 + 错误清单 |
| 导入一次性全量事务 | 慢锁行、部分失败全废 | 分批事务 |
| 重导重复入库 | 数据翻倍 | 业务唯一键幂等 |
| 用户自造列 | 列错位数据错 | 强制模板下载，禁止改列 |
| 导出不限行数 | 被拖库 | 单任务上限 + 权限 + 审计 |
| 导出文件永久留存 | OSS 费用爆 | 生命周期 7~30 天清理 |
| 错误只说"导入失败" | 用户不知道改哪 | 行号 + 字段 + 原因 + 原始行 |

### 5.3 演进路线
```
阶段1 同步导出：列表页直接 EasyExcel 写 response（小数据够用）
   ↓
阶段2 异步导出：任务表 + MQ + OSS，前端轮询（解决大数据/超时）
   ↓
阶段3 通用导入导出中心：业务只给接口和表头映射，平台统一处理
   ↓
阶段4 企业级能力：预检/错误清单/脱敏/审计/多租户隔离/历史任务管理
```

### 5.4 业界参考实现
- **EasyExcel（阿里）**：重写 POI 解析，3M 文件从 100M 内存降到几 M，SAX 逐行；
- **Apache POI SXSSF**：流式 Workbook，滑动窗口 + 磁盘临时文件；
- **SaaS 导出中心**：BaseExport<Q,R> 抽象基类 + MQ + MinIO + 任务表；
- **B 端批量导入**：模板下载 + 预检 + 错误清单是产品通用做法。
