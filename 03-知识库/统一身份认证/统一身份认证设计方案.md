# 统一身份认证设计方案（账号中心 / SSO / IAM）

> 整理日期：2026-09-17
> 用途：软件产品模块设计知识库。覆盖统一身份认证的业务场景全景、各场景解决方案、通用设计方案（最优解）与设计说明。
> 一句话本质：回答"**你是谁**"——账号生命周期、密码与多因素认证、登录凭证（令牌/会话）、SSO 单点登录。与「权限模块」（你"能做什么"）组成身份与访问管理（IAM）完整闭环。

---

## 一、模块概述：身份是唯一可信源

统一身份认证把"账号、认证、会话、登录协议"收口到**一个身份中心（IdP）**，各应用（SP）委托认证：

```
用户 → 登录门户（统一认证：账号密码 / MFA / 第三方 / 扫码）
   → IdP 认证成功 → 颁发会话/令牌
   → 应用 SSO：一次登录，多系统互通（OAuth2 / OIDC / SAML / CAS）
   → 会话管理：多端登录/踢下线/全端下线/登出
   → 账号生命周期：注册→激活→锁定→注销→离职回收
```

| 能力域 | 说明 |
| --- | --- |
| 账号中心 | 账号注册/激活/锁定/注销/离职回收、资料与安全设置 |
| 认证能力 | 密码认证、MFA（App 令牌/Passkey/短信）、第三方登录 |
| 会话与令牌 | 双 Token（Access+Refresh）、设备管理、踢下线、令牌轮换 |
| SSO/协议 | OIDC / OAuth2 / SAML / CAS 多协议接入，统一登出（SLO） |

## 二、业务场景全景

### 场景 1：SSO 单点登录（一次登录多系统互通）
- 员工/合作伙伴/客户：登录一次门户，访问权限内所有应用，跨应用免重复输密码；
- 支持协议：OIDC、OAuth2、SAML、CAS；含**统一登出（SLO）**——全局登出后各应用会话全部失效；
- 第三方登录（微信/QQ/钉钉/支付宝）：OAuth2 授权，免注册体验。

### 场景 2：账号生命周期管理
- 注册（手机/邮箱/邀请）、激活（邮箱/短信验证）、锁定（多次失败）、注销、**离职/停用即时回收**；
- 员工入离职与 HR 系统联动：入职自动开号、离职自动禁用并回收应用权限；
- 账号状态机：正常/锁定/停用/注销，全状态留痕（对接触发器+审计日志）。

### 场景 3：密码安全与找回
- 密码策略（长度/复杂度/历史/有效期）、密码哈希（bcrypt/argon2，禁止明文与 MD5）；
- 密码重置（reset）而非找回（recovery）：单次使用令牌 + 15~60 分钟过期 + 指数退避锁定；
- 重置成功后**立即失效所有会话与令牌**（防攻击者持旧会话继续）。

### 场景 4：会话与多端管理
- 多端登录控制：单设备/多设备策略、设备列表、踢下线、全端下线；
- 会话超时：空闲超时、绝对超时、敏感操作二次认证（步骤升级）；
- 登录态安全：登录后重建会话（防 session fixation）、HTTP-only Cookie、Secure/ SameSite。

### 场景 5：多因素认证（MFA）
- 高价值系统强制：管理员、远程访问、邮箱、财务；
- 方式优先级：**Passkey/硬件安全密钥 > App 认证器（TOTP/推送）> 短信（最弱，有条件禁用）**；
- MFA 注册时生成恢复码（哈希存储）、支持多种 MFA 类型互备、MFA 变更出带外通知。

### 场景 6：登录风控与异常检测
- 异地登录提醒、设备指纹、连续失败锁定（3~5 次 + 指数退避）、IP/时段异常；
- 风控规则触发二次验证或拦截，异常事件推送审计与告警（对接消息通知中心/审计日志）。

### 场景 7：B2B/B2E 多租户与外部身份
- 企业租户各自管理成员；合作伙伴/客户账号独立域；
- 与权限模块的多租户模型联动：租户内账号 → 角色 → 权限。

## 三、各场景的解决方案

### 3.1 认证协议选型（核心决策）
| 协议 | 定位 | 适用 |
| --- | --- | --- |
| **OIDC（OpenID Connect）** | 在 OAuth2 之上构建的**认证协议**，含标准身份声明（ID Token）+ 受众校验 | **现代企业应用首选**（SSO/SLO、M2M） |
| OAuth2.0 | **授权框架，不是认证协议** | 第三方授权、API 委托访问 |
| SAML 2.0 | XML 断言，企业传统标准 | 存量企业系统、强合规场景 |
| CAS | 老牌中央认证 | 历史系统兼容 |

**关键**：不要把纯 OAuth2 当登录协议（缺标准身份声明与受众校验，易被构造令牌攻击）；现代新应用选 OIDC。

### 3.2 登录凭证设计（双 Token 方案）
```
登录成功
  ├─ Access Token：短期（15 分钟），业务接口 Bearer 凭证，泄露窗口小
  └─ Refresh Token：长期（7 天），存服务端（Redis/DB），HTTP-only Cookie 安全存放
刷新：Access 过期 → /refresh 用 Refresh 换取新双令牌 → 旧 Refresh 轮换（reuse=false）
```
- **Refresh Token 族跟踪**：服务端记录族（family），旧令牌重用视为重放 → **使整个族失效**；
- 设备维度记录：支持"单设备退出、全端下线、踢下线"；
- 登出必须真正失效：撤销服务端会话/Refresh Token + 清 Cookie。

### 3.3 会话与登录态
- 登录成功后 `session.regenerate()` 重建会话，防会话固定攻击；
- Redis 存会话：`user_id → 设备列表`，支持强制下线；
- 密码/凭据变更后：立即撤销所有会话与令牌（安全事件全端下线）。

### 3.4 密码安全
- 哈希：bcrypt/argon2（加盐），禁止明文、MD5/SHA1 快速哈希；
- 策略：长度 ≥ 12、复杂度、密码历史（防重复）、定期轮换可选（现代不强制频繁轮换）；
- 重置令牌：密码学随机、单次使用、15~60 分钟过期、重置失败指数退避 + 3~5 次锁定、全程审计；
- 注册验证：邮箱/短信一次性验证码。

### 3.5 MFA 分级
| 因素类型 | 示例 | 强度 |
| --- | --- | --- |
| 硬件密钥/Passkey | WebAuthn、YubiKey | ★★★ 抗钓鱼 |
| App 认证器 | TOTP（30 秒）、推送确认 | ★★☆ |
| 短信验证码 | SMS OTP | ★☆☆（可被 SIM 劫持，有条件禁用） |

- 按风险分级启用：管理员/财务/远程访问强制，普通用户可选；
- MFA 恢复：注册时生成恢复码（哈希存）、多类型互备、支持客服严格核验。

### 3.6 SSO 安全要点
- 校验 ID Token 的**签发方（iss）、受众（aud）、有效期**——防构造令牌；
- 全局会话（IdP）与本地会话（应用）时长匹配，避免"全局已登出、本地仍可用"；
- 支持 SLO 统一登出，广播到所有已接入应用。

## 四、通用设计方案（最优解）

### 4.1 总体架构
```
登录门户/统一认证入口（账号密码 · 扫码 · MFA · 第三方 · 密码重置）
   │
认证服务（IdP）：
   账号中心（生命周期/状态机）｜ 认证引擎（密码/MFA/第三方）｜ 令牌服务（双Token/轮换/族跟踪）
   会话管理（Redis：user_id→设备列表）｜ 风控引擎（规则→二次验证/拦截）
   │
协议接入：OIDC / OAuth2 / SAML / CAS（SP 注册、回调、SLO 广播）
   │
数据：user / account / credential / refresh_token_family / login_log / mfa / audit
   │
集成：权限（角色）· 通知中心（验证码/异地提醒）· 审计日志（登录/锁定/重置全留痕）
```

### 4.2 核心数据模型
```sql
user（账号主表）：id, tenant_id, username, phone, email, status（正常/锁定/停用/注销）,
                  nickname, avatar, last_login_time, create_time
user_credential（凭证表）：user_id, type（password/webauthn/totp/sms）, credential_value（哈希）,
                           status, updated_at
refresh_token（刷新令牌表）：user_id, device_id, family_id, token_hash, expires_at,
                             revoked_at, replaced_by   -- 族跟踪：旧令牌重用→族失效
user_session / user_device（会话/设备）：user_id, device_id, device_info, login_ip,
                                          login_time, last_active_time, status
mfa_setting（MFA 配置）：user_id, mfa_type, secret（加密）, recovery_codes_hash,
                         enabled, enrolled_at
login_log（登录审计）：user_id, login_time, login_ip, user_agent, result, fail_reason
password_reset_token：user_id, token_hash, expires_at, used_at
```

### 4.3 账号生命周期状态机
```
注册（校验手机/邮箱唯一）→ 待激活（验证码）→ 正常
   ├─ 连续失败 3~5 次 → 锁定（指数退避解锁/管理员解锁）
   ├─ 离职/停用 → 停用（即时回收应用权限，审计留痕）
   └─ 注销 → 注销（匿名化/保留合规审计）
```

### 4.4 安全事件处理（密码/凭据变更联动）
- 修改密码、重置密码、MFA 变更 → **全端下线**（撤销所有 Refresh Token/会话）；
- 异地登录/新设备 → 通知 + 可选二次验证；
- 全部事件进审计日志（五要素），异常规则触发告警。

## 五、设计说明

### 5.1 核心设计原则
| 原则 | 说明 |
| --- | --- |
| 身份唯一可信源 | 所有应用委托 IdP，不在业务系统散落账号密码 |
| 现代协议优先 | 新应用走 OIDC；OAuth2 仅用于授权场景 |
| 短 Access + 轮换 Refresh | 泄露窗口最小化 + 族跟踪防重放 |
| 凭据变更即全端下线 | 密码/MFA 变更后旧会话立即失效 |
| MFA 按风险分级 | 高价值系统强制，抗钓鱼方式优先 |
| 密码重置不找回 | 单次令牌 + 短过期 + 指数退避锁定 |
| 全程可审计 | 登录/锁定/重置/MFA 变更全留痕 |

### 5.2 常见设计坑与规避
| 坑 | 后果 | 规避 |
| --- | --- | --- |
| 把 OAuth2 当登录协议 | 缺身份声明/受众校验，被构造令牌攻击 | 用 OIDC |
| 只验签不校验 iss/aud | 伪造令牌放行 | 校验签发方/受众/有效期 |
| Access Token 过长 | 泄露后长期可用 | 短 Access（15 分钟）+ Refresh 轮换 |
| Refresh 不轮换 | 重放盗用 | 轮换 + 族跟踪，旧令牌重用族失效 |
| 密码明文/弱哈希 | 拖库即泄露 | bcrypt/argon2 加盐 |
| 重置令牌可复用/长过期 | 重放重置 | 单次使用 + 15~60 分钟过期 |
| 重置后不清会话 | 攻击者持旧会话继续 | 凭据变更全端下线 |
| 本地会话远长于全局 | SLO 失效、登出不彻底 | 会话时长匹配 + SLO 广播 |
| 登录后不重建会话 | session fixation | 登录成功 regenerate |
| 短信作唯一 MFA | SIM 劫持风险 | App 认证器/Passkey 优先 |

### 5.3 演进路线
```
阶段1 单应用账号：用户名密码 + Session + 找回密码
   ↓ 多系统
阶段2 统一认证+SSO：账号中心 + OIDC/SSO + 双Token + 多端会话
   ↓ 安全加固
阶段3 零信任化：MFA 分级 + Passkey + 风控引擎 + 条件访问策略
   ↓ 身份网格
阶段4 统一 IAM：与权限/审计/组织树打通，生命周期自动化（入职开号/离职回收）
```

### 5.4 业界参考实现
- **Microsoft Entra ID / Auth0 / Okta**：企业身份平台范本（SSPR、MFA、条件访问）；
- **阿里云 IDaaS**：OIDC+M2M 应用 SSO/SLO、统一认证门户；
- **Keycloak / Authentik / Authorizer**：开源 IdP（OIDC/OAuth2/SAML/CAS）；
- **360 统一身份认证 / 宁盾**：国内 B2B/B2E 身份安全实践；
- **OWASP Cheat Sheet**：账号恢复、会话管理、认证安全清单（防 fixation/令牌重放）。
