# 组织架构管理设计方案（组织树 / 部门 / 岗位 / 汇报线）

> 整理日期：2026-09-18
> 用途：软件产品模块设计知识库。覆盖组织架构管理的业务场景全景、各场景解决方案、通用设计方案（最优解）与设计说明。
> 一句话本质：把"**组织长什么样、谁在哪个部门什么岗位、向谁汇报**"结构化建模——是**数据权限的范围骨架**、**审批链的汇报线来源**、**账号归属与员工生命周期的载体**，与权限模块、工作流引擎、统一身份认证强联动。

---

## 一、模块概述：组织是系统的主干数据

```
组织树（公司/集团 → 子公司/事业部 → 部门 → 子部门）
   │
岗位与职级（岗位 ≠ 职级：岗位定义职责，职级定义带宽/层级）
   │
人员归属（员工 → 主部门 + 兼职部门/项目组；汇报线 manager_id）
   │
消费方：
   ├── 权限模块：数据权限范围（本人/本部门/本部门及下级/全公司）
   ├── 工作流引擎：审批节点按组织维度解析（部门经理/汇报线/跨级）
   └── 统一身份认证：入职开号/调动改权限/离职回收（JML 生命周期）
```

| 能力域 | 说明 |
| --- | --- |
| 组织树 | 多层级树建模（集团/公司/事业部/部门）、部门增删改调、版本化 |
| 岗位职级 | 岗位（Position）与职级（Grade）分离，岗位-职类-职级体系 |
| 人员归属 | 主部门、兼职部门/虚拟组织/项目组（矩阵式虚线汇报）、汇报线 |
| 调整与生命周期 | 组织调整（合并/拆分/迁移）联动权限与审批；入转调离 JML |
| 审计与合规 | 组织变更留痕、敏感岗位数据分级 |

## 二、业务场景全景

### 场景 1：组织树建模（多层级多形态）
- 单组织树：部门 id+pid 父子结构（产品部 → app 产品部）；
- 集团多层级：集团/子公司/事业部/部门，按管理层级如实还原；
- 组织形态：直线职能型、事业部制、矩阵式、平台型+小微——同一棵树内支持"部门"与"虚拟组织"两类节点。

### 场景 2：数据权限的范围骨架
- 组织树是**数据权限（数据范围）**的天然来源：本人 / 本部门 / 本部门及下级部门 / 全公司 / 自定义范围；
- "本部门及下级"判定依赖组织树的子树查询，是高频且必须高效的场景。

### 场景 3：审批链与汇报线
- 审批节点按**角色/组织维度**而非按人指派（部门经理、分管领导、跨级审批）；
- 汇报线（reporting line）驱动：请假/报销等自动找到直属上级，跨级审批取上级的上级；
- 部门经理变更后，该部门员工审批人**自动更新**，无需人工改流程节点。

### 场景 4：岗位与职级体系
- 岗位（Java 开发工程师）定义职责、属于某职类（研发类）与职级（P6）；
- **按流程功能设计角色而非镜像岗位**（设计者/审核者/批准者角色优于穷举岗位）——组织变化时权限不失效。

### 场景 5：矩阵式/虚拟组织
- 项目组、跨部门协作、矩阵结构：虚线汇报（dotted line），人员可多部门/多项目归属；
- 一人多岗：主岗位 + 兼职岗位；薪酬/考勤按主部门，协作按项目组。

### 场景 6：组织调整与过渡
- 部门合并/拆分/迁移、人员批量调动：审批 → 落地 → 过渡期双轨运行（1~3 个月）；
- 权限与审批路径随架构调整**自动更新**，调整过程版本化留痕。

### 场景 7：员工生命周期联动（JML）
- **入职（Joiner）**：自动开号、按岗位分配权限、加入群组；
- **调动（Mover）**：移除旧岗位权限、添加新岗位权限、更新群组与审批链；
- **离职（Leaver）**：立即禁用账号（不删除）、撤销全部会话与令牌、移出所有组、邮件转发、权限回收。

### 场景 8：审计与合规
- 组织变更（调整/任命/离职）全程留痕，对接触发器与审计日志；
- 敏感数据分级：薪酬、绩效、联系方式等 PII 仅限授权 HR 管理层查看（字段级/范围级）。

## 三、各场景的解决方案

### 3.1 树结构存储方案对比
| 方案 | 实现 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 邻接表 | id + parent_id | 简单直观、增删改易 | 深树递归查询性能差 |
| 物化路径 | path（1/2/3/…） | 一次查询取子树，范围判定快 | 移动节点需批量更新 path |
| 闭包表 | 关系表（ancestor/descendant） | 任意子树/祖先查询快 | 存储冗余、维护复杂 |
| 层次化类型 | SQL hierarchyid / Oracle | 内置层级运算 | 平台绑定 |

**推荐**：邻接表 + 冗余 path + level 组合——邻接表保证编辑直观，path 保证"本部门及下级"范围判定与子树查询一次完成。

### 3.2 数据权限范围（与权限模块联动）
```
数据范围模型（DataScope）：
  1 = 仅本人
  2 = 本部门
  3 = 本部门及下级（子树查询：WHERE dept.path LIKE '根path%'）
  4 = 全公司
  5 = 自定义（指定部门/人员集合）
范围随组织调整自动更新：部门合并 → 子树路径重算 → 权限范围即时生效
```

### 3.3 审批链解析（与工作流联动）
- 审批节点配置支持：**角色**（如"部门经理"）+ 组织维度（按发起人部门解析）；
- 汇报线：employee.manager_id 自引用，逐级向上取审批人；
- 部门经理变更：审批人实时取自"当前组织快照"，**不固化具体人**；
- 跨级审批：按层级步数（隔级/直到某职级）向上找。

### 3.4 岗位-职级-角色
```
岗位 Position（研发工程师）──属于──职类（研发类）＋ 职级 Grade（P5/P6）
岗位（业务语义）≠ 权限角色 Role（设计者/审核者/批准者）
映射：Position → Role（按流程功能聚合），人员 → Position → Role → 权限
```
**要点**：权限角色按流程功能设计（author/reviewer/approver/viewer），不按岗位穷举——组织架构变动时 ACL 不失效（Teamcenter 实践）。

### 3.5 员工生命周期（JML 自动化）
```
入职 Joiner：HR 建档 → 自动开账号 → 按岗位分配权限/群组 → 通知
调动 Mover：岗位/部门变更审批 → 旧权限移除 + 新权限授予 → 审批链更新 → 审计
离职 Leaver：申请→交接→审批 → 账号立即禁用（不删除）→ 撤销会话/令牌
              → 移出全部组 → 邮件转发 → 权限回收 → 审计归档
```

### 3.6 组织调整
- 调整流程：方案 → 评审 → 审批 → 过渡期（双轨运行，明确截止）→ 落地；
- 调整动作：部门合并/拆分/迁移/撤销、人员批量调动；
- 变更联动：子树 path 重算、权限范围重算、审批路径重解析、群组重映射；
- 版本化：每次调整生成组织版本，可回溯历史组织快照。

## 四、通用设计方案（最优解）

### 4.1 总体架构
```
组织架构中心（单一事实源）：
  组织树服务（部门 CRUD / 子树查询 / 路径重算 / 版本化）
  岗位职级服务（Position/Grade/职类）
  人员归属服务（员工-部门多对多 / 汇报线 / 兼职/项目组）
  变更引擎（调整事务 → 联动：权限范围 / 审批链 / 群组 / 通知 / 审计）
   │
数据：dept / position / grade / employee / employee_dept / org_change_log
   │
消费：权限（数据范围）· 工作流（审批链）· 身份认证（JML）· 审计（变更留痕）
```

### 4.2 核心数据模型
```sql
dept（部门/组织单元）：
  id, parent_id, name, code, type（company/bu/dept/virtual）, path（1/2/3/）, level,
  manager_id, sort, status（启用/停用）, effective_date, expire_date

employee（员工主表）：
  id, emp_no, name, primary_dept_id, manager_id（汇报线，自引用）, hire_date,
  status（在职/试用/停用/离职）, job_status（正常/长假/离职待办）

employee_dept（员工-部门多对多，矩阵式/兼职）：
  employee_id, dept_id, is_primary, position_id, start_date, end_date

position（岗位）：id, name, category_id（职类）, grade_id（职级）, status
grade（职级）：id, name, level（P1~P10 或 1~15）, salary_band_min/max

org_change_log（组织变更审计）：id, change_type（合并/拆分/迁移/任命/离职）, target_id,
  before_snapshot, after_snapshot, operator_id, create_time
```

### 4.3 树查询与范围判定
```sql
-- 邻接表 + path：取"本部门及下级"（数据权限范围 3）
SELECT * FROM dept WHERE path LIKE '1/3/%' OR id = 3;

-- 移动部门（变更联动）：
-- 更新该节点 path，并级联更新所有子节点 path（用新父 path + 原相对路径）
```

### 4.4 关键联动清单（架构调整时）
| 联动对象 | 动作 |
| --- | --- |
| 数据权限 | 范围按新子树重算，"本部门及下级"即时生效 |
| 审批链 | 部门经理/汇报线解析取当前组织快照，自动更新 |
| 身份认证 | 调动移除旧权限加新权限；离职禁用账号、撤销会话令牌 |
| 通知中心 | 入职/调动/离职/组织变更事件通知相关人 |
| 审计日志 | 组织变更、任命、权限变更全留痕 |
| 数据字典 | 部门类型/岗位职类/员工状态枚举 |

## 五、设计说明

### 5.1 核心设计原则
| 原则 | 说明 |
| --- | --- |
| 组织为单一事实源 | 权限范围/审批链/账号归属都读组织中心，不各自维护 |
| 树 + path 组合 | 编辑直观 + 范围判定高效 |
| 岗位≠职级≠角色 | 岗位管业务语义、职级管层级、角色管权限（按流程功能） |
| 审批按角色/维度不按人 | 组织变化自动生效，不固化具体人 |
| 生命周期 JML 自动化 | 入职开号/调动换权/离职回收，账号禁用不删除 |
| 调整版本化留痕 | 组织变更全程可追溯、可回滚 |
| 敏感分级 | 薪酬/绩效等字段级权限，PII 限授权查看 |

### 5.2 常见设计坑与规避
| 坑 | 后果 | 规避 |
| --- | --- | --- |
| 深树只存邻接表 | 数据权限"本部门及下级"查询慢 | 冗余 path/闭包表 |
| 审批人固化到人 | 部门经理变更要改流程节点 | 按角色+组织维度解析 |
| 角色镜像每个岗位 | 组织变动权限失效 | 按流程功能聚合角色 |
| 离职只删账号 | 会话/令牌未撤销、数据残留 | 禁用+撤销会话令牌+回收权限 |
| 调动只改部门 | 旧权限未移除、审批链错乱 | Mover 全量联动 |
| 调整无过渡期 | 业务突变中断 | 双轨运行+明确截止 |
| 无版本/快照 | 历史组织无法回溯审计 | 调整版本化 |
| 矩阵式强行单部门 | 跨部门协作无法表达 | employee_dept 多对多+兼职 |

### 5.3 演进路线
```
阶段1 单组织树：部门 CRUD + 人员归属 + 汇报线
   ↓ 权限联动
阶段2 数据权限范围化：树+path，本部门及下级/全公司范围
   ↓ 流程联动
阶段3 审批链自动解析 + 岗位职级体系 + 虚拟组织/矩阵
   ↓ 生命周期自动化
阶段4 JML 自动化 + 组织版本化 + 变更联动引擎（调整→权限/流程/群组全联动）
```

### 5.4 业界参考实现
- **Microsoft Entra ID Governance 生命周期工作流**：Joiner-Mover-Leaver 自动化模板；
- **Teamcenter 组织结构**：按流程功能设计角色、基于角色的 ACL 而非硬编码组；
- **红海 eHR / 薪人薪事**：流程引擎自适应组织调整、员工全生命周期模块；
- **轻流 OA 组织配置**：管理层级还原、审批按角色、权限随组织自动更新五项检查；
- **人力资源系统通用模型**：Employee/Department/Position 三实体 + 自引用汇报线。
