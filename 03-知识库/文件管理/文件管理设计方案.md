# 文件管理设计方案（附件服务 / 对象存储）

> 整理日期：2026-09-20
> 用途：软件产品模块设计知识库。覆盖文件管理的业务场景全景、各场景解决方案、通用设计方案（最优解）与设计说明。
> 一句话本质：把"**文件字节**"与"**业务数据**"分离——DB 存元数据、对象存储存字节，业务系统只持有文件 ID/引用；解决上传（大文件分片/秒传/断点续传）、下载（CDN 分发）、预览、权限（绑定单据数据权限）、安全（病毒扫描/签名 URL）全链路问题。

---

## 一、模块概述：文件与业务数据分离

```
客户端 → 业务 API（申请上传授权：预签名 URL）
   → 直传对象存储（OSS/COS/S3/MinIO），不经过业务服务器
   → 回调登记元数据（file_id / object_key / checksum）
   → 异步处理（缩略图 / 转码 / 病毒扫描 / 压缩）
   → 业务绑定（单据附件：file_id ↔ 业务单据）
下载/预览：业务鉴权 → 签发限时签名 URL → 客户端直读 OSS（CDN 加速）
```

| 核心原则 | 说明 |
| --- | --- |
| 文件与数据分离 | 业务库只存元数据，字节存对象存储；文件只存一份，分发只传引用 |
| 前端直传 + 签名 | 服务端签发限时预签名 URL，客户端直传 OSS，业务服务器不扛流量 |
| 元数据为中心 | 一切按 file_id 引用；权限、分享、预览都挂在元数据上 |

## 二、业务场景全景

### 场景 1：业务附件上传（单据附件）
- 报销发票、合同、表单附件：随业务单据上传，附件与单据强绑定；
- **访问权限跟随单据**：无单据查看权限则不能访问对应附件（绑定数据权限）。

### 场景 2：大文件上传（视频/大文档）
- 分片上传：固定大小切片（4~8MB）并行上传；
- 断点续传：中断后续传失败分片，不重头来；
- 秒传：相同内容 hash 命中，跳过上传直接返回已存在文件；
- 合并校验：全部分片上传完按序合并，总 hash 校验完整性。

### 场景 3：高并发下载/分发
- 一个文件发给上万人：字节只存一份，分发只传文件引用；
- CDN 边缘节点承接下载流量，OSS 作源站。

### 场景 4：在线预览
- 图片/PDF/Office 无需下载直接预览；
- 图片自动压缩、缩略图、格式转换（ImageMogr 参数化，无需预生成所有尺寸）。

### 场景 5：文件权限与分享
- 角色：owner（全部含分享/删除）、editor（传新版本/重命名）、viewer（下载/预览）；
- 分享链接：限时、密码、可下载/只读、过期自动失效。

### 场景 6：安全与合规
- 病毒扫描：上传后 ClamAV 异步扫描，感染文件隔离区；
- 签名 URL：私有桶限时授权，防外链泄露；
- 类型/大小校验、Content-Type 检测。

### 场景 7：临时文件与垃圾清理
- 上传走 `temp/` 目录，业务提交后"转正"；
- 未转正文件按生命周期自动清理（如 1 天）。

### 场景 8：多端头像/图片处理
- 头像、商品图：自动压缩、多尺寸缩略图、WebP 转换。

## 三、各场景的解决方案

### 3.1 存储选型对比
| 方案 | 适用 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 云对象存储（OSS/COS/S3） | 互联网应用、多副本、CDN | 免运维、高可用、签名 URL、全球分发 | 持续付费、内网访问成本 |
| 自建对象存储（MinIO/Ceph） | 私有化、高可靠备份 | S3 兼容、纠删码、跨机房复制 | 自运维 |
| 本地磁盘 | 小型内网、低延迟 | 简单 | inode 耗尽、扩容/备份难 |
| FastDFS/HDFS | 大文件/海量 | 分布式 | 运维复杂 |

**推荐**：互联网应用用 OSS（MinIO 私有化替代）；本地磁盘仅用于小项目临时方案。

### 3.2 上传方案：预签名直传 + 异步处理
```
1. 客户端向业务 API 申请上传（带文件名/大小/类型）
2. 业务校验权限 → 签发预签名 PUT URL（限时、限定 object_key）
3. 客户端直传 OSS（字节不经过业务服务器）
4. 上传完成回调业务 → 登记元数据
5. 异步任务：生成缩略图/转码/病毒扫描
6. 业务绑定 file_id 到单据
```

### 3.3 大文件三件套（分片/秒传/断点续传）
| 能力 | 实现 |
| --- | --- |
| 分片 | 客户端 Blob.slice 切成固定片（1~5MB 常用），带 fileHash + 片索引并行上传 |
| 秒传 | 上传前先算整文件 hash → 查库是否已存在 → 命中则直接绑定，不重复传字节 |
| 断点续传 | 服务端记录已传分片列表；中断后只补传缺失片 |
| 合并校验 | 全片到齐按序合并，用总 hash 校验完整性，损坏则报错 |
| 去重 | 以内容 hash（SHA-256）寻址（content-addressable），相同字节只存一份 |

### 3.4 下载与 CDN
- 私有文件：业务鉴权 → 签发限时签名 URL → 客户端直读 OSS；
- 公共/重复下载：OSS 配 CDN 加速，边缘节点承接；
- 分发只传引用："给一万人发 200M 文件"——元数据只写 file_id，不复制字节。

### 3.5 权限模型
```
文件级三角色：owner / editor / viewer
绑定单据数据权限：无单据权限 = 无附件权限
分享：链接 + 过期 + 可选密码 + 可下载标志
```

### 3.6 临时文件与清理
- 上传落 `temp/`，业务确认后移动/复制到正式路径并登记 DB；
- OSS 生命周期规则：`temp/` 下超期（如 1 天）自动删除，未转正垃圾静默回收。

## 四、通用设计方案（最优解）

### 4.1 总体架构
```
文件服务（独立模块，无业务耦合）：
  上传授权服务（预签名 URL 签发/校验）
  元数据服务（file_id ↔ object_key ↔ 业务单据）
  异步处理管道（缩略图/转码/压缩/病毒扫描）
  权限服务（文件级角色 + 单据数据权限联动）
   │
存储：OSS/MinIO（业务文件）｜ CDN（下载加速）｜ DB（元数据）
   │
集成：权限模块（单据权限）· 审计日志（下载/分享留痕）· 通知中心（分享通知）
```

### 4.2 核心表结构
```sql
file_meta（文件元数据）：
  id, tenant_id, owner_id,
  object_key, bucket, version_id,
  original_name, display_name, file_ext, mime_type,
  file_size, checksum（SHA-256/MD5）,
  thumbnail_url, status（待扫描/正常/隔离/已删除）,
  biz_type, biz_id（绑定业务单据）,
  expire_time, create_time, update_time

file_permission（文件权限）：
  file_id, principal_id（user/group）, role（owner/editor/viewer）

file_chunk（分片记录，可选/Redis）：
  file_hash, chunk_index, chunk_size, uploaded_status
```

### 4.3 关键设计点
- **object_key 规划**：按业务/租户分桶或前缀（`company-xxx/`、`user-avatar/`、`video/`），便于隔离与生命周期；
- **元数据冗余**：文件名/大小/checksum 落库，下载/预览不依赖 OSS 反查；
- **病毒扫描隔离**：上传后状态先置"待扫描"，扫描通过才"正常"，感染转隔离；
- **临时文件生命周期**：`temp/` 目录自动清理，防止垃圾堆积；
- **内容寻址**：checksum 唯一，相同文件只存一份（去重 + 秒传）。

## 五、设计说明

### 5.1 核心设计原则
| 原则 | 说明 |
| --- | --- |
| 文件与业务数据分离 | DB 存元数据，字节存对象存储 |
| 前端直传 + 签名 | 业务服务器不扛文件流量 |
| 内容寻址去重 | 以 hash 为唯一键，秒传 + 去重 |
| 权限跟随业务 | 附件权限 = 单据权限的延伸 |
| 异步处理 | 缩略图/转码/扫描不阻塞上传 |
| 临时文件自动清理 | 生命周期规则兜底 |
| 私有桶 + 签名 URL | 不暴露永久外链 |

### 5.2 常见设计坑与规避
| 坑 | 后果 | 规避 |
| --- | --- | --- |
| 文件存在业务库服务器本地 | 扩容/备份/多实例共享灾难 | 对象存储统一 |
| 业务服务器中转上传 | 带宽打满、CPU 高 | 预签名直传 |
| 大文件整体上传 | 中断重头来、弱网不可用 | 分片 + 断点续传 |
| 相同文件重复存储 | 空间浪费 | 内容 hash 去重 + 秒传 |
| 附件不跟单据权限 | 越权下载敏感附件 | 绑定单据数据权限 |
| 永久外链 | 链接泄露即公开 | 限时签名 URL |
| 不做病毒扫描 | 恶意文件入库 | 异步扫描 + 隔离区 |
| 未转正文件堆积 | 存储垃圾 | temp/ 生命周期清理 |
| 缩略图全量预生成 | 存储浪费 | 参数化按需变换 |

### 5.3 演进路线
```
阶段1 基础附件：本地磁盘/OSS 简单上传下载 + 元数据表
   ↓
阶段2 直传 + 权限：预签名直传 + 单据权限绑定 + 缩略图
   ↓
阶段3 大文件三件套：分片/断点续传/秒传 + CDN 分发 + 病毒扫描
   ↓
阶段4 统一文件服务：无业务耦合 + 多存储适配 + 去重 + 分享/预览/协作
```

### 5.4 业界参考实现
- **阿里云 OSS / 腾讯云 COS**：对象存储 + CDN + 图片处理（ImageMogr）；
- **MinIO**：S3 兼容私有化对象存储；
- **字节通用文件服务**：无业务耦合文件服务 + 元数据 MongoDB 结构；
- **网盘系统设计**：User/File/Block 三表模型、秒传与限速；
- **Dropbox/Google Drive 设计**：4~8MB 分块 + content hash 寻址 + 去重。
