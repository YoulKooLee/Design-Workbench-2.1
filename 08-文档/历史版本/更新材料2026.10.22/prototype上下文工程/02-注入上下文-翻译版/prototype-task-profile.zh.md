# OD Next Prototype 任务档案 v3.1.9

> 发布：active

任务路由、澄清、构建与 ship-on-write 边界遵循通用编排技能。用档案字段与交付要求作为可读计划中的设计指导；不要序列化成机器契约。

## 适用性（Applicability）

只把本档案应用于当前请求中要求这类交付物的部分。核心指令顺序适用：显式用户范围与格式高于这些默认。独立的媒体或文档请求不需要本档案的 HTML 源码、页面结构或导出工作流。构建对应原型、deck、营销布局或 HyperFrames 合成时保持常规 HTML 要求。不要仅因为本档案已加载就添加包装。

## 档案字段（Profile fields）

解析产品表面与目标设备、受众、主流程、必需屏幕与交互、保真度、基线制品、内容锁定、品牌引用与所需输出格式。把解析后的调色板、字体阶梯、间距、组件语言、图标族、交互状态与动效规则放入共享 Design Spec。

绝不静默省略缺失字段：按通用编排技能决定进入澄清阶段，或把缺口转为显式假设并在正文披露其风险。保真度为线框或低保真时，内容与交互状态要求降级为结构草图，且下方视觉方向规则不适用；保真度未指定时默认高保真。

质量焦点：信息层级、交互清晰度、流程完整性、视觉一致性、响应式行为与参考遵循。

## 制品契约（Artifact contract）

原型工作交付可编辑 HTML 源码 + 稳定可运行入口。新原型优先根 `index.html`，编辑时保留现有入口。此要求不适用于原型项目内请求的独立媒体文件。必需交付物注明源码入口与任何用户请求的派生包。按钮、导航、表单与主控件实现声明的流程，而非充当装饰。

默认交付是一个可打开、可运行、仍可编辑的原型：核心流程从入口端到端真实可用，按钮、导航与关键控件永不只是装饰。

编写源码时保持 DOM 查询基数显式：`querySelector` 返回一个元素或 null；`querySelectorAll` 返回集合。不迭代单元素查找，不混用选择器辅助的返回类型。初始化错误不得让种子内容与控件保持未绑定。切换 `hidden` 时保留 `layout.css` 中携带的原生隐藏态规则（含其 `until-found` 例外）。组件 flex/grid 显示规则不得暴露隐藏对话框、验证消息或空状态。保持无 `open` 的原生 dialog 不可见，即使其组件类用了 flex/grid；打开与关闭必须保留原生 dialog 状态。保持未触碰且成功重置的表单无错误消息；只有用户验证了无效值后才显示字段错误。结果与其空状态绝不同时出现。保持处理器、标签与验证反馈选择器与实际渲染的标记中的 ID 一致。不要混用输入与字段命名方案来派生反馈 ID。可选反馈节点必须空安全；缺失消息元素不得抛出或阻塞原本有效的状态更新。对渲染器插入或替换的控件，从稳定祖先委托事件或在插入后绑定。初始化时查找无法绑定尚不存在的详情或购物车动作。重新打开视图必须保留可用处理器而不累积重复动作。

**把主 HTML 交付物写盘 IS 交付**：写后无打开、无预览、无走查、无任何形式的二次 pass。在写源码的一次 pass 内满足下方质量底线。必需交付物存在且符合契约时报告完成；残余质量风险在正文摘要披露——它们不改变结果。

## 构建要求（Build Requirements）

全局优先级遵循核心系统提示；本档案不建立自己的顺序。上层指令与契约静默处：修改任务延续已确认品牌、设计系统与现有设计语言；用户引用只在其指定范围内适用；本档案默认只填补其余未指定部分。

### 保持明确设计方向（Hold a clear design direction）

- 从产品目标、用户、使用上下文与参考资产形成统一视觉方向；新制品中，字体、颜色、间距、圆角、图形与动效必须服务单一产品性格。
- 修改基线制品时先延续其设计语言，保留现有路由、组件约定与授权范围；除非用户显式要求，绝不随意重做或意外改动锁定内容、用户指定资产或无关区域。
- **反陈词滥调规则：** 严格执行核心反陈词滥调默认——默认不用暖米色/奶油页面底、不用库存 UI 人脸作展示字体、不用紫渐变晕染。另避免无商业理由的渐变、玻璃效果、霓虹光、超大圆角与装饰性卡片堆叠；绝不交付暴露设计者或演示者控件的产品制品——视口选择器、平台切换、演示面板与生成设计元数据都不是应用 UI。
- **风格方向推断示例：** 政府/考试类产品倾向冷静、可信的低饱和蓝绿、细节克制；工具/效率类倾向中性高对比极简；儿童/教育类倾向明亮圆角、插画感。无品牌时按场景选，并用一句话说明选择。

任务配置提供以下值时执行并记录到 Design Spec：

- **视觉风格**设定调色板性格、字体配对与圆角/阴影强度；所选风格绝不豁免上述反陈词滥调规则。
- **信息密度**设定间距档位：relaxed 24–96px、standard 16–64px、compact 8–32px；compact 绝不意味着缩小字号或压扁留白层级。
- **动效强度**设定动效范围：restrained 只做状态反馈；standard 加转场与列表入场；rich 可用滚动驱动与多元素编排。三档都保持在基线时长限制内且必须支持 reduced-motion。

### 建立清晰信息层级（Build a clear information hierarchy）

- 页面目标、主内容与主行动第一眼可见。
- 用字号、字重、颜色、留白、对齐、对比与位置建层级——绝不只靠边框、卡片或装饰。
- 复杂页面保持稳定阅读顺序与稳定视觉锚点。

### 设计完整交互状态（Design complete interaction states）

- 关键动作有清晰可点击的可得性与结果反馈，声明的流程需要处处理 default、hover、focus、selected、loading、empty、success、failure、disabled 各态。
- 模态、菜单、抽屉与页面转场有明确入场、出场与返回路径。
- 模态表单优先原生 `<dialog>` + `showModal()`。对话框可见后再放初始焦点，而不是入场动画隐藏它时。每条关闭路径把焦点还给活跃控件：重建列表后按稳定条目 ID 找新触发器；条目不再可见时聚焦主行动而非游离节点。
- 重建或移动条目的内联动作也把焦点恢复到新渲染的等价控件，过滤器移除时给可见回退。
- 按钮驱动的视图变化与成功跳转由本地状态驱动并直接调用视图渲染器。不依赖赋 `location.hash` 或原生文档导航在沙箱中更新视图。URL 元数据可选；被拒的 URL 更新不得阻塞导航、已提交结果或保留用户过滤器的返回路径。
- 每次本地变更提交到渲染界面的同一状态；显示列表、过滤结果、合计、可用性与图表标签前从该已提交状态派生。仅保存复制的列表不得让可见列表或其摘要过期。刷新每个已挂载的已变更值视图，包括抽屉或编辑器后面的复核页；使基于旧值的确认失效。关闭编辑器不得暴露过期复核；最终确认使用用户在该复核中看到的同一当前值。
- 状态措辞从与显示合计相同的值派生。区分无记录、零、正净额与负净额；零不得称为正余额或增长。空周期显示诚实的空状态，无过期图表段或编造百分比。
- 热搜索建议与键入搜索用同一匹配规则。可见建议必须能找到其预期的现有内容，包括建议缩写较长标题时。清空搜索恢复适用的列表与过滤器。
- 原型动作必须在产品的沙箱预览内工作，无原生表单提交或导航。本地增/存用 `type="button"` 点击处理器与 Enter 键处理器调用同一本地更新；不单靠表单 submit 事件。localStorage 不可用时保留内存兜底，不承诺在阻止存储的预览中持久化。不削弱宿主沙箱。
- 使用语义控件、可见键盘焦点、可访问名、有用 alt、非颜色状态线索与 reduced-motion 行为。
- 动效只存在于解释状态变化、层级或动作结果——绝不是无目的装饰。

### 适配真实使用环境（Fit the real usage environment）

- 移动端：优先触控可达、单手使用、内容滚动与系统安全区；触控目标不小于 44×44pt，相邻目标间距 ≥8px。
- Web 应用：优先多变窗口宽度、内容重排与键鼠操作；可点击元素给 pointer 光标与 hover 反馈。
- 落地页：建立清晰叙事顺序，核心价值与主 CTA 尽早呈现。
- 响应式布局按 375 / 768 / 1024 / 1440 断点组织，重组内容而非缩放整页；每个断点适配而不隐藏关键动作或破坏阅读顺序；移动端永不横向滚动、不禁缩放。
- 固定页头、底栏与浮动控件为覆盖内容预留匹配 padding。

### 手持设备外壳（Handheld device shell）

目标设备为手机时——brief 点名 iPhone/iOS、Android，或未点名平台的移动/手机 App——原型必须装进捆绑手持外壳，绝不手绘近似。Open Design 把外壳 staging 在项目目录 `.od-frames/`，并在解析平台后把所选外壳写入 `device-frame` 上下文事实、在 `device-frame-shell` 中引用其源码。

| Brief 点名 | 外壳 |
|---|---|
| iPhone、iOS、SwiftUI、UIKit、App Store | `.od-frames/iphone.html` |
| Android、Material、Pixel、Galaxy、HarmonyOS、APK | `.od-frames/android.html` |
| 未点名平台的手机/移动 App | `.od-frames/neutral.html` |
| Web 应用、落地页、响应式站点、桌面应用、平板 | 无外壳——页面即产品 |

- 用所选外壳的标记与 CSS 作文档骨架，产品放入 `APP CONTENT START` / `APP CONTENT END` 槽；应用只挂载在 `.phone-content`，别处不挂。
- 外壳的 `--phone-*` 声明放在与产品令牌分离的独立 `:root` 块。保留外壳 CSS 中捆绑的 `var(--phone-*, fallback)` 值：替换产品令牌绝不能塌缩手机的宽、高、边框或安全区。不依赖预览宿主提供这些值。
- 新手机输出：先整体复制所选外壳文件到请求的 HTML 入口，再替换 APP CONTENT 槽、添加作用域产品样式与行为。不从记忆重建外壳、不只拷其 body：其 head 样式、安全区变量、系统 chrome 与响应式回退必须一起保留。添加 layout.css 时保持它们完整。
- 整个原型一个手持外壳。屏幕导航与 hash 路由在屏内交换内容；仅当用户要求并排看板时才每条路由一个新手持。
- 保留外壳的硬件与系统 chrome：金属边框、比屏半径更深的外壳半径、侧键、平台摄像头处理、带时钟的 SVG 状态字形、以及作为最后一个可见系统元素的 Home 指示条。`border: 1px solid` + `border-radius: 24px` 的卡片不是手机。
- 应用在 `.phone-content` 内滚动、手持外壳保持固定；内容遵守 `--phone-safe-top` / `--phone-safe-bottom`，不有东西压到状态栏或 Home 指示条下。
- 外壳是呈现，不是设计系统：它不为应用设定字体、调色板、间距、组件或导航。绝不把 Android 应用放进 iPhone 外壳或反之。
- 弹层、对话框、toast 与遮罩挂在外壳屏内，常在应用自身包裹之外，所以产品设计令牌在 `:root`——绝不在内层包裹上，否则叠加层无法继承。
- 保留外壳的窄视口回退（480px 以下手持 chrome 塌缩、屏幕填满视口），使制品仍满足上面的 375px 规则。

### 变长文本与堆叠信息（Variable-length text and stacked information）

Open Design 把 `.od-frames/layout.css` 与手持外壳并列 staging，并在 `layout-primitives` 上下文事实中引用它。它只是结构——display、flex/grid、溢出、换行、比例与可选图标几何——不设调色板、字体、间距阶梯或组件外观。把整块放进文档自己的 `<style>` 作为首个规则集（`@layer od-layout` 必须最前，让产品的普通布局 CSS 胜出）。其原生隐藏与已关 dialog 规则故意优先于组件显示声明；保留这些规则与 `OD-LAYOUT-PRIMITIVES v1` 标记注释，并从它组合下方形状，而不是按卡/行/瓦片/chip 逐个重推导。

保留捆绑块中的 `[hidden]:not([hidden="until-found" i]) { display: none !important; }`。用 `hidden` 表示非活动屏幕、空状态、对话框与遮罩；仅显示该元素时移除它。组件 `display: flex/grid` 不得让隐藏元素可见。出场动画先加状态类再设 `hidden`；不覆盖 hidden 规则。保留 `hidden="until-found"` 供浏览器页内查找。

两类文本、两种处理：

- **作者文案**——标题、标语、chip 标签、按钮标签、瓦片与区块标题——按长度预算书写且**绝不截断或钳制**：chip ≤ 4 汉字；tile 名 ≤ 5 汉字且 ≥14px；媒体上标语 1–2 行且 ≤ 12 汉字；按钮标签单行。放不下就缩短文案或改容器；带省略号的标语不是设计。
- **数据文本**——名称、地址、描述、评论、任何用户数据——列表/chip/轨道中可截断（`.od-truncate`），卡片中可钳制（`.od-clamp-2/3`）；确认、订单与详情屏中全文换行。截断值点按可达（展开、弹层或详情屏）——`title` 单独不是移动路径。
- **永不截断、钳制或换行**：价格、时间、数量、可用性与状态、主行动标签、错误。

| 内容 | 容器 | 形状 |
|---|---|---|
| 数字+说明 | 统计条、主视觉统计 | `.od-stat` —— 数字在上、说明在下，各自独立块 |
| 标签+辅助文本 | 设置行、表单行 | `.od-row > .od-field.od-fill + control.od-fixed`；辅助是标签下块，≤ 2 行 |
| 星期+日期+可用性 | 日期轨道单元格 | `.od-cell` —— 三个块；售罄整体变暗并保留其文本（约满 / 余 2） |
| 电商/服务卡 | 列表行、2–3 列瓦片 | `.od-tile > .od-media + body`：名 ≤ 5 汉字单行；卖点 ≤ 3 个标签 chip，非 2 行描述；价格 `¥98起`（起更小、附连）放 `.od-nowrap`，在名行或右下——绝不换行。媒体：裸 `.od-media` 保留照片全幅（产品照、封面、作品）；只有刻意统一瓦片裁切才设 `--od-ratio` **并**同时加 `.od-media-cover` |
| chip 轨道 | 过滤栏 | `.od-rail` —— 下一个 chip 在边缘露出；chip ≤ 4 汉字；更长的进列表行 |
| 屏幕 chrome | 顶栏/内容/底栏 | `.od-screen > header + .od-scroll + footer` —— 各栏占自己的空间、中间滚动，不用高度常数当 padding；半透明叠加栏是显式选择，配 `backdrop-filter` 且主视觉为第一个子元素 |
| 栏内居中占位 | 顶栏 | `.od-spacer` 尺寸像对侧控件——绝不是空按钮 |
| 少用解释（费用、条款） | 标签或价格旁 | ≥44px 的 ⓘ 控件，点按开弹层（hover 只在 `@media (hover: hover)` 下）；卖点与保障是 chip 或保障行，不是隐藏详情 |

处处适用：一条信息 = 一个块级行——兄弟 `<span>` 永不携带两条信息，`<button>` 内也如此；`width`/`height`/`min-height` 只加在已声明 block 或 flex 的元素上；数字与其单位、价格与起、日期与其星期放 `.od-nowrap`；短 CJK 标签用 `.od-keep` 加 `<wbr>` 在短语边界（精油洗护`<wbr>`SPA），使断行永不落在词内；pointer-only 样式放 `@media (hover: hover)`。`<img>` 保留 `width`/`height` 属性保布局稳定，`.od-media` 定其尺寸——绝不给图像加 CSS 高度。建于 `<a>` 的卡/瓦片/行自设 `color` 与 `text-decoration: none`；浏览器默认链接样式永不进入产品 UI。

### 图表渲染为真实图形（Render charts as real graphics）

- 保持 SVG 绘制元素在真实 `<svg viewBox="...">` 根内。JS 构建时用 `document.createElementNS('http://www.w3.org/2000/svg', ...)` 或把 SVG 标记插入现有 SVG 根；绝不向 HTML `div` 注入裸 `path`/`line`/`text` 元素。
- 给图表可见视口与显式尺寸。绘点、轴与标签保持在视口内、符合目标屏幕尺寸；空图表容器不是已渲染图表。

### 约束功能图标几何（Bound functional icon geometry）

`viewBox` 定义内部坐标，不定义渲染尺寸。把功能内联 SVG 当作一个组件契约，写标记前先定：

- 每个 UI 字形的生产者——`icon()` 辅助或直接内联标记——发出 `<svg class="od-icon" ...>`；绝不发裸 `<svg>` 只靠 `viewBox` 定布局几何。
- 把 staging 的 `.od-icon` 原语复制进制品。默认尺寸 `1em`；需要其他尺寸时在图标或语义修饰符上设 `--od-icon-size`。图标自己拥有此几何——绝不把尺寸散布到父级选择器如 `.menu-item svg` 或 `.card-meta svg`。
- 本可选契约适用于菜单勾选、定位钉、箭头、状态标记与控制图标等 UI 字形。内容 SVG——图表、方案、示意图、logo、地图与插画——保留自己的显式几何；绝不通过 `.od-icon` 或全局 `svg` 规则定尺寸。
- 按 SVG 在页面上的角色分类，不按其画布大小、也不按其是否带 `viewBox`。logo 即使在按钮或导航栏内仍是内容 SVG；刻意的大 UI 字形仍是功能性并取 `--od-icon-size` 尺寸。

### 保持动态结构与数据分离（Keep dynamic structure and data separate）

动态 UI 优先把 DOM 结构与数据分离。纯文本用 `textContent`，属性用 DOM 属性或 `setAttribute`。生成 HTML 时复杂片段优先模板字面量 `${...}`，不用嵌套引号分隔符的长连接链；按插入上下文转义数据。仅当重复片段的结构与含义一致时才复用渲染函数。简单代码保持简单；不只为遵循本指导加抽象。

### 设计可用表单与反馈（Design usable forms and feedback）

- 每个输入有持续可见标签——绝不让 placeholder 代替；必填字段清晰标记。
- 错误消息出现在违规字段旁并解释原因与补救——绝不只是"输入无效"；多错误时顶部给汇总并链接到各字段。
- blur 时验证而非每击键；提交期间显示加载态，结束时给成功或失败反馈。
- 复杂选项渐进披露，不首屏倾倒所有字段；高频动作突出、危险动作视觉区分、破坏性动作前要确认步骤。
- 空状态解释为何为空与下一步——绝不是空白屏。

### 组织可预测导航（Organize predictable navigation）

- 底部导航最多 5 项，图标配文字标签；当前位置有明显选中态。
- 同级绝不混用底部导航、侧栏与顶部标签；大屏优先侧栏、小屏底部或顶部导航。
- 返回行为可预测：回到上一级恢复滚动位置与已输入内容——绝不静默跳回首页。
- 模态与抽屉有明确关闭方式；绝不用模态承载主流程导航。
- 导航跨页同位，不随页面类型移动。

### 控制感知性能（Control perceived performance）

- 声明图像宽/高或比例，为异步内容预留空间，加载后不位移。
- 超 300ms 的等待给骨架屏或进度指示——绝不长空白或裸 spinner。
- 超 50 项的列表分页、虚拟化或分批加载。
- 只动 transform 与 opacity；绝不触碰 width、height、top 或 left。

### 使用真实、一致的内容（Use real, consistent content）

- 优先用户提供的文案、图片、品牌资产与真实数据。
- 无真实数据时，用与业务一致的可信示例内容——绝不用无意义占位文本；保持名字、日期、数字与状态一致。
- 图片、图标与插画匹配内容含义并保持统一风格。
- 本地化图片匹配可见主体：不把无关图像改名当作请求的地点或对象。精确图像不可用时，用清晰披露的中性占位符而非误导性照片。用户认可的占位符仍区分所示对象种类。
- 绝不编造用户未提供或未确认的品牌事实、功能承诺或业务数据。
- **图像：** 对界面中每张图像遵循核心按类型取图规则，本地化进项目。
- **演示内容默认真实指称物：** 原型中的示例数据默认是真实知名实体及其真实获取的图像——书架显示真书真封面；音乐应用显示真专辑真艺术。虚构替身是例外：仅当用户要求虚构内容或许可禁止真实资产时使用，并在交付说明披露替换。不为了规避获取而"去真实化"演示内容。像菜肴这样的通用类别如何取源由核心图像规则决定，不由本默认决定。

### 质量底线（Quality floor）

写源码的同时一次满足以下各项：

- 字体引用可解析；布局无溢出或裁剪风险；对齐结构完整。
- 图片几何成立：本地化图像的容器按实测固有尺寸取比例并整幅渲染；cover 裁切只留给装饰背景，无内容图被裁剪或扭曲。
- 功能图标几何成立：每个内联 SVG UI 字形在其生产者处带 `.od-icon`、尺寸取 `--od-icon-size`、绝不依赖父级上下文或全局 `svg` 尺寸规则；内容 SVG 在本原语之外。
- 布局机制成立：每个堆叠文本盒、截断、chip 轨道与屏内栏按上方文本处理表由 `layout-primitives` 类组成；兄弟内容区绝不重叠、流内容正常流、不把 chrome 高度常数当内容 padding。
- 核心流程每步真实实现；按钮、导航与关键控件绑定真实行为，不是装饰。
- 响应式覆盖 375px 与宽屏；无横向滚动；固定栏为覆盖内容预留 padding。
- 正文对背景对比选色 ≥4.5:1；暗色独立选色。
- 主控件前后景都设，含 hover、focus 与 disabled 态；继承正文不得消失进深色行动填充。反色区辅助文本可读。
- 主交互键盘可达、源码显式定义焦点样式与焦点顺序。
- 锁定内容、用户指定资产与非目标区域保持未触碰——无意外编辑。
