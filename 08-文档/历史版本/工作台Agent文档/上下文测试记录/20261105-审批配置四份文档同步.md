## 五、返工归因

### 返工 1：`indicator_apply` / `grant` 表格列数不匹配（历史遗留，本轮暴露）

- **现象**：表头是 2 列（`| apply | 说明 |`），但数据行是 3 列（`| 字段 | 类型 | 说明 |`），Markdown 渲染会错位。
- **归因**：这是**改前就存在**的格式问题，我新增的 `flow_def_id` / `current_node_id` 两行沿用了原表的写法，把问题带过来了。
- **修法**：两个表的表头都补成 3 列（`| apply | 类型 | 说明 |` / `| grant | 类型 | 说明 |`）。
- **教训**：往既有表格追加行前，先数一遍表头列数与数据行列数是否一致；不一致就别跟着抄，顺手修掉。

### 返工 2：`sys_flow_node.id` 主键设计错误（自查发现，未流出）

- **首版**：`| id | varchar(32) PK | 节点 ID：start / end / 业务节点为生成值 |`
- **问题**：流程定义按 version 新增版本，每个版本都会有 `start` 和 `end` 节点。若业务标识直接做主键，**第二版就主键冲突**。
- **修法**：拆成两个字段——`id` bigint 自增主键 + `node_key` varchar(32) 业务标识，唯一约束改为 `(flow_def_id, node_key)`；`pass_to` / `reject_to` 存 `node_key`（同版本内），`indicator_apply.current_node_id` 存自增 `id`（锁定具体版本）。
- **教训**：多版本共存的配置表，「业务标识」和「主键」必须分开。改版整组复制时，存业务标识而非自增 ID，就不需要做 ID 重映射。

### 返工 3：`len(grants) != MAX_GRANT` 的提示语不准确

- **现象**：授权节点有 2 个时会报「流程缺少授权节点」，语义相反。
- **修法**：拆成 `== 0` 报「缺少」、`> MAX_GRANT` 报「最多 1 个」。

### 返工 4：分支指向自己未校验

- **补**：`if n.node_key in (n.pass_to, n.reject_to): errs.append('分支指向了自己')`。

### 返工 5：曾误加「节点名称不能重复」校验

- **起因**：担心同名节点让审批日志难辨认。
- **撤回**：原型允许用户把两个节点改成同名，文档加这条会与已验收的原型行为冲突。**文档口径必须与已验收原型一致，不能夹带自己的新想法。**
