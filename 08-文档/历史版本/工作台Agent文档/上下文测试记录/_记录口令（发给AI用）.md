# 测试记录口令（发给 AI 用 · v2，2026-11-05）

> 用法：**每轮都要带**。首轮发完整版，后续轮发缩写版。
> 落点：`08-文档/工作台Agent文档/上下文测试记录/<YYYYMMDD>-<主题>.md`
> 与 v1 的差别：①「压缩与快照」提到第 2 位并加硬规则；②给了体积与格式硬上限；③归因扩到 7 类。

---

## 一、首轮：完整版（复制即用）

```
【测试记录】本轮结束前先写记录，再回我。写入
08-文档/工作台Agent文档/上下文测试记录/<YYYYMMDD>-<主题>.md
固定 7 项，编号 1–7、一行一项、不加粗不缩进，总量 ≤20 行：

1. 任务型：原型·从0 / 原型·抄袭 / 开发 / 大屏（可加括号子型）
2. 压缩与快照：本轮是否发生压缩（是 / 否 / 不确定）；若发生，压缩后是否已补模块快照（是 / 否）；
   快照里「最终输出」一句话 + 路径。
   ——未发生压缩也必须写「否」；写了「已压缩未补」，本轮记录判为不合格，必须补完快照再重写这行。
3. 流程步骤：①需求设定 ②框架方案 ③三件初稿 ④模块循环 ⑤转SRS；
   写明「当前模块：xxx；为什么这么切」。
4. 上下文装载：只写路径，一行一个，4–8 行；不写说明、不写摘要。
5. 技能：具体 skill 名；没用则写「无」；用自建脚本或方法论则写「无专用技能（自建 X / 用 Y 方法）」。
6. 返工归因：从下面 7 类里选一类 + 一句依据。
7. 纠正次数：数字 + 我那句话的原话（原话必填）。

归因 7 类（照这个判，不许一律写「无返工」）：
· 同类点未穷举＝只改了 A 处，同样的 B/C 处没改
· 语义偏差＝我要求的意思和你实现的不一样（含口径理解偏差）
· 加载缺失＝没读到工程包/文档里的既有约定，导致重复发明或违背
· 功能未闭环＝页面/弹窗能开能填能保存，但点下去状态或数据没变、列表没更新、跨页不同源
· 基线未回写＝实现改了但 PRD/SRS/HLD/LLD 没跟上，留下旧口径
· 验证工具不可靠＝脚本/用例自身误判，把正常当坏、或把坏当正常
· 无返工＝真的一次过

体积规矩：七项合计 ≤20 行。排查细节、命令输出、逐条对比写不下时，
另存 <同名>-细节.md 或写进 project-memory.md，记录里只留一行路径。
```

## 二、后续轮：缩写版（每轮都带）

```
【测试记录】照旧 7 项（任务型 / 压缩与快照 / 流程步骤 / 装载 / 技能 / 归因 / 纠正次数），
≤20 行，写进本轮记录文件后再回我。
```

## 三、每项判据（写的人对照）

| # | 项 | 判据 | 常见错法 |
|---|---|---|---|
| 1 | 任务型 | 4 主类 + 括号子型 | 自造类名，无法聚合 |
| 2 | **压缩与快照** | 发生 / 未发生都要写；「未补」即不合格 | 只写「否」，不写「最终输出」 |
| 3 | 流程步骤 | 五步走一步报一步 + 模块名 + 切分理由 | 只写「第④步」，不写模块 |
| 4 | 上下文装载 | 只写路径，4–8 行 | 塞过程说明（10 月那批中位 274 字） |
| 5 | 技能 | 具体名或「无」 | 把方法论当技能名 |
| 6 | 返工归因 | 7 类选一 + 一句依据 | 一律「无返工」 |
| 7 | 纠正次数 | 数字 + 用户原话 | 只给数字（会被填 0） |

## 四、不合格判定（写完自检一遍）

- [ ] 7 项齐全、编号 1–7、总量 ≤20 行
- [ ] 第 2 项写了「是否压缩 + 是否补快照 + 最终输出」
- [ ] 第 4 项只有路径
- [ ] 第 7 项带原话
- [ ] 归因不是「无返工」却纠正次数 >0（矛盾）

任一条不过 → 先改好再回话。

## 五、抽检（前两轮必做）

- [ ] 文件生成了吗
- [ ] 第 2 项是不是只写了「否」了事
- [ ] 归因有没有一律「无返工」
- [ ] 超 20 行没有

第一轮回读一次、纠正一次，后面它就照着来。
