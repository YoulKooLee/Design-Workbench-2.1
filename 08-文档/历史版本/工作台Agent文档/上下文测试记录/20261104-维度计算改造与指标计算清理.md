## 9. 预览改成真算（本轮核心）

### 9.1 新建 `dim-calc.ts`：聚合口径唯一真源

配置面板第五步预览与指标列表「图表预览」共用这一份。不共用的后果很具体：同一份配置在两个入口算出两个数，开发照哪份实现都错。

导出：`AGG_OPTIONS` / `AGG_SQL` / `canonicalAgg` / `parseNum` / `normLabel` / `normDate` / `isDateText` / `normGrain` / `grainOptionsOf` / `aggregateBy` / `fmtValue` / `dateAxisLabel` / `clipText` / `withUnit` / `CHART_PALETTE`。

三条硬约定：

```ts
// 数值解析容错全角、千分位、前后空白；N/A、空串、null 视为无效，跳过而不按 0 计入
// 维度值归一（去首尾与全角空格）；日期先统一成 YYYY-MM-DD 再按粒度归桶
// 聚合函数与生成的 SQL 一一对应（AGG_SQL），界面文字与 SQL 函数不许各叫一套
```

`aggregateBy(rows, dims, mEn, agg)`：`dims` 为空 → 全表算一个值，供数字卡片用。

`grainOptionsOf(values)`：按真实取值判断能支持哪些粒度（全是年 → 只给按年；到月 → 按月 / 按年；到日 → 按日 / 周 / 月 / 年），不按字段名猜。

## 13. 踩坑

34. **`captureBeyondViewport` 的 clip 要文档坐标**：`getBoundingClientRect()` 给的是视口坐标，页面一滚就对不上，截出来全是空白。必须 `+ window.scrollX / scrollY`。第一次跑 4 张全是 `no data`，就是这个原因。
35. **CDP 脚本漏了初始导航**：`--headless` 起来停在 `about:blank`，直接点元素必然 `Cannot read properties of null`。必须先 `Page.navigate` 且等足时间（4s+）。
36. **空态提示说错原因比不说更糟**：「5 行被跳过」会把人引去查数据，实际该改的是配置。空态必须回答「为什么空」——哪个字段不在结果集、当前结果集有哪几列。
37. **色板容量是硬约束**：7 色画 35 条线，必然有 28 条与他人同色。图看起来正常，但读不出来是哪一条，等于画了张假图。大基数必须收窄并明确告知收窄了什么。
38. **图例宽度不能固定**：`x = PL + i * 96` 在 7 个图例时会互相压住，且中文按 7 字截断后全是「综合楼-2…」。要按可用宽度均分、必要时排两行。
39. **预览数据源决定能算什么**：预览跑在「指标 SQL 的结果集」上，物理表有 `update_time` 但结果集没有，就按时间分不出组。这不是 bug，是数据边界——但界面必须说清，且要提示用户去改 SQL。

## 14. 第二轮 · 按用户四条固定规则改形态（同日 17:17）

### 14.1 用户给的规则（以此为准）

1. 维度 + 时间都不分组 → 数字卡片
2. 只按维度分组 → 饼图 / 环形图 / 柱状图
3. 只按时间分组 → 单图例折线图 / 柱状图
4. 维度 + 时间都分组 → 多图例折线图 / 柱状图

### 14.2 与我上一轮的做法冲突在哪

上一轮我按「可加性」把形态收窄：求平均、最大值、最小值只给柱状图，理由是饼图/环形表达「部分占整体」，5 个在线率相加等于 468%，那个数没有意义。

这个判断本身没错，但**结论做错了**：错的是「环形图中心显示合计」这一步，不是「不该给饼图」。用户要的是三个形态都能切，那就都給；把中心那个错数处理掉即可。

### 14.3 改法

`SHAPES_FOR` 去掉 `agg` 入参，改成按**实际生效的分组数**取形态：

```ts
export const SHAPES_FOR = (dimCount: number, hasUserDim: boolean): PreviewShape[] => {
  if (dimCount === 0) return [];
  if (dimCount === 1) return hasUserDim ? ['pie', 'donut', 'bar'] : ['line', 'bar'];
  return ['line', 'bar'];
};
```

关键点：入参从「表里有没有时间」换成「`dimsForCalc.length`」。因为用户把日期字段选成维度、又选了按日粒度时，两者指向同一列，`dimsForCalc` 已去重为一维，此时应给饼图/环形/柱状，而不是多图例折线。

### 14.4 环形图中心与占比口径

| 聚合方式 | 环形图中心 | 表脚占比说明 |
|---|---|---|
| 求和 / 计数 | 显示合计（`1,284台`） | 占比即业务份额 |
| 求平均 / 最大值 / 最小值 | 显示分组项数（`5 项`） | 注明「占比 = 各项数值 ÷ 各项之和，仅供参考，不代表业务份额」 |

扇区仍按「各组数值 ÷ 各组之和」切分——这个比例在任何聚合下都能算，只是含义不同。**绝不能显示合计**：5 个在线率相加曾显示 468.37%，是个假数。

**两个入口必须同步**：配置页第五步预览（`dim-calc-preview.tsx`）与指标列表「图表预览」（`pages-indicator-chart.tsx`）都改了，否则同一个指标在两处显示的环形图中心不一致。

### 14.7 新增踩坑

40. **把「数算错了」当成「形态不该给」**：468% 的根因是环形图中心把各项平均值相加，不是饼图这个形态有问题。修错了地方就会把用户要的功能一起删掉——用户本轮直接指出「应该有三种」。正确做法是保留形态、修口径。
41. **形态判定要按「实际生效的分组数」而不是「配置项有没有填」**：维度与时间粒度指向同一列时必须先去重再判，否则会给出多图例折线，图上出现两组一样的日期。
42. **同一份配置有多个展示入口时必须同步改**：本次配置页与列表页各有一份环形图实现，只改一处会让用户看到两个数。
