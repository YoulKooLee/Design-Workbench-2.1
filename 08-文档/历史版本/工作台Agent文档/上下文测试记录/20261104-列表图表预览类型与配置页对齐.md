## 一、缺陷是什么

列表页弹窗自己写死了一份图表类型：

```ts
const CHART_TYPES = ['折线图', '柱状图', '饼图', '环形图'];
const [type, setType] = useState(0);   // 默认永远是折线图
```

而配置页第五步的形态是按「实际生效的分组数」算出来的，规则在 `SHAPES_FOR`：

| 分组情况 | 配置页给的候选 |
|---|---|
| 0 维（不分组） | 数字卡片，无类型可选 |
| 1 维，且是该配置的第一维（用户维） | 饼图 / 环形图 / 柱状图 |
| 1 维，时间粒度 | 折线图 / 柱状图 |
| 2 维（用户维 + 时间粒度） | 折线图 / 柱状图 |

于是同一份指标配置会出两种结果。用户截图里的「园区设备在线率」：配置页只有「饼图 / 环形图 / 柱状图」三项、默认环形图；列表页却给四项、默认折线图。**用户在列表页把按大类分组的在线率切成折线图，看的是 5 个互不相关的类别，折线本身没有趋势含义**——配置页之所以不给折线，正是因为这个。

## 二、改法：让候选集只有一个来源

不是「把列表页的数组改成和配置页一样的四项」，那样只是把第二份规则源抄了一遍，下次还会漂。做法是直接调用配置页那个函数：

```ts
import { SHAPE_LABEL, SHAPES_FOR } from './dim-calc-preview';

const shapes: PreviewShape[] = useMemo(() => {
  const cfgDims = dimCalc?.dims || [];
  if (cfgDims.length > 0) return SHAPES_FOR(cfgDims.length, true);
  if (!dim) return [];
  return SHAPES_FOR(1, !isDateDim);
}, [dimCalc, dim, isDateDim]);
```

第二个参数为什么恒传 `true`：配置页的 `hasDim` 是「用户选了维度」，而它的 `dimsForCalc` 第一项就是用户选的维度，所以 `dims.length > 0` 恒等于「有用户维」。镜像这个反推，两边的入参才完全同源。

`type` 这个数字下标保留下来了（`line=0 / bar=1 / pie=2 / donut=3 / card=-1`），因为下面四大块渲染代码是按下标分支的。留着当「形态 → 渲染分支」的翻糖，比把四百行渲染整体重写风险小。

## 三、默认选中项也要同源

只对齐候选项不够，默认值也会漂：配置里存的 `chartType` 是 `donut`，列表页 `useState(0)` 却默认画折线。

```ts
const shape: PreviewShape =
  shapes.length === 0 ? 'card'
  : pickedShape && shapes.includes(pickedShape) ? pickedShape   // 手动点过优先
  : cfgShape && shapes.includes(cfgShape) ? cfgShape            // 否则跟随配置
  : shapes[0];                                                  // 存的值不在候选里就回落首项
```

第三层的回落是必须的：`工单处置压测样本` 存的是 `line`，它的 dims 有 2 项（`area_name` + `biz_date`），候选恰好是「折线图 / 柱状图」，`line` 在候选里，直接用；但如果某个指标存的是 `donut` 而它的 dims 变成 2 项，`donut` 就不在候选里，此时不能硬画环形图（会与配置页冲突），要回落首项。

手动优先排在配置之前，是因为弹窗明确的定位是「临时看图、不落库」——用户在这个弹窗里点一下切类型，不该被配置里存的值压回去。

## 四、顺带修的两处不一致

**① 扇区上限。** 列表页原来是 `TOP.donut = 6`，配置页用 `PALETTE_CAP = 7`（色板容量）。同一份 8 项的配置，配置页画 6 项 + 「其他 2 项」，列表页画 6 项 + 「其他 2 项」也能凑巧一致，但 7 项时会分歧：配置页全画 7 项，列表页合并成 6 + 「其他 1 项」。改成 `PALETTE_CAP`。

**② 0 维配置的渲染。** 配置里一个维度都不配时，配置页画数字卡片（全表聚成一个值），列表页原来落到「该条件下没有可绘制的数据」。补了 `type === -1` 卡片渲染。同时发现 `aggregate()` 传空字符串当维度会被当成「维度值为空」整行跳过，改成空串时传 `dims: []` 才是真正的零维聚合。

## 六、踩坑

1. **「两个入口必须一致」要分数据侧和形态侧两遍查**。前几轮我把 aggregateBy / planPieSlices / judgeDim 都统一了，以为对齐完成；形态侧还留着一份写死的数组。同一个要求，我对齐了一半就以为全齐了。
2. **写死的常量最容易漏。** `const CHART_TYPES = [...]` 长得不像缺陷，但它就是第二份规则源。判断标准：**只要同一个规则在代码里出现了两次，第二次就一定会在某次改动后漂移**。修法不是「把两份改成一样」，是「让第二份消失」。
3. **`hasDim` 这类布尔参数要按调用方的算法反推，不能按字面理解。** 我第一版写成「当前选中这一维是不是 dims[0]」，结果 `应急值班到岗率` 判错——它的 `dims[0]` 是带按日粒度的 `duty_date`，属时间维，而配置页的 `hasDim` 指的是「用户选没选维度」，与该维是时间还是类别无关。判据要以配置页 `dimsForCalc` 的构成为准。
4. **CDP 里按钮文字带全角/半角空格。** 「保 存」中间有空格，用 `textContent.trim() === '保存'` 找不到。用 `replace(/\s/g,'')` 归一后再比。
5. **弹窗内切类型不该回写定义。** 这是原本就有的定位（临时看图、不落库），改的时候要守住：`pickedShape` 只存组件内 state，不调 `onDimCalcChange`。否则用户在预览里随手点一下，就把指标定义改了。
