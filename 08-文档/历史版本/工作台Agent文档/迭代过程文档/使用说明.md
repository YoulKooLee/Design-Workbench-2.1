# 产品设计工作台 v2 · 使用说明

> 适用版本：本地工作面板（产品设计工作台根目录 = 本文件所在目录）
> 后端：`工作台面板/server.mjs`（Node 纯内置模块，零第三方依赖）
> 访问地址：`http://127.0.0.1:7788`（绑定本机，仅本机可访问）

---

## 一、这是什么

一个**本地工作的产品设计面板**，帮你统一管理 Axhub Make 项目：

- 以「工作面板」方式归类文件（项目 / 模板 / 组件库 / 维护台账 / 回收站 / 运行脚本 / 日志 / 文档 / 协作 / 记忆）。
- 提供 Web 工作台，可视化查看、启动、复制、删除项目，并管理每个项目的 Git 历史版本（提交 / 回滚 / 删除）。
- 项目开发栈（Vite + Axhub Make）可从面板一键拉起。

---

## 二、目录结构

```
产品设计工作台/                ← 工作空间根目录（本文件所在处）
├─ 启动工作台.cmd           ← 一键启动器（双击即可，服务在独立最小化窗口运行）
├─ 停止工作台.cmd           ← 一键停止 7788 服务
├─ workbench.config.json    ← 唯一配置真源（端口 / 绑定主机 / 各模块路径）
├─ 使用说明.md             ← 本文件
├─ 01-项目/                ← 【唯一】真实项目存放处（工作台只扫描这里）
│   ├─ **你的项目**/      ← 你的项目
│   └─ 演示项目/            ← 只读演示项目（见下文「演示项目」说明，列表排末尾）
├─ 02-模板/                ← 模板库（含 _project-template，不算项目）
├─ 03-组件库/              ← v1.7 组件库（frame + ui-libs + catalog/registry）
├─ 04-维护台账/            ← 备份收敛 / 补丁台账 / 归档
├─ 05-回收站/              ← 删除项目时移入此处（非彻底删除）
├─ 06-运行脚本/            ← launch-project.ps1 等启动脚本
├─ 07-日志/                ← 启动 / 运行日志
├─ 08-文档/
├─ 09-协作/                ← 共享信息目录（多智能体通信，唯一真源）
├─ 10-智能体记忆/          ← 共享记忆主干（5 家分区维护）
└─ 工作台面板/             ← 工作台后端（server.mjs + public 前端）
```

> ⚠️ **项目只认 `01-项目` 目录**。`_project-template` 属于模板（在 `02-模板`），不会出现在项目管理列表中。

## 三、快速开始

### 方式一：双击启动（推荐）
双击根目录的 **`启动工作台.cmd`**：
- 若 `:7788` 已在运行 → 直接打开浏览器。
- 若未运行 → 在**单独的最小化窗口**中启动后端服务，随后打开浏览器；启动窗口本身会自动退出，关闭它**不影响后台服务**。
- 启动成功后，浏览器访问 `http://127.0.0.1:7788`。`Axhub Server` 的最小化窗口会留在后台，里面是 `node 工作台面板/server.mjs` 进程。

### 方式二：命令行启动
```bash
cd 产品设计工作台/工作台面板
node server.mjs
# 浏览器访问 http://127.0.0.1:7788
```
> Node 说明：优先用 WorkBuddy 自带的 node（`%USERPROFILE%\.workbuddy\binaries\node\versions\*\node.exe`），否则用系统 `node`（需 18+）。

### 停止服务
- **推荐**：双击根目录的 **`停止工作台.cmd`**，自动结束占用 `:7788` 的 `node.exe`。
- 或在任务管理器结束占用 `:7788` 的 `node.exe`。
- 关闭 `Axhub Server` 的最小化窗口也会停止服务。

## 四、工作台功能

### 1. 项目管理（默认标签页）
列表列：**项目名称 / 项目路径 / 操作**。

操作按钮（保持单行，不跨行）：
| 按钮 | 作用 |
|---|---|
| 启动开发栈 | 拉起该项目的 Vite + Axhub Make（默认端口 53817 为全局单例） |
| 复制 | 复制项目到 `01-项目` 下新目录 |
| 历史版本 | 打开版本管理弹窗（见下文） |
| 删除 | 移入 `05-回收站`（可还原，非彻底删除） |

顶部「+ 新增项目」可在 `01-项目` 下创建新项目。

#### 演示项目（只读）
列表**末尾**会显示一个带「演示」徽标的 **演示项目**，它由工作台内置，用于集中展示三个开箱即用的示例原型：

- **标注演示**（`annotation-demo`）
- **新手指导**（`beginner-guide`）
- **批注演示**（`touch-and-talk-annotation-demo`）

演示项目的行为与普通项目不同，已做**只读**处理：

| 项目 | 启动开发栈 | 复制 | 历史版本 | 删除 |
|---|:---:|:---:|:---:|:---:|
| 自建项目 | ✅ | ✅ | ✅ | ✅（移入回收站） |
| 演示项目 | ✅ | ❌ 禁用 | ❌ 禁用 | ❌ 禁用 |

> 启动**自建项目**的开发栈时，只启动该项目自身的 Vite + 共用 Make 单例，不会连带启动演示项目；演示项目与正常项目互不干扰。
> 演示项目在目录内以 `.axhub/demo.flag` 标记识别（`01-项目/演示项目/.axhub/demo.flag`）。**删除该文件即恢复为普通项目**，此后复制 / 历史版本 / 删除等功能会重新可用。

### 2. 历史版本弹窗
点击某项目的 **历史版本** 打开。弹窗内：
- 列表展示 Git 提交记录（提交哈希 / 日期 / 说明）。
- **初始提交**会标橙色「初始提交」标签，且不可单独删除。
- 打开后默认自动选中最新的一条非根提交。

底部三个操作（点击记录先选中，再点按钮）：
| 操作 | 说明 | 注意 |
|---|---|---|
| **提交** | 暂存当前改动并生成一个新提交 | 弹窗填写说明，可留空用默认 |
| **删除选中版本** | 从 Git 历史中移除该提交 | 仅能删非根提交；删中间提交若冲突会自动中止、不破坏历史 |
| **回滚到选中版本** | 把项目文件还原到该历史版本 | 该版本**之后**的提交会被丢弃（Git reflog 30 天内可恢复） |

> 未启用 Git 的项目，弹窗提供「初始化 Git 并创建首次提交」入口。

## 六、使用步骤：
1. 把整个 `产品设计工作台` 文件夹原样复制到电脑任意位置。
2. 双击其中的 `启动工作台.cmd` 即可。
3. 前提：电脑装有 WorkBuddy（自带 node）或 Node.js 18+。

> 注：工作台界面、列表、历史版本管理都不依赖项目依赖；只有「启动开发栈」真正跑 Vite 时才需要各项目目录里有 `node_modules`（没带的需在项目目录执行 `pnpm install` / `npm install`）。

## 七、常见问题

**Q1：双击 `.cmd` 报 `'rt' 不是内部或外部命令` 或 `系统找不到指定的路径`**
旧版启动器有编码/中文路径问题。请确认 `启动工作台.cmd` 为 ASCII + CRLF 格式且 Node 路径用自动探测（已修复）。如仍报错，改用「方式二」命令行启动。

**Q2：删除历史版本报 400「该版本是根提交，无法单独删除」**
这是正确行为——Git 的**初始提交没有父提交**，无法单独删除。请选择后续提交再删；或删除最新提交、或保留初始提交。

**Q3：删除中间版本提示冲突自动中止**
删除非最新且与后续提交改动同一文件的提交，Git 会产生冲突。系统会**自动中止并保留历史**，不丢数据。可改删最新版本，或手动处理。

**Q4：项目列表出现 `_project-template`**
不应出现。列表只扫描 `01-项目`。若出现，请检查 `server.mjs` 的 `listProjects()` 是否指向 `01-项目`。

**Q5：误整理文件如何还原**
项目删除后移入 `05-回收站`（暂未提供面板内还原入口，可手动移回 `01-项目`）；备份与补丁台账见 `04-维护台账/`。

**Q6：列表末尾有个「演示项目」，能改吗**
那是工作台内置的只读演示项目（含标注 / 新手指导 / 批注三个示例）。它只能「启动开发栈」，复制 / 历史版本 / 删除都已禁用。想把它变普通项目，删除 `01-项目/演示项目/.axhub/demo.flag` 即可；想彻底移除，把它移入 `05-回收站` 后刷新列表。
