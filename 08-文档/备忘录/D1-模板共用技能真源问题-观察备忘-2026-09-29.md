## 二、豆包核实到的事实（2026-09-29）

### 2.1 两个模板的真实形态

| | `_project-template` | `_admin-template` |
|---|---|---|
| 定位 | React 原型工程模板 | Vue3 研发工程模板 |
| 技能数（skills-lock.json） | 51（2026-09-25 生成） | 32（2026-09-19 生成） |
| 顶层结构 | `.agents/` + `src/` + `templates/` + vite 工程 | `.agents/` + `src/admin/` + `frame/` + `templates/` |

### 2.2 两边同名且改造后研发包仍需保留的 13 个技能

经文件级对比，这 13 个技能在两边**文件集合完全一致**（12 个 0 差异，`common/` 差 1 个文件），是 9-19 那次整体拷贝留下的同一份：

| 类别 | 技能 |
|---|---|
| 设计方法 | `hld-design` `lld-design` `feature-list` |
| 开发流程 | `systematic-debugging` `test-driven-development` `verification-before-completion` `finishing-branch` |
| 编排 | `delivery-plan` `pm-product-pipeline` |
| 通用工具 | `diagram-generator` `brainstorming` `skill-creator` `slides` `common/` |

### 2.3 关键事实：演化发生在项目层，不在模板层

通过翻 `工作台面板/server.mjs`（2612 行）确认：

- 建项目时（L1153），admin 框架把 `AGENTS.md`、`.agents/`、`frame` 三样整体 `cpSync` 到 `01-项目/<名>/`；
- 项目建完后，项目里的 `.agents/skills/` 是**独立副本**，与模板再无运行时关系；
- 智能体在项目里改技能，改的是项目副本，**不会自动回灌模板**；
- 模板只影响"新建项目"那一刻的初始状态。

**结论**：所谓"各自演化"不是两个模板之间分叉，而是每个项目的技能副本各自分叉、互不同步。模板之间这 13 个技能目前根本没分叉。

### 2.4 "抽到中立位置"短期不可行

方案曾考虑抽到 `02-模板/shared-skills/`。但：
- server.mjs L1153 写死只拷 `['AGENTS.md', '.agents', 'frame']`；
- 智能体从项目里的 `.agents/skills/` 加载技能；
- 中立目录既不在拷贝清单、也不在加载路径，建项目后根本不会出现在项目里——**是死代码**。

要让中立位置生效，必须同时改：①server.mjs 拷贝清单；②智能体技能搜索路径。超出本次改造范围。

## 三、待观察的问题

观察期（建议 1–2 个研发项目周期）内记录：

1. **这 13 个技能在新项目里被改过吗？** 改了的话，改动是改在项目里，还是回灌到模板了？
2. **_project-template 在原型项目里演进新技能时，哪些被证明是研发包也需要的？** 触发"需要同步"的真实信号是什么？
3. **项目层的技能改进有没有自发的回灌机制？** 如果没有，半年后各项目技能版本会怎样分裂？
4. **是否真的出现了"同一份技能，两个模板语义分叉"的情况？** 现在还没有，别预设。

## 四、观察期默认约定（暂不落地为硬规则）
