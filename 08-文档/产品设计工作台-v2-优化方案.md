## 2. 参考版（朋友简化版）借鉴分析

> 来源：`AI work\知识库\工作台（参考）`——5 个文件（server.mjs 42KB + app.js 79KB + index.html + style.css + start.bat），零依赖单页。

### 2.1 架构思路差异（核心）

| 维度 | 我们的旧版 | 朋友参考版 |
|---|---|---|
| 入口形态 | 面板管理 + 启动脚本拉栈 + 弹浏览器窗口 | **一个页面包全部**：Make 管理页、原型预览都嵌 iframe |
| 与 Make 的关系 | 调 Make API + 自己维护项目扫描/状态 | **整体反代 Make**（流式兼容 SSE），增强能力走 `/wbapi/*` 挂在同源上 |
| 原型预览 | 直接开 Vite 端口页面 | `/proto/<projectId>/` **同源反代**到 dev server，iframe 内 DOM 可访问 |
| 项目依赖 | launch 脚本检测 + pnpm/npm 自愈安装 | **从兄弟项目本地复制 node_modules**（robocopy /MT:16，145MB≈1s） |
| Make 运维 | 启动脚本拉起，崩了手动重拉 | **看门狗** 20s 探测、掉线自动重拉；前端 4s 轮询状态灯 |
| 新增能力 | 改自己代码 | 不改 Axhub 任何源码，全部在代理层补齐 |

**结论**：参考版的「反代同源 + iframe 一体化」形态明显更优——浏览器标签不乱飞、状态一处可见、还能做旧版做不到的事（读 iframe 内 DOM）。v2 应整体转向这个形态。

### 2.2 可直接借鉴（按价值排序）

| # | 借鉴点 | 解决我们的什么痛点 | 价值 |
|---|---|---|---|
| J1 | **依赖复用 `/wbapi/deps/ensure`**：锁文件 hash 一致→整树 robocopy；不一致→清单 diff 只对缺口 `npm install --prefer-offline` 增量补；失败自动回滚；无母本才走网络 | P1 启动链路脆、原生模块重装慢；同机复制=同架构，天然规避 x64/arm64 错配 | ★★★ |
| J2 | **反代同源 + `/proto/` 原型代理**：子资源靠 Referer 归属项目，二级模块引用用"最近会话"兜底（10 分钟窗口） | 旧版弹窗式预览无法深入原型内部；为附注模式打底 | ★★★ |
| J3 | **附注模式**：`annotations.json` 存项目 `.axhub/make/` 下按原型分组、**随 git 走**；CSS 选择器定位元素 | 直接匹配你"批注定位元素→发给助手改代码"的现有工作流，把口头批注变成结构化数据 | ★★★ |
| J4 | **看门狗**：20s 探测 Make 活性、崩溃自动重拉；前端 4s 轮询 `/api/version` 驱动状态灯 | P1 中"Make 崩了 Vite 还在跑"的假死状态 | ★★ |
| J5 | **AI Agent 体系**：面板内一键 npm 安装 CLI（防重复）；spawn 时把 npm 全局 bin 目录补进 PATH（治"装完仍检测不到"）；项目级默认 Agent 存 `.axhub/make/wb-agent.json`；反代拦截 `POST /api/ai/runs`，未显式选 Agent 时注入项目偏好、显式不覆盖 | ACP/CLI 安装配置的纯手工现状 | ★★ |
| J6 | **前端工程细节**：`api()` 统一注入 projectId；`WB_BUILD_ID` 每 60s 比对、代码更新后提示并 5s 自动刷新（治"改了没生效"）；侧栏三态（全/半/收）存 localStorage；`Promise.all` 并行加载 AI/Git 面板 | P4 前端体验 | ★★ |
| J7 | **版本管理补强**：git checkout 分支切换（axhub 原生只读）、变更按原型/资源/主题/技能/规则分组提交、单文件还原 diff | 旧版只有 init/commit/rollback 粗粒度 | ★★ |
| J8 | **路由匹配顺序**：静态 → wbapi → 原型反代 → 兜底反代 Make，层次清晰 | v2 server 重构时照此分层 | ★ |

### 2.3 不宜照搬 / 必须补强的

| 点 | 参考版现状 | v2 对策 |
|---|---|---|
| NODE_OPTIONS 注入 | **完全没处理**——`spawnAxhub` 直接继承 `process.env`，在 CodeBuddy/WorkBuddy 环境里照样启动即崩 | 我们的 env-doctor + `set NODE_OPTIONS=` 清洗是**刚需保留项**，合并进参考版的 spawn 逻辑 |
| 启动静默失败 | spawn `stdio:'ignore'`，Make 起不来时无任何输出可查 | 保留我们的日志体系，spawn 输出重定向到 `07-日志/` |
| 会话兜底单项目假设 | `lastProtoProjectId` 单值，多项目并行切 iframe 会串 | 本地单用户场景可接受，但面板要标"当前预览项目"；多项目并行预览需按 iframe sessionStorage 隔离（二期再说） |
| 项目组织 | 无 `01-项目` 目录约定、无模板、无回收站、无端口管理 | 这些是我们的优势，保留并叠加到参考版架构上 |
| start.bat | 极简但无 node 架构检测 | 合并：参考版的简洁 + 我们的 x64 node 探测 |

### 2.4 融合后的 v2 架构（修订）

```
产品设计工作台/
├─ start.bat / 启动工作台.cmd            ← 参考版简洁度 + x64 node 探测
├─ workbench.config.json                ← 唯一配置源（端口/目录/识别规则）
├─ server.mjs                           ← 【以参考版为底】反代 + wbapi + 看门狗 + 【我们的】NODE_OPTIONS 清洗、日志、端口池
├─ public/                              ← 【以参考版为底】三态侧栏单页 + 【我们的】运行仪表盘页
├─ 01-项目/ 02-模板/ 07-日志/ 08-文档/    ← 我们的目录骨架保留
├─ 04-组件库/frame/                      ← 【新】vibepm 需求前端组件母版（见第 3 节）
└─ .workbuddy/                          ← 记忆/skills 收敛（不变）
```

## 3. vibepm-dev-agent v1.7 资产整合（需求前端组件）

> 来源：`AI work\更新资料\vibepm-dev-agent-v1.7\vibepm-dev-agent\`——`.agents/`（30+ 技能/知识库/角色/规则/hooks）+ `frame/`（共享母版）+ `templates/`。

### 3.1 包内容盘点

| 区域 | 内容 | 对 v2 的价值 |
|---|---|---|
| `frame/` | **需求前端组件母版**：admin 48 个页面型样板（HTML+JS+CSS 三件套）+ 11 个组件演示页 + gallery 预览墙 + `_meta/pages.catalog.json` 登记 | ★★★ 你点名的核心资产 |
| `.agents/skills/annotation` | 原型标注技能：React/Vue 标注组件 + vite 插件 + `.annot-xxx` class 定位（契约 v17），SRS 驱动生成字段/规则/交互标注 | ★★★ 与参考版附注模式互补（见 3.6） |
| `.agents/skills/` 其余 | srs-writer、feature-dev、prd-writer、prototype-to-prd、pm-* 系列等 30+ | ★★ 与你已有 skill 大量重名，需去重（见 3.5） |
| `.agents/knowledge/` | conventions 14 篇 + ui-libs 5 库（arco/antd-pro/element-plus/shadcn/vant）+ phase1-4 阶段规范 | ★★ AI 重写页面时的规范真源 |
| `.agents/agents|rules|hooks` | 角色调度、软门禁、厂商适配器 | ★ 与记忆收敛统一考虑，不单独成体系 |

### 3.2 关键认知：frame 的消费模型是「对照重写」，正好契合你的工作流

vibepm 明确：**frame/ 不是 npm 包、不可 import、不是运行时**——AI 增页时按 catalog 点名 page-type → 读母版三件套 → 在交付工程里用项目技术栈**重写**，继承 `pro-*` 结构，禁止粘贴母版 HTML、禁止运行时引用。

这对我们是好消息而非障碍：你的 Axhub 项目是 React+TSX+Tailwind（母版是 HTML/Vue-Arco），本来就不可能直接引用；"AI 读母版→按项目栈重写"正是 Axhub Make 变异工作流的原生方式。**frame 的真正价值是它的信息架构**：48 个 page-type 的选型目录 + 复用规则，与技术栈无关。

资产分三层（都来自 `pages.catalog.json`）：

| 层 | 资产 | 消费方式 |
|---|---|---|
| page-type 目录 | 48 个页面型（login×3、dashboard×9、list×10、form×4、detail×2、result/exception×7、user×3 等） | 增页选型真源：先点名，再对照 |
| 组件演示 | 11 个 componentShowcases（表单/表格/图表/指标卡/富文本…） | 样板缺控件时抄用法与类名 |
| 共享层 | Shell（boot/shell/mountProPage）、`pro-*` 类名、pages-common.css、arco-theme-pro、charts | 结构与交互模式基线 |

### 3.3 整合设计：组件库进工作台（可拓展、可维护、可调用）

| 目标 | 设计 |
|---|---|
| **可调用** | ① 落位 `04-组件库/frame/`（工作台级唯一真源）；② server.mjs 加 `/frame/*` 静态路由（照搬参考版静态分层），gallery 与母版页可 iframe 预览；③ 面板新增「组件库」页：page-type 列表 + 预览 + "应用到当前项目"（把选中的 catalog 条目写入项目上下文，AI 增页时读取） |
| **可拓展** | 照搬 `index.json` 登记机制：新组件库 = `frame/` 根下新建文件夹 + `index.json` 登记 + 补 `_meta/catalog`。⚠️ **v1.7 的 `index.json` 本身是坏 JSON**（web/app 两段缺 key，第 18/29 行），迁入时必须先修复 |
| **可维护** | 单一真源在工作台，项目内**禁改母版、禁运行时引用**；版本化（保留 CHANGELOG）；升级流程 = 整目录替换 + 核对 catalog 变更；`_project-template` 只引用 catalog，不复制母版文件 |

### 3.4 调用约定（写进 `_project-template` 与项目 README-DEV）

```
AI 增页 SOP：
① 读 04-组件库/frame/index.json + 对应库 _meta/pages.catalog.json
② 点名 page-type → 读母版三件套（html/js/css）
③ 按项目技术栈（React + TSX + Tailwind / AntD X）重写，
   继承 pro-* 结构与类名语义、筛选区/表格/状态机/主次操作布局
④ 禁止：只换文案的换皮、丢开样板裸写、运行时引用 frame/、改母版
```

⚠️ **视觉冲突预警**：母版皮肤是 Arco 系（`pro-*`），你的大屏/医疗项目有自己的 `.style/` 规范。约定：**母版只借结构与交互模式，配色/字体/圆角一律以项目 `.style/` 为准**（既有视觉规范约定不变，优先级更高）。

### 3.5 技能/知识资产去重（与记忆收敛合并处理）

你已有的 skill 与 vibepm 大量重名（prd-writer、prototype-to-prd、proto-to-prd、brainstorming、skill-creator、prototype-review 等）。收敛原则：

| 类别 | 处理 |
|---|---|
| 重名技能 | **你已安装的优先**，vibepm 版作参考比对，不覆盖 |
| vibepm 独有且高价值 | 迁入 `.workbuddy/skills/`：`srs-writer`、`annotation`、`feature-dev`（需改造为"Axhub 项目 + frame 对照"版） |
| pm-* 系列（roadmap/sprint/metrics 等 13 个） | 按需第二批迁，先不搬 |
| `knowledge/conventions` + `ui-libs` | 并入工作台知识库（`.workbuddy/` 或 `08-文档/`），AI 重写页面时引用 |
| agents/rules/hooks 体系 | 不整体迁，其"先读后改/完成前验证"等软门禁精神与你的工作铁律一致，已被现有记忆覆盖 |

### 3.6 附注模式：两套实现的分工（回答之前的决策点 5）

| | 参考版附注 | vibepm annotation |
|---|---|---|
| 原理 | 代理层存 `annotations.json`，**不改代码** | 代码注入 `.annot-xxx` class + 标注组件，**永久精确命中** |
| 数据来源 | 人随手写 | **SRS 驱动**（prd-analyzer 提功能点 → code-locator 定位 → 注入） |
| 适合 | 日常 UI 迭代口头批注（"这个按钮往左挪"） | 正式需求标注（字段说明/业务规则/交互逻辑，给开发看的） |
| 建议 | 一期上，支撑现有批注工作流 | 二期随 `.agents` 收敛评估接入，与 Dingcan_app 的字段-接口映射梳理场景很配 |

**结论：两套都留，分工使用，不冲突。**

## 4. v2 优化方向

### 4.1 总原则

1. **不重写启动链路**——8 步流程已稳定，只做加固（P1/P2），不推倒。
2. **记忆层收敛**——以 WorkBuddy 原生 `.workbuddy/`（skills + memory）为主干，旧 `Agent_Memory`/`Agent_Stack` 作为内容来源一次性并入，不再双写（P3）。
3. **面板底座切换**——以参考版「反代同源 + iframe 单页」为 v2 底版（见第 2 节），我们的上下文管理、日志、端口池等能力合并进去，不再维护旧 `axhub-manager`（P4）。
4. **一切配置外置**——端口、路径、项目识别规则集中到 `workbench.config.json`，脚本和文档从此文件生成/校验（P8/P9）。
5. **卫生自动化**——回收站定期清理、tmp 文件即产即删、导出目录中文名校验（P5/P6）。

### 4.2 目标目录结构

以 **2.4 融合后架构**为准（参考版平铺底座 + 我们的目录骨架），此处只补充项目级约定：

```
01-项目/<项目>/
├─ _backups/          ← 【改】项目备份统一收回项目内（P6）
├─ project-memory.md  ← 项目层记忆，沿用
└─ .axhub/make/
    ├─ wb-agent.json      ← 【新】项目级默认 Agent（参考版 J5）
    └─ annotations.json   ← 【新】附注数据，随 git 走（参考版 J3）
```

卫生规则：`05-回收站` 超 30 天自动清、tmp 文件即产即删、导出目录中文名校验（P5）。

❓ **决策点 1**：`Agent_Stack` 的 router/rules 两层，WorkBuddy 原生 skill 触发机制已覆盖大半。建议**只迁内容、不迁分层**（rules → skill 正文里的"约束"小节；router.json → skill 的触发词描述）。如果你想保留独立 rules/router 层，也可以原样搬。

### 4.3 启动链路加固（P1/P2）

| 措施 | 说明 |
|---|---|
| **env-doctor 前置检查** | 新增 `06-运行脚本/env-doctor.ps1`：一键输出 Node 架构、NODE_OPTIONS 是否被注入、三个关键端口占用、原生模块架构匹配，启动前自动跑，异常直接红黄绿面板展示 |
