## 1. 经验总结：旧版踩坑全景（按主题）

> 来源：`Agent_Memory/000~004`、`08-文档/TROUBLESHOOTING_LOG.md`、`工作台架构与排错手册.md`，以及本次对 `server.mjs`(1470 行) / `launch-project.ps1`(755 行) / `public/index.html`(1042 行) 的实地核验。

### 1.1 启动链路类（最高频、最烧时间）

| # | 坑 | 根因 | 现状 | 给 v2 的启示 |
|---|---|---|---|---|
| 1 | 启动"必点两次" | launch-log 状态解析用全文 `includes('AXHUB_LAUNCH_STATUS: done')`，但日志是 **append 模式**，读到的是上一次的 done | 已修：从 `lastIndexOf('启动 <relative>')` 切片 | append 日志的"最后状态"必须按时间切片 |
| 2 | 启动"必点两次"（另一根因） | 状态机**缺 starting 过渡态**：spawn PS1 要几十秒，期间前端 reconcile 判 `isProjectAlive=false` 直接降级 stopped | 已修：新增 starting，reconcile 对该态不降级 | 异步流程必须有过渡态，reconcile 不得对未完成态判死 |
| 3 | 项目错升 editing 后 ERR_CONNECTION_REFUSED | 升级只看 Vite 心跳，Make(53817) 未就绪 | 已修：升级前必须 Vite + Make 双健康 | "完成" = 所有依赖服务就绪 |
| 4 | Make active 不切到刚启动的项目 | spawn PS1 后**立即**调 `syncMakeActiveProject`，但 Make 是 PS1 第 3 步才起的 | 已修：等 stdout 出现 done 标记再调 | 跨进程联动必须等就绪标记 |
| 5 | 9 个汉字的项目名必现启动失败 | `Read-JsonFile` 用 `Get-Content -Raw`（未指定编码），PS 5.1 按 ANSI/GBK 解码 UTF-8 心跳 → 吞掉转义反斜杠 → `ConvertFrom-Json` 抛错；连锁导致误杀健康 Vite + 端口占用 + 永不注册 | 已修：`-Encoding UTF8` + 心跳新鲜则反查端口复用 + 杀进程后轮询等端口释放 | **PS1 读任何 JSON 一律显式 UTF-8**；中文字节奇偶性是真实故障源 |
| 6 | 项目已注册但浏览器仍报"管理服务尚未启动" | 第 7 步只 register，**没 PUT active**；而全局单例的 activeProjectId 还停在别的项目 | 已修：注册后紧跟 `PUT /api/projects/active` | 全局单例的共享状态：注册 ≠ 激活 |
| 7 | **所有**项目启动都卡第 7 步 60 秒超时 | 关机/强杀后 `~/.axhub/make/.admin-server-info.json` 残留死实例记录，Make 单例校验 `exit 1`；且 `Start-NodeBackground` **丢弃了 Make 的 stdout**，日志只有"无响应" | 已修：启动前把残留改名 `.stale-<ts>`；面板加「⟳ 重启 Make」 | 单例服务的残留状态要自愈；**后台进程输出绝不能丢** |

### 1.2 环境与依赖类

| # | 坑 | 要点 |
|---|---|---|
| 8 | CodeBuddy 向所有子进程注入 `NODE_OPTIONS=--require=…\node-language-shim.cjs`（路径含中文+空格），Make/ACP 启动即崩 | PowerShell 里 `$env:NODE_OPTIONS=''` **无效**（赋值晚于进程启动）；必须 `cmd /c "set NODE_OPTIONS= && <cmd>"` |
| 9 | Node 架构错配（本机 arm64 系统 node vs 受控 x64 node）→ `Cannot find module @rollup/rollup-win32-*` | 启动脚本需把受控 x64 node **前置到 PATH**，不能信系统 PATH |
| 10 | pnpm 布局：真实内容在 `node_modules/.pnpm/`，顶层只是软链 | 只看顶层会误判"原生模块缺失"；**对 pnpm 项目跑 `npm install` 会误删包**（实测一次删 67 个） |
| 11 | 曾用"删 lock 文件"解决架构问题 | 锁文件本身是双架构的，删除会破坏版本一致性 → 架构问题只用重装解决 |

### 1.3 编码与路径类（Windows 中文环境专属）

| # | 坑 | 要点 |
|---|---|---|
| 12 | PS 5.1 `Start-Process -ArgumentList` 按空格拆参数 → `Documents\AI work` 被截断 | 改用 .NET `System.Diagnostics.Process`；PS 5.1 还不能在赋值表达式里写 `if` |
| 13 | 命令行内联中文路径 → `01-项目` 变 `01-椤圭洰` | 用 UTF-8 脚本内部写字面量路径，node 执行 |
| 14 | `.cmd` 存成 UTF-8 BOM → `﻿@echo` 报错闪退；`chcp 936` + `if not errorlevel` 嵌套 → 乱码命令 | 用子函数结构 `call :killport`；不要 `chcp 936` |
| 15 | `safeName()` 用 `[^a-zA-Z0-9]` 过滤 → 三个中文项目映射到**同一个** log，openUrl 全错乱 | **Windows 路径计算禁止过滤非 ASCII** |
| 16 | `path.join` 反斜杠 vs Make 返回正斜杠 → active 永远切不过去 | 比较前统一 `norm()` |

### 1.4 前端与模板类

| # | 坑 | 要点 |
|---|---|---|
| 17 | Tailwind 4 默认不生成 `.contents` utility → grid 三栏塌成单列 | 关键布局属性用 inline style 兜底，别赌 utility |
| 18 | PrototypeLayout `fullWidth` 下父容器**没有高度** → `h-screen`/`calc(100vh-X)` 全失效 | 用 viewport 单位自建比例容器 |
| 19 | `fs.cpSync` 的 filter 用子串 `includes('\\.git')` 排除 `.git` → **误伤** `.gitignore`/`.gitkeep`（崂山项目丢 35 个点文件） | 排除目录用 `path.basename() !== '.git'` 精确匹配 |
| 20 | 模板混入运行时产物（`.axhub/sessions`/`.workbuddy`/`node_modules`/`dist`） | 模板只放框架资产；`pnpm-lock.yaml` 与 `packageManager` 必须成对 |
| 21 | `fs.cpSync` 在部分环境抛 `EIO: Access is denied` | 改用 `mkdirSync + copyFileSync` 逐文件复制 |

### 1.5 提炼：v2 铁律清单（建议直接落成规则文件）

```
T1  append 日志的"最后状态"必须按时间切片，禁止全文 includes
T2  异步启动流程必须有过渡态，reconcile 不得对未完成态判死
T3  "完成" = 所有依赖服务都健康（Vite + Make）
T4  跨进程联动必须等对方就绪标记，不能 spawn 后立即调
T5  PowerShell 读 JSON 一律 -Encoding UTF8
T6  外环境注入（NODE_OPTIONS / CODEBUDDY_*）必须显式清洗，且要写进启动模板
T7  Windows 路径计算禁止用"非 ASCII 过滤"
T8  排除目录用 basename 精确匹配，不用子串 includes
T9  永不删锁文件；依赖架构问题只用重装解决
T10 命令行禁止内联中文路径；.cmd 编码按原编码写回
T11 后台启动的进程必须把 stdout/stderr 落到 07-日志
```

## 3. 迭代方案

### 3.1 设计原则

1. **能跑的坚决不重写**：`server.mjs`（零依赖 + 全相对路径推导，可整目录搬运）与 `launch-project.ps1`（755 行，已自带端口粘滞/原生模块自愈/环境清洗/多级健康检查）**只加固**。
2. **配置单一真源**：端口、路径、项目识别规则、node 选择优先级全部进 `workbench.config.json`，脚本与文档由它生成/校验，禁止散落手写。
3. **记忆去厂商化**：主干用中立的 `Agent_Memory/`，各 agent 私有目录只做适配。
4. **有账可查**：补丁、临时脚本、文档版本都登记成册，不再"改了但没人知道"。
5. **卫生自动化**：tmp 即产即删、一次性脚本收纳即登记、导出中文名校验、回收站可还原。

### 3.3 六个专项改造

#### A. 配置单一真源 `workbench.config.json`（治 P9/P14/P15）

```jsonc
{
  "ports": { "panel": 7788, "make": 53817, "acp": 32124, "vitePool": [51720, 51729] },
  "paths": { "projects": "01-项目", "template": "02-模板/_project-template", "logs": "07-日志" },
  "projectRules": { "markers": [".axhub/make", "src/prototypes"], "exclude": ["_backups","node_modules","05-回收站"] },
  "node": { "prefer": ".workbuddy/binaries/node/versions/*", "fallback": "PATH", "minVersion": 18 }
}
```
- 排错手册的端口表 / 目录树改为**由该文件生成**，从根上消除漂移。
- 脚本启动时校验配置存在且合法，非法即红字报错。

#### B. 启动链路加固（治 P1/P2/P12）

| 措施 | 说明 |
|---|---|
| **env-doctor 前置体检** | `06-运行脚本/env-doctor.ps1` 一键输出：node 版本+架构、`NODE_OPTIONS` 是否被注入、`CODEBUDDY_*` 是否存在、4 个端口占用、原生模块架构匹配（含 pnpm `.pnpm` 布局）。红黄绿面板，启动前自动跑 |
| **环境清洗固化** | `cmd /c "set NODE_OPTIONS= && …"` 包裹写进启动命令模板，不再靠人记（T6） |

#### C. 记忆层收敛 + 自举入口（治 P3/P10/P11/P19）
