**分发就绪面：尚未达标**——存在 **4 个 P1**（发出去会出事）＋ **4 个 P2**（体验/维护问题）。核心矛盾：当前安装包把**工作台工作区（含协作数据、文档、记忆）整个内置进了安装目录**，这是给"另一台电脑上的你自己"准备的镜像，不是给"其他用户"准备的产品。

## 二、P1 问题（分发阻塞项）

### P1-1 用户数据写在安装目录，覆盖升级即毁数据
- **证据**：`extraResources` 把 336MB workbench 内置到 `resources\workbench`；建项目写 `01-项目`、回收站写 `05-回收站`、日志写 `07-日志`、`.workbuddy` 状态——全部落在安装目录内；NSIS 配置 `deleteAppDataOnUninstall: false` 只保卸载、**不保覆盖升级**（electron-builder NSIS 覆盖安装会清理旧程序目录）。
- **影响**：用户装了新版本，自己建的项目全部丢失。这是分发事故级问题。
- **修法**：数据与程序分离——安装目录只放程序+模板+组件库（只读资产），`01-项目`/`05-回收站`/`07-日志`/`.workbuddy`/`09-协作` 运行时数据迁到 `%APPDATA%\产品设计工作台\`（`server.mjs` 顶部路径推导改为 `app.isPackaged ? userData : repo`，面板需支持 `WORKBENCH_DATA_DIR` 环境变量注入——main.mjs 已经在传 `NODE_BIN`，加一个即可）。

### P1-2 安装包内混入内部协作数据与项目信息
- **证据**：内置 workbench 含 `08-文档`（1355 文件：审查报告、深挖报告、答疑手册、交接文档）、`10-智能体记忆`（34 文件）、`09-协作`（195 文件：5 个智能体的 agents 工作文档、16 个真实房间名如「崂山国家实验室项目」「学校卫生」「健康档案」）；`01-项目` 反而缺失。
- **影响**：发给其他用户＝把内部项目名、协作记录、智能体工作文档原样泄露。
- **修法**：打包脚本建立**白名单清单**（只进：`02-模板`、`03-组件库`、`04-维护台账` 精简版、`06-运行脚本`、`工作台面板`、`README`），杜绝"整目录拷贝"；`08-文档/打包输出` 加 `.gitignore`（现在未跟踪但也未被 ignore 规则覆盖，属裸奔）。

### P1-3 "检查更新"在打包版是死功能
- **证据**：`runGit` 用 `spawnSync('git', ...)` + `cwd: AXHUB_ROOT`（内置 workbench）；实测内置**无 `.git`**、tools 内**无 git.exe**；`checkForUpdates` 的 fetch/rev-parse/rev-list 会全部失败 → 用户永远看到"无法连接 GitHub"，一键更新必挂。
- **影响**：分发后无法升级（更新通道坏 + 就算修好 git，让用户电脑对安装目录做 `git pull --ff-only` 本身也不成立——见 P1-1）。
- **修法**：打包版更新与开发版**分道**：开发版保留 git 通道；分发版要么接 electron-updater（GitHub Releases + blockmap 差量，产物里 `.blockmap` 已经在生成，基础具备），要么首版先隐藏"检查更新"入口，给个版本号+手动下载提示。

### P1-4 安装包代码落后 HEAD 三个修复，跨版本断裂引发互杀
- **证据**：内置 server.mjs（md5 `5b69dde678`）缺 `9dbb253`（x-axhub-root 面板身份头）、`762b963`（监听关闭不保活）、`ff7a5bb`（房间滚动）；而 main.mjs 的 `probePanel` **依赖** `x-axhub-root` 判定 owned。
- **影响**：打包版面板不响应身份头 → `owned` 恒 false → 每次启动桌面应用都会 `killPortOwner(7788)` **强杀端口占用进程再重拉**；同机跑两个用户实例（或用户开着开发版面板）会互踩；通信看板长列表无滚动修复、监听关不掉。
- **修法**：重打包前把 `08-文档/打包输出/workbench` 从 HEAD 重新导出（见 P2-5 的可复现流程），并约定"发版 = git tag → 导出 → 打包"，禁止用工作区残留快照直接 pack。

## 三、P2 问题（分发前应处理）

| # | 问题 | 证据 | 建议 |
|---|---|---|---|
| P2-5 | **打包不可复现**：`extraResources` 指向 `08-文档/打包输出/`（336+83MB，未入 git、未被 ignore 规则命中）；tools 的 portable node 83MB 来源无记录 | `git ls-files` 0 命中；`git check-ignore` 未命中 | 建 `npm run export-workbench` 脚本（HEAD checkout→裁剪→落打包输出）；portable node 记录版本与下载源；打包输出处放 `BUILD.md` |
| P2-6 | 主进程防御缺口：`api:request` 无 path 前缀/方法白名单（renderer 可拼任意 `p` 打到 7788）；无 `requestSingleInstanceLock`（多开→互杀 7788，叠加 P1-4 更糟）；无 `setWindowOpenHandler`/CSP | main.mjs 走查 | 单实例锁必加；path 校验加一行 `startsWith('/') && !p.includes('//')`；file:// 加载风险低，CSP 可后置 |
| P2-7 | 版本号混乱：`package.json` 3.1.0，但 dist 里 3.1.0 与 4.2.0 双安装包并存（4.2.0 是更早的设计稿 v4.2.0 误用命名），根级还有未跟踪的 `工作台启动程序.exe`（5.6KB，身份无文档） | 产物目录 + git status | 删旧包只留最新；根级 exe 要么入 git+README 说明，要么清理；发版走 tag 对齐 |
| P2-8 | 国内网络首装风险：Vue 工程首次 `pnpm install` 回退 `npx -y pnpm@10 install` 走默认 registry，无镜像配置（对比 desktop-launcher 给 electron 配了 npmmirror） | server.mjs L1651/L1815 | 回退路径同样注入 `--registry=https://registry.npmmirror.com`，或把 pnpm.cjs 直接内置 tools |

## 四、实测通过项（正面清单）

1. **HEAD 面板 API 11/11 通过**：ping（含 x-axhub-root 身份头 ✓）、projects、upstreams（4 项目含无 framework 标记的崂山/结构监测——10-01 改造的过滤修正在真实链路生效 ✓）、update/status、update/config、templates（46 模板 ✓）、collab/overview（16 房间+5 agents，4.3KB ✓）、trash、knowledge、404 探针。
2. **通信看板数据真实**：agents 心跳字段在位（codebuddy/deepseek/doubao… lastSeen 有值）。
3. **渲染层安全实践合格**：`WB.api` 统一代理（45 处调用、零直接 fetch/XHR）、`esc()` 三字符转义、模板插值可疑面 0。
4. **主进程路径推导正确**：`WORKBENCH_ROOT` 双模式（dev=仓库根、packaged=resources/workbench）、内置 node 注入 PATH、面板拉起失败有兜底日志、`killPortOwner` 用 netstat 解析（绕开 Get-NetTCPConnection 模块坑——历史修复在位）。
5. **启动脚本编码正确**：`启动桌面应用.cmd` 纯 ASCII 壳 + `desktop-launcher.ps1` UTF-8 BOM 承载中文（历史裁决的 A 方案），首次自动装依赖并配 npmmirror。
6. **dev 模式 Electron 实测**：主进程正常启动、窗口加载 file:// renderer、CDP 就绪；GPU cache 报错为 dev 噪声非缺陷。

## 五、测试未尽项（如实声明）

- **UI 视图切换逐项点击**：CDP 脚本在视图切换阶段超时未完成（脚本自身 WebSocket 等待问题，非应用缺陷——首屏与导航渲染已被截图与文本量采集证实正常）。安装包 exe 的实机安装/升级/卸载**未测**（避免动本机程序目录），其结论全部来自产物静态解剖。
- 建议补测路径：在**无 git、无 node、无 pnpm 的干净 Windows 账户/虚拟机**里装 4.2.0→覆盖"新版"，看 P1-1/P1-3 是否如分析复现。

## 六、给"开箱即用"的最小改造顺序

1. **数据外置**（P1-1，改路径推导）→ 2. **白名单打包**（P1-2/P2-5，export 脚本+ignore）→ 3. **从 HEAD 重导重打包**（P1-4）→ 4. **更新通道决策**（P1-3，electron-updater 或先隐藏）→ 5. 单实例锁+path 校验（P2-6）→ 6. 镜像兜底（P2-8）→ 7. 版本/文件清理（P2-7）。

其中 1、2、4 是产品决策（数据放哪、怎么升级、发给谁用），需要你拍板方向后我可以出细化方案或直接列任务书交豆包。
