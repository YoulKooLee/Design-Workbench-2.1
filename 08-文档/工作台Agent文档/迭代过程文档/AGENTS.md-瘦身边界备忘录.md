## 二、决策：需求文档路由（`## 需求文档技能路由` 段，~4.4K 字符）**不外置** ✅

**结论：保持留在 AGENTS.md，不搬到 `.agents/`。**

理由（写死，后续判断以此为准）：
1. **预加载 vs 按需读**：AGENTS.md 的内容在会话启动时**预加载进 Agent 上下文**；`.agents/` 下文件是"按需读"。需求文档路由（req-doc / prd-writer / prototype-to-prd 的 6 级优先级、冲突裁决、PRD→SRS 门禁）是**高频裁决规则**——每次需求文档任务都必须看到。外置 = 变成可跳过，路由错误风险上升。
2. **与 AGENTS.md 既有原则自洽**：AGENTS.md 明确"技能 description 已由运行时预加载，严禁遍历 SKILL.md"。技能匹配不依赖 AGENTS.md 详表（所以详表可以压缩）；但**路由/门禁/铁律是裁决规则，必须预加载**。两者性质不同。
3. **可外置的是"参考型正文"，不是"裁决规则"**：技能详表（参考，已压缩为索引）、技能正文（在 `.agents/skills/`）可外置；路由表、门禁、铁律、编排规则不可外置。

## 三、瘦身边界（防越界清单）

- ✅ 可压缩/外置：技能详表（参考型，靠运行时 description 匹配）、旧路径残留、重复示例
- ❌ 不可动（除非有预加载替代方案）：`需求文档技能路由` 段、`交付铁律`、`执行优先级`、`知识库与 Hook 门禁`、`子 Agent 编排`、`记忆分层与门禁`

## 四、未来若再被提"AGENTS.md 太大"

1. 先引用本备忘录第二节（不外置的理由不变）
2. 若确需再瘦：候选是「核心工作流」细节表（可外置到 `.agents/rules/` 并在 AGENTS.md 留一句入口），**不得**动路由/铁律
3. 评估基线：AGENTS.md 目标 ≤ 30KB 需整体方案（如把交付模式、编排细则挪 `.agents/rules/`），属排期项，需用户拍板
