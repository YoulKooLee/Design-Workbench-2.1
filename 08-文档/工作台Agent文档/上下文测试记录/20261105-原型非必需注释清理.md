## 五、返工归因

### 返工 1：验证脚本连点两次「下一步」跳到第三步

- **现象**：第一次跑脚本，`CFG_CHECK.hasFieldsHead: false`、`hasAddBtn: false`，截图显示停在「入参配置」（第三步）。
- **原因**：脚本为了「确保进入第二步」写了两次点「下一步」的调用，第一次成功进第二步后，第二次又推进到第三步。
- **修法**：改成只点一次，并先断言按钮 `disabled` 状态。
- **教训**：验证脚本里对分步向导不要用「多点几次保证到达」这种兜底逻辑，会直接跳过目标步骤。**要断言当前步骤，而不是盲目推进**。

### 返工 2：`hasTipOut: true` 的假阳性

- **现象**：第二步截图已确认标题行提示消失，但断言 `body.innerText.includes('勾「是否使用」的字段进入指标出参')` 仍为 `true`。
- **原因**：右侧「设计说明」面板的卡片（`index.tsx` 的 `cfg-fields` 卡）正文里也有这句话，属于 `body.innerText` 的一部分。
- **结论**：不是残留，是断言范围太宽。**判断界面元素是否存在，要限定到内容区选择器，不能用整页 `body.innerText`**；或者像本次一样用截图二次确认。

## 三、踩坑（本轮新增 5 条）

48. **批量删 JSX 元素必须处理「块里只剩提示」的情况**。`{cond && (<div className="dcalc-hint">…</div>)}` 删掉 div 后剩下空块 → `SyntaxError: Expression expected`。本轮出现 4 处（`dim-calc-preview` / `pages-indicator-rule` ×2 / `pages-datasource-interface` / `pages-system`）。**修法**：删元素后若父级是 `cond && (...)` 或三元分支，整块替换成 `null` 或干脆删条件；不能只删内层元素。
49. **`tsconfig` 未开 `noUnusedLocals` → 删代码后死变量不报错**。本轮 `dim-calc-preview` 删了 `{hidden > 0 && …}` 提示块后 `hidden` 变量仍被 `series.length + hidden` 使用（幸运命中），但若真成了死变量 `tsc` 不会提醒。必须靠 Grep 兜。
50. **dev server 转换缓存拿到空 `code` 会伪装成「模块没有导出」**。删完 106 处后 `tsc` 全绿，但浏览器白屏 + `SyntaxError: does not provide an export named 'SHAPES_FOR'`。`Invoke-WebRequest` 直拉模块只有 1,341 字节（正常 85,030），只剩注入插件 4 行常量。**修法：改一处注释（加个 `// touch` 再删掉）触发重新 transform，不重启 dev server。**
51. **CDP 逐页验证要用真实 page key**。首轮用了臆造的 `ind-list` / `ind-config`，17 页全部 `textLen: 0` 且无报错——因为 hash 不匹配路由，渲染成空壳。真实 key 是 `indicator-list` / `indicator-config` / `approval-config` 等（见 `index.tsx` 的 `defineHashPageRoute`）。**判定「页面是否真空」不能只看 `errs`，要看 `textLen` 与 `[data-proto-id]` 数量。**
52. **脚本干跑（`--dry`）能提前暴露破坏性删除**。两轮都先 `--dry` 看到分布再执行；第二轮干跑时发现 `pages-api` / `pages-datasource` 命中 1-2 处但全是数据计数，从而把「保留清单」写进脚本 `KEEP_IF`，避免误删「共 N 个接口」。
