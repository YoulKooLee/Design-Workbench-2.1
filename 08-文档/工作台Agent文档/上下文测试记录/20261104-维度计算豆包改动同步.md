## 9. 发现的问题（未修，待定）

### P1 · 指标列表里仍有 2 条「指标计算」指标，规则 chip 全不选中

`data.ts` 里 `rule` 取值分布：维度计算 5 / SQL开发 1 / **指标计算 2**。

被删掉规则的两条指标：
- `ZB-2026-000058` 应急值班到岗率
- `ZB-2026-000065` 设备在线率反算校验

实测（CDP）：从列表点「应急值班到岗率」→ `指标配置`，**SQL开发 与 维度计算 两个 chip 都是白底（`active` 均 false）**，但下方渲染的却是维度计算面板。

成因：`pages-indicator-config.tsx:50`
```ts
const initRule: RuleKind = (editing?.rule as RuleKind) || 'SQL开发';
```
`'指标计算'` 被强制断言成 `RuleKind`，绕过了类型检查（tsc 因此不报错），传给 `RulePicker` 的 `value` 匹配不到任何 chip。

**影响**：这两条指标打开配置页时，用户看不到自己指标的规则是哪一个，面板显示与规则标签不一致。

### P2 · 我上一轮的字段口径改动被覆盖

上一轮确立的三件事在重写中丢失：
1. 原始列 / 结果列双 `<optgroup>` 分组
2. 选中结果列时的二次聚合告警
3. 「分堆」话术与 `· 分 N 堆` 提示

代码里 `colFields`、`metricIsCol` 仍被定义但**没有任何地方使用**（第 126–134 行），属死代码。

**影响**：用户无法分辨下拉里哪些是表字段、哪些是已建指标算出的派生列——正是上一轮用户提的那个问题。

### P3 · 新面板用列名正则猜时间字段，与我上午演示页的结论冲突

```ts
const timeFields = rawFields.filter((f) => /date|time|month|year|day/i.test(f.en) || ['Date','DateTime','Month','Year'].includes(f.type));
```

这正是上午盲数据演示页验证过的「靠形状猜含义」做法。当前 mock 数据字段名规范（`update_time`/`create_time`），所以能猜对；真实接口字段名是 A/B/C/D/E 时，这条规则会全部失效，时间选项整块不可用。
