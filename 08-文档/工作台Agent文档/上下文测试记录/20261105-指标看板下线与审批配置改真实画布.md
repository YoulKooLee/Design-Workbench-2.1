## 一、指标看板：删页面要删 12 处

只把路由删掉是不够的。这个原型的页面注册分散在六七个地方，漏一处就是编译红或菜单里挂死链：

| 位置 | 漏了会怎样 |
|---|---|
| `ui.tsx` `PageKey` 联合类型 | `tsc` 直接报 `PageKey` 不含 `'dashboard'` |
| `ui.tsx` `MENUS` | 侧栏还留一个「指标看板」入口，点进去空白 |
| `ui.tsx` `PAGE_TITLES` | 类型要求全量 Record，少一个键编译红 |
| `ui.tsx` `Sidebar` 的 `open` 初始态 | 无害但留脏数据 |
| `index.tsx` route 数组 | 路由不存在，`#page=dashboard` 落空 |
| `index.tsx` `CRUMBS` | 面包屑少一项 |
| `index.tsx` `buildModules` 分支 | 右侧设计说明面板留着 6 张死卡 |
| `index.tsx` `PageView` case | 编译红（`DashboardPage` 已删） |
| `index.tsx` `defaultPageId` | **首屏直接落空**，进站白屏 |
| `annotation-source.json` 目录节点 | 批注工具目录里留一个死路由 |
| `data.ts` `menuTree` | 菜单权限页仍能勾一个不存在的菜单 |
| `pages-system.tsx` `basePerms` | 同上，权限模板里留残键 |

另外 `data.ts` 的 5 组看板数据（`dashboardStats` / `alertDirDist` / `alertLevelDist` / `alertTrend` / `indicatorGraph`）与 `style.css` 的两处看板样式也一并清了。

`defaultPageId` 是这一组里最容易漏、后果最重的一个——它不参与编译、不影响菜单，但只要忘了改，登录后首屏就是空白。本轮改成 `topic-library`，登录成功回调里的 `setPage('dashboard')` 也同步改成 `setPage('topic-library')`。

`style.css` 里有一组 `.dash-row` 样式，名字看着像看板，实际是「虚线行」的缩写（指标配置页用），已确认无引用后**保留**——按名字猜会误删。

## 二、审批配置：从静态演示改成真画布

改前的问题很直接：节点坐标是写死的，SVG 连线是手画的四条 `<line>`，左侧四个组件挂在 `cursor: grab` 上但没有任何拖拽逻辑。用户看到的「拖拽」只是鼠标指针变了。

改后按用户的四条要求逐条落地：

**① 画布固定有开始节点和结束节点**
- 这两个节点在 `DEFAULT_NODES` 里，`isFixed()` 判断 `kind === 'start' | 'end'`
- `onNodeDown` 里对固定节点直接 `return`，不进入拖动分支
- 视觉上用虚线边框区分，鼠标移上去不出现删除按钮
- 组件库只列审批、授权两项，下方一行说明写清「开始节点与结束节点已固定在画布上，不可添加、移动或删除」——否则用户会以为漏配了

**② 组件只能添加审批节点和授权节点**
- `PALETTE` 只有 `['approve', 'grant']`
- 投放时二次校验 `if (kind !== 'approve' && kind !== 'grant') return;`，防止外部拖入的 dataTransfer 伪造类型

**③ 真实可拖动**
- `mousedown` 记下鼠标相对节点左上角的偏移 `dx/dy`，`mousemove` 时用画布 `getBoundingClientRect()` 换算成画布坐标
- 位置用 `clamp` 夹在 `[0, CW-NW] × [0, CH-NH]`，节点不会被拖出画布
- 监听器挂在 `window` 上而不是节点上——鼠标拖快了会跑出节点边界，挂在节点上会丢事件

**④ 审批节点到下游节点可加条件：审批通过 / 审批不通过**
- 条件不单独建「条件节点」，而是作为连线的属性存在：`passTo` 与 `rejectTo` 两个字段
- 连线按这两个字段现算（`useMemo`），所以删节点、改流向时不会留下悬空线
- 通过绿 `#10b981`、不通过红 `#ef4444`，连线中段有胶囊标签，箭头用 SVG `marker`
- 右侧面板分别是两个下拉，选下游节点

**简化**：审批节点只留四个配置项（名称、审批角色、审批人、两条分支）；授权节点只留两个（名称、有效期）。原来的「自动节点」改名为「授权节点」——用户说的「授权节点」语义更准，就是这个节点在拿到审批通过后写授权关系。

**校验**：审批节点的两条分支必须都选、且不能指向同一节点。不满足时画布底部状态条显示红字具体原因，点「保存配置」不落库、弹提示。这一层是必要的：一条分支没配，流程跑到那里就断了。

## 三、截图发现的两处视觉问题

### 3.1 条件标签「审批不通过」被截断

首版：

```tsx
<rect x={mid.x - 26} y={mid.y - 10} width={52} height={20} rx={10} ... />
```

「审批不通过」5 个字、字号 11.5，实宽约 57.5，塞进 52 的框里末字被裁。

关键是**DOM 断言查不出来**：脚本判的是「`svg text` 里有几个、文字对不对」，文字确实在 DOM 里、内容也对，只是被 `rect` 盖住看不见。这类问题只有截图能发现。

改成按字数算宽：

```tsx
const label = e.cond === 'pass' ? '审批通过' : '审批不通过';
const w = label.length * 11.5 + 16;
```

### 3.2 新增节点压线

首版双击投放固定给 `CW/2, CH/2`——第二次加节点就叠在既有节点和连线上。

改成「全画布扫空格」后更糟：空格扫描从左上角开始，新节点跑到左上，它到结束节点那条虚线横穿整块画布。

最终方案是让落点跟流程位置一致：

```tsx
const findFreeSpot = () => {
  const tail = chainTail(nodes);              // 主链末端（从开始节点沿 passTo 走到最后一个）
  const baseX = tail ? tail.x + NW + 44 : 40; // 接在末端右边一格
  const baseY = tail ? tail.y : 60;
  const cands = [
    { x: baseX, y: baseY },
    { x: baseX, y: baseY + NH + 46 },         // 右边满了往下挪
    { x: baseX, y: baseY - NH - 46 },         // 再往上
    { x: baseX - NW - 44, y: baseY + NH + 46 },
    { x: 40, y: CH - NH - 20 },
  ];
  // ...AABB 粗判是否撞已有节点
};
```

新增节点的逻辑同时也把主链接续了：`chainTail` 找到的末端节点的 `passTo` 改指向新节点，新节点 `passTo` 指向结束。所以新增之后流程仍是连通的，不会出现「加了个孤岛」。

## 五、踩坑

1. **删页面要列清单，不能想到哪删到哪。** 这个原型的页面注册分散在 12 个位置，靠记忆删一定漏。固定做法：先在整目录 `grep 页面名`，把命中处逐条对照「漏了会怎样」，删完再 `grep` 一次确认零命中。
2. **`defaultPageId` 不参与编译，漏了就是白屏。** 它不在 `PageKey` 约束范围内，类型检查发现不了。凡删首页，必须单独确认这一处。
3. **按名字猜会误删。** `.dash-row` 看着像看板样式，实际是指标配置页的「虚线行」。删样式前要 `grep` 类名的使用处，不能按字面判断。
4. **SVG 里装可变文字的 `rect` 不能给固定宽度。** DOM 断言只看文字在不在，看不见文字被裁；要么按字数算宽，要么截图目视。
5. **新增节点的落点要跟流程语义一致。** 「找一块空地放下」在流程图上是不对的——用户会以为它在流程外。新节点接在主链末端，位置就该在末端旁边，否则那条线一定要横穿画布。
6. **用户拍板可以被推翻，但推翻要留痕。** J10 当时明确「画布不做」，本轮改成要做。旧结论不能直接当没写过，也不能照着旧结论说「这是欠账」，要在基线变更登记里写清「何时、由谁、为什么推翻」，否则后续接手的人会对不上账。
7. **`window` 上挂 mousemove 而不是节点上。** 拖快了鼠标会跑出节点矩形，事件就丢了，节点会「粘」在鼠标上一次的位置不动。
